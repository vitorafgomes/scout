---
name: git-commit
description: use this when the user wants help writing a commit message, structuring commits, or following git commit conventions
---
Write commit messages that explain intent:

1. Subject line in the imperative mood, under ~50 characters, no trailing period.
2. Use a conventional prefix when the project does (e.g. feat, fix, refactor, test, docs).
3. Leave a blank line, then a body that explains why the change is needed and any trade-offs.
4. Reference issues or context, but keep the body focused on this change.
5. Prefer small, atomic commits over one large mixed commit.

Do not add attribution or co-author trailers unless the user explicitly asks for them.
