Wiki/About this wiki

About this wiki

A Karpathy-style LLM wiki, tuned for engineering and rendered as static HTML inside the Scout repo.

reference statusactive version 1.0 date 2026-06-01 sources GamifYou LLM Wiki Template; Scout README; Obsidian vault scout/

This wiki adapts the three-layer LLM-wiki pattern to Scout. It is the cheap context layer: a teammate or an agent should be able to answer most questions here before grepping src/. Where the wiki cannot answer, read the code, then fold the finding back into the relevant page.

Page-type taxonomy

Every content page declares a page_type in its metadata header. The badge colour matches the type.

TypeFolderPurpose
serviceservices/One page per active backend project: responsibility, contract, dependencies, hot spots.
adrdecisions/Accepted architecture decision, numbered NNNN-slug. Superseded, never deleted.
invariantinvariants/A rule the code must preserve, with enforcement sites and the tests that prove it.
conventionconventions/How we write and ship code: testing, style, secrets, commits.
runbookrunbooks/An operational procedure with steps, verification, and rollback.
roadmaproadmap/An initiative or backlog. Forward-looking and date-stamped.
domaindomain/Anchor page for a term Scout overloads, linked from everywhere it is used.
overview / referenceoverview/, history/Project snapshot, vision, and retrospectives on completed efforts.
incidentincidents/Per-incident note. Scout is pre-alpha, so this is currently a stub.

The metadata header

HTML has no front-matter, so each page opens with a .wiki-meta block — the visual analog of the YAML front-matter used by the Markdown template. It carries:

  • page_type — the badge, from the taxonomy above.
  • status — active, accepted, proposed, deprecated, stub, or archived.
  • version and date — start at 1.0 on creation; the date is the creation date.
  • sources — where the content traces back to. Nothing on a page is written from memory alone.

Conventions

Read first, code second

Before any non-trivial change, read the affected service page, the invariants it links, and any related ADR. A change that violates an invariant needs either a revision or a superseding ADR.

  • Cross-links are inline (the HTML analog of wikilinks); every page ends with a Related footer.
  • This wiki is the in-repo HTML render. The editable source of truth for design records remains the Obsidian vault at obsidian-vault/scout/.
  • ADRs are renumbered 0001..0013 here in chronological order; the vault keeps them date-named.
