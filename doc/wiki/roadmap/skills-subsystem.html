Wiki/Roadmap/Skills Subsystem

Skills Subsystem — Improvement Initiative

Make Scout's Skills auto-injection actually reach the model, then tune what reaches it: fix the agent-path prompt gate first, switch to card-mode injection, retune retrieval for a weak embedder, rewrite the bodies for read-only chatops, and add an LLM-driven selection fallback.

roadmap statusactive version 1.0 date 2026-06-01 sources vault 02-architecture/skills-subsystem-improvement-roadmap.md

Why now

A multi-agent review workflow (scout-skills-optimization: 14 agents across 6 dimensions, each recommendation adversarially verified against the code) produced 30 recommendations, all 30 actionable, on branch feat/project-knowledge. The review surfaced one finding that invalidates the entire feature as shipped.

The gate (critical finding)

The auto-injected skill content — and the base persona prompt — never reach the model on the shipped config. When a project is configured (the live setup), ChatGateway routes through StreamAgentAsync, which calls _agent.InvokeStreamingAsync(messages, thread, options: null, ct) and never references request.SystemPrompt. The composed base prompt plus injected skill body built in LlmStreamingRouter.StreamWithToken is discarded every turn; the response uses only the Project Expert agent's own Instructions. In effect, all embedding-based Skills auto-injection was a silent no-op whenever a project was active.

Until the gate is fixed, every downstream retrieval improvement is invisible to the model, so the initiative is sequenced around it.

Scope

In scope

  • Honoring request.SystemPrompt on the agent path so the composed prompt and injected skill content reach the model.
  • Retrieval tuning for the weak selection embedder (asymmetric prefixes, name-aware indexing, threshold calibration, per-turn selection logging).
  • Switching auto-injection from full body to a condensed card, with load_skill as the single source of the full body.
  • Rewriting the 7 skill bodies and descriptions for Scout's read-only chatops persona.
  • An optional LLM-driven selection fallback, structured injection framing, and a shared skill store with operator-triggered reload.

Out of scope

  • list_skills grouping/scaling — the catalog is 7 skills, so near-zero ROI; deferred.
  • Replacing the embedding/LLM models themselves — the work uses the right lever per model (see below), not a model swap.
  • OTel exporter wiring — spans/metrics are dropped today (no exporter registered); only the lower-priority config bucket touches it.

Model split (use the right lever)

The subsystem leans on two models with very different strengths; each workstream targets the appropriate one.

nomic-embed-text (weak)
Drives SELECTION — which skill fires. Levers: asymmetric task prefixes, name-aware indexing, threshold calibration.
qwen3.5:9b (capable)
Drives everything downstream — LLM classification fallback, calling list_skills/load_skill, absorbing larger or multiple bodies.

Status

As of 2026-06-01, sourced from the improvement roadmap (branch feat/project-knowledge):

  • Gate fix (A) — in progress; it is the hard dependency for the entire auto-inject roadmap.
  • Quick wins and bigger moves B–G — planned and ordered, not yet executed.
  • All 30 recommendations are actionable and were adversarially verified against the code during the review.

Workstreams / Phases

A Gate fix — honor SystemPrompt on the agent path

Do first. Without it nothing reaches the model. Unblocks everything below.

  • In ChatGateway.StreamAgentAsync, pass request.SystemPrompt via ChatCompletionAgentInvokeOptions.AdditionalInstructions. Verified settable property in SK 1.77.0 Agents.Abstractions.
  • Guard null/empty so the agent's own Instructions still apply.

QW Quick wins (small effort)

  • Add a Scout:Skills section to appsettings.json — the contract is invisible today though the binding already exists. Optional: clamp TopN >= 0 and 0 <= SimilarityThreshold <= 1 in AddScoutSkills.
  • nomic asymmetric prefixes: search_document: on skill text, search_query: on the message; add QueryPrefix/DocumentPrefix to SkillsOptions. Biggest selection lever for the weak embedder.
  • Embed name + description, not description alone — Skill.Name carries the discriminating token; one-line change in BuildIndexAsync.
  • Log per-turn selection (top skill, score, threshold, cleared?, runner-up). Names and scores only, never message text. Prerequisite-evidence: cannot retune 0.55 / TopN without it.
  • Add a skills clause to the system prompt telling the model list_skills/load_skill exist. Depends on the gate fix; qwen-dependent.
  • Remove dangling sub-file refs (Scout has no file-read tool) in 5 skills. Subsumed by the body rewrite.
  • Telemetry on the tool path via ILogger<SkillsPlugin>: log list_skills count, load_skill name + hit/miss.

D Inject a condensed skill card, not the full body

Do early, right after the gate, to stop dumping multi-KB bodies into every turn.

  • Add SkillsOptions.InjectionMode {Card|FullBody}, default Card.
  • Card emits Name + Description plus a "load via load_skill" pointer; load_skill becomes the single source of the multi-KB body.
  • Resolves the auto-inject vs tool double-surfacing.
  • Router must receive IOptions<SkillsOptions> (Compose is static). qwen-dependent.

C Rewrite descriptions as retrieval keys

The description is the entire retrieval signal today.

  • Remove literal quotes in brainstorming.md:3.
  • Sequence after the logging, with name + description indexing in place; re-validate the threshold from real scores.

B Rewrite skill bodies for read-only chatops

Large. The 7 bodies are verbatim Claude-Code process guides.

  • They are full of git commit / "delete the code" / "dispatch a subagent" imperatives that contradict Scout's read-only persona.
  • Treat as Scout-owned: keep the mental models, drop write/exec/subagent/DOT-digraph content.
  • Update SKILLS-ATTRIBUTION.md to "adapted from". Subsumes dangling-refs and body-trim.

E LLM-driven selection fallback

Add when selection robustness is wanted. Latency-gated: runs before the first token.

  • Cheap embedding pre-filter; on empty / grey-zone, ONE qwen classification call over list_skills.
  • Implement as an ISkillSelector decorator, not a ctor edge into SkillSelector — avoids the kernel-to-embedder DI cycle; resolve IChatGateway lazily.
  • Gate behind LlmFallbackEnabled + GreyZoneThreshold.

F Structured delimiter + budget / dedup

Matters once TopN > 1; after D.

  • Replace # Relevant skill: (collides with skills' own #) with <skills><skill name="..."> plus a framing preamble neutralizing imperative language.
  • Add a MaxInjectedBytes budget and dedup-by-Name.

G Lifecycle: shared ISkillStore + hot-reload

Lowest user-visible payoff; do last.

  • Collapse the two ResolveDirectory / file-load implementations into one singleton.
  • Add operator-triggered reload — preferred over FileSystemWatcher, which would watch the build-output copy rather than the source.

Sequencing

A (gate) first — without it nothing reaches the model. Then D (card mode) to stop dumping multi-KB bodies, then logging to get real scores, then C + name/description indexing + prefixes tuned from those scores, then B (body rewrite). E (LLM fallback) when selection robustness is wanted. F follows D once TopN > 1; G is last.

Lower-priority config

  • Frontmatter metadata (enabled/priority/channels) — the parser already builds the dict but drops extra keys — feeding channel scoping (message.ChannelId is currently dropped in Route).
  • A skills_status KernelFunction.
  • A ScoreAllAsync threshold-calibration probe.
  • OTel spans/metrics are dropped today (no exporter registered): ILogger half works, Meter half does not.

Risks

  • The gate is a hard dependency. If A is skipped or regresses, every retrieval improvement (B–G) silently does nothing whenever a project is active — exactly the failure mode that motivated this initiative.
  • Weak selection embedder. nomic-embed-text is the limiting factor on which skill fires; prefixes, name-aware indexing, and threshold calibration are mitigations, not a guarantee. Retuning cannot proceed without per-turn selection logging first.
  • DI cycle on the LLM fallback. A ctor edge into SkillSelector would reintroduce the kernel-to-embedder DI cycle; the decorator + lazy IChatGateway resolution is mandatory.
  • Read-only persona drift. The unrewritten bodies carry write/exec/subagent imperatives that contradict No Executive Writes; until B lands, injected content can nudge the model toward forbidden actions.
  • Latency on the fallback path. The qwen classification call in E runs before the first token, so it is latency-gated behind LlmFallbackEnabled + GreyZoneThreshold.
