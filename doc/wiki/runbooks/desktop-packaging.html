Desktop Packaging

Run this when you need to produce distributable Scout Desktop installers from the ui/ workspace with electron-builder — and to confirm the Linux build always ships an AppImage.

runbook statusactive version 1.0 date 2026-06-01 sources ui/README.md; README Desktop UI

When to run this

Scout Desktop is the Electron 41 provisioning shell for the read-only chatops bot: it detects installed chat clients, runs per-platform provisioning wizards, and supervises the local Scout.Host.Console worker as a child process. Packaging turns that workspace into platform installers via electron-builder. Reach for this runbook when you want to:

  • Produce a Linux build — an AppImage plus a .deb (x64).
  • Produce a macOS build — a DMG (arm64 + x64).
  • Produce a Windows build — an NSIS installer (x64).
  • Package quickly for the current host machine while developing.
Release invariant. Every Linux release must ship an AppImage. ui/README.md states AppImage is always produced on Linux builds and calls it a release invariant; do not drop it from the dist:linux target.

Preconditions

  • Bun 1.3 or newer installed (the workspace toolchain drives install, scripts, and tests). Install from https://bun.sh/.
  • .NET SDK matching ../global.json (currently 10.x), because the published Scout.Host.Worker is bundled as the supervised child process.
  • Dependencies installed from the ui/ workspace with bun install.
  • Cross-platform note: electron-builder targets are built on their matching OS — DMG on macOS, NSIS on Windows, AppImage/.deb on Linux. CI runs the matrix across Ubuntu, macOS, and Windows.
  • Awareness that all artifacts are UNSIGNED in this repo — do not distribute them as official releases until signing and notarisation are set up.

Steps

1. Enter the UI workspace and install

All packaging commands run from ui/. Install once (or after dependency changes).

# from the repository root
cd ui
bun install

2. (Optional) Build the worker and renderer first

The workspace root bun run build chains the packages in the correct order (shared → preload → renderer → main). electron-builder consumes those outputs, so a clean build before packaging avoids stale bundles. 

# workspace root build: shared -> preload -> renderer -> main
bun run build

3. Package for a target

Choose the target that matches what you need. Artifacts land under ui/build/dist/. 

# package for the current host platform
bun run dist

# Linux: AppImage + .deb, x64
bun run dist:linux

# macOS: DMG, arm64 + x64
bun run dist:mac

# Windows: NSIS installer, x64
bun run dist:win

Target matrix

dist
Packages for the current host platform only. Use during local development.
dist:linux
AppImage + .deb, x64. The AppImage is a mandatory release artifact.
dist:mac
DMG for arm64 and x64. Build on macOS.
dist:win
NSIS installer, x64. Build on Windows.

Verification

  • The packaging command exits with status 0 and writes artifacts under ui/build/dist/.
  • For dist:linux, both an .AppImage and a .deb are present — the AppImage is non-negotiable per the release invariant.
  • For dist:mac, a .dmg is present (covering arm64 and x64); for dist:win, the NSIS .exe installer is present.
  • Remember the artifacts are unsigned — verification here means "the package was produced", not "the package is release-ready".

CI provides an independent check: every push to main and every PR touching ui/** or the .NET worker runs .github/workflows/ui-ci.yml on Ubuntu, macOS, and Windows. That job lints, typechecks, tests, publishes the worker binary, and packages the unsigned artifacts, which are then downloadable from the workflow run page.

Troubleshooting

  • "Preload not found" at startup of a packaged build. Build the preload before packaging: bun run --cwd packages/preload build, then let the renderer and main builds follow (or just run the workspace-root bun run build from step 2).
  • SingletonLock stuck from a previous crash. The app self-recovers from a dead-PID lock on startup; if it persists, remove ~/.config/@scout/desktop/SingletonLock* manually and relaunch.
  • Missing or wrong .NET worker. The worker is published into the bundle, so a mismatched .NET SDK (not matching global.json) can break the supervised child process.

Rollback

Packaging is non-destructive: it only writes into ui/build/dist/ and never mutates an external system (consistent with Scout's read-only invariant). To discard a build, delete the artifacts under ui/build/dist/ and re-run the appropriate dist target. There is no deployment step to reverse — these unsigned artifacts are not published anywhere by this workflow.
