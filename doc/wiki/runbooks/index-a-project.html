Wiki/Runbooks/Index a Project

Index a Project

Run this when you want Scout to answer questions about a local repository: it chunks the repo, embeds it, and writes the vectors into the project-knowledge database so the search_project plugin can retrieve them.

runbook statusactive version 1.0 date 2026-06-01 sources README index command; Scout:Projects config

When to run this

The console host exposes a one-shot index command that indexes a single configured project and exits immediately, without starting any chat adapters. Reach for it in these situations:

  • First-time setup — you have just added a repository to Scout:Projects and want it searchable before the host starts serving chat.
  • Full re-index — the repository has changed substantially and you want a clean pass rather than waiting for incremental updates.
  • No file-watch — Scout:Projects:Watch:Enabled is false (the default), so re-indexing is a manual step.
  • Batch / CI provisioning — you want to populate the knowledge database as a discrete step in a script, with the process exiting on completion.

If incremental file-watch re-indexing is already enabled, ongoing edits are picked up automatically and you only need this command for the initial pass or a deliberate rebuild. See Project Knowledge RAG for how indexing and retrieval fit together.

Preconditions

  • .NET SDK 10.0.100 or later is installed (pinned in global.json with rollForward: latestMinor).
  • The repository to index is registered under Scout:Projects — either as an explicit Items entry or discoverable under a Roots directory (see below).
  • The configured LLM provider can produce embeddings. With the default Ollama provider, Ollama must be running locally (default http://localhost:11434) with the embedding model available (nomic-embed-text by default).
  • The process can write to the knowledge database location (see Verification).
  • You are running from the repository root, where Scout.slnx and src/ live.

Steps

  1. Register the project. The project name passed to index must match a Name value under Scout:Projects:Items, or an auto-discovered project under one of the directories in Scout:Projects:Roots. Items entries are { "Name": "...", "RepoPath": "/absolute/path" } pairs. 
    // src/Scout.Host.Console/appsettings.json (excerpt)
"Scout": {
  "Projects": {
    "Items": [
      { "Name": "scout", "RepoPath": "/home/me/WorkSpace/Scout" }
    ],
    "Roots": [ "/home/me/WorkSpace" ]
  }
}
  2. Confirm the embedding provider is reachable. With the default local-first setup, make sure Ollama is up and the embedding model is pulled. The relevant keys live under Scout:Llm; the embedding model defaults to nomic-embed-text and the endpoint to http://localhost:11434.
  3. Run the one-shot index command from the repository root, passing the project name after the -- separator so it reaches the application rather than the dotnet CLI. 
    # index a single configured project, then exit
dotnet run --project src/Scout.Host.Console -- index <project-name>
    For the example above, <project-name> would be scout. The host does not start any chat adapter for this command; it indexes the named project and exits.
  4. Override configuration from the environment if needed. All Scout: keys can be set via environment variables using a double underscore as the separator. This is handy in CI where you do not want secrets or paths in appsettings.json. 
    # example: point the embedding provider at a remote Ollama
Scout__Llm__Ollama__Endpoint=http://ollama.internal:11434 \
  dotnet run --project src/Scout.Host.Console -- index <project-name>

Verification

Indexing writes embeddings into the project-knowledge database. Confirm the run succeeded by checking that the database file exists and has grown after the command completes: 

# Linux
~/.local/share/Scout/project-knowledge.db

# Windows
%LOCALAPPDATA%\Scout\project-knowledge.db
  • The command exits with code 0 when indexing completes — it is one-shot, so a clean exit (rather than the host staying alive) is the success signal.
  • The knowledge database file is present at the path above and its size reflects the freshly written vectors.
  • Once the host is running normally, the search_project Semantic Kernel plugin exposed by Scout.Knowledge can retrieve from the indexed content. Ask the assistant a question whose answer lives only in that repository and confirm it grounds its reply in the indexed files.

Troubleshooting

  • Project not found — the name does not match any Scout:Projects:Items Name nor any repository discovered under Scout:Projects:Roots. Check spelling and that the RepoPath is an absolute path that exists.
  • Embedding failures — the configured provider could not produce embeddings. For the default Ollama provider, verify Ollama is running and the embedding model is pulled; see Local Models.
  • No effect on running host — the index command is one-shot and does not start adapters. To serve chat, run the host without the index argument; see Run the Console Host.

Rollback

Indexing only writes into the local project-knowledge database; it never touches the source repository or any external system, consistent with Scout's No Executive Writes invariant. To discard an index, stop the host and delete the database file at the path shown under Verification; it is recreated on the next index run. Removing or correcting a Scout:Projects:Items entry, then re-running the command, replaces the indexed content for that project.
