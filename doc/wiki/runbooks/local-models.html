Local Models (Ollama)

Run this when the AI Sources / Models surface in Scout Desktop misbehaves — a runtime will not connect, a download fails, or the UI and disk disagree about what is installed.

runbook statusactive version 1.0 date 2026-06-01 sources vault 05-operations/local-models-runbook.md

When to run this

Reach for this runbook when working with the AI Sources / Models surface in the Scout Desktop app and something is broken. Typical triggers:

  • A Connected badge stays Not Connected even though Ollama or LM Studio is running.
  • An Ollama pull fails with a manifest or identity-key error, or with model not found.
  • A Whisper GGML download stalls or returns a 4xx.
  • The UI shows a model as downloaded but the file is not actually on disk (or vice-versa).

Background and rationale for this surface live in the two decisions 0007 AI Sources Screen and 0008 Local Model Downloads; this page is the "what do I do when X is broken" companion to those.

Preconditions

  • You have Scout Desktop open and can reach its DevTools (Ctrl+Shift+I on Linux/Windows, Cmd+Opt+I on macOS).
  • A local runtime is installed: Ollama (HTTP API on http://localhost:11434) and/or LM Studio (http://localhost:1234).
  • You can open a host shell to run curl, which, and (for Ollama identity) ssh-keygen.
  • You know which OS the app runs on — Whisper model paths differ per platform (see the table below).

How a Connected badge is computed

Each card's Connected state is derived, not stored. Use this to reason about why a badge is or is not lit.

CardConnected when
OllamaGET http://localhost:11434/api/tags returns 2xx
LM StudioGET http://localhost:1234/v1/models returns 2xx
Local ModelsOllama or LM Studio is Connected and LocalModelsStore.selected has at least one non-null value
Cloud (all)Always Not Connected (placeholder cards)
If a runtime is running but the badge stays Not Connected, the HTTP endpoint is not reachable from inside the Electron sandbox. Confirm from a host shell with curl http://localhost:11434/api/tags.

Steps

Pick the procedure that matches the symptom.

1. Ollama pull fails: open ~/.ollama/id_ed25519: no such file or directory

Ollama refuses to pull because its identity key has never been generated. The app handles this automatically since the 2026-05-16 build: before the first pull, the main process runs ssh-keygen to create the key. 

# what the app runs automatically before the first pull
ssh-keygen -t ed25519 -f ~/.ollama/id_ed25519 -N "" -q

If this error still fires after the upgrade, work through these in order:

  1. Confirm ssh-keygen is on PATH — which ssh-keygen should resolve. If missing, install openssh-client (Linux) or rely on Windows 10+'s built-in OpenSSH.
  2. Delete any half-written file at ~/.ollama/id_ed25519 — a zero-byte file can confuse the existence check.
  3. Re-launch the app and retry the download.

2. Ollama returns model not found

The tag is not in the registry. Check the catalog → tag mapping in local-models.component.ts against ollama.com/library. A known prior correction: qwen-3-vl-2b was originally mapped to qwen2.5vl:3b (non-existent) and now points to qwen2.5:3b.

3. Whisper download stalls or returns a 4xx

The Hugging Face URL is hard-coded to ggerganov/whisper.cpp/resolve/main/<file>.bin. If Hugging Face changes the path shape, this breaks — check the URL in packages/main/src/ipc/whisper.ts. Hugging Face also throttles unauthenticated downloads occasionally; in that case the user can simply retry.

4. UI shows a model as downloaded but disk does not (or vice-versa)

The local store flag and the disk state can diverge if the user deleted the file outside the app, or an update changed the storage layout.

  • Whisper: re-launch the app. ngOnInit calls whisperListInstalled(), which reconciles the store against the files actually on disk.
  • Ollama: there is no automatic reconciliation today. Reset the renderer mirror by hand from the DevTools console, then redo the downloads from the UI.
# DevTools console — reset the Ollama-side local store, then redo downloads
localStorage.setItem('scout:local-models',
  JSON.stringify({ downloaded: [], selected: { transcription: null, analysis: null } }))

5. Connected badge stays "Not Connected" after install

Symptom: the user installed Ollama or LM Studio after opening the app, and the badge does not refresh. There is no automatic re-scan on focus or on an interval.

  1. Click the Scan for X button on the affected card — that re-runs the endpoint probe.
  2. If it still fails, confirm the endpoint from a host shell (curl http://localhost:11434/api/tags) per the callout above.

Where to find error details

  1. Per-row inline error — appears under the offending model row in the Manage Downloaded Models screen.
  2. Logs view (/logs) — every download failure also appends to LogStore via appendDiagnostic, so the verbatim error text (e.g. pull model manifest: ...) is searchable there alongside worker stdout/stderr.
  3. DevTools console — the main process logs through Electron's logger; renderer-side exceptions surface here too.
  4. AppImage stdout — if launched from a terminal, the main process logger writes structured logs to stderr.

Verification

  • The relevant card shows Connected, or curl http://localhost:11434/api/tags (Ollama) / curl http://localhost:1234/v1/models (LM Studio) returns 2xx from a host shell.
  • The failed download retried from the UI completes and the model appears in the Manage Downloaded Models list.
  • For Whisper, the file exists under the OS-specific store and a re-launch (whisperListInstalled()) keeps it marked installed.
  • The Logs view (/logs) shows no new failure diagnostics after the retry.

Rollback

This runbook only re-syncs state and re-triggers downloads; it makes no irreversible change. If the manual Ollama store reset in step 4 leaves things in a worse state, restore the prior value of localStorage['scout:local-models'] (DevTools → Application → Local Storage) or re-launch the app and re-select models from the UI.

What this runbook does not cover

  • Worker-side transcription / inference — not built yet.
  • Cloud provider authentication — not built yet.
  • Multi-user / multi-profile isolation — storage is per-OS-user.
