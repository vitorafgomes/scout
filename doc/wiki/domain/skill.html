Wiki/Domain/Skill

Skill

A Skill is a behavioral instruction unit loaded from a markdown file — a name, a retrieval description, and an instructional body — that Scout selects by embedding similarity and injects into the system prompt before a turn runs. The model reads it as guidance text, not as a callable tool.

domain statusactive version 1.0 date 2026-06-01 sources src/Scout.Skills/; README skills

Meaning in this project

In Scout, a Skill is a process guide written in markdown — for example systematic-debugging.md, writing-plans.md, or a language guide such as csharp.md. Each file carries a frontmatter name and description and an instructional body. The retrieval system reads these files, embeds each description, and on every turn compares them against the user message by cosine similarity. The top matches (capped by configuration) have their bodies appended to the base system prompt for that single turn. The skill is therefore context the model is told to follow, woven into the prompt text.

This is the crux of the distinction from a Semantic Kernel Plugin:

  • A Skill is injected text. The model never “calls” a skill; it just reads the injected guidance. Selection happens deterministically in Scout code (embedding match), before the model runs, with no function-calling involved.
  • A Plugin is a callable Semantic Kernel function the model can choose to invoke during a turn (e.g. list_repositories, search_project). The model decides when to call it via function-calling.

Scout offers skills through both doors. The primary door is retrieval auto-injection (a skill becomes prompt text). A secondary door exposes the catalog as a Semantic Kernel plugin named Skills — list_skills and load_skill — so the model can browse and pull a skill’s body on demand. Even there the skill content is still text the model receives; the plugin is only the mechanism for fetching it.

Where it lives

Owned by

Scout.Skills

Scout.Skills defines the Skill record and owns loading (SkillFileLoader), embedding-based selection (SkillSelector), prompt composition (SkillPromptComposer), the embedding-free catalog (SkillCatalog), and the tool surface (SkillsPlugin). The markdown files themselves ship under src/Scout.Skills/skills/ and are copied next to the binary.

Referenced by

Scout.Conversation Scout.Llm

Scout.Conversation consumes skills per turn: its router calls ISkillSelector.SelectAsync with the user message, then SkillPromptComposer.Compose folds the selected bodies into the system prompt that is sent to Scout.Llm. Selection depends on the embedding generator provided by Scout.Llm. The Skills Subsystem page covers the end-to-end flow.

Key attributes

  • Name — from the frontmatter name. Used as the section header in the prompt (# Relevant skill: <name>) and as the lookup key for load_skill.
  • Description — from the frontmatter description. This is the only part embedded; it is cosine-matched against the user message to decide relevance.
  • Body — the markdown after the closing frontmatter fence. This is the instructional text injected into the system prompt; it is not embedded.
  • SourcePath — the absolute path of the source markdown file the skill was parsed from.
  • Selection is bounded and degrades silently — only skills scoring at or above Scout:Skills:SimilarityThreshold (default 0.55) qualify, and at most Scout:Skills:TopN (default 1) are injected per turn. Any failure during selection or index build yields zero skills, never an exception into the conversation.
  • Lazy, file-name-ordered loading — files are read from Scout:Skills:Directory (default skills, relative to the binary) on first use, sorted by ordinal name; malformed files (missing fence, missing name/description, empty body) are skipped with a warning.
  • Not a plugin to the model — an injected skill is prompt text, never a function the model can call. The tool-based Skills plugin is a separate, optional path for the model to fetch a body by name.

Related terms

  • Semantic Kernel Plugin — the callable counterpart. A skill is injected; a plugin is invoked. Scout exposes the skill catalog through both, but they are distinct concepts.
  • Project Knowledge — another retrieval system, but one that surfaces indexed repository chunks via the callable search_project plugin rather than injecting markdown into the prompt.
  • LLM Provider — supplies the embedding generator that powers skill selection and the chat model that receives the injected skill.
