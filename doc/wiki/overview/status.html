Status & Pending Work

Scout is pre-alpha. The core backend pipeline builds and its tests pass on CI; the Desktop UI builds on its own pipeline but is not yet release-ready. A first PR off feat/project-knowledge is still pending.

overview statusactive version 1.0 date 2026-06-01 sources README Status; vault 01-overview/pending-work.md
pre-alpha core pipeline green on CI Desktop UI not release-ready 8 LLM providers nothing pushed yet

Where things stand

The core pipeline — the LLM gateway, conversation core, chat adapters, project knowledge RAG, and skills — builds and its tests pass on CI. The Desktop UI, an Electron provisioning shell, has its own CI pipeline but is not yet in a release state. The solution file is Scout.slnx; all active source lives under src/, and everything under src/old/ and tests/old/ is deprecated legacy code outside the build.

All work to date sits on the local branch feat/project-knowledge and has not been pushed. The next milestone is to assemble the first PR against main — see Current Focus & Backlog and the Commit & PR Policy.

What builds and tests green

  • LLM gateway — eight providers selectable via Scout:Llm:Provider; build reported 0 warnings with 233 Scout.Llm tests green.
  • Conversation core — platform-agnostic, per-channel/per-user in-memory history, streaming through the gateway. See Scout.Conversation.
  • Project knowledge RAG — chunking, SQLite-backed embeddings via sqlite-vec, and the search_project plugin. See Scout.Knowledge.
  • Skills library — retrieval-based system loading markdown skills (curated adapted set plus authored roles/languages/cloud/architecture skills). See Scout.Skills.
  • Chat adapters — Discord, Slack (Socket Mode), and Teams, each self-gating on its credentials.
  • Read-only GitHub plugin — list_repositories, list_pull_requests, list_issues, get_repository. See Scout.Plugin.GitHub.

Done this session (committed, not pushed)

  • Conversation memory + grounding fix — bounded in-memory per-conversation history keyed by channel+user, agent grounded on the configured project; review passed. Only effective after a redeploy. See Conversation Memory Fix.
  • Skills library — curated 5 adapted skills plus roughly 52 authored ones; *.bkp files gitignored.
  • LLM providers — Gemini, OpenAI, AzureOpenAI, Mistral, HuggingFace, AzureAIInference, and OpenRouter added alongside Ollama, giving the eight selectable providers.
  • Doc site — overview, architecture diagram, active projects, roadmap, and an LLM Providers config section committed under scout/doc/.

In flight

  • Local auto-discovery (read). A Plan→Impl→Review workflow was running at the last context clear, adding ProjectDiscoveryService and ProjectResolutionService in Scout.Knowledge with tests. The feature reads Scout:Projects:Roots, auto-discovers repositories by marker files, lazily indexes on first search, and adds a list_projects tool. Explicit Scout:Projects:Items entries win on name clash.
  • Capability Engine Step 2. Unified persona + skill retrieval is stashed (partial). See Capability Engine roadmap and the architecture page.

Pending work — prioritised

Security (do first)

  • Rotate the three keys exposed during the session: the Gemini API key, the Discord bot token, and the GitHub PAT — they leaked through chat and local .bkp files even though the .bkp files were gitignored, not committed.
  • Delete the .bkp files from the tree after migrating config to appsettings.Development.json.
  • Stop re-adding the CopyToOutputDirectory line in Scout.Host.Console.csproj that ships the secret backup to bin/; it was reverted twice. See Secrets Never Committed and Secrets Handling.

New capability — WRITE (PR-gated + allowlist, not built)

  • A decided-but-unbuilt milestone that would reverse the read-only stance to gated-write: Scout creates a branch and commit and opens a PR proposal, but never pushes to main/dev and never merges (merge stays a human gate).
  • Guarded by an allowlist of users authorised to trigger writes, a diff-plus-confirmation step before opening the PR, a minimal fine-grained PAT, and an audit log of every write.
  • Requires updating ADR 0009 Descriptive vs Executive Writes, the doc site, and the read-only check used in review. See the No Executive Writes invariant.

Remote repo access (read)

  • Public repositories should always be readable with no config; private ones via the configured GitHub PAT, whose scope decides visibility.
  • Deep analysis of remote repos would fetch/clone and index them like Project Knowledge. The GitHub plugin is currently per-repo, requires owner/repo, and has no default. See Scout.Plugin.GitHub.

Test gaps (from the audit)

  • A guard test that loads the real src/Scout.Skills/skills/ directory and asserts every skill parses (name, description, non-empty body) — content is currently tested only via fixtures.
  • Provider boundary-failure tests (LLM endpoint timeout/5xx degrading gracefully) per the Production Readiness convention — current provider tests cover wiring and validation only.

Deploy & PR

  • Plan the first PR off feat/project-knowledge; consider squashing the noisy skills import→drop→author history.
  • Run the production-readiness-checks skill before the PR across the LLM HTTP, memory store, knowledge store, and GitHub boundaries.
  • Deploy/restart the bot so the conversation-memory and grounding fix takes effect live.
  • Confirm the active model is tool-capable end-to-end before relying on function-calling.

Minor / cleanup

  • Remove the duplicated cycle-explanation comment block in src/Scout.Llm/LlmServiceCollectionExtensions.cs (flagged repeatedly).
  • Document Scout:Projects:Roots and the "pick a tool-capable model" caveat for HuggingFace/OpenRouter on the doc site.
