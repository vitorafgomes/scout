Local-First Default

A fresh clone must run end to end with no paid credentials: the default LLM provider is Ollama, talking to a local daemon, and no code path may make a paid cloud provider the out-of-the-box default.

invariant statusactive version 1.0 date 2026-06-01 sources src/Scout.Llm/Configuration/LlmOptions.cs; README

Why this exists

Scout is an open-source, read-only chatops assistant. The fastest way to lose a contributor is to require an API key and a billed cloud account before the project will even start. Picking Ollama as the default provider means a clone, a build, and a single ollama serve are enough to get a working chat loop on a developer laptop — no OpenAI key, no Azure subscription, no per-token charges.

The principle is broader than one default string. It keeps the whole solution honest about the pluggable-everything contract: if the local provider works as a first-class citizen, then every cloud provider is genuinely interchangeable rather than the privileged path. It also matches the wiki tagline — Scout is described as local-first — and the README, which lists Ollama as the one provider marked (default).

Local-first is about the default, not a restriction. Any of the eight providers can be selected by configuration. The invariant only guarantees that the zero-configuration path costs nothing and reaches no external paid service.

Scope

Applies to

  • The default value of LlmOptions.Provider and the fallback used when the configuration key is blank.
  • The default chat and embedding model identifiers and the default Ollama endpoint — all of which must point at a local daemon out of the box.
  • The committed appsettings.json shipped in the repository: it must default to the local provider, never to a credentialed cloud block.

Does not cover

  • What a deployed operator chooses at runtime. Overriding Scout:Llm:Provider to a cloud provider is fully supported and expected in production.
  • Whether a contributor has actually installed and started Ollama — that is a setup prerequisite documented in the README and the Local Models runbook, not something the code can enforce.
  • The model quality of the default. The default exists to be runnable, not to be the best model; function-calling work uses a tool-capable model the operator pulls.

Where it is enforced

The invariant lives in two places: the default on the options class, and the startup fallback that honours that default when the key is missing.

The default on the options class

LlmOptions.Provider is initialised to "Ollama". Because the property carries the default in its initialiser, a configuration section that omits Provider binds to the local provider rather than to nothing. 

// src/Scout.Llm/Configuration/LlmOptions.cs:16
public string Provider { get; set; } = "Ollama";

The Ollama block in turn defaults every connection detail to a local daemon, so even the endpoint and models require no cloud account:

Endpoint = http://localhost:11434 Chat.Model = llama3.1 Embeddings.Model = nomic-embed-text
  • LlmOptions.cs:207 — OllamaOptions.Endpoint defaults to http://localhost:11434.
  • LlmOptions.cs:221 — ChatModelOptions.Model defaults to llama3.1.
  • LlmOptions.cs:229 — EmbeddingModelOptions.Model defaults to nomic-embed-text.

The startup fallback

The composition root does not blindly trust the bound options object. It reads the raw Provider key and, when it is null or whitespace, explicitly falls back to a fresh LlmOptions().Provider — i.e. the local default — before the provider switch runs. 

// src/Scout.Llm/LlmServiceCollectionExtensions.cs:48
var provider = configuration.GetSection("Scout:Llm")["Provider"];
if (string.IsNullOrWhiteSpace(provider))
{
    provider = new LlmOptions().Provider; // "Ollama"
}
  • LlmServiceCollectionExtensions.cs:48-52 — the blank-key fallback to the local default.
  • LlmServiceCollectionExtensions.cs:56-58 — the "Ollama" arm of the provider switch, which registers the local provider.
  • LlmServiceCollectionExtensions.cs:80-85 — the default arm throws InvalidOperationException for any unknown provider name, so a typo fails fast rather than silently degrading.

How it is verified

The default and the fallback are simple, deterministic surfaces that lend themselves to unit testing: constructing LlmOptions and asserting Provider == "Ollama", and exercising AddScoutLlm with no Provider key to confirm the local provider is registered.

  • Provider selection is covered by the Scout.Llm unit tests described on the Scout.Llm service page; a dedicated assertion pinning the default string to Ollama is pending and should be added alongside any change to this invariant.
  • All assertions use Shouldly per Shouldly-Only Tests and the testing convention.

Known exceptions

  • Runtime override. Operators routinely set Scout:Llm:Provider to a cloud provider via environment variables or a secrets manager. That is intended behaviour, not a violation — the invariant only constrains the committed default.
  • Embeddings still local by default. The default embedding model (nomic-embed-text) is also served by the local Ollama daemon, so the Project Knowledge RAG path does not silently reach a paid embeddings endpoint on a fresh clone.
  • No fail-open to cloud. If the chosen provider is unknown the host throws at startup rather than quietly falling back to a billed provider; the only implicit fallback is to the local default.

Change protocol

  • Changing the default provider away from a local, credential-free option requires an ADR and a wiki update here; it reverses a stated project principle and would break the zero-configuration contributor path.
  • Adding a new provider must not change the default. New providers are added as additional switch arms in LlmServiceCollectionExtensions, leaving LlmOptions.Provider untouched.
  • Any edit to the committed appsettings.json must keep Scout:Llm:Provider on the local provider and must not commit real credentials — see Secrets Never Committed.
  • When the default chat or embedding model identifier changes, update both LlmOptions.cs and the README provider table so the documented and coded defaults stay in lockstep.
