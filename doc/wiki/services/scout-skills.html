Wiki/Services/Scout.Skills

Scout.Skills

The retrieval-based skills subsystem: it loads markdown skill files, embeds their descriptions, and selects the most relevant skill per turn via cosine similarity to inject into the system prompt.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.Skills/; README

Responsibility

Scout.Skills turns a directory of markdown skill files into per-turn behavioral guidance. Each skill is a name/description frontmatter header plus an instructional body. The subsystem embeds the descriptions, and for every user message it ranks the skills by cosine similarity, keeps those above a threshold, and hands the top matches back to the conversation layer for injection into the system prompt. The retrieval path is best-effort: any failure degrades to "no skills" rather than breaking the turn.

It also exposes a second, tool-based surface. A Skills Semantic Kernel plugin lets the model explicitly list available skills and load a named skill's full instructions on demand. That surface is deliberately embedding-free: it reads from a plain catalog so the shared kernel can aggregate the plugin without re-entering the embedding generator and forming a DI construction cycle.

It does not own the system prompt or the conversation turn — that is Scout.Conversation, which calls the selector and then composes the prompt. It also never writes anything; skills are read from disk only.

Public contract

  • ISkillSelector — SelectAsync(message, cancellationToken): returns the skills whose descriptions best match the message, ordered by descending similarity, limited and thresholded by configuration. Implementations never throw; on any failure they return an empty list.
  • ISkillCatalog — All() and Find(name): embedding-free access to the loaded skills, backing the tool-based plugin so the kernel can aggregate it without the embedder.
  • SkillsPlugin — the Skills kernel plugin: list_skills and load_skill [KernelFunction]s for LLM-driven discovery and on-demand loading.
  • SkillPromptComposer.Compose(basePrompt, skills) — appends each selected skill's body under a labeled delimiter beneath the base prompt; returns the base prompt unchanged when no skills are supplied.
  • AddScoutSkills(services, configuration) — the composition root: binds Scout:Skills and registers the selector, catalog, and plugin (or only the no-op selector when disabled).

Key types

Skill
sealed record of Name, Description (embedded for retrieval), Body (injected into the prompt), and SourcePath.
SkillSelector
Embedding-driven ISkillSelector. Builds the embedded index lazily on first SelectAsync; ranks by cosine, filters by threshold, takes TopN. Never throws.
NoOpSkillSelector
ISkillSelector that always returns an empty list. Registered when the feature is disabled so consumers depend on the interface uniformly.
SkillCatalog
Embedding-free ISkillCatalog. Loads skills once lazily via SkillFileLoader and caches them for the process lifetime.
SkillFileLoader
Parses *.md files: requires opening/closing --- fences, name and description keys, and a non-empty body. Malformed files are skipped with a warning; loading never throws.
SkillsPlugin
Kernel plugin over the catalog. list_skills returns one name: description line per skill; load_skill returns a named skill's body. Always returns a clean, non-empty string.
VectorMath
internal static cosine helper. Returns 0 when vector lengths differ or either magnitude is zero.

Invariants

  • No Executive Writes — the subsystem only reads markdown files from disk; it never writes to any external system.
  • Local-First Default — embeddings flow through the shared embedding generator, which defaults to local Ollama, so skill retrieval needs no paid credentials.
  • Pluggable Everything — the feature is toggled by Scout:Skills:Enabled; when off, only NoOpSkillSelector is registered and consumers are unaffected.

Hot spots

  • SkillSelector.cs:49 — SelectAsync: embeds the message, ranks the index by cosine, filters by SimilarityThreshold, takes TopN; the whole body is wrapped in a try that logs and returns [] on any failure.
  • SkillSelector.cs:88 — BuildIndexAsync: built lazily (SkillSelector.cs:44, ExecutionAndPublication) so DI build and host startup do zero file I/O, embedding, or network work.
  • SkillFileLoader.cs:63 — TryParse: the frontmatter contract — opening fence at line 0, name + description required, non-empty body — with malformed files skipped via warnings.
  • SkillPromptComposer.cs:18 — Compose: appends each selected skill body under a # Relevant skill: delimiter; returns the base prompt verbatim when no skills are supplied.
  • VectorMath.cs:15 — Cosine: the similarity primitive used for ranking; guards against mismatched lengths and zero magnitude.
  • SkillsServiceCollectionExtensions.cs:43 — the Enabled branch: registers loader, selector, catalog, and the Skills kernel plugin; the else arm at SkillsServiceCollectionExtensions.cs:69 registers only the no-op selector.
  • SkillsServiceCollectionExtensions.cs:48 — the selector resolves the embedding generator directly from DI rather than from the shared kernel, and the catalog/plugin at :57–:65 stay embedding-free, both deliberate to avoid the kernel-to-embedder construction cycle.

Cross-service dependencies

Used by

Scout.Conversation

Depends on

Scout.Llm (embedding generator) Microsoft.SemanticKernel.Abstractions Microsoft.Extensions.AI.Abstractions

Scout.Conversation's LlmStreamingRouter calls ISkillSelector.SelectAsync for the user message, then SkillPromptComposer.Compose to fold the selected skills into the system prompt before streaming the turn. The selector consumes the same IEmbeddingGenerator<string, Embedding<float>> registered by Scout.Llm, and the Skills kernel plugin is aggregated onto the shared kernel for function-calling.

Configuration

All keys live under Scout:Skills. Code defaults make the feature work with no section present.

# appsettings.json (excerpt)
"Scout": {
  "Skills": {
    "Enabled": true,
    "Directory": "skills",
    "TopN": 1,
    "SimilarityThreshold": 0.55
  }
}
  • Enabled (default true) — toggles the whole subsystem; when false only the no-op selector is registered.
  • Directory (default skills) — scanned recursively for *.md; resolved relative to AppContext.BaseDirectory when not absolute.
  • TopN (default 1) — maximum skills injected per turn.
  • SimilarityThreshold (default 0.55) — minimum cosine similarity for a skill to be selected.

Testing footprint

  • Unit tests in tests/Scout.Skills.Tests/ cover the loader (SkillFileLoaderTests), catalog (SkillCatalogTests), selector ranking and graceful degradation (SkillSelectorTests), prompt composition (SkillPromptComposerTests), the plugin and its metadata (SkillsPluginTests, SkillsPluginMetadataTests), and DI wiring (SkillsServiceCollectionExtensionsTests).
  • The selector is exercised with a FakeEmbeddingGenerator so retrieval is tested without a live embedding backend. Assertions use Shouldly per the testing convention.
  • Because the embedding generator is an external boundary, failure tests (embedder throwing / empty index → empty result) are required here per Production Readiness.
