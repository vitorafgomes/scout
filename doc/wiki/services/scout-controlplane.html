Scout.ControlPlane & Contracts

The transport-agnostic control-plane domain: provider lifecycle, feature catalog, credential storage and runtime config — exposed to the desktop UI through three gRPC contracts whose .proto files are the single source of truth.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.ControlPlane/, src/Scout.ControlPlane.Contracts/; ADR 0010, 0011

Responsibility

Scout.ControlPlane holds the domain logic that powers the desktop control panel: which local runtimes exist and how to start/stop them, which features Scout offers and how to configure their credentials, and where the per-feature and per-runtime preferences live on disk. Each operation is a plain async method on a domain facade with no HTTP or gRPC shell baked in.

Scout.ControlPlane.Contracts is the wire boundary. It carries three .proto files — providers.proto, models.proto and features.proto — compiled with Grpc.Tools to GrpcServices="Both" so the host gets server stubs and the in-process test client gets matching client stubs from one definition. The gRPC services in Scout.Host.ControlPlane are thin adapters that map these wire messages onto the domain facades; the facades themselves know nothing about gRPC.

It does not own the transport (UDS / named pipe binding, the per-session token interceptor and Kestrel wiring live in the host per ADR 0011), and it does not own the live Semantic Kernel — feature activation is delegated to an injected IFeatureActivator so the kernel reference stays in the host (ADR 0010).

Public contract

Domain facades (Scout.ControlPlane)

  • ProvidersService — list/status, Start/Stop/Restart, autostart toggle, a status WatchAsync stream, and model pull/list/delete. Ollama is fully wired; LM Studio is a fixed stub whose lifecycle calls throw ProviderLifecycleUnsupportedException.
  • FeaturesService — ListAsync, SetCredentialsAsync, SetupAsync, DeleteCredentialsAsync, EnableAsync, DisableAsync. Each returns a merged FeatureSnapshot built from catalog metadata + persisted state + credential presence.
  • AddControlPlaneDomain(services, configuration) — the composition root: binds the options, registers the Ollama stack, and registers the feature stack with in-memory credential store and null activator as overridable defaults.

gRPC services (Scout.ControlPlane.Contracts)

  • Providers — ListProviders, GetProviderStatus, StartProvider, StopProvider, RestartProvider, SetAutostart, and the server-streaming WatchProviderStatus.
  • Models — server-streaming PullModel (replaces the old SSE pull-progress endpoint), plus DeleteModel and ListModels.
  • Features — ListFeatures, SetCredentials, Setup, DeleteCredentials, Enable, Disable; all return the merged Feature message.

Key types

ProvidersService
Domain facade over provider operations. Dispatches on the provider id; LM Studio is a stub. WatchAsync yields a status snapshot every 2 seconds until cancelled.
OllamaProviderService
Composes binary locator, HTTP API client, process launcher, runtime registry, readiness probe and config store into the live Ollama status + start/stop/restart lifecycle. Scrubs the control-plane session token from the spawned daemon's environment.
FeaturesService
Validates and persists credentials/settings, enable/disable activation, and the merged-snapshot build. Validates the whole setup body before any write so a bad request never leaves a half-configured feature.
FeatureCatalog
Hard-coded catalog of two features (github, kubernetes) with credential fields, settings fields, scope matrix and setup steps. Single source of truth for both runtime logic and the UI snapshot.
ICredentialStore
Opaque secret store abstraction. Current behaviour: the only implementation shipped is InMemoryCredentialStore, so feature credentials (GitHub PAT, kubeconfig) live in the worker process's memory only — they are not written to any OS keyring, are lost on restart, and must be re-entered. When no durable backend is reachable the store reports IsAvailable=false and StoreAsync returns false, so FeaturesService fails closed (throws FeaturePersistFailedException) instead of reporting a false success. A real OS-keyring / Electron safeStorage backend (libsecret / Keychain / Windows Credential Manager) is a planned follow-up.
IFeatureStateStore
Persists per-feature enabled / last-error / settings state. JsonFileFeatureStateStore writes via temp file + atomic move and serialises concurrent writers behind a semaphore.
IFeatureActivator
Attach/detach surface for a feature's kernel plugin. NullFeatureActivator reports CanActivate=false so enable returns not-yet-implemented until the host supplies a real activator.
FeatureSnapshot / Feature
Merged catalog + state + credential-presence view; the gRPC adapter maps the domain FeatureSnapshot onto the wire Feature message.

Invariants

  • Secrets Never Committed — credentials are held in process memory through ICredentialStore (in-memory only today; durable OS-keyring backing is a planned follow-up) and are never persisted to disk; only the non-secret settings dictionary lands in the JSON state file.
  • No Executive Writes — every catalog feature is declared WriteClass.None; even GitHub issue creation is classified as a descriptive write in the scope matrix.
  • Local-First Default — the provider stack manages local Ollama (and stubs LM Studio) so contributors run Scout without any paid provider.
  • Streaming-First — long-running flows (model pull, status watch) are server-streaming RPCs rather than polled request/response.
  • Pluggable Everything — credential store and feature activator are registered with TryAddSingleton so the host overrides the in-memory / null defaults.

Hot spots

  • FeaturesService.cs:97 — SetupAsync: collects every credential and settings validation error first and throws a single FeatureValidationFailedException before any persistence, so a bad body never half-writes a feature.
  • FeaturesService.cs:186 — credential persistence wraps non-cancellation, non-persist exceptions into FeaturePersistFailedException; per-key idempotent writes leave a re-runnable state if a later step fails.
  • FeaturesService.cs:245 — EnableAsync: requires the keyring to hold every required credential and the activator to report CanActivate; an activation failure stores LastError and re-throws.
  • FeaturesService.cs:386 — credential keys are namespaced as scout/<featureId>/<fieldKey> in the store.
  • ProvidersService.cs:97 — WatchAsync: server-stream loop that re-snapshots status on a 2-second interval and yields cleanly on cancellation.
  • ProvidersService.cs:163 — LmStudioStub: the fixed not-installed snapshot returned for the unmanaged LM Studio provider.
  • OllamaProviderService.cs:199 — the spawned daemon's environment removes SCOUT_CONTROLPLANE_TOKEN so the session token is never inherited (and thus not visible via /proc/<pid>/environ).
  • OllamaProviderService.cs:255 — StopCoreAsync: refuses to kill an externally-started daemon Scout does not own, returning a providers/externally-managed error instead of a name-globbed kill.

The dependency on the live Semantic Kernel is deliberately inverted: rather than referencing Scout.Llm or a kernel directly, the domain takes an IFeatureActivator the host fulfils (see ADR 0010).

Configuration

All keys live under Scout:. The Ollama options block is validated on start; the two store paths fall back to %LocalAppData%/Scout/ when unset.

# appsettings.json (excerpt)
"Scout": {
  "Providers": {
    "Ollama": {
      "Endpoint": "http://localhost:11434",
      "PingTimeout": "00:00:02",
      "StartTimeout": "00:00:30",
      "WarmupBudget": "00:00:05"
    }
  },
  "LocalRuntime": {
    "Config": { "FilePath": null }
  },
  "Features": {
    "StateStore": { "FilePath": null }
  }
}
  • Scout:Providers:Ollama — endpoint and the readiness/start timeouts; bound with ValidateOnStart(). The HTTP client uses Timeout.InfiniteTimeSpan so long model-pull streams are not capped; short ops apply their own bounded token.
  • Scout:LocalRuntime:Config — path of the runtime preference file (autostart flag); default %LocalAppData%/Scout/local-runtimes.json, autostart defaults to true.
  • Scout:Features:StateStore — path of the feature state file; default %LocalAppData%/Scout/features.json.

Testing footprint

  • tests/Scout.ControlPlane.Tests/Features/FeaturesServiceTests.cs and Providers/ProvidersServiceTests.cs cover the domain facades: validation, credential/settings persistence, enable/disable, snapshot status resolution, provider dispatch and the LM Studio unsupported-lifecycle paths. Providers/OllamaProviderServiceTests.cs drives the lifecycle through stub locator/launcher/API harnesses.
  • Integration/ControlPlaneBoundaryTests.cs are the production-readiness failure-injection tests for the gRPC-over-UDS boundary — backend not listening, host disappears mid-stream, token rejected — each call bounded by a deadline so a hang fails fast. Companion Integration/ControlPlaneUdsIntegrationTests.cs and Transport/ / Security/ suites exercise the host-side transport and per-session token interceptor.
  • All assertions use Shouldly per the testing convention, satisfying the boundary-failure bar in Production Readiness.
