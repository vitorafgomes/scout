Wiki/Services/Scout.Plugin.GitHub

Scout.Plugin.GitHub

A read-only GitHub plugin: it lists repositories, pull requests, and issues and summarizes a single repository, exposed to the LLM as Semantic Kernel functions and never writing back to GitHub.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.Plugin.GitHub/; README; ADR 0009

Responsibility

Scout.Plugin.GitHub gives the model a read-only window onto GitHub. It contributes a single KernelPlugin named "GitHub" whose functions the LLM can call by name through Semantic Kernel function-calling: list the authenticated user's repositories, list a repository's open pull requests and open issues, and fetch a single-repository overview for describing a project. Listing and retrieval only — no create, comment, merge, or push operation exists on the surface by design.

It owns the GitHub REST contract and nothing else: it does not talk to the model directly (that is Scout.Llm's shared kernel), and it does not manage conversation state. The plugin self-gates on a configured token, so a host with no GitHub token simply starts without the feature.

Public contract

  • list_repositories — GitHubPlugin.ListRepositoriesAsync; no parameters. Returns one repository per line, private ones tagged (private), or "No repositories." when empty.
  • list_pull_requests — ListPullRequestsAsync(owner, repo, ct). Open PRs only, formatted #number title (by author).
  • list_issues — ListIssuesAsync(owner, repo, ct). Open issues only; PR-backed items are filtered out by the client.
  • get_repository — GetRepositoryAsync(owner, repo, ct). A multi-section overview (description, languages, topics, license, default branch, stars/forks, top-level structure, README excerpt), or a not-found message.
  • AddGitHubPlugin(services, configuration) — the composition root. Binds Scout:Plugins:GitHub, self-gates on the token, and registers both the typed client and the kernel plugin.

Key types

GitHubPlugin
public sealed. Holds the four [KernelFunction] methods. Every method wraps the client call in a try and converts handled failures into a clean error line, so a tool call never throws back into the kernel.
IGitHubClient
Read-only client contract: ListRepositoriesAsync, ListOpenPullRequestsAsync, ListOpenIssuesAsync, GetRepositoryAsync. "Listing only: no create, merge, push, or comment operations exist by design."
GitHubClient
internal sealed REST client over an injected HttpClient. Maps non-success responses to GitHubApiException; timeouts and transport faults bubble unchanged.
RepositoryInfo / LanguageUsage
Read-only projection for get_repository: metadata, language breakdown by byte count, topics, license, README excerpt, and top-level entries.
GitHubApiException
public sealed. Carries a user-safe Message and the originating HttpStatusCode when known.
GitHubOptions
Bound from Scout:Plugins:GitHub; a single Token (read-only PAT). Empty disables the plugin.

Invariants

  • No Executive Writes — the plugin exposes only listing and retrieval; per ADR 0009 it is allowed descriptive writes in principle but ships with none, and executive writes (merge, push, branch, repo settings) are forbidden outright.
  • Pluggable Everything — the feature is a contributed KernelPlugin registered by configuration, not a hard dependency of the kernel.
  • Secrets Never Committed — the PAT is read from configuration (User Secrets / env vars), never source; an empty token is a clean no-op.

Hot spots

  • GitHubPlugin.cs:29 — the [KernelFunction("list_repositories")] attribute; the four function names (:29, :51, :76, :101) are the stable contract the model calls by name.
  • GitHubPlugin.cs:160 — IsHandledFailure: only GitHubApiException, HttpRequestException, and OperationCanceledException are caught; ErrorLine (:163) maps them to a chat-safe message.
  • GitHubServiceCollectionExtensions.cs:37 — the self-gate: an empty/whitespace Token returns early, so no client and no plugin are registered.
  • GitHubServiceCollectionExtensions.cs:43 — the typed HttpClient: base address https://api.github.com/, 30s timeout, Bearer auth, GitHub API version 2022-11-28, and a required User-Agent.
  • GitHubServiceCollectionExtensions.cs:56 — KernelPluginFactory.CreateFromObject(..., "GitHub") registers the plugin under the name "GitHub".
  • GitHubClient.cs:47 — the issues endpoint also returns PRs; PR-backed items (pull_request present) are excluded so list_issues lists issues only.
  • GitHubClient.cs:169 — ToApiException: 401 → auth message, 403 with X-RateLimit-Remaining: 0 → rate-limit message, 404 → not-found, 5xx → unavailable.

Configuration

All keys live under Scout:Plugins:GitHub. A read-only Personal Access Token activates the plugin; an empty token leaves it inactive.

# appsettings.json (excerpt)
"Scout": {
  "Plugins": {
    "GitHub": {
      "Token": ""
    }
  }
}

The token is supplied as a Bearer credential. Read-only scopes are sufficient, matching the plugin's listing-only surface. In development use .NET User Secrets or environment variables (Scout__Plugins__GitHub__Token); never commit a live token.

Testing footprint

  • tests/Scout.Plugin.GitHub.Tests/GitHubPluginTests.cs — formatting and empty-state messages for all four functions, plus that a GitHubApiException, timeout, and transport failure each return a clean error line without throwing.
  • GitHubClientTests.cs — header construction, JSON parsing, PR-vs-issue filtering, and the boundary failures: 401, rate-limited 403, plain 403, 404, 5xx, plus TaskCanceledException and HttpRequestException propagation. This is the per-boundary failure coverage required by Production Readiness.
  • GitHubServiceCollectionExtensionsTests.cs — the self-gate (no/missing token registers nothing), the with-token path registers the "GitHub" plugin and client, and the configured HttpClient headers.
  • GitHubPluginMetadataTests.cs — the LLM-facing metadata: stable function names and non-empty descriptions on functions and their owner/repo parameters.
  • Assertions use Shouldly per the testing convention; doubles use NSubstitute and a stub HttpMessageHandler.
