Scout.Adapter.Slack

The Slack chat adapter: a single SlackNet Socket Mode connection that turns inbound message events into Scout chat turns and streams the reply back into the message's own thread — and nowhere else.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.Adapter.Slack/; README

Responsibility

Scout.Adapter.Slack is the Slack implementation of the inverted IChatAdapter contract owned by Scout.Conversation. It holds one Socket Mode connection — no public URL is required — receives Slack message events, decides which of them are actually for Scout, normalizes each into a provider-agnostic ChatMessage, and hands it to the conversation handler together with a SlackResponseSink bound to the originating channel and thread.

It does not own conversation state, routing, or the streaming pump — those live in Scout.Conversation, which drives the sink. The adapter's only job is the Slack edge: connect, translate inbound, render outbound. Outbound rendering lives in SlackResponseSink; the translator and the sink share no SlackNet types across their respective Scout-facing seams, keeping each one independently unit-testable.

Public contract

  • SlackChatAdapter — implements IChatAdapter and IAsyncDisposable. Name is "Slack"; StartAsync(handler, ct) resolves the bot's own user id via auth.test, arms the handler, and opens the socket; StopAsync cancels the lifetime token and disconnects.
  • SlackResponseSink — implements IResponseSink over a single Slack message: BeginAsync posts a cursor placeholder, UpdateAsync edits with cumulative text plus cursor, CompleteAsync renders the final text with a citation footer, FailAsync appends a connection-error footer.
  • SlackMessageTranslator — pure TryTranslate gate: rejects bot-authored, subtyped, and unaddressed messages, strips the bot mention, and emits a ChatMessage only when one is genuinely for Scout.
  • AddSlackAdapter(services, configuration) — DI composition root. Binds SlackOptions and registers the adapter as an IChatAdapter only when both tokens are present; otherwise a clean no-op.

Key types

SlackChatAdapter
sealed. Owns the SlackNet service graph and the Socket Mode connection. Forwards every MessageEvent through a private MessageEventForwarder into OnMessageReceivedAsync.
SlackResponseSink
sealed IResponseSink. Single-message, single-threaded lifecycle (one Begin, N Update, one terminal). Owns its own Slack 429 backoff-and-retry so the pump stays platform-agnostic.
SlackMessageTranslator
sealed partial. Source-generated mention regex; pure inbound gate. No SlackNet type crosses its boundary.
SlackAdapterLifecycle
internal sealed. Single-connect state machine (Idle → Started → Stopped) with a lifetime CancellationToken; a restart after stop is rejected.
InboundSlackMessage
sealed record. Minimal projection of a Slack message event that the translator reads, so the inbound glue is testable without SlackNet's MessageEvent.
SlackMessageHandle
sealed record (ChannelId, Ts). The single message a sink owns; captured once from Begin and reused for every chat.update edit.
SlackOptions
sealed. BotToken (xoxb-) and AppLevelToken (xapp-). Neither is ever logged.

Invariants

  • Pluggable Everything — Slack is one interchangeable IChatAdapter; AddSlackAdapter self-gates on configuration and registers nothing when the tokens are absent, so an unconfigured host still starts.
  • Streaming-First — SlackResponseSink renders progressively via chat.update with a live cursor glyph; the terminal call drops the cursor and appends citations.
  • No Executive Writes — the descriptive-write boundary: a sink can only ever target the (channel, ts) handle captured from its own Begin post, which is itself bound to the originating channel and thread. It can never write elsewhere.
  • Secrets Never Committed — both tokens are injected via environment variables or User Secrets; SlackOptions never logs them, and an empty token cleanly disables the adapter.

Hot spots

  • SlackChatAdapter.cs:43 & :51 — the constructor self-gate: a blank BotToken or AppLevelToken throws ArgumentException with a pointer to the SCOUT__ADAPTERS__SLACK__* environment variables.
  • SlackChatAdapter.cs:63 — builds the self-contained SlackNet service graph from the two tokens (UseApiToken + UseAppLevelToken) and registers the per-event forwarder; Socket Mode needs both the bot token (Web API) and the app-level token (gateway).
  • SlackChatAdapter.cs:103 — StartAsync resolves _botUserId via Auth.Test before arming the handler (line 110), so the self-loop guard is in force for the very first delivered event.
  • SlackChatAdapter.cs:170 — thread selection: reply in the parent thread when the message is already threaded, otherwise start a thread on the message itself; the sink is bound to the originating channel only.
  • SlackMessageTranslator.cs:39 — bot-author rejection (own messages, other bots, bot_message subtype) that prevents self-trigger loops on the sink's own chat.update edits.
  • SlackMessageTranslator.cs:64 — channel vs DM addressing: channels require an explicit @-mention, DMs (channel_type "im") are implicitly addressed.
  • SlackResponseSink.cs:218 & :233 — the Slack 429 backoff-and-retry: on SlackRateLimitException wait for Retry-After (or a 1s default) on the injected clock, then retry once.
  • SlackResponseSink.cs:286 — head-preserving truncation against the 3000-char body budget, so the start of the answer is never lost.
  • SlackServiceCollectionExtensions.cs:32 — the registration self-gate: missing either token returns services unchanged (no-op).
  • SlackAdapterLifecycle.cs:31 — single-connect Start: an already-started or already-stopped lifecycle throws, since the disposed socket client cannot reconnect.

Cross-service dependencies

Depends on

Scout.Conversation SlackNet Microsoft.Extensions.Options Microsoft.Extensions.Logging

Used by

Scout.Host.Console

The adapter references only Scout.Conversation for the IChatAdapter / IResponseSink / ChatMessage abstractions; it never touches Scout.Llm or any plugin directly. The conversation core supplies the handler and the streaming pump that drive each turn.

Configuration

Keys live under Scout:Adapters:Slack. Both tokens are required for the adapter to register; leaving either empty disables it. Inbound runs over Socket Mode, so no public URL is configured.

# appsettings.json (excerpt) — values injected via env / User Secrets
"Scout": {
  "Adapters": {
    "Slack": {
      "BotToken": "",        # xoxb- ; empty disables the adapter
      "AppLevelToken": ""    # xapp- ; Socket Mode gateway
    }
  }
}

Testing footprint

  • Unit tests in tests/Scout.Adapter.Slack.Tests/ cover the inbound projection (SlackInboundProjectionTests), the translation gate (SlackMessageTranslatorTests), the single-connect lifecycle (SlackAdapterLifecycleTests), the full adapter path (SlackChatAdapterTests), and DI self-gating (SlackServiceCollectionExtensionsTests). Assertions use Shouldly per the testing convention.
  • Streaming/SlackResponseSinkTests exercises the Begin/Update/Complete/Fail lifecycle, cursor rendering, citation footer, and head-preserving truncation through injected post/edit delegates — no Slack network.
  • Streaming/SlackSinkBoundaryTests is the boundary failure suite required by Production Readiness: it drives the sink's own Slack 429 Retry-After backoff-and-retry and the 5xx interim-drop path through the real StreamPump with a FakeTimeProvider, fully hermetic.
  • Internals are exposed to the test project via InternalsVisibleTo Scout.Adapter.Slack.Tests; the adapter and sink both carry internal test-seam constructors that inject the SlackNet client and post/edit delegates.
