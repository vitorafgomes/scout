Wiki/Services/Host.ControlPlane

Scout.Host.ControlPlane

The ASP.NET Core gRPC host for the control-plane: it binds a Unix domain socket or a Windows named pipe — never a TCP port — gates every call with a per-session token, and exposes provider, model, and feature management to the desktop UI.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.Host.ControlPlane/; ADR 0011

Responsibility

Scout.Host.ControlPlane is the executable host that puts the Scout.ControlPlane domain on the wire for the desktop front-end. It is a Microsoft.NET.Sdk.Web app (OutputType Exe) that builds a WebApplication, configures Kestrel to listen on a Unix domain socket (Linux/macOS) or a named pipe (Windows) over h2c, registers the three gRPC services plus a token interceptor, and runs.

It owns the transport and the security boundary, not the business logic: provider lifecycle, model pull/delete, and feature setup all live in Scout.ControlPlane. The host's gRPC services are thin adapters that translate wire messages to domain calls and domain exceptions back to gRPC status codes. Per the transport decision in ADR 0011, there is deliberately no network-reachable surface: filesystem permissions plus a session token gate access.

This is a control-plane only. It never performs executive writes against external systems — see No Executive Writes; the operations it exposes manage Scout's own local providers, models, and feature configuration.

Public contract

  • AddControlPlaneHost(services, config, token?) — DI composition root in ControlPlaneServiceRegistration. Registers the SessionToken (caller-supplied for tests, else FromEnvironmentOrMint), the TokenAuthInterceptor, gRPC with that interceptor, and the control-plane domain.
  • MapControlPlaneServices(endpoints) — maps the three gRPC services: ProvidersGrpcService, ModelsGrpcService, FeaturesGrpcService.
  • Providers RPCs — ListProviders, GetProviderStatus, StartProvider, StopProvider, RestartProvider, SetAutostart, and the server-streaming WatchProviderStatus.
  • Models RPCs — the server-streaming PullModel (maps IAsyncEnumerable<PullProgress> onto a stream), DeleteModel, and ListModels.
  • Features RPCs — ListFeatures, SetCredentials, Setup, DeleteCredentials, Enable, Disable.

Key types

ControlPlaneServiceRegistration
Shared DI wiring used by Program and tests: registers gRPC, the token interceptor, the session token, and the domain; maps the three services.
KestrelTransportConfigurator
Applies the per-OS bind. On Unix it runs the anti-hijack pre-flight before binding and returns the socket path; on Windows it binds the named pipe and returns null. Always h2c (HttpProtocols.Http2).
ControlPlaneEndpoint
Resolves the UDS path under $XDG_RUNTIME_DIR (0700 fallback under temp), runs PreflightSocketPath, and HardenSocket to 0600 after Kestrel creates it.
NativeUnix
internal P/Invoke surface for geteuid and stat (owner + socket-ness). Tri-state StatOutcome; unsupported arch or unresolved symbol degrades to Unavailable (fail-closed).
NamedPipeSecurity
Windows-only: ACLs the named pipe to the current user (CurrentUserOnly = true plus an explicit PipeSecurity owner rule).
SessionToken
Per-session bearer token from SCOUT_CONTROLPLANE_TOKEN or a freshly minted 256-bit value; constant-time Matches via FixedTimeEquals. Never logged.
TokenAuthInterceptor
gRPC interceptor over all four call kinds. Reads x-scout-token or authorization (optional Bearer prefix); rejects absent/invalid tokens with Unauthenticated.

Invariants

  • No Executive Writes — the control plane manages Scout's own providers, models, and feature config; it does not mutate external code, infra, or data.
  • Secrets Never Committed — the session token is minted at runtime or handed in via environment out-of-band, held only in memory, and never logged.
  • Streaming-First — progress and status flows (PullModel, WatchProviderStatus) are gRPC server-streaming RPCs, matching the transport decision.

Hot spots

  • Program.cs:35 — the native-stat self-test gate: if NativeUnix.SelfTest() fails on a non-Windows platform the host logs critical and refuses to start rather than bind without a trustworthy ownership check.
  • Program.cs:49 — on ApplicationStarted, logs the UDS bind line and calls HardenSocket to tighten the file to 0600; a chmod failure is logged as a warning, not fatal.
  • KestrelTransportConfigurator.cs:32 — resolves the socket path, runs PreflightSocketPath, then ListenUnixSocket with HttpProtocols.Http2; Windows takes the named-pipe branch and returns null.
  • ControlPlaneEndpoint.cs:54 — PreflightSocketPath: refuses to bind when stat is Unavailable, when the path is a non-socket, or when an existing socket is owned by another uid; only a stale socket owned by the current uid is deleted and recreated.
  • NativeUnix.cs:62 — the IsSupportedArchitecture gate (x64/arm64 only); any other arch returns Unavailable so a future mis-port of the hardcoded struct stat offsets fails closed instead of misreading bytes.
  • SessionToken.cs:54 — Matches compares the presented token in constant time with CryptographicOperations.FixedTimeEquals, returning false for null/empty input.
  • TokenAuthInterceptor.cs:63 — Authenticate runs on every unary, client-stream, server-stream, and duplex call; a missing or mismatched token throws Unauthenticated before the domain handler runs.
  • ModelsGrpcService.cs:30 — PullModel forwards the domain async stream to the server stream and swallows OperationCanceledException when the client cancelled, ending the stream cleanly; HttpRequestException from the backend becomes Internal.

Cross-service dependencies

Depends on

Scout.ControlPlane Scout.ControlPlane.Contracts Grpc.AspNetCore

Consumed by

Electron main process (gRPC client) Desktop Provisioning UI

The renderer never touches the socket. Per ADR 0011, the Electron main process is the sole gRPC client and brokers an allow-listed surface to the Angular renderer over contextBridge. The Node/Electron client, TypeScript codegen, and the Windows named-pipe spike are a follow-on phase; the .NET server side described here is implemented and tested.

Configuration

The host reads two inputs. Scout:ControlPlane:SocketPath overrides the resolved UDS path (otherwise it is computed under $XDG_RUNTIME_DIR/scout). The session token is read from the SCOUT_CONTROLPLANE_TOKEN environment variable when present, otherwise minted at startup. 

# appsettings.json (excerpt) — SocketPath is optional
"Scout": {
  "ControlPlane": {
    "SocketPath": "/run/user/1000/scout/controlplane.sock"
  }
}

# environment (out-of-band, never on disk world-readable)
SCOUT_CONTROLPLANE_TOKEN=<per-session token>
UDS: $XDG_RUNTIME_DIR/scout/controlplane.sock pipe: scout-controlplane protocol: h2c UDS mode: 0600

Testing footprint

  • Unit tests live in tests/Scout.ControlPlane.Tests/ (the host's InternalsVisibleTo target). Transport/ControlPlaneEndpointTests.cs and Transport/NativeUnixTests.cs cover socket-path resolution and the pre-flight refusals; Security/SessionTokenTests.cs and Security/TokenAuthInterceptorTests.cs cover token matching and header extraction.
  • Integration/ControlPlaneUdsIntegrationTests.cs boots the host on a real temp UDS with a pinned token and a stubbed Ollama backend, including NoTcpListenerExists_AfterStartup which asserts every advertised TCP address refuses a connect and PullModel_ServerStream_ConsumedToCompletion.
  • Integration/ControlPlaneBoundaryTests.cs is the production-readiness boundary suite — one test per transport failure mode: backend not listening (no hang), host disappears mid-stream, absent token, bad token (neither executes the domain), and client cancel mid-flight aborting the backend pull. Assertions use Shouldly per the testing convention and Production Readiness.
