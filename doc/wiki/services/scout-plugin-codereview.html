Wiki/Services/Scout.Plugin.CodeReview

Scout.Plugin.CodeReview

A code-review plugin exposed to the LLM as Semantic Kernel functions: six snippet reviews that run entirely on the configured model, plus read-only repository analysis that reads a bounded set of key files from GitHub. Every call returns a clean, user-safe string and never throws back into the kernel.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.Plugin.CodeReview/; reuses Scout:Plugins:GitHub:Token; ADR 0009

Responsibility

Scout.Plugin.CodeReview contributes a single KernelPlugin named "CodeReview" whose functions the LLM can call by name through Semantic Kernel function-calling. Six of them review a piece of supplied text — assess quality, detect vulnerabilities, suggest improvements, generate tests, explain code, and review a pull-request diff — and run as a single model completion with no GitHub access. A seventh, analyze_repository, reads a bounded selection of a repository's key files from GitHub (read-only, GET only) and asks the model to review the project's purpose, architecture, and risks.

It owns the review prompts and the GitHub read path and nothing else. It does not hold a chat session — each function is one stateless completion — and it does not talk to the model directly: it goes through the shared Scout.Llm chat service. Snippet review works whenever an LLM is configured; repository analysis self-gates on the GitHub feature's token, so a host with no token simply exposes the six snippet functions and returns a clear message if the model asks to analyze a repository.

Public contract

  • analyze_code_quality — AnalyzeCodeQualityAsync(code, ct). Readability, naming, structure, error handling, and conventions for a snippet.
  • detect_vulnerabilities — DetectVulnerabilitiesAsync(code, ct). Injection, secrets, unsafe I/O, and auth flaws with severities and fixes.
  • suggest_improvements — SuggestImprovementsAsync(code, ct). Concrete, actionable changes: correctness, performance, clarity, idioms.
  • generate_tests — GenerateTestsAsync(code, framework?, ct). Focused unit tests over main paths and edge cases; optional framework hint (xUnit, pytest, Jest).
  • explain_code — ExplainCodeAsync(code, level = "intermediate", ct). Plain-language explanation at beginner/intermediate/advanced.
  • review_pull_request — ReviewPullRequestAsync(diff, ct). Reviews a unified diff and ends with VERDICT: approve or VERDICT: request-changes. Does not call GitHub.
  • analyze_repository — AnalyzeRepositoryAsync(repositoryUrl?, ct). Reads key files from GitHub and returns a repository-level review; falls back to the configured default URL; requires a GitHub token.
  • AddCodeReviewPlugin(services, configuration) — the composition root. Binds Scout:Plugins:CodeReview, always registers the reviewer and the "CodeReview" plugin, and registers the repository fetcher only when a GitHub token is present.

Key types

CodeReviewPlugin
public sealed partial (split across .cs, .Repository.cs, .Snippets.cs). Holds the seven [KernelFunction] methods. Every method wraps the call so handled failures become a clean error line — a tool call never throws back into the kernel.
ICodeReviewer / CodeReviewer
internal sealed. Builds a two-message chat (system prompt per ReviewKind + an untrusted-wrapped user message) and runs one completion with kernel: null — no function-calling, no tool round-trips. An empty response becomes LlmReviewException. The chat service is resolved lazily via a factory to avoid re-entering the kernel under construction.
IRepositoryFetcher / GitHubRepositoryFetcher
internal sealed, GET-only over a pre-configured HttpClient. Resolves the default branch, lists the recursive tree, selects key files via KeyFileSelector, and decodes each as strict UTF-8 within size caps. Binary/oversize/undecodable/missing files are skipped best-effort; a truncated tree or non-success status raises CodeReviewFetchException.
ReviewKind
enum: Quality, Vulnerabilities, Improvements, Tests, Explain, PullRequest, Repository. Selects the system prompt and how the input is framed.
CodeReviewPromptTemplate
Static prompt builder: SystemFor(kind), plus WrapSnippet/WrapDiff/WrapFiles that fence supplied content as untrusted input within the model's CorpusCharBudget.
RepositoryUrlParser / RepositoryCoordinates
Parses a clone or browser URL into (Owner, Repo); an unparseable URL returns a clean message rather than failing.
CodeReviewOptions
Bound from Scout:Plugins:CodeReview: DefaultRepoUrl, Temperature, MaxTokens, MaxFileBytes (200 KB), MaxFiles (12), CorpusCharBudget (60 000). No token is stored here.
LlmReviewException / CodeReviewFetchException
Carry user-safe messages; both are caught by the plugin and surfaced as the function's return string.

Invariants

  • No Executive Writes — the plugin only reads from GitHub (GET only) and runs model completions; no create, comment, merge, push, or branch operation exists on the surface.
  • Pluggable Everything — the feature is a contributed KernelPlugin registered by configuration, not a hard dependency of the kernel.
  • Secrets Never Committed — repository analysis reuses Scout:Plugins:GitHub:Token from configuration; no token is stored in this feature, and an absent token cleanly disables only the repository function.
  • Reviews run with kernel: null, so untrusted code or diffs supplied for review can never trigger tool calls — the model reviews them as data, not instructions.

Hot spots

  • CodeReviewServiceCollectionExtensions.cs:49 — the reviewer is registered with a lazy Func<IChatCompletionService>; pulling the chat service eagerly would re-enter the kernel under construction and deadlock.
  • CodeReviewServiceCollectionExtensions.cs:55 — reads Scout:Plugins:GitHub:Token; the repository fetcher (and its configured HttpClient) is registered only when the token is present.
  • CodeReviewServiceCollectionExtensions.cs:80 — KernelPluginFactory.CreateFromObject(..., "CodeReview") registers the plugin under the name "CodeReview".
  • CodeReviewer.cs:50 — the single completion runs with kernel: null; :44–45 add the per-kind system prompt and the untrusted-wrapped user message.
  • CodeReviewPlugin.cs:47 — IsHandledFailure catches only LlmReviewException, CodeReviewFetchException, HttpRequestException, and OperationCanceledException; :53 ErrorLine maps them to a chat-safe message (timeout → "The review timed out.").
  • CodeReviewPlugin.Repository.cs:41 — a null fetcher returns the token-required message; :52 short-circuits an empty snapshot instead of asking the model to review nothing.
  • GitHubRepositoryFetcher — GET-only: default branch → recursive tree → KeyFileSelector → strict UTF-8 within caps; a truncated tree and non-success statuses surface as CodeReviewFetchException, while timeouts and transport faults bubble unchanged.

Configuration

Plugin keys live under Scout:Plugins:CodeReview. None are required — the six snippet functions work with no configuration. Repository analysis reuses the read-only token from Scout:Plugins:GitHub; no token is stored in this section.

# appsettings.json (excerpt)
"Scout": {
  "Plugins": {
    "CodeReview": {
      "DefaultRepoUrl": "",
      "MaxFileBytes": 200000,
      "MaxFiles": 12,
      "CorpusCharBudget": 60000
    },
    "GitHub": { "Token": "" }
  }
}

DefaultRepoUrl is used by analyze_repository when the caller passes none. MaxFileBytes, MaxFiles, and CorpusCharBudget bound how much repository text reaches the model. Supply the GitHub token via .NET User Secrets or environment variables (Scout__Plugins__GitHub__Token); never commit a live token.

Testing footprint

  • tests/Scout.Plugin.CodeReview.Tests/CodeReviewPluginTests.cs — each function's happy path, the token-required and empty-repository messages for analyze_repository, and that an LlmReviewException, a fetch failure, a timeout, and a transport failure each return a clean error line without throwing.
  • CodeReviewerTests.cs — the two-message chat is built per ReviewKind, the completion runs with no kernel, and an empty/whitespace model response becomes LlmReviewException.
  • CodeReviewServiceCollectionExtensionsTests.cs — the reviewer and plugin are always registered, and the repository fetcher is registered only when a GitHub token is present. This is the per-boundary failure coverage required by Production Readiness.
  • CodeReviewPromptTemplateTests.cs — system prompts per kind and the untrusted-input wrapping/corpus budget.
  • CodeReviewPluginMetadataTests.cs — the LLM-facing metadata: stable function names and non-empty descriptions on functions and parameters.
  • Assertions use Shouldly per the testing convention; doubles use NSubstitute (InternalsVisibleTo exposes the internal IRepositoryFetcher seam).
