Wiki/Services/Adapter.Discord

Scout.Adapter.Discord

The Discord chat adapter: it owns a single Discord.Net gateway client, decides which inbound messages are for Scout, and streams each reply by editing one embed in the originating channel.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.Adapter.Discord/; README; vault sessions/2026-05-23-discord-streaming.md

Responsibility

Scout.Adapter.Discord is the Discord side of the chat adapter boundary. It implements IChatAdapter over a single DiscordSocketClient: it logs in with a bot token, subscribes to gateway events, normalizes each inbound message into a platform-agnostic ChatMessage, and invokes the conversation handler with an IResponseSink bound to the channel the message came from. It is a self-contained NuGet-style module — the host calls AddDiscordAdapter(configuration) and the adapter wires itself in only when a token is present.

It does not own conversation state, routing, or the LLM call — that is Scout.Conversation, which drives the sink. The adapter only decides whether a message is addressed to Scout, normalizes it, and renders the streamed reply back to Discord. Replies write only to the originating channel: that is the descriptive-write boundary, never an executive write to any other system.

Public contract

  • DiscordChatAdapter : IChatAdapter — Name returns "Discord"; StartAsync(handler, ct) logs in and starts the gateway; StopAsync(ct) tears it down. Also IAsyncDisposable.
  • DiscordMessageTranslator — pure, Discord.Net-free translator. TryTranslate(inbound, botUserId, out ChatMessage?) applies the @-mention / DM gate and strips bot mentions.
  • DiscordResponseSink : IResponseSink — streams a reply into one Discord embed via BeginAsync / UpdateAsync / CompleteAsync / FailAsync.
  • AddDiscordAdapter(services, configuration) — the composition root. Binds Scout:Adapters:Discord and registers the adapter as an IChatAdapter only when a bot token is configured; otherwise a clean no-op.
  • DiscordOptions / InboundDiscordMessage — the bound settings record and the minimal projection passed to the translator.

Key types

DiscordChatAdapter
sealed IChatAdapter + IAsyncDisposable. Owns the DiscordSocketClient, subscribes gateway handlers, projects each SocketMessage and dispatches accepted ones to the conversation handler.
DiscordAdapterLifecycle
internal sealed single-login state machine (Idle → Started → Stopped). Holds a lifetime CancellationToken that trips on stop so in-flight conversations unwind. A start after a stop is rejected — Discord.Net cannot re-login a stopped session.
DiscordMessageTranslator
Pure partial class. Rejects bot-authored messages, applies the guild @-mention gate (DMs bypass it), strips bot mentions, and emits a ChatMessage. No Discord.Net type crosses this boundary.
InboundDiscordMessage
record projection of the fields the translator needs (ids, content, mentions-self flag, timestamp, optional guild id). Exists so the translator stays unit-testable without the sealed SocketMessage.
DiscordResponseSink
sealed IResponseSink. Renders the stream into one embed with a ▌ cursor; owns its own Discord.Net 429 backoff-and-retry; head-preserving truncation against the 4096-char embed limit.
DiscordOptions
Bound from Scout:Adapters:Discord; carries the BotToken. Default empty string disables the adapter.

Invariants

  • Streaming-First — the sink renders the response incrementally by editing one embed (Discord has no SSE for bot replies), driven by the conversation pump's cumulative UpdateAsync calls.
  • Pluggable Everything — the adapter is self-gating: present a token and it registers, omit it and the host starts without Discord. No host code references Discord.Net.
  • No Executive Writes — the sink binds to the originating channel only; the bot writes its reply there and nowhere else.
  • Secrets Never Committed — the bot token comes from environment variables or User Secrets; the options doc-comment and constructor error message both forbid committing it.

Hot spots

  • DiscordChatAdapter.cs:49 — gateway intents: Guilds | GuildMessages | DirectMessages | MessageContent. The DirectMessages + MessageContent pair is what lets the bot read DMs and message text.
  • DiscordChatAdapter.cs:108 — OnMessageReceivedAsync: projects the message, runs the translator gate, and on accept builds a channel-bound DiscordResponseSink and invokes the handler under the lifetime token.
  • DiscordChatAdapter.cs:150 — the sink is constructed against message.Channel only, enforcing the descriptive-write boundary in code.
  • DiscordMessageTranslator.cs:45 — the gate: guild messages require an explicit @-mention; DMs (GuildId is null) are implicitly addressed and skip the mention requirement.
  • DiscordAdapterLifecycle.cs:31 — Start uses Interlocked.CompareExchange to reject a double-start and a restart-after-stop, then links the lifetime token to the host token.
  • Streaming/DiscordResponseSink.cs:201 — WriteWithRateLimitRetryAsync: catches Discord.Net RateLimitedException, backs off once (default 1s on the injected TimeProvider), then retries; other exceptions propagate to the caller.
  • Streaming/DiscordResponseSink.cs:129 — interim edits are best-effort: a non-rate-limit transport failure is logged and dropped, since the pump keeps the buffer and the terminal call re-renders the full body.
  • Streaming/DiscordResponseSink.cs:252 — TruncateHead: head-preserving truncation against the 4096-char embed limit so the start of the answer is never lost; ComposeTerminalBody drops the citation footer first when over budget.

Cross-service dependencies

Used by

Scout.Host.Console

Depends on

Scout.Conversation Discord.Net Microsoft.Extensions.Options

The adapter references only Scout.Conversation for the IChatAdapter / IResponseSink / ChatMessage / Citation abstractions; it has no dependency on Scout.Llm. The host composes the adapter together with the conversation core, and the conversation core (not the adapter) reaches the LLM.

Configuration

All keys live under Scout:Adapters:Discord. An empty or absent BotToken disables the adapter; the host then continues with whatever other adapters are configured.

# appsettings.json (excerpt) — token never committed; inject via env / User Secrets
"Scout": {
  "Adapters": {
    "Discord": {
      "BotToken": ""
    }
  }
}

In development the token is supplied through User Secrets; in any environment it can be overridden with the environment variable SCOUT__ADAPTERS__DISCORD__BOTTOKEN (double-underscore separator). The adapter requires the bot's Message Content privileged intent to be enabled in the Discord developer portal, matching the MessageContent gateway intent it requests.

Testing footprint

  • Unit tests in tests/Scout.Adapter.Discord.Tests/ cover the translator gate (DiscordMessageTranslatorTests), the inbound projection (DiscordInboundProjectionTests), the single-login lifecycle (DiscordAdapterLifecycleTests), and the DI self-gating (DiscordServiceCollectionExtensionsTests). Assertions use Shouldly per the testing convention.
  • Streaming/DiscordResponseSinkTests drives the sink through its full lifecycle via the injected post/edit delegates — cursor seeding, cumulative updates, terminal body, and the 4096-char truncation rules — with no Discord.Net network.
  • Streaming/DiscordSinkBoundaryTests is the boundary-failure suite required by Production Readiness: a 429 backs off on a FakeTimeProvider then retries once (interim and terminal), and a 5xx on an interim edit is dropped without breaking the terminal render.
  • Internals are exposed to the test project via InternalsVisibleTo, so the pure projection, lifecycle, and sink seams are exercised directly without a live login.
