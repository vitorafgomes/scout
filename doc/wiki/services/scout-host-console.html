Wiki/Services/Host.Console

Scout.Host.Console

The primary composition root: it wires every Scout service into one .NET Generic Host, starts the configured chat adapters and the conversation worker, and also handles the one-shot index <project> command.

service statusactive version 1.0 date 2026-06-01 sources src/Scout.Host.Console/; README

Responsibility

Scout.Host.Console is the main runnable host and the single composition root for the backend. It builds a .NET Generic Host, registers every service Scout needs through one AddScoutHost extension, and runs the host loop. Two top-level commands share the same process: the default run command starts the configured chat adapters plus the conversation worker, and the one-shot index <project> command builds a minimal graph, indexes a single project, then exits with a process code.

It owns process-level concerns the libraries deliberately stay out of: command parsing, the stdout SCOUT_READY readiness marker the Electron supervisor watches for, stderr startup markers, and the parent-death watchdog. It does not own conversation routing, LLM access, knowledge storage, or any adapter protocol; those belong to their respective services, which this host only composes. Each chat adapter self-gates on its own credentials, so the host runs whatever combination is configured and starts none when nothing is set.

Public contract

The host is an executable (OutputType Exe), not a library, so its surface is its command line and a handful of internal seams exposed to tests via InternalsVisibleTo.

  • Command line — index <project> runs the one-shot indexer and exits; any other arguments run the host loop.
  • AddScoutHost(services, configuration) — the full service graph for the run command: readiness signal, LLM, skills, conversation, project knowledge, the self-gating adapters, the GitHub plugin, the conversation worker, and the gated parent watchdog. Shared verbatim by Program.cs and the composition smoke test so tested wiring cannot drift from production.
  • AddScoutIndexHost(services, configuration) — the minimal graph for index: only LLM embeddings and project knowledge, with no adapters, conversation, skills, worker, or watchdog.
  • IndexEntryPoint.RunAsync(services, projectName, ct) — resolves the project, initializes the store, indexes, and returns 0 on success or 2 on a usage/configuration error.

Key types

HostComposition
internal static root holding AddScoutHost and AddScoutIndexHost; the only place the run and index service graphs are defined.
ConsoleCommand
readonly record struct with a Command enum (Run / Index) and optional project. Parse maps args to a decision with no side effects.
ConversationWorker
BackgroundService that connects every configured IChatAdapter to the ConversationConductor; signals readiness once all are up, or stops the host gracefully when none are configured.
IReadinessSignal / StdoutReadinessSignal
Emits the literal SCOUT_READY line to stdout, kept outside the logging pipeline so the supervisor's exact-match parse sees a clean line.
IndexEntryPoint
internal static one-shot indexer: resolves the named project, initializes the knowledge store, runs the indexer, returns an exit code.
ParentWatchdogService / IParentLivenessProbe
Stops the host when the supervising parent dies ungracefully; the default probe detects parent death via stdin EOF. Registered only when opted in.

Invariants

  • Local-First Default — the bundled appsettings.json defaults the LLM provider to Ollama, so the host runs with no paid credentials.
  • Pluggable Everything — adapters and the GitHub plugin self-gate on configuration, so the same host binary runs any combination of chat surfaces with nothing else changed.
  • Secrets Never Committed — tokens come from User Secrets or environment-variable overrides (double-underscore separator); the committed defaults are empty for every secret.
  • Shouldly-Only Tests — the host test project asserts exclusively with Shouldly.

Hot spots

  • Program.cs:8 — the command branch: index builds the minimal index host and returns its exit code; otherwise the full host is built and run.
  • Program.cs:17 & :32 — both builders pin ContentRootPath to AppContext.BaseDirectory so config loads from the binary directory regardless of the working directory.
  • Program.cs:38 — logging providers are cleared and replaced with a console logger writing to stderr, keeping stdout clean for the SCOUT_READY marker.
  • Program.cs:46 — startup visibility: it inspects the configured adapter tokens and writes a synchronous stderr marker listing which adapters are configured, bypassing the async log pipeline.
  • HostComposition.cs:39 — skills are registered before conversation so the embedding-driven selector wins over the conversation core's TryAdd NoOp fallback.
  • HostComposition.cs:45 — the three adapters and the GitHub plugin are added unconditionally; each self-gates internally on its own credentials.
  • ConversationWorker.cs:25 — when no adapter resolved, it logs actionable guidance and calls StopApplication() instead of throwing.
  • ConversationWorker.cs:66 — readiness.Signal() is called only after every configured adapter connected without throwing, so the supervisor flips to "running" exactly once.
  • IndexEntryPoint.cs:27 & :35 — missing project name and unknown project both return exit code 2.
  • ParentWatchdogRegistration.cs:24 — the watchdog and its stdin probe are registered only when SCOUT__PARENT_WATCHDOG equals "1", so interactive runs are never killed by a terminal stdin EOF.
  • StdinEofParentLivenessProbe.WaitForParentExitAsync (IParentLivenessProbe.cs:25) — a zero-byte read (EOF) or a read failure is treated as the parent having gone.

Configuration

The host reads no Scout: keys of its own beyond what it forwards to the composed services. It does inspect the adapter credential keys at startup to print the configured-adapter marker, and reads one environment variable to gate the watchdog. Configuration loads from the bundled appsettings.json (copied next to the binary) plus environment-variable overrides using the double-underscore separator. 

# appsettings.json (excerpt) — defaults are local-first, secrets empty
"Scout": {
  "Llm": { "Provider": "Ollama" },
  "Adapters": {
    "Discord": { "BotToken": "" },
    "Slack":   { "BotToken": "", "AppLevelToken": "" },
    "Teams":   { "AppId": "", "AppPassword": "", "TenantId": "" }
  },
  "Projects": { "Items": [] }
}
# environment variables
# override any key with the double-underscore separator
SCOUT__ADAPTERS__DISCORD__BOTTOKEN="…"
# opt the parent-death watchdog in (set by the supervisor only)
SCOUT__PARENT_WATCHDOG="1"

The host emits two stdout/stderr signals the supervisor relies on:

SCOUT_READY (stdout)[scout] markers (stderr)

Testing footprint

  • Unit tests live in tests/Scout.Host.Console.Tests/ and assert with Shouldly per the testing convention.
  • ConsoleCommandTests covers argument parsing: index <name>, bare index (null project), and the default run path.
  • HostCompositionSmokeTests and IndexHostCompositionSmokeTests build each service graph and resolve the key services, proving the run graph exposes the conversation worker, Discord adapter, and ProjectKnowledge/Skills plugins, while the index graph registers no adapters, conversation, or worker.
  • ConversationWorkerTests exercises the boundary failures the worker must survive: no adapter configured (graceful stop) and an adapter that throws on start (synchronous stderr surface plus a single StopApplication), satisfying Production Readiness for the adapter boundary.
  • ParentWatchdogRegistrationTests and ParentWatchdogServiceTests verify env-var gating and that the host stops on parent death but not on normal shutdown.
