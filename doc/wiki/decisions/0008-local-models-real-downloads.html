ADR 0008 — Local Models: Real Downloads

The Manage Downloaded Models screen performs real network operations against local backends — Ollama /api/pull for analysis LLMs and the HuggingFace whisper.cpp repo for transcription models — instead of flipping a mocked localStorage flag.

adr statusaccepted version 1.0 date 2026-05-16 sources vault 06-decisions/2026-05-16-local-models-real-downloads.md

Status

  • Accepted — 2026-05-16. Two backends wired: Ollama for Local Analysis models and HuggingFace GGML for Local Transcription models.

Context

The first iteration of "Manage Downloaded Models" used mocked state: clicking Download just flipped a flag in localStorage. The user quickly noticed ollama list was empty despite the UI claiming a download had happened. To avoid lying to users — and to make the screen actually useful — the Download button needs to perform a real network operation against a real local backend.

Two backends are wired in this ADR:

  • Ollama (/api/pull) for Local Analysis models — text LLMs in the Qwen 2.5 and Gemma 3 families.
  • HuggingFace (ggerganov/whisper.cpp) for Local Transcription models — Whisper Large v3 and v3-Turbo in GGML format.

Each path streams progress events back to the renderer in real time and persists the downloaded set so ngOnInit can resurrect state on app reopen.

Decision

Ollama integration

Three new IPC channels carry the pull lifecycle:

  • scout:llm.pullOllamaModel — request/response handler.
  • scout:llm.pullOllamaProgress — one-way event from main → renderer, dispatched per chunk of the NDJSON stream.
  • scout:llm.deleteOllamaModel — request/response handler.

The main process opens POST <endpoint>/api/pull with { name: <tag>, stream: true } and reads the response body as a WHATWG ReadableStream<Uint8Array> directly. Each newline-delimited JSON line is parsed; the completed and total fields drive the percent calculation. The pull is considered done when the stream emits { "status": "success" } or terminates cleanly. Delete uses DELETE <endpoint>/api/delete with { name: <tag> }; a 404 is treated as success (idempotent removal).

Ollama identity bootstrapping

Before each pull, the main process checks for ~/.ollama/id_ed25519. If missing, it runs ssh-keygen -t ed25519 -f <path> -N "" -q as a subprocess to generate the key Ollama requires, so the user does not need to drop to a terminal on first run. If ssh-keygen is missing, Scout surfaces a clear actionable error pointing at openssh-client.

The catalog → Ollama tag mapping lives in local-models.component.ts as a frozen Record<string, string>:

The qwen-3-vl-2b catalog id is a legacy identifier — the visible card is labelled "Qwen 2.5 3B" with a text-only badge. Renaming the id requires a localStorage migration and was deferred.

Whisper integration

Four new IPC channels carry the transcription-model lifecycle:

  • scout:whisper.listInstalled — scans <userData>/whisper-models/ for known GGML filenames and returns the set of variants present on disk.
  • scout:whisper.downloadModel — request/response.
  • scout:whisper.downloadProgress — one-way event.
  • scout:whisper.deleteModel — request/response.

Models are pulled from the ggerganov/whisper.cpp HuggingFace repo, not from OpenAI's original PyTorch checkpoints. The GGML format pairs natively with whisper.cpp, which is what the future Whisper.net binding on the .NET worker will consume — so the desktop app avoids shipping a PyTorch runtime.

VariantHF fileSize
large-v3ggml-large-v3.bin2.9 GB
large-v3-turboggml-large-v3-turbo.bin1.5 GB
  • Atomic write — the download streams to <file>.bin.partial, then rename() to <file>.bin on success. An interrupted download leaves a .partial file that the next attempt deletes before re-opening.
  • Progress source — the Content-Length header from HF plus bytes received from the reader. Percent caps at 99 until the final rename, then 100 is emitted to unfreeze the UI, guaranteeing 100% only fires once the file is renamed and verified.
  • Storage location — app.getPath('userData')/whisper-models/<file>.bin, cross-platform via Electron's standard path resolution (Linux ~/.config/Scout Desktop/whisper-models/, macOS ~/Library/Application Support/Scout Desktop/whisper-models/, Windows %APPDATA%\Scout Desktop\whisper-models\).

Error surfacing

The renderer captures the rejection from llmPullOllamaModel / whisperDownloadModel and writes the message to two places:

  • A per-row inline error component (row-error) under the model row, in red, with a "See logs" link to /logs.
  • LogStore.appendDiagnostic(...), a new method that fabricates a synthetic WorkerEvent (kind: 'stderr') so the message appears in the Logs view alongside worker output.

Error messages preserve Ollama's verbatim text (e.g. pull model manifest: open id_ed25519: ...) plus a prefix identifying the context ([Ollama pull qwen2.5:3b]). Log lines are not strongly typed against an error code, but the messages are searchable and link directly to the failing row in the UI.

State synchronisation

  • On LocalModelsComponent.ngOnInit, the renderer calls whisperListInstalled() and reconciles its response against LocalModelsStore: any variant present on disk that the store does not flag as downloaded is marked downloaded.
  • The Ollama side has no equivalent reconciliation today — the store is the single source of truth for the Analysis tab. A model pulled outside the app (via ollama pull in a terminal) will not appear in the Models tab; accepted because the product flow funnels every pull through the in-app screen.
Read-only invariant preserved

All writes touch only the user's own machine: /api/delete against the local Ollama daemon, fs.rm on whisper model files, and ed25519 key generation in the user's home directory. These paths were added to LOCAL_WRITE_ALLOWLIST in shared/test/ipc-contract.test.ts with justification.

Consequences

Better

  • The Download button no longer lies — ollama list and the on-disk whisper directory match what the UI claims.
  • Real-time progress streams back per chunk, so large multi-gigabyte pulls show live feedback rather than a frozen spinner.
  • First-run friction is removed: the ed25519 key Ollama needs is generated automatically instead of failing with an opaque error.
  • Downloaded state survives an app restart via on-disk reconciliation (Whisper) and the persisted downloaded set.
  • Failures are surfaced both inline on the failing row and in the Logs view, with Ollama's verbatim message preserved for searchability.

Worse

  • A hand-rolled NDJSON parser is used instead of a library; acceptable because the format is simple, but it is bespoke code to maintain.
  • A hard dependency on ssh-keygen being on PATH (default on Linux/macOS/Windows 10+) is introduced.
  • The whisper download depends on a third-party mirror (ggerganov is the upstream whisper.cpp maintainer, so the risk is low).
  • The final percent is a one-percent lie — it caps at 99 until the rename completes.
  • Ollama models pulled outside the app are invisible to the Models tab because there is no Ollama-side reconciliation.
  • Log lines are not strongly typed against an error code.

Deferrals

  • Whisper inference on the .NET worker (Whisper.net + GGML) — download is wired, runtime is not.
  • Cancellation of an in-flight pull — leaving the screen lets the download continue in the background until success or failure.
  • Concurrent download throttling — multiple downloads run in parallel without rate limiting.
  • Auto-resume of .partial files after a crash — the next attempt deletes the partial and re-downloads from scratch.
  • Persistent download history beyond the current downloaded set.

Open questions

  • Whether to verify the SHA of downloaded files against HF's manifest to detect mid-stream corruption — cheap to add but no concrete motivating incident yet.
  • Whether qwen-3-vl-2b should be renamed in the catalog now that it maps to a text-only Ollama tag — touches a localStorage shape and was deferred to avoid breaking existing user state.
