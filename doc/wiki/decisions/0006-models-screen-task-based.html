Wiki/Decisions/0006

ADR 0006 — Models Screen (Task-Based)

Reframe the Scout Desktop Models screen around tasks — Transcription, Analysis, Translation — each with its own provider/model panel, instead of one global provider/model pair.

adr statusaccepted version 1.0 date 2026-05-15 sources vault 06-decisions/2026-05-15-models-screen-task-based.md

Status

  • Accepted 2026-05-15. Amended 2026-05-16 during implementation (see Amendments below).

Context

The original /llm screen in Scout Desktop was single-purpose: it let the user pick one Ollama model that the worker used to compose chat answers. The screen was titled "LLM", its top-level radio group was "Provider" (Ollama / OpenAI / Azure), and the rest of the page was a single endpoint + model picker.

That shape is too narrow for where Scout is heading. Scout needs to handle multiple model-driven tasks beyond chat composition — at minimum speech-to-text (Whisper) for voice inputs, and likely translation as a separate cross-cutting concern. Forcing all of that into a single "LLM" screen with one provider/model pair is misleading: the chat-completion model that drives Analysis (llama3.x, qwen2.5, …) is a different class of artifact from the STT model that drives Transcription (Whisper Large v3, Whisper Large v3 Turbo).

The redesign reframes the screen around tasks rather than providers. Each task gets its own panel with the providers and models appropriate for it. The provider/model pair stops being a global selection and becomes per-task, and the screen is renamed accordingly.

Decision

The page UI is reframed as "Models". The side-nav label and route stay at /llm initially so no router or bookmark breaks, and the title shown at the top of each panel is the active task name (Transcription, Analysis, Translation), not the word "Models". The top of the page becomes a segmented tab control with three tabs that replace the old provider radio group: pick the task first, then the model.

Task panels

Transcription — one provider group, Local Whisper (On Device), with two selectable models: Whisper Large v3 and Whisper Large v3 Turbo. No remote Whisper option in this iteration, preserving the local-first default. The panel surfaces a warning bar when the worker is running ("Stop transcription to change the transcription model"), gated on the existing worker supervisor state (running).
Analysis — re-uses the current LLM flow verbatim: Ollama provider, endpoint input, model dropdown populated from /api/tags, plus Refresh and Save buttons. No behaviour change beyond being nested under a tab.
Translation — rendered but marked coming soon: a small badge on the tab, a "Coming soon" message in the panel, and the tab is disabled. It surfaces roadmap intent without committing to an adapter.

Persistence

A second namespace is added to the vault for transcription settings (stt.provider, stt.model). Existing llm.* keys keep their current meaning and continue to drive Analysis. LlmConfigStore gains a sibling TranscriptionConfigStore rather than being widened — two typed stores instead of one polymorphic store, so touching transcription cannot break chat.

Scope boundary

No backend changes are in this ADR's scope. Saving a transcription model writes to the vault, but the worker is not yet wired to consume those keys. The worker continues to ignore STT configuration until a follow-up ADR lands a Whisper adapter (Scout.Stt.WhisperLocal or equivalent). The screen redesign ships independently of the STT adapter.

Invariant

Transcription is read-only by definition — Whisper consumes audio and emits text, never writing externally. No change to Scout's read-only invariant.

Consequences

Better

  • An obvious mental model — pick the task first, then the model — replaces a single misleading "LLM" provider radio group.
  • Per-task provider/model selection makes room for STT and Translation without overloading the chat-completion picker.
  • Two typed config stores give isolation: transcription changes cannot regress chat behaviour.
  • The screen redesign ships independently of the still-unbuilt Whisper worker adapter.
  • Roadmap intent (Translation) is visible in the UI without committing to an adapter.

Worse

  • Minor inconsistency between the route name (/llm) and the visible label ("Models") until a separate rename ADR lands.
  • One more component to maintain (the segmented tab control) plus visible-but-inert Translation UI.
  • Visual asymmetry between the card-based Transcription panel and the form-based Analysis panel.
  • A Save action on Transcription that has no runtime effect until the worker is wired up.
  • The warning-bar copy slightly overpromises while the worker does not yet own STT.

Amendments (2026-05-16)

The original draft kept Analysis backed by the legacy LlmComponent and the side-nav label at "LLM". Both moved during implementation:

  • The side-nav label was renamed to "Models" the same day, keeping the /llm route stable for bookmark compatibility. The page H1 reflects the active tab name as planned.
  • LlmComponent is no longer mounted anywhere — the Analysis panel was rewritten to consume LocalModelsStore like Transcription. Selecting a model in Analysis now persists via that store, not via LlmConfigStore (now orphan code pending removal).
  • The "Manage Downloaded Models" path landed as /sources/local-models with a dedicated LocalModelsComponent. See ADR 0007 and ADR 0008.
  • The stt.provider / stt.model vault keys reserved by this ADR were never wired to the worker. Transcription selection state now lives in LocalModelsStore.selected.transcription (localStorage key scout:local-models). The stt.* keys remain in VaultKey but unused — a cleanup candidate once TranscriptionConfigStore is removed.

Deferrals

  • Whisper inference on the .NET worker (Whisper.net binding around whisper.cpp). The model file is now downloaded in real time (see ADR 0008), but the worker does not yet read it for transcription. Separate ADR + plan.
  • Translation task: provider choice, model list, language matrix, default behaviour. The tab stays disabled until that ADR.
  • Cloud Whisper providers (OpenAI Whisper API, Azure OpenAI Whisper).
  • Audio source pipeline. Whether Scout listens to Discord voice channels, ingests uploaded files, or both is a product decision that precedes the worker inference ADR.

Open questions

  • Does the warning bar belong on every task panel, or only when the worker is actively using the model being edited? For now it is gated on worker.state === 'running' on Transcription only.
  • Should LlmConfigStore and TranscriptionConfigStore be removed entirely? Both are orphan code after the Analysis rewrite. Deferred to a cleanup PR.

Testing

  • Current Vitest patterns are kept. New specs cover the tab component, the Transcription panel, and the TranscriptionConfigStore round-trip.
  • The existing llm.component.spec.ts keeps testing Analysis behaviour (asserting the right title) but is otherwise unchanged.
