ADR 0005 — Scout Desktop M1 Scope

Scout Desktop M1 ships a reproducible, unsigned, local-build desktop provisioner — Bun + zoneless Angular 21 + Electron with a bundled self-contained .NET worker — and explicitly defers signing, auto-update, and the Slack/Teams wizards to a follow-up milestone.

adr statusaccepted version 1.0 date 2026-04-24 sources vault 06-decisions/2026-04-24-scout-desktop-m1-scope.md

Status

  • Accepted · 2026-04-24. Captures the M1 technical decisions and deferrals so post-M1 work builds on the same foundation without rediscovery.

Context

Plan 5 bootstrapped Scout Desktop end-to-end: the Electron shell, the Angular provisioning renderer, the bundled .NET worker, the supervisor that runs it, and the packaging and CI to ship it. M1 made a long string of toolchain and architecture choices along the way. This ADR records each of those decisions together with their tradeoffs, plus the work that was knowingly left out, so the milestone boundary is explicit rather than implied.

Decision

Toolchain and renderer

  • Bun over npm/yarn/pnpm for the workspace toolchain — one binary runs every workspace script, faster installs. Tradeoff: fewer eyes on edge-case lockfile behaviour.
  • Angular 21 with zoneless change detection, Signals, standalone components, and the new @if / @for control flow. No NgModules, no zone.js, no RxJS in the renderer. Tradeoff: smaller third-party library surface that assumes NgModules, in exchange for a cleaner mental model and smaller bundle.

Electron and IPC

  • Electron main in ESM ("type": "module"); preload in CommonJS because a sandboxed preload cannot be ESM. Tradeoff: two module systems in the repo, in exchange for a modern main plus a sandboxed preload.
  • Full ScoutBridge IPC surface typed in @scout/shared; no generic ipcRenderer exposure to the renderer. Tradeoff: every new channel requires a contract update, in exchange for a compromised renderer being unable to call unknown handlers.
  • SingletonLock stale-PID recovery with strict same-host validation and a positive-integer parser, so the app survives a previous crash without manual cleanup.

Security posture

  • CSP strict in production, relaxed only under NODE_ENV=development for the Angular dev server. Tradeoff: an extra code path to review, in exchange for HMR during development.
  • safeStorage for the bot token at rest; localStorage only for non-secret renderer state (clientId, guildId, guildName). Tradeoff: no cross-device sync of provisioning state, in exchange for no secrets touching disk in cleartext.
  • OAuth2 loopback on strict 127.0.0.1:53682 with a findFreePort fallback up to 53690; PKCE S256 verifier included even though the Discord bot install does not require it, so the flow is PKCE-ready for Slack or other IdPs.

Worker, supervisor, and baseline behaviour

  • The .NET worker ships inside the Electron bundle via electron-builder extraResources; single-file self-contained publish per RID. Tradeoff: ~60-80 MB per RID, in exchange for a zero-prerequisite install on the end-user's machine.
  • Supervisor exponential-backoff restart (1/2/4/8/16s; 5 failures in 60s → crashed); 30s readiness timeout keyed on the SCOUT_READY stdout marker; SIGTERM → 5s → SIGKILL on stop. Tradeoff: a crashed state surfaced to the user, in exchange for never looping a broken worker forever.
  • Help plugin registered unconditionally as the baseline responder (ping, help, version), so the bot is observable end-to-end with no external config.

Packaging and CI

  • electron-builder for packaging; electron-forge considered and rejected. Tradeoff: slightly more verbose YAML, in exchange for a more mature cross-platform matrix and better extraResources ergonomics.
  • Unsigned artifacts across all three platforms; AppImage is the Linux release invariant. Tradeoff: Gatekeeper / SmartScreen warnings on end-user machines, in exchange for M1 shipping without a signing pipeline.
  • 3-OS CI matrix on pushes to main and PRs touching ui/** or the worker. Tradeoff: longer CI minutes, in exchange for catching platform-specific regressions at PR time.

Out of M1 scope (deferred)

  • Code signing / notarization / electron-updater — deferred to post-M1; the cert and Apple Developer ID setup is non-trivial, and unsigned is enough for contributor testing.
  • Slack wizard via apps.manifest.create — deferred to a follow-up milestone.
  • Teams detection/wizard — detection only; no provisioning, because sideloading is policy-blocked in most tenants.
  • Internationalisation, telemetry, and multi-bot management — post-M1 expansion.
  • scout init CLI convergence — will share packages/shared when the CLI is built.
  • Discord adapter ID-redaction for logs — accepted as Info level for operator triage; revisit if a remote log sink is added.
  • Observability — OpenTelemetry in the renderer and main is not in M1 scope.

Consequences

Better

  • A reproducible local build story: bun install && bun run dist:linux produces a runnable artifact.
  • A 3-OS CI matrix that fails loudly on platform-specific regressions at PR time.
  • A Help plugin that makes the bot observable end-to-end with no external config.
  • A security posture solid for a read-only bot: no secret leaves the main process, and no IPC channel exposes an external write.

Worse

  • Unsigned distribution triggers Gatekeeper and SmartScreen warnings on end-user machines.
  • No auto-update channel exists yet. Together with unsigned distribution, this blocks taking Scout Desktop beyond internal testing — these two are the primary inputs to the post-M1 roadmap.
  • Two module systems (ESM main, CommonJS preload) and a relaxed dev-only CSP path add review surface.
  • Per-RID self-contained worker bundles add ~60-80 MB to each platform artifact.

Alternatives

  • npm / yarn / pnpm for the workspace — rejected in favour of Bun for install speed and single-binary script execution.
  • NgModules + zone.js + RxJS renderer — rejected in favour of zoneless Angular 21 with Signals for a cleaner mental model and smaller bundle.
  • electron-forge for packaging — considered and rejected; electron-builder has a more mature cross-platform matrix and better extraResources ergonomics.
  • Teams provisioning wizard — rejected for M1; sideloading is policy-blocked in most tenants, so only detection is provided.
