Wiki/Conventions/Code Style

Code Style

Scout is English-only, .NET 10-only source: code, identifiers, comments, and documentation are all in English, with no emojis and no AI-attribution headers — and .editorconfig enforces the rest.

convention statusactive version 1.0 date 2026-06-01 sources obsidian-vault/scout/CLAUDE.md; .editorconfig

The rule

Every source file in Scout follows one style. The human-facing rules come from the project instructions, and the mechanical formatting and naming rules are codified in the repository-root .editorconfig so the compiler and dotnet format can check them.

Language and authorship

  • All code, identifiers, and comments in English. No exceptions, regardless of who is contributing.
  • All documentation in English — Scout is an open-source project.
  • No emojis in source files.
  • No AI-attribution comments or marketing headers in source. Authorship attribution rules also extend to commits and PRs (see Commit & PR Policy).

Stack

  • .NET 10 only. No .NET 8/9 artifacts.
  • Microsoft Semantic Kernel is the orchestration core; no project references a provider SDK or a Semantic Kernel type outside the LLM gateway (see Scout.Llm).
  • OpenTelemetry for traces, metrics, and logs.

Formatting (from .editorconfig)

  • charset = utf-8, end_of_line = lf, insert_final_newline = true, and trim_trailing_whitespace = true apply to all files.
  • Default indentation is 4 spaces (indent_style = space, indent_size = 4).
  • Markdown, YAML, and JSON use 2-space indentation; so do project files (.csproj, .props, .targets).

C# language rules (from .editorconfig)

  • File-scoped namespaces — csharp_style_namespace_declarations = file_scoped at warning severity.
  • Always use braces — csharp_prefer_braces = true at warning severity.
  • Interfaces are prefixed with I and PascalCase — a naming rule raised to warning severity.
  • System using directives sort first (dotnet_sort_system_directives_first = true); import groups are not separated by blank lines.
  • var is discouraged for built-in types but allowed when the type is apparent — both at suggestion severity.
  • Nullable-reference diagnostics CS8600, CS8602, and CS8603 are escalated to warning.

Rationale

  • One contributor language. Scout is open-source and accepts work from humans and other agents; English-only code and docs keep the codebase readable for everyone and avoid mixed-language drift.
  • No noise in source. Emojis and AI-attribution headers add no engineering value and clutter diffs and blame; the authorship rule is the in-file counterpart of the commit/PR policy that the human who requested the work is the author.
  • Single target framework. Pinning to .NET 10 avoids multi-targeting complexity and keeps build, test, and packaging deterministic.
  • Mechanical rules belong in tooling. Putting formatting and naming in .editorconfig means the IDE, the compiler, and dotnet format agree, so review can focus on design rather than whitespace.
  • Severity is intentional. Style and naming sit at warning so they surface in CI; var preferences stay at suggestion because they are guidance, not gates.

Examples

Namespaces and braces

Do — file-scoped namespace, braces on every block. 
namespace Scout.Llm;

public sealed class ChatGateway
{
    public bool CanStream(ChatRequest request)
    {
        if (request is null)
        {
            return false;
        }

        return true;
    }
}
Don't — block-scoped namespace and a brace-less if trip the warning rules. 
namespace Scout.Llm
{
    public sealed class ChatGateway
    {
        public bool CanStream(ChatRequest request)
        {
            if (request is null) return false;
            return true;
        }
    }
}

Interface naming

Do — interfaces start with I in PascalCase. 
public interface IChatGateway { }
public interface ILlmProviderFactory { }
Don't — a missing I prefix raises the naming warning. 
public interface ChatGateway { }

Comments and authorship

Do — terse, technical, English-only comment that explains a non-obvious decision. 
// Resolve the embedder from the factory, not the shared kernel,
// to avoid a DI construction cycle.
Don't — emoji, non-English text, or AI-attribution headers in source. 
// Generated with an AI assistant (with an emoji prefix)
// Valida a requisicao antes de transmitir

Enforcement

The quality gates below must pass before opening a PR against main:

  • dotnet format clean — applies the .editorconfig formatting and style rules across the solution.
  • dotnet test green — see the Testing convention; assertions use Shouldly only.
  • architect-reviewer agent reviews any change touching Scout.Core or plugin contracts.
  • code-reviewer agent for any new plugin or adapter.
  • security-auditor agent for any change touching credentials, token handling, or external API calls.
  • The .editorconfig rules are honored by the IDE and the compiler, so the warning-severity style and naming rules surface during the build and in CI, not only at review time.
  • Nullable diagnostics (CS8600/CS8602/CS8603) raised to warning keep null-safety regressions visible in the same build output.
  • Authorship and emoji rules are caught in review; commit and PR attribution is governed by Commit & PR Policy.
