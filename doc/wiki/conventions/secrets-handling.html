Secrets Handling

Secrets never live in source: use .NET User Secrets in development, environment variables (or a secrets manager) in production, and keep credentials out of every tracked file.

convention statusactive version 1.0 date 2026-06-01 sources obsidian-vault/scout/CLAUDE.md; README Configuration

The rule

Scout has one line on credentials, taken verbatim from the project instructions: User Secrets in dev, env vars in prod. Never in source. The README restates it in the Configuration section: all keys live under the Scout: prefix, and secrets must never be committed — use .NET User Secrets or environment variables in development and inject via environment variables or a secrets manager in production.

  • Development — store secrets with .NET User Secrets, which keep values outside the repository tree on the developer's machine.
  • Production — supply secrets as environment variables, or pull them from a secrets manager. Nothing sensitive ships in appsettings.json.
  • Source — a credential value never appears in a tracked file. The placeholders in appsettings.json stay empty strings; each adapter and plugin is self-gating and simply stays disabled when its credential is absent.

Because every adapter and plugin self-gates on its own credential key, an empty value is the safe default: the README notes that an empty Scout:Adapters:Discord:BotToken, Scout:Adapters:Slack:BotToken, Scout:Adapters:Teams:AppId, or Scout:Plugins:GitHub:Token disables the corresponding component rather than failing the host.

Rationale

  • Open source. Scout is a public, MIT-licensed repository. A committed token is published to the world and to history; rotating it is the only remedy, and history rewrites are painful.
  • Local-first by default. The default provider is Ollama, which needs no paid credential, so a fresh clone runs with empty secret placeholders and contributors never need to add a real token just to build and test.
  • Environment parity. Keys are identical across environments under the Scout: prefix; only the source of the value changes (User Secrets locally, environment or secrets manager in production), so configuration stays predictable.
  • Least privilege. Read-only scopes are sufficient for the GitHub plugin, matching Scout's read-only invariant; there is no reason to grant write tokens.

Examples

The configuration key path uses a colon; environment-variable overrides replace each colon with a double underscore.

Development — User Secrets

Do

Set a secret with the .NET CLI so it lives outside the repo, then leave the tracked placeholder empty.

# from the host project directory
dotnet user-secrets set "Scout:Adapters:Discord:BotToken" "<your-token>"

Production — environment variables

The Console Host reads appsettings.json plus any environment-variable overrides, using a double underscore as the separator. The same key in production becomes: 

# double-underscore replaces the ':' separator
Scout__Adapters__Discord__BotToken=<your-token>
Scout__Plugins__GitHub__Token=<read-only-pat>
Scout__Llm__OpenAI__ApiKey=<your-api-key>

Tracked appsettings stays empty

Do

Keep secret-bearing keys present but blank in the committed file. The self-gating adapters and plugins treat an empty value as "disabled", so the repo builds and runs without any real credential.

"Scout": {
  "Adapters": {
    "Discord": { "BotToken": "" }
  },
  "Plugins": {
    "GitHub": { "Token": "" }
  }
}

Don't

Never paste a live token into any tracked file, including appsettings.json. Once committed it is in history and must be rotated.

"Scout": {
  "Plugins": {
    // real token committed to a public repo — published forever
    "GitHub": { "Token": "ghp_" }
  }
}

Enforcement

  • Security review gate. The Scout quality gates require the security-auditor agent to review any change touching credentials, token handling, or external API calls before a PR against main.
  • Branch + PR flow. Every change lands on main through a Pull Request from a feature branch; no direct pushes. The diff is the place a stray secret is caught before it reaches main.
  • Read-only invariant alignment. The GitHub plugin needs only read-only scopes, so tokens granted to Scout should never carry write permissions in the first place.
  • If a secret leaks. Treat the credential as compromised: rotate or revoke it immediately, then remove it from the tracked file. Rotation, not deletion, is the fix — history retains the old value.
