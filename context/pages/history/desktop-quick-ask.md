# Desktop quick ask - history

> Dated changes to [[pages/services/desktop-quick-ask]]; the service page states how it works now.

## 2026-11-10 - The quick-ask tests tear down after every test, and the restart path has its own file

- **Asked for:** two findings of Scout's audit of this repository: each quick-ask test disposed its quick ask as its last line, which a failed assertion skips, and one test file covered the worker restart, its IPC handler and the bell along with quick ask.
- **What changed:** tests only, no production code. `tearDown` in `ui/packages/main/test/quick-ask-fakes.ts:164`, run in `afterEach`, restores real timers and the clock, disposes every quick ask `setup()` registered and stops the worker it was given; the inline `dispose()` that only tore down is gone, and a `dispose()` a test asserts on stays. The shared `setup()` and its fakes moved to that module, and the describe "main restart path: a restart waits for the running answer and the live listen", the only one that wires the restart path, the restart channel and the notification store, moved unchanged to `ui/packages/main/test/worker-restart.test.ts:22`. Every other describe tests the quick-ask module, through `registerQuickAsk` or its exports, and stays in `quick-ask.test.ts`.
- **Tests:** the same titles as before, all passing, plus a pair that proves the hook (`ui/packages/main/test/quick-ask.test.ts:4094`): a test that leaves a quick ask open, a worker, fake timers and a fixed clock, then a test that finds them disposed, stopped and real.

## 2026-11-08 - The microphone and the speaker chosen in Settings

- **Asked for:** the owner, translated: "Should we have the device configuration in Settings? That way we can select what we want to use." ([[pages/decisions/0050-read-aloud-and-conversation-mode]], amendment "the microphone and the speaker").
- **What changed:** Settings has an Audio section with a Microphone and a Speaker picker and a held Test with a level meter marking the room and the worker's speech threshold ([[pages/services/desktop-ui]], Settings). Dictation, the conversation and a meeting's own lane now open the chosen microphone through one opener, read aloud and voice samples play on the chosen speaker, and an unplugged device falls back to the default with one notice. A refused microphone used to say "Scout could not use the microphone." like any other failure, and on the Chat screen a hold whose microphone did not open showed nothing at all; refused, missing and busy now each have their own sentence, on the Chat screen too.
- **Tests:** the quick-ask row "shows a clear message when the microphone is refused" changed on purpose, from the general sentence to "Scout was not allowed to use the microphone."; the Settings order row now lists Audio between the floating button and Desktop. New: `audio-devices.spec.ts`, `level-meter.spec.ts`, `audio-settings.component.spec.ts`, eight live-listener rows, five conversation-mode rows, five audio-player rows and three Chat screen rows.

## 2026-11-08 - The display choice of the floating button works

- **Asked for:** the owner, translated: in Settings the floating button's corners work, but the display choice does not: "Display with the mouse cursor" never puts the button on the other monitor, and only one monitor is ever used. Then: list each monitor by name and size so one can be chosen.
- **Found:** the owner's probe (Electron 45 under XWayland on COSMIC, laptop panel 1920 by 1080 at 0,190, external 3440 by 1440 at 1920,0, no RandR primary marked) showed moving a 64 px window across monitors works and `getPrimaryDisplay` returns the external monitor. The button was placed once, when it was shown, and never again: it did not follow the cursor and ignored displays added, removed or changed. Clicking in Settings on the external monitor made both choices resolve to the external monitor, since it is the primary and the cursor was over Settings there.
- **What changed:** with the mouse cursor the button follows the pointer with a 500 ms check and moves only on a new display; any display event places it again; a third choice puts it on one monitor by display id, with the primary as fallback and one notice while that monitor is away; Settings names the primary and lists the monitors from main, refreshed by the new push `scout:local.bubbleChanged`; each placement is logged, and a cursor still for 30 s on Wayland with two monitors is logged once and shown as a hint until the pointer is reported moving again, because Xwayland is told the pointer position only over its own windows. The quick-ask window keeps what the owner confirmed: it reopens at the bounds it was left at on any connected monitor, and the display choice places it only when nothing is saved or the saved bounds lie off every monitor.
- **Tests:** two main rows changed on purpose (`scout:local.setBubble` and `getBubble` answer the status with `monitors` and `hint`), one Settings row changed on purpose (the primary's label names the monitor); the rest are new, in the service page's Tests line.

## 2026-11-08 - Conversation mode that never fails silently

- **Asked for:** the owner, translated: "Conversation still does not work: I enabled it, spoke, and nothing was captured. No error in the logs." ([[pages/decisions/0050-read-aloud-and-conversation-mode]], amendment "a conversation that hears in a noisy room").
- **What changed:** a second listen on the microphone lane, a dictation hold or a quick ask while the Chat screen converses, replaced the conversation's session in main with no event, and every later chunk was refused and the refusal swallowed, so the button stayed on Listening with no error; main now ends the replaced session with "Another listen took the microphone." and the conversation turns off with that reason, as it does for refused audio. A click cleared the session before the stop, so the worker's flushed final was dropped; the conversation now follows the listen until it ends and asks what was said, while Esc drops it, also when pressed after the click while the listen drains, and so does closing the window or the Chat screen. The partial now shows after Listening, and the conversation's microphone opens without automatic gain.
- **Tests:** the main row "a second listen stops the open session first" changed on purpose, from no event for the old session to its `ended` with the reason; two main rows, eleven conversation-mode cases and one talk-button case are new.
