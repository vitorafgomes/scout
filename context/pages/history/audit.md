# Audit - history

> Dated changes to [[pages/services/audit]]; the service page states how it works now.

## 2026-11-13 - The checks before a review starts, first part

- **Asked for:** the owner's request that a process be validated before it starts, shown in progress, after reviews in which tests could not connect to Docker inside Scout's container and a review that read a few of its files ([[pages/decisions/0055-pull-request-review-as-a-job-in-batches]]).
- **What changed:** the review start answers `ReviewStart(Started, Sentence, Preflight)` and takes the head commit's check counts; five checks run before a review job is created (size, Docker runs, head, another review, grants), each ok, a warning or a block; a review running or done at the same commit blocks, the size is never shown past 60 minutes; a block starts no review and asks the gate for nothing; the checks are kept once with the job in a new `preflight` column through the `ReviewPreflight` migration, in the job's one save; `IReviewEnvironment`, adapted by the host from `Scout:Sandbox:Enabled`, read once; the batch turn's two tries became a named constant the size check uses. The AI Source, Docker on this computer, tests that need a Docker daemon and the stack were left for a next change, because the whole set passed the size of one change.
- **Tests:** `Scout.Audit.Tests` 221 to 235, the second start's theory asserting the check for another review; `Scout.Host.Console.Tests` three rows for the review environment; the review start's earlier tests green before and after.

## 2026-11-13 - A pull request review is started and planned, with no function to call it

- **Asked for:** the second change of the pull request review as a job ([[pages/decisions/0055-pull-request-review-as-a-job-in-batches]]): start and plan a review in the service only, so no turn can promise a review nothing runs.
- **What changed:** `IPullRequestReviews` with `StartAsync` and `StatusAsync`, on the same `RepositoryAudits` as the audit and registered with it; the audit's snapshot block became one method taking the reference, the audit passing the default branch and the review the head commit; a review is planned by patch length through the list planner, the files with no diff kept in one last batch not covered, `GitHub returned no diff`; `AuditBatchPlan` gained an optional failure that the store keeps as not covered when it creates the job; a start refuses a pull request with no file to read and stops a running or paused review of it at an earlier head; the worker runs audits only and leaves a running review as it is. The checks before a review starts, which ADR 0055 placed in this change, follow in a change of their own.
- **Tests:** `RepositoryReviewsTests` (30 cases), one store test and one worker test; the audit's start tests unchanged and green before and after; `Scout.Audit.Tests` 187 to 221. After review: a pull request number of 0 or below and a head that is not a commit SHA are refused, and the repository names are matched whole, so a trailing line break is refused on the audit's start too.

## 2026-11-12 - Entity Framework Core 10.0.14 to 10.0.15

- **Asked for:** the owner's "update all the DLLs that are out of date".
- **What changed:** `Microsoft.EntityFrameworkCore.Sqlite`, `Microsoft.Data.Sqlite` and the `dotnet ef` tool moved to the 10.0.15 servicing release with the rest of the .NET 10 packages; no code and no migration changed, and `dotnet ef migrations has-pending-model-changes` reports no pending change ([[pages/decisions/0052-persistence-behind-stores-on-entity-framework]], amendment of 2026-11-12). The 11.0.0 line targets `net11.0` only and is held back ([[pages/roadmap/followups]]).
- **Tests:** `Scout.Audit.Tests` (180) and `Scout.Meetings.Tests` (32) green at their earlier totals.

## 2026-11-11 - A model the AI Source does not have pauses the job

- **Asked for:** the missing-model refusal ([[pages/history/llm]]) applies to the audit too: a batch the AI Source answers HTTP 404 for its model was run twice and left not covered with a generic reason.
- **What changed:** the batch passes the chat service's model id to `LlmFailures.Translate`, so the 404 becomes `LlmModelNotFoundException`; that type joins the refusals that are not run again and pause the job, with the reason "the AI Source does not have the model <id>", like a rejected key. A start resumes the job once the model is installed.
- **Tests:** two rows in `A_batch_the_provider_refuses_for_its_limit_is_not_retried_and_asks_the_job_to_pause`, `model` with the exception and `http-404-model` with Ollama's 404 as the chat service raises it, the fake chat service naming its model; `ScriptedChat.Attributes` became settable for it.

## 2026-11-11 - The account out of credit is said as such

- **Asked for:** the Claude API's refusal for a credit balance too low ([[pages/history/llm]]); the owner asked that it read as the credit having run out, never as an error.
- **What changed:** `AuditBatchRunner.Reason` gives the quota code `credit_balance_too_low` the reason "the AI provider's account has run out of credit"; every other quota code keeps "the AI provider's usage limit was reached". The batch still asks the job to pause.
- **Tests:** two rows in `A_batch_the_provider_refuses_for_its_limit_is_not_retried_and_asks_the_job_to_pause`, one with the exception and one with the Claude API's 400 as the gateway sees it; the other rows unchanged and green.

## 2026-11-11 - A start wakes a worker left after an error; a retry counts only its own reads

- **Asked for:** two findings of the second automated audit: a transient worker error could strand a running audit, because the worker waits for the next start and a start of a running job answered "already running" without waking it; and a retry reused the file coverage of its failed turn.
- **What changed:** `StartAsync` wakes the worker when it finds the repository's job running, which the worker drops while busy; the two rows of the action table for a start on a running job now say the worker is woken. `AuditBatchRunner.RunAsync` gives the retry its own files-read set, and a second failure keeps the reads of that last attempt.
- **Tests:** `A_transient_worker_error_does_not_strand_a_running_audit_asking_to_start_it_runs_it_to_the_end` in `AuditWorkerTests.cs`, over a store whose first read of the running jobs fails; `A_retry_does_not_reuse_file_coverage_from_the_failed_turn` in `AuditBatchRunnerTests.cs`.

## 2026-11-10 - Pause, continue and stop from Scout Desktop, the .NET half

- **Asked for:** the owner's design for the bell's In progress list: a running audit has Pause and Stop, a paused one Continue and Stop; a click in the desktop is the owner's own decision.
- **What changed:** `IRepositoryAudits.ContinueAsync`, which resumes only a paused job, in the conversation it holds when the caller has none, and answers in a sentence for a running job or none to continue; a start would have started a new audit, with a new snapshot, for a stopped or done job. `StartAsync` and `ContinueAsync` share the resume. The desktop's pause and stop reuse `PauseAsync` and `StopAsync`, so the notices of the owner's pause and stop reach the job's conversation as they do from the chat.
- **Not done here:** the desktop half (the bell's buttons and the patterns for the stop notices) ([[pages/roadmap/followups]]).
- **Tests:** `Each_desktop_control_on_the_latest_audit_in_each_state_tells_the_desktop_one_sentence_and_keeps_the_jobs_conversation` (21 cases) and `Continuing_with_a_name_that_could_leave_the_snapshots_folder_is_refused` in `RepositoryAuditsTests.cs`; `A_control_from_the_desktop_posts_the_same_notice_as_the_chats_to_the_conversation_the_job_was_started_from` (three cases) in `AuditWorkerTests.cs`.
- **Review round, same day:** `IRepositoryAudits.ControlAsync(owner, repo, action)` answers `AuditControlAnswer(Applied, Sentence)`, so the desktop's record says whether a click changed the job; the string methods wrap it, unchanged for the chat.

## 2026-11-10 - The owner pauses an audit from the chat

- **Asked for:** "we should have a way to pause the audit"; this change is the worker side, the chat's pause and continue. The desktop's own controls are not built.
- **What changed:** `IRepositoryAudits.PauseAsync` and the GitHub plugin's `pause_repository_audit`, a write declared on the `Scout's data folder` row like the stop, listed on the `code-audit` skill's functions line and named in its text and description ("pause the audit", "pausa a auditoria"). A running job is paused with the reason `you paused it` through the store's existing `PauseAsync`; no new status, column or table. The worker already left a job that is no longer running after the batch in progress, so the batch in progress completes and its findings are kept and posted. `IAuditJobStore.PauseAsync` now answers whether it paused: it always paused only a running job, and the answer lets the owner's pause say "already paused" with the reason the job holds when the AI Source paused it first, and lets the worker post the AI Source notice only when its own pause took.
- **Behaviour that changed beside the pause:** a batch the AI Source refused on a job the owner stopped while it ran used to post "The audit of owner/repo paused: ..." for a stopped job; it now posts nothing, the job stays stopped.
- **Kept as it was:** a restart resumes no paused job, whoever paused it; the worker reads only running jobs at start. A start resumes a job the owner paused exactly as one the AI Source paused. Stop on a paused job works as before.
- **Review round 1, same day:** every post now goes to the conversation the job holds when it is posted, read again before each batch's posts, so an audit paused in one chat and continued from another posts there (it kept posting to the first one before). `IAuditJobStore.FinishAsync` answers whether it marked the job done, and the last post goes out only then: a pause or stop landing between the last area and the finish used to post `is done` for a job that was not, and continuing posted it again. When the worker leaves a job for the owner's pause it posts `The audit of owner/repo paused: you paused it. Ask Scout to continue the audit of owner/repo to resume it from the first area not done.`, also when the AI Source refused the area the owner had already paused; for the owner's stop it posts `The audit of owner/repo ended at your request: k of n areas done, f findings kept on the cards.`; each once, and none for a pause lifted before the area ended. The pause and stop replies say `; an area in progress finishes first.` instead of `after the batch in progress`, which was false between areas, for a job waiting behind another, and for stopping a paused job.
- **Not done:** the desktop bell has no pattern for the stop notice, so the audit's entry stays `running` after a stop (the notice shows as its own entry); a desktop path to pause, continue or stop without the model.
- **Tests:** the 28-case table `Each_action_on_the_latest_audit_in_each_state_tells_the_owner_one_sentence_and_leaves_the_status_row_as_the_rules_say`, `Pausing_an_audit_the_AI_Source_paused_after_it_was_read_says_it_is_already_paused_and_keeps_the_AI_Sources_reason` and the Rule I test `A_pause_the_database_refuses_to_save_is_told_as_a_sentence_and_leaves_the_audit_running_as_it_was` in `RepositoryAuditsTests.cs`; `Pausing_the_audit_while_a_batch_runs_keeps_and_posts_that_batchs_findings_and_runs_no_further_batch_until_it_is_continued`, `Pausing_during_the_last_batch_leaves_nothing_pending_and_continuing_ends_the_audit_with_its_last_post`, `The_AI_Source_refusing_a_batch_of_an_audit_the_owner_paused_keeps_the_owners_reason_the_batch_pending_and_posts_no_AI_Source_notice` and `A_restart_does_not_resume_a_paused_audit_whoever_paused_it` (the AI Source case green on the tree before the change too) in `AuditWorkerTests.cs`, and from the review round `What_the_owner_does_while_the_audit_runs_is_posted_once_to_the_conversation_the_job_holds_when_it_takes_effect` (five cases), `A_pause_landing_after_the_last_area_but_before_the_finish_posts_no_done_until_continued_and_the_done_post_once` and `A_stop_landing_after_the_last_area_but_before_the_finish_posts_the_stop_and_never_the_done`, with `RacingStore` in `Fakes.cs` as the seam that lands a write just before a pause or a finish; `Stopping_the_audit_ends_it_after_the_batch_in_progress_and_makes_no_further_call` now expects the stop notice; `The_plugins_pause_function_pauses_the_audit_job_through_the_write_gate_and_a_start_continues_it` in `HostAuditTurnTests.cs`. The lists that pin the functions and writes (58 functions, 21 writes) were updated. Each new rule failed its test with the rule taken out in a backup copy.

## 2026-11-10 - No clean verdict for code nobody read

- **Asked for:** the open review threads on the pull request for Scout's own finding "An unread batch is accepted as covered": the earlier fix took an unread area out of the covered count, but the last post still opened with `Verdict: sound (0 High, 0 Medium, 0 Low)` when an area was not read, and the runner still reported such a batch as a plain success.
- **What changed:** `BatchOutcome` carries `Unread`, the batch's files the model did not read on a turn that ended without error, computed by `AuditBatchRunner.Unread`, the one rule the last post also applies to the kept rows. The last post's verdict is `incomplete`, with the counts of what was found, when any area was not read in full or not covered; the batch card of an area whose outcome names an unread file says `incomplete` whatever verdict the model gave. The model's vocabulary is unchanged: `incomplete` is the job's word only.
- **Not covered by a case:** an area with no files, which the planner never produces (every batch it cuts holds at least one file, and an empty plan is refused before a job exists).
- **Not changed:** a partly read batch keeps its done row and its findings and is not run again, so a model that keeps skipping a file cannot loop the area. The last post is still built from the kept rows, not from the outcomes, because it runs after a restart too and the rows hold exactly the files each outcome read; carrying the outcome's unread list into the rows would need a new column and migration. A file read only in its first 20,000 characters does not make the verdict incomplete.
- **Desktop:** the notification of the last post shows the rest of its first line as text, and the audit card accepts any non-empty verdict text and keeps it without displaying it (its preview shows the issues, not the review body); `incomplete` needs no desktop change.
- **Tests:** `A_clean_report_is_never_given_with_files_never_read` (eight cases: no read at all, an area read in part with and without a High finding, everything read with and without one, a failed area, a failed area beside one read in part) and `The_card_of_an_area_read_in_part_says_incomplete_whatever_verdict_the_model_gave` (five cases, nothing read among them) in `AuditWorkerTests.cs`; `An_unread_batch_is_not_accepted_as_covered_its_outcome_names_every_file_the_model_did_not_read_and_keeps_its_findings` (four cases) in `AuditBatchRunnerTests.cs`. Five earlier tests that pinned `sound` for an unread or failed area now expect `incomplete`. Each new test failed with its rule taken out in a backup copy.

## 2026-11-09 - Coverage only for files read, findings only inside the batch, a turn time limit above zero

- **Asked for:** Scout's own audit of this repository (issues "An unread batch is accepted as covered", "A failed file read is recorded as successful", "Presented findings are not constrained to the batch", "Invalid timeouts can make every batch fail").
- **What changed:** the read filter calls the function first and records the path only once the read returned the file's content, so a read that threw is not coverage, and neither is a read the GitHub plugin answered with a sentence instead of the file (not found, a directory, a binary, a refused name, GitHub not reached): the filter opens a `ReadOutcome` scope around each call, a per-call signal in `Scout.Llm.Abstractions` shaped like `TurnAttachments`, the plugin's `get_file_contents` marks every answer that is not the file's text, and the filter records the path only when the call is unmarked. The answer the model receives and the function's signature are the same as before, and the audit reads no answer text to decide. Such a file is named among the unread files of its area in the last post. A batch answered without reading every file still keeps its findings and its done row, but the last post no longer counts its area as covered: it names it on a `Not fully read: area (not read: a, b).` line, and `Every area was covered.` appears only when no area failed and none was read in part. `FindingsBlock.Read` takes the job's owner, repository and commit and drops a block for another repository or commit (a block that names no commit is taken as the job's); the batch runner then drops findings in files outside the batch, comparing paths without case as the merge does, and logs one Warning with the count. `Scout:Audit:TurnTimeout` is validated above zero with `ValidateOnStart`, so a zero or negative value stops the host at start instead of leaving every area not covered.
- **Not changed:** a batch answered without reading every file keeps its done row; only the last post tells it apart. A read made outside an audit scope, the chat's, answers as before and marks nothing.
- **Tests:** `A_file_whose_read_failed_is_not_counted_as_read_when_the_model_carries_on` and `Findings_outside_the_batchs_files_repository_or_commit_are_dropped_and_logged` (six cases) `A_file_the_plugin_could_not_read_is_not_counted_as_read_and_a_file_read_normally_is` (not found, an error line), `Of_two_reads_at_once_only_the_one_the_plugin_could_not_read_is_left_uncounted` and `A_read_that_marks_nothing_counts_as_before_whatever_its_answer_says` in `AuditBatchRunnerTests.cs`; `An_area_whose_files_were_not_all_read_is_not_counted_as_covered_and_its_unread_files_are_named`, `An_unread_batch_is_not_accepted_as_covered_and_every_file_it_did_not_read_is_named` and `A_file_the_plugin_could_not_read_is_named_among_the_unread_files_in_the_final_post` in `AuditWorkerTests.cs`; `ReadOutcomeTests.cs` in the Llm tests, `GitHubPluginReadOutcomeTests.cs` in the plugin's (every answer that is not the file's text marked, the text whole or cut left unmarked, from GitHub and from a snapshot, the failing read being the Rule I test) and `A_batch_turn_on_ollama_counts_the_file_the_plugin_read_and_not_the_one_it_did_not_find` in `HostAuditTurnTests.cs`; `A_turn_time_limit_that_is_not_above_zero_is_rejected_when_the_host_starts` and `A_turn_time_limit_above_zero_or_the_default_starts` in the new `AuditServiceCollectionExtensionsTests.cs`. `The_earlier_titles_a_batch_is_told_are_only_those_of_its_own_files` and `A_finding_an_earlier_batch_reported_is_not_posted_again` now seed the earlier finding through the store, because a batch turn can no longer report a finding in another batch's file.

## 2026-11-08 - The batch kernel from KernelScope, and an undeclared call logged

- **Asked for:** phase S2 of [[pages/roadmap/security-hardening]] ([[pages/decisions/0054-functions-scoped-per-skill-and-job]]): one helper for every scoped turn, and a log line when the model reaches for a function its job did not declare.
- **What changed:** the batch turn builds its kernel with `KernelScope.Only` from `Offered` instead of its own loop; after the turn, every function call in the history that names none of the six is logged as a Warning, without its arguments; automatic function choice is sent only when the copy holds one of the six.
- **Tests:** `A_batch_turn_offers_the_model_only_the_reads_the_project_search_and_present_audit_findings` green before and after (the behaviour lock); `A_call_to_a_function_the_batch_does_not_offer_is_logged_by_name_without_its_arguments` and, on the Ollama connector, `HostAuditTurnTests.On_ollama_a_batch_turn_whose_model_calls_an_unoffered_write_never_runs_it_and_logs_it_by_name` are new.

## 2026-11-08 - The store behind IAuditJobStore, on Entity Framework Core

- **Asked for:** persistence behind one specific store per use case, no SQL queries in code, Entity Framework Core ([[pages/decisions/0052-persistence-behind-stores-on-entity-framework]]).
- **What changed:** `IAuditJobStore` and `AuditStatus` came out of `SqliteAuditStore`, and `RepositoryAudits`, `AuditWorker` and the registration use the interface; the store reaches `audit.db` through an internal DbContext and an `Initial` migration instead of SQL strings; the `ALTER TABLE ... ADD COLUMN` upgrade of the first schema is gone, and a file an older build wrote is deleted and created again, its jobs lost. The `Initial` migration also creates `audit_job (status, started)`, `audit_job (owner, repo, started)` and `audit_finding (job_id, seq)`, after `EXPLAIN QUERY PLAN` showed the running jobs, the latest job and the findings scanning or sorting. An older build's file is deleted only when every table it holds is a known one; the Initial migration class is internal.
- **Tests:** `A_database_written_before_the_pause_reason_and_partial_columns_opens_and_keeps_its_jobs` was replaced by `A_database_an_older_build_wrote_without_the_migration_history_is_created_again_with_the_current_schema`; the WAL test leaves EF's and SQLite's own tables out of its list and checks the migration history; `A_database_that_refuses_a_write_is_a_sentence_naming_the_sqlite_error_and_keeps_what_it_held` is new. The status constants in four test files and `HostAuditTurnTests` moved to `AuditStatus` and `IAuditJobStore`.
