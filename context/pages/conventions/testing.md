# Testing

> Test behaviour at the project boundary with fakes and substitutes; the build fails on any warning; CI runs build then test on every push and pull request to `main`.

## Stack

Versions come from `Directory.Packages.props` (central package management).

- xUnit 2.9.3 (`Directory.Packages.props:58`) with `xunit.runner.visualstudio` 4.0.1 (still runs xUnit v1, v2 and v3 test projects) and `Microsoft.NET.Test.Sdk` 18.12.0 (`:59`, `:60`).
- Shouldly 4.3.0 for assertions (`Directory.Packages.props:63`). FluentAssertions was removed because v8 went commercial; do not mix two assertion libraries (comment at `:61`).
- NSubstitute 6.2.0 for substitutes (`Directory.Packages.props:64`).
- `Microsoft.Extensions.TimeProvider.Testing` 10.11.0 for a fake clock (`Directory.Packages.props:65`); the adapter and conversation tests use it.
- `coverlet.collector` 10.1.0 for coverage (`Directory.Packages.props:66`).
- `Grpc.Net.Client` for the control-plane integration tests (`tests/Scout.ControlPlane.Tests/Scout.ControlPlane.Tests.csproj`).
- `Microsoft.AspNetCore.Mvc.Testing` is declared (`Directory.Packages.props:19`) but no test project references it.

## What the build enforces

`Directory.Build.props` applies to every project, test projects included.

- `TreatWarningsAsErrors` true (`Directory.Build.props:7`): any compiler or analyzer warning fails the build.
- `AnalysisLevel` latest (`Directory.Build.props:8`) and `EnforceCodeStyleInBuild` true (`:9`): code-style rules run in the build.
- `Nullable` enabled and target `net10.0` (`Directory.Build.props:5`, `:3`).
- XML documentation is generated and `CS1591` suppressed for non-test projects only (`Directory.Build.props:10`, `:11`). Test projects set `IsTestProject` (for example `tests/Scout.Llm.Tests/Scout.Llm.Tests.csproj:5`), so they generate no documentation file.
- Because test projects emit no documentation file, unused-using diagnostics (IDE0005) are not raised by the plain build. `tools/checks/check-diagnostics.sh:1` forces them on and fails on any remaining diagnostic; run it on a single project for speed. CI runs it on the whole solution.
- `AnalysisMode` Recommended (`Directory.Build.props:9`) and fifteen rules raised to warning in the root `.editorconfig` (`.editorconfig:43`), since 2026-11-06; the list, the triage and the gate that keeps them on are on [[pages/conventions/tooling]].
- `tests/Scout.ArchTests` (2026-11-06) is the suite about the repository itself: the layering of [[pages/architecture/project-map]] as NetArchTest rules (leaves reference no other Scout assembly, `tests/Scout.ArchTests/ArchitectureTests.cs:58`; adapters and plugins reference neither each other nor a host, `:72`; the conversation core reaches only Llm and Skills, `:106`; Operator reaches the control plane only through its own abstraction, `:116`), the analyzer gate, the test-suite health (no skipped test, `tests/Scout.ArchTests/TestSuiteHealthTests.cs:26`; every source project has `tests/<Name>.Tests` except the two the map covers from `Scout.ControlPlane.Tests`, `:15`; every test project is in `Scout.slnx`; no test directory without a project), and three source scanners: a format specifier in an interpolated string names its culture (`tests/Scout.ArchTests/CultureExplicitFormattingTests.cs:74`), a comment never cites a context folder path, an ADR number or an issue number (`tests/Scout.ArchTests/CommentReferenceTests.cs:36`; the context folder cites code, code does not cite the context folder), and every test project asserts with Shouldly and none references FluentAssertions (`tests/Scout.ArchTests/AssertionLibraryTests.cs:12`). The scanners blank string literals and comments before matching, with their own tests in `SourceTextTests.cs`. `PersistenceTests` (2026-11-08) keeps persistence inside the stores ([[pages/decisions/0052-persistence-behind-stores-on-entity-framework]]): no type outside the store classes, their `Storage` namespaces and the knowledge store depends on SQLite or Entity Framework (`tests/Scout.ArchTests/PersistenceTests.cs:66`), and no source file under `src/` outside the store files holds a SQL statement or names either namespace (`:79`, `:92`); this scan reads the string literals, where SQL lives.

## Patterns in use

- **Composition tests.** Build a `ServiceCollection` from an in-memory configuration and resolve the graph. `tests/Scout.Host.Console.Tests/HostCompositionSmokeTests.cs:121` builds the full host with a handler that throws on any network call, which proves resolution does no I/O.
- **Self-gating tests.** Each optional module has a test for "not configured means not registered" (for example `tests/Scout.Plugin.GitHub.Tests/GitHubServiceCollectionExtensionsTests.cs:22`).
- **Boundary fakes.** SDK edges are faked: a fake HTTP handler for GitHub (`tests/Scout.Plugin.GitHub.Tests/Fakes/`), a recording sender for Teams (`tests/Scout.Adapter.Teams.Tests/Streaming/RecordingSender.cs`), a recording sink for the conversation core (`tests/Scout.Conversation.Tests/Fakes/RecordingResponseSink.cs`), a fake embedder for skills (`tests/Scout.Skills.Tests/FakeEmbeddingGenerator.cs`).
- **One failing-call test per external boundary (Rule I).** A failing-call test makes the real client library raise its real exception, by placing a fake `HttpMessageHandler` under the real connector, instead of constructing the exception by hand: `tests/Scout.Llm.Tests/ChatGatewayRateLimitTests.cs:151` drives the real OpenAI connector into a 429, which a hand-made `HttpOperationException` had hidden ([[pages/history/llm]]).
- **Stdio boundaries.** The local adapter is tested over a real `AnonymousPipeServerStream` for stdin and a capturing `TextWriter` for stdout (`tests/Scout.Adapter.Local.Tests/LineCapture.cs`), so the line splitting, the 20 MB cap and end of file run through the same stream code as production; its wait helper fails with a Shouldly message that names the missing event and prints the captured stdout, never a bare timeout. On the desktop side the supervisor's stdin is a Node `Writable` whose callback fails with EPIPE (`ui/packages/main/test/worker-supervisor.test.ts`).
- **Regression tests named for the bug.** `tests/Scout.Llm.Tests/CompositionCycleRegressionTests.cs` pins the kernel and embedder construction cycle.
- **Real integration.** `tests/Scout.ControlPlane.Tests/Integration/ControlPlaneUdsIntegrationTests.cs` starts the control-plane host on a real Unix socket; the `uds` collection (`tests/Scout.ControlPlane.Tests/Integration/UdsCollection.cs:10`) serialises those tests. SQLite tests use a real file (`tests/Scout.Knowledge.Tests/SqliteProjectKnowledgeStoreTests.cs`).
- **Relative times pin the clock.** A test that asserts a relative time (`now`, `12 min`, a date) runs with the clock pinned (`vi.useFakeTimers({ toFake: ['Date'] })` and `vi.setSystemTime`), because a `Date.now()` read at module load drifts on a loaded machine and turns `12 min` into `13 min` (`ui/packages/renderer/src/app/shell/notification-bell.component.spec.ts:19`).
- **Process-wide stores.** Tests that assert on a static, process-wide store run in one xUnit collection with parallelisation disabled, because another class reaching the store with a different clock expires or evicts their entries: `ChatOrigin` keeps its marks in one static dictionary capped at 256, so `ChatOriginMarksTests` and `ChatOriginTurnEndTests` share the `chat-origin-kept-marks` collection (`tests/Scout.Conversation.Tests/Abstractions/ChatOriginKeptMarksCollection.cs`).
- **No live services.** No test calls Discord, Slack, Teams, GitHub, Azure or an LLM.
- **A test that depends on a machine capability** asserts an exact outcome for each capability, chosen by an oracle independent of the code under test, and is never skipped (2026-11-12, issue 372). `WhisperAudioTranscriberTests.A_File_That_Is_Not_A_Whisper_Model_Fails_As_A_Model_Load_Error_Where_The_Runtime_Loads_And_As_Unavailable_Where_It_Does_Not` asks the operating system whether `libgomp.so.1` loads (`NativeLibrary.TryLoad`), not Whisper.net, and expects exactly `WhisperModelLoadException` where it does and exactly `TranscriptionUnavailableException` with its sentence where it does not; on GitHub Actions it first asserts the capability is there, so CI cannot drift into the other branch without failing ([[pages/services/transcription-whisper]]).
- **A guard ships with the input that fires it.** A new validation, precondition or error branch has a test whose input reaches it and that asserts the outcome it promises; a check no input can reach is a defect ([[pages/invariants/a-guard-must-be-able-to-fire]]). Behaviour that reads as a bug and is intended is recorded in [[pages/conventions/decisions-that-look-like-defects]], with the test that locks it.

## Running

- All tests, one project at a time with a verdict per project: `bash tools/checks/test-per-project.sh`. A solution-wide `dotnet test` from the root still works but reports one total. When `docker version` gets no answer from a daemon, the script runs `Scout.Sandbox.Tests` with `--filter Category!=Docker` and prints "Docker is not reachable; the Docker end-to-end tests did not run." (`tools/checks/test-per-project.sh:18`); those tests never pass without Docker, they fail with a sentence naming that filter. On the owner's machine the selected Docker context may be a stopped Docker Desktop; `DOCKER_CONTEXT=default` reaches the native engine.
- One project: `dotnet test tests/Scout.Llm.Tests`.
- One test: `dotnet test tests/Scout.Llm.Tests --filter "FullyQualifiedName~Unknown_Provider"`.
- Pinned SDK 10.0.100 with `latestMinor` roll-forward (`global.json`).

## CI

`.github/workflows/ci.yml`, triggered on push and pull request to `main`:

1. The seven hook self-tests, the self-test of the review workflow (`.claude/workflows/scout-review.test.sh`), the seven script self-tests (`check-context-refs`, `test-per-project`, `next-version`, `with-test-version`, `release-workflow`, `check-diagnostics`, `install-git-hooks`), then `tools/checks/check-context-refs.sh` (`.github/workflows/ci.yml:18`), which resolves every `path:line` citation in `context/pages`.
2. Setup .NET from `global.json`, then `dotnet restore`.
3. A second SDK, 10.0.2xx, which `global.json`'s `latestMinor` roll-forward then selects for the rest of the job, and `dotnet format Scout.slnx --verify-no-changes --no-restore` (`.github/workflows/ci.yml:54`): the 10.0.1xx band cannot open the workspace `dotnet format` needs.
4. One build, through the gate: `tools/checks/check-diagnostics.sh Scout.slnx info Release` (`.github/workflows/ci.yml:62`) rebuilds the solution in Release with the documentation file and the IDE rules forced on, and fails on any diagnostic at any severity.
5. `tools/checks/test-per-project.sh --configuration Release --no-build` with the trx logger and XPlat coverage (`.github/workflows/ci.yml:67`), on the gate's output: one verdict per project, Skipped must be 0.
6. The `Category=Docker` tests of `Scout.Sandbox.Tests` again, on their own (`.github/workflows/ci.yml:72`): the script above leaves them out when no daemon answers, and ubuntu runners have one, so a missing daemon fails the job instead of thinning the suite.

The format check was disabled from 2026-10-21 to 2026-11-06 because `dotnet format --verify-no-changes` times out on the 10.0.1xx SDK; it runs again under 10.0.2xx. Locally, the same SDK from `$HOME/.dotnet` runs it (tooling page); `dotnet format whitespace --folder` is the fallback under the pinned one.

- **The voice model switch.** `ui/packages/main/test/whisper-model-switch.integration.test.ts` is the guarantee that the worker running after the owner changes the voice model loads the model the UI marks In use: it drives the real vault, Whisper and notification handlers, the restart policy, `buildEnv` and the supervisor over a real `whisper-models` folder in a temp directory, and only the worker is fake, a small JavaScript file the supervisor spawns through the test runner's own executable (so it runs on the Windows runner too) that records the `SCOUT__TRANSCRIPTION__MODELPATH` of each spawn (Use this, removing the loaded model with and without another one, a download from the bell, the Desktop dialog and the Transcription screen, a live listen deferring the restart, Use this while stopped, a saved choice that is not installed). The worker side is `tests/Scout.Host.Console.Tests/HostVoiceCompositionTests.cs` (a model path registers the Whisper transcribers; none, or a deleted file, registers none). Removing the restart from the shared path fails seven of its nine rows.
- The `Build control-plane host` step (`.github/workflows/ui-ci.yml:110`) builds `Scout.Host.ControlPlane` in Release before `Test (UI)`, because `ui/packages/main/test/control-plane-integration.test.ts` launches the real binary and fails, never skips, when it is missing.

- **Teardown runs in a hook.** A test that leaves something behind (IPC handlers, a global shortcut, module state, a worker, fake timers or the clock) undoes it in `afterEach`, never as its last line, which a failed assertion skips: the quick-ask and worker-restart files run `tearDown` (`ui/packages/main/test/quick-ask-fakes.ts:168`) after each test over the `setup()` they share, one test file per module (2026-11-10).
- **Catch a rejection before triggering it.** In `bun:test`, a promise that rejects while the test awaits something else is reported as an unhandled rejection and fails the test, even when `expect(...).rejects` is awaited right after; the OAuth loopback tests awaited a `fetch` first and failed on macOS only, where the server rejects before `fetch` resolves. An unawaited `expect(...).rejects` does not help: Bun evaluates it at once and blocks the test until the promise settles. Attach `const settled = promise.catch((err: unknown) => err)` before the call that triggers the rejection, then assert `expect(await settled).toBeInstanceOf(...)` (`ui/packages/main/test/oauth-loopback.test.ts:111`).
