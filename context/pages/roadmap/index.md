# Roadmap

- [[pages/roadmap/approve-together|Approve together: one decision for a set of listed actions]] - Accepted, phase 1 started: the owner approves the issues or comments one request queued with one decision on a listed, fixed set, in the Chat's approval strip and on Approvals, and a findings card's Open issues is itself the approval; each action stays one row, one log entry and one send.
- [[pages/roadmap/candidate-features|Candidate features: what Scout could take on later]] - Features seen in the projects surveyed on 2026-11-07, and ideas that came up while building the gap plan, kept as candidates: each with its fit with Scout's purpose, the writes it would need, what it depends on and a rough size. None is committed; the owner picks.
- [[pages/roadmap/chatgpt-plan-provider|ChatGPT plan provider]] - Let the desktop owner sign in with a ChatGPT Plus or Pro plan and have Scout answer through it, via OpenAI's official Sign in with ChatGPT plan usage, entirely behind Semantic Kernel.
- [[pages/roadmap/code-quality-assistant|Code quality assistant]] - Initiative: from a chat message, Scout reviews a pull request and posts the review on it, or finds what a project could improve and opens the issues, in any language, under the owner's write grant and per-action approval.
- [[pages/roadmap/control-plane-client|Control plane client]] - Give the desktop UI a gRPC client to Scout.Host.ControlPlane so the Providers, Features and Models screens and the Ollama pull run through the .NET control plane instead of Node.
- [[pages/roadmap/desktop-auto-update|Desktop update notice and one-click update]] - Initiative: Scout Desktop learns from GitHub Releases that a newer version exists, shows what is new, and installs it only after the user says yes; AppImage and Windows first, macOS after code signing.
- [[pages/roadmap/followups|Follow-ups]] - Deferred work found while doing something else: each entry names the blocker, the evidence and what unblocks it.
- [[pages/roadmap/future-improvements|Future improvements: what widens Scout]] - The ordered list of improvements that widen Scout once the gap plan is done: project memory, ideas and roadmap from a repository, AI Sources with usage, Claude as a provider, Angular Material screens, audit validation, the code graph, credentials in a keyring, the YouTube operator.
- [[pages/roadmap/gap-plan|Gap plan: what blocks real use today]] - The ordered list of defects and missing pieces that stop the owner from using Scout on a real repository today; one change per version, the sister page of the future-improvements plan.
- [[pages/roadmap/live-assistant|Live assistant: hear, see and translate for the owner]] - Initiative: Scout hears a call or meeting, shows the owner a live transcript the chat can answer about, captures the screen on request, reads its text and translates, all on the owner's machine, declared as reads under ADR 0032.
- [[pages/roadmap/live-voice-spike|Live voice conversation in Discord (spike)]] - Research spike for Scout joining a Discord voice channel, listening only to allowed users, transcribing locally, answering through the conversation core and speaking the answer; verdict go, gated on a Discord.Net DAVE fix, with a sidecar as the fallback.
- [[pages/roadmap/ollama-local-models|Ollama and local models: make the whole flow work]] - The survey of the whole local-model flow in the desktop (connect, install, choose, chat, switch away), the decisions taken, the defaults in force, every finding with its evidence and the order of the lanes that fix them.
- [[pages/roadmap/phase-2-audit-findings|Phase 2: the findings of Scout's audit of its own repository, lane by lane]] - Tracker of pull request 120: the 98 findings Scout's audit opened on this repository and the prototype screens migrated beside them, with the branch, the state and the next step of each lane, the decisions that wait for the owner and the order to resume.
- [[pages/roadmap/production-screen|Production screen: the owner's working area first]] - Initiative: rearrange Scout Desktop's Production screen around the project the owner is working on, with the presenter block in two columns, removable presenter versions, claims readable at a glance, a close for the detail and a help mark on every block.
- [[pages/roadmap/project-memory-spike|Project memory spike]] - Research: why a whole-repository audit stops early and forgets, what two outside projects do about memory, audits, ideas and roadmaps (mechanisms only), and the design both plans adopt.
- [[pages/roadmap/prototype-migration|Prototype migration: the desktop screens brought to the approved artboards]] - A screen-by-screen audit of the built Scout Desktop against the approved prototype artboards, with each difference's severity and component, and the order in which the screens migrate to the artboards and to Angular Material, one version per screen.
- [[pages/roadmap/security-hardening|Security hardening: Scout's own agent safety and a sharper security dimension]] - Measured prompt-injection resistance, functions scoped per skill and job, Electron fuses and a sender check on grant IPC, an evidence chain on security findings, and Scout's own threat model.
- [[pages/roadmap/teams-adapter-spike|Teams adapter live: inbound endpoint spike]] - Research and design for making Microsoft Teams reach Scout on the owner's machine: what Teams needs, which .NET SDK is current, how to expose a local endpoint safely, streaming, packaging and what the desktop can automate.
- [[pages/roadmap/voice-meetings-spike|Voice and meetings spike]] - Research: voice and meeting mechanisms from an open-source dictation app (mechanisms only), mapped to the quick-ask window and the Chat screen, with the owner's machine findings, items 0 to 11, sizes and a phase order.
- [[pages/roadmap/youtube-channel-operator|YouTube channel operator]] - Initiative: Scout runs a YouTube channel end to end, from topic research and scripts through narration, visuals and an assembled video, to a review step, upload and scheduling the owner approves, and a learning loop over the channel's analytics; own C# code, official APIs, per-feature permissions (ADR 0032).
- [[pages/roadmap/youtube-creator-assistant|YouTube creator assistant]] - Initiative: give Scout what the claude-youtube skill offers (channel audit, analytics, competitor research, SEO, scripts) as a read-only plugin over the YouTube APIs with browser sign-in, grounded in live data and dated benchmarks.
