## Docker card

[[pages/decisions/0047-the-docker-card]] parts 1 and 2: the Docker card sits right after the GitHub card in the Features grid (`ui/packages/renderer/src/app/features/features.component.ts:488`) and its sections fill the Docker side panel (`ui/packages/renderer/src/app/features/features.component.ts:276`). It is not a catalog feature and declares no function the model can call.

- **Main's docker module** (`ui/packages/main/src/docker/docker.ts:287`), the `docker` command line as a subprocess through the detect helper (`ui/packages/main/src/detect/deps.ts:7`), which now tells a command that could not start (`failure: 'missing'`, ENOENT) and a killed one (`failure: 'timeout'`) apart from a non-zero exit (`ui/packages/main/src/detect/deps.ts:27`, `:53`):
  - `state()` (`ui/packages/main/src/docker/docker.ts:294`) runs `docker version --format '{{json .}}'` with a 5 s timeout: the command missing is `notInstalled`; a non-zero exit, a timeout or JSON without a `Server` is `notRunning`, with the reason in an `info` log line; otherwise `running` with the server's version. Only when Features opens and on Refresh, never on a timer.
  - `images()` (`ui/packages/main/src/docker/docker.ts:313`) runs `docker image inspect` for each pinned reference; anything but exit 0 reads as missing. `PINNED_IMAGES` (`:18`) is main's copy of `SandboxImages` in `src/Scout.Sandbox/SandboxStacks.cs`, 33 images in seven stacks (.NET SDK 8, 9 and 10, Node 18 to 26, Bun 1, Python 3.10 to 3.14, Go 1.23 to 1.26, Java (Maven) on JDK 8, 11, 17, 21 and 25, Java (Gradle) 7, 8 and 9 on several JDKs), each new one appended at the end in its stack's group; a test reads that file and fails on any drift.
  - `pull(stack)` (`ui/packages/main/src/docker/docker.ts:325`) runs `docker pull` of the missing images of one stack only, one at a time, 30 minutes each, pushing `pulling`, `done` or `failed` per image to the window that asked; a stack Scout does not pin is refused before any call, so no request pulls all 20. The first failure stops it and answers "Docker could not download <reference>: <reason>. The other N images were not downloaded."; a 429 or `toomanyrequests` answers "Docker Hub is limiting downloads; try again later." (`:603`); a second pull while one runs is refused.
  - `pullImage(reference)` (`ui/packages/main/src/docker/docker.ts:335`) downloads one pinned image when Docker lacks it, through the same loop as `pull` (`download`, `:345`): the same progress, the same sentences, the 429 sentence included, and the same one-download-at-a-time refusal. A reference that is not in `PINNED_IMAGES`, a pinned tag with another digest included, answers "<reference> is not an image Scout pins." before any `docker` call. It is how the card fetches a repository's image without the rest of its stack.
  - `workFolder()` and `clear()` (`ui/packages/main/src/docker/docker.ts:389`, `:401`): the folder's size, counted without following a symbolic link, and `runs`, the number of `<id>.run.json` records in it (never the run folders or the logs, and never a record that says `running`), 0 when the folder is missing or cannot be listed; Clear deletes the folder's contents with `fs.rm`, which removes a link and never what it points to, and is refused while a pull runs, while a run's folder is younger than 21 minutes (the sandbox's 20-minute limit and a minute more, because main does not know when a run starts or ends), or when the folder exists but cannot be listed ("Scout could not read the work folder, so nothing was deleted.", `CLEAR_UNREADABLE`, logged with the error code only); a folder that does not exist yet clears with no refusal.
  - `repositories()` (`ui/packages/main/src/docker/docker.ts:454`) reads every `<owner>__<repo>.stack.json` the GitHub plugin writes in the snapshots folder ([[pages/services/plugin-github]]), newest `detectedAt` first; `lastRun()` (`:459`) reads every `<id>.run.json` the sandbox writes beside its logs in the work folder ([[pages/services/sandbox]]) and answers the newest `finishedAt` of a finished run, a `running` record never being the last run, or null; `running(repository, pullRequest)` (`:471`) answers the command and `startedAt` of the newest running record of that pull request, the repository compared without case, or null, and skips a record that does not parse without a log line, because the bell asks every 2 seconds. Each record is checked field by field (`toRepository`, `:515`: text repository and commit, an image or a refusal and never both or neither, each declared version with its file, a time; `toRun`, `:552`: `running` with a command, a start and a null `finishedAt`, or `passed`, `failed` or `notRun` with a finish time, the command as text or null, `startedAt` a time or null, an older record without either read as null, whole numbers or null for the pull request and the exit code, a finite duration, a time) and copied without any other field; one that does not parse or does not match is skipped with a `warn` line naming the file, and the others are read. A missing folder reads as none. Both are reads of Scout's own folders; nothing is written.
  - Pull and Clear are the owner's writes, from his click only: the pull into Docker's own image store, the clear inside Scout's work folder. Each is logged with the reference or the path and the byte count, never Docker's own error text.

- **The snapshots folder** main reads is the work folder's sibling, `LocalApplicationData/Scout/github-snapshots` (`githubSnapshotsFolder`, `ui/packages/main/src/docker/docker.ts:225`, `ui/packages/main/src/main.ts:648`), the worker's default; it is not passed to the worker, so a `Scout:Plugins:GitHub:SnapshotsDirectory` set outside Scout Desktop is not seen by the card.

- **The work folder** is main's: .NET's `LocalApplicationData/Scout/sandbox` per OS (`sandboxWorkFolder`, `ui/packages/main/src/docker/docker.ts:200`), passed to the worker as `SCOUT__SANDBOX__WORKDIRECTORY` (`ui/packages/main/src/worker/build-env.ts:131`).

- **Channels** (`ui/packages/shared/src/ipc-contract.ts:129`): `scout:docker.state`, `scout:docker.images`, `scout:docker.pull`, the pushed `scout:docker.pullProgress`, `scout:docker.workFolder`, `scout:docker.clear`, `scout:docker.repositories`, `scout:docker.lastRun` and `scout:docker.pullImage` (`ui/packages/shared/src/ipc-contract.ts:135` to `:137`), none with a write verb, registered by `registerDockerHandlers` (`ui/packages/main/src/ipc/docker.ts:13`, `ui/packages/main/src/main.ts:746`) and bridged by preload.

- **The switch** "Run a project's tests in isolated containers" is Scout's own setting, the public vault key `sandbox.enabled` (`ui/packages/shared/src/client-kinds.ts:22`, `:66`): the card reads it back with `scout:vault.getPublic`, writes `true` or `false` with `scout:vault.store`, and restarts a running worker through main's restart path, showing a deferred answer under the switch and a failed one as its error (`ui/packages/renderer/src/app/features/docker-card.component.ts:1175`). `buildEnv` passes `SCOUT__SANDBOX__ENABLED=true` only while it is `true` (`ui/packages/main/src/worker/build-env.ts:132`); the supervisor drops an inherited `Scout:Sandbox:Enabled` or `Scout:Sandbox:WorkDirectory` in any spelling (`ui/packages/main/src/worker/supervisor.ts:481`), so neither the switch nor the folder can come from the desktop's own environment; and the host's sandbox adapter runs nothing without it ([[pages/services/sandbox]]). It is disabled until GitHub is connected; its help says a run also needs GitHub's write permission on its card, and, while Docker is not running, that runs wait for Docker. A vault that refuses the write puts the switch back and says why.

- **The credential dialog of a control-plane feature** (`sc-credential-dialog`, `ui/packages/renderer/src/app/features/credential-dialog.component.ts:220`) is the artboard's card: "Fields marked * are required. Values stay in this computer's protected storage.", a * after each required label, Required permissions folded with each scope in words, How to get this credential, Cancel focused when it opens, the focus held inside (`:222`) and Esc cancelling. Save stays enabled: pressed with a required field empty it saves nothing, marks the empty fields `aria-invalid` and says how many are empty (`:399`, `onSubmit` `:561`). A password field stays a password field, and no value is written into text, a title or a label.

- **The voice model dialog** opens 160 px from the top in the panel class `sc-voice-dialog` (`ui/packages/renderer/src/app/features/voice-model-dialog.component.ts:224`), which `ui/packages/renderer/src/styles.scss` themes once: 14 px corners, a 17 px title at 600 and the artboard's paddings.

tests `ui/packages/renderer/src/app/features/github-connect.component.spec.ts:1645`, `ui/packages/renderer/src/app/features/features.prototype.spec.ts:3693`), "YouTube connected as <channel>" or "with an API key" (`ui/packages/renderer/src/app/features/youtube-connect.component.ts:400`), "YouTube disconnected" (`:324`), "Kubernetes connected: <labels>" (`ui/packages/renderer/src/app/features/kubernetes-connect.component.ts:378`), "Kubernetes disconnected" (`:396`), "Downloading the <stack> images in Docker" once Docker reports the pull's progress (`ui/packages/renderer/src/app/features/docker-card.component.ts:1196`), "Work folder cleared", "Docker is running", "Docker is still not running" or "Docker is still not installed" after Refresh in the Docker panel or on its card, once Docker answered and never when the card loads or the bridge could not ask (`REFRESHED`, `ui/packages/renderer/src/app/features/docker-card.component.ts:83`; `refresh`, `:1128`), "Scout may run a project's tests in isolated containers" after the card's Turn on once the switch was saved and Scout's restart did not fail, never from the panel's own switch, as the artboard draws it (`enable`, `:1139`; tests `ui/packages/renderer/src/app/features/docker-card.component.spec.ts:1285`, `ui/packages/renderer/src/app/features/features.prototype.spec.ts:2872`, `:2942`, `ui/e2e/tests/features-loaded.spec.ts:250`), and "<feature> credentials saved" (`ui/packages/renderer/src/app/features/features.component.ts:821`). A connection already there when the screen opens toasts nothing, and a failed action keeps its error where it was and toasts nothing.
