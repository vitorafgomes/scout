## Theme and notices

**Pause, Continue and Stop on a running job** (2026-11-11, ADR 0045 v1.5). A running audit's entry offers Pause and Stop, a paused one Continue and Stop, and a running test run Stop; none while a click waits for the worker, and none on any other entry (`jobControls`, `ui/packages/shared/src/ipc-contract.ts:2022`). The bell sends `scout:notifications.control` with `{id, action}`, which main takes only from the main and operator windows (`registerJobControlHandler`, `ui/packages/main/src/notifications/job-controls.ts:368`, `:376`, wired at `ui/packages/main/src/main.ts:651`); main checks that it holds that entry, that the entry offers that control and that no other click on it is unanswered, reads the job from the entry's own id, never from the request (`ui/packages/main/src/notifications/job-controls.ts:91`, `:219`), and calls the control plane's `ControlJob`, a write the control plane already declares and logs, which only the desktop's token reaches (`ui/packages/main/src/control-plane/client.ts:1065`). While main asks, the buttons stay and are inactive; a queued click replaces them with what Scout does, "Pausing after this area", "Stopping after this area", "Continuing", or "Stopping" on a test run and on a paused audit, where no area is in progress (2026-11-12); each control is named for its job as the entry's title writes it, "Stop the tests for Acme/API#41", not from the entry's key, which has no case (`controlLabel`, `ui/packages/renderer/src/app/shell/notification-bell.component.ts:677`; `ui/packages/renderer/src/app/shell/notification-bell.component.ts:94`, `:688`). Main then reads the write log every 2 seconds for the click's record (`listWrites`, `ui/packages/main/src/control-plane/client.ts:1059`; `check`, `ui/packages/main/src/notifications/job-controls.ts:171`): a click that changed nothing, expired or was not confirmed shows the recorded sentence on the entry with the buttons back, and no record within 150 seconds says "Not confirmed" with the buttons back. A record that says applied waits for the worker's notice up to 11 minutes (`NOTICE_WAIT_MS`, `ui/packages/main/src/notifications/job-controls.ts:43`; `awaitNotice`, `:188`), because an audit's pause, stop and continue are noticed only once the area in progress ends, which the worker gives ten minutes by default (`src/Scout.Audit/AuditOptions.cs:25`); a notice inside that bound changes the entry and no note is written, and without one the entry keeps its state and gets the note "Scout recorded this click as applied, but the job did not report it; look at the job before clicking again." with the buttons back (`:206`). Every worker line and notice goes through the job controls (`ui/packages/main/src/main.ts:857`, `:859`): a running audit's next area keeps a waiting click, an audit's pause keeps a waiting Stop, so a Stop the AI Source's pause overtook still ends the paused audit as "Audit of owner/repo stopped" with the areas done and the findings kept read from the record (`ui/packages/main/src/notifications/job-controls.ts:273`), and any other notice on the entry ends the wait. A test run gets its own entry, `tests:owner/repo#n` without case (`ui/packages/main/src/notifications/sources.ts:70`), opened by the local turn's progress line "Run pull request tests: owner repo n" and closed only by the end of the last turn that runs that pull request's tests, as finished ("The result is in the conversation.", never passed) or not finished, by its stop notice as stopped, or by the worker stopping as not finished (`ui/packages/main/src/notifications/job-controls.ts:289`, `:292`, `:333`, `ui/packages/main/src/notifications/sources.ts:157`); the worker stopping or crashing also ends every waiting click with "Scout stopped before it said how this click ended" (`ui/packages/main/src/main.ts:900`). What answers the owner's own click leaves the entry read when it was, but a note on the entry makes it unread, so the badge says a click needs him again (the owner, 2026-11-12; `put`, `ui/packages/main/src/notifications/job-controls.ts:137`). The entry never shows a state the worker has not reported, and the Writes history on Approvals colours an owner's click by its control status, never by its text (`ui/packages/renderer/src/app/review/review.component.ts:698`). Tests: `ui/packages/main/test/notifications-job-controls.test.ts:255` (every control on every entry against every answer), `:310` (the record and the notices after a click, the 150-second bound), `:576` (a Stop overtaken by the AI Source's pause, in both orders and while the control plane is still asked), `:676` (the 11-minute bound after an applied record, per control), `:729` (the test run's entry, two runs of one pull request at `:800`), `:1167` (the channel from every sender and the forged requests), `:910` (a read job entry against every event, from an area that ends to a note: whether it is unread again, the badge, the kind, the title and the detail); `ui/packages/main/test/notifications-store.test.ts:148` (the unread rule per update) and `:586` (Scout reopened with a running audit, a running test run and a paused audit); `ui/packages/main/test/notifications-sources.test.ts:39` (the share rounded down) and `:138` (one sentence per pause reason and the worker's own words); `ui/packages/renderer/src/app/shell/notification-bell.component.spec.ts:691`, `:1422` (every state the artboard draws and every state only the app has, the icon's tokens and the panel's measures) and `ui/packages/renderer/src/styles.spec.ts:314` (the tone pairs, the unread row and the shadow in both themes); `ui/e2e/tests/bell-job-controls.spec.ts:15`, `:124` and `:155` through the real control plane.
