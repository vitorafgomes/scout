## Control plane

At app start `ui/packages/main/src/main.ts:635` calls `connectControlPlane` (`ui/packages/main/src/control-plane/launcher.ts:231`), before the YouTube sign-in starts, so a revoke it sends at start reaches the host, and before the worker supervisor exists. It launches the host through `launchControlPlane`, waits up to 10 s for the socket file (`ui/packages/main/src/control-plane/launcher.ts:190`), then opens the gRPC client with the protos from `resolveProtoDir` (`ui/packages/main/src/worker/resolve-binary.ts:70`): `resources/protos` when packaged, the source tree otherwise. Any failure on the way, whether a missing binary, a host that exits, a socket that never appears, an insecure socket directory or `win32`, becomes `ControlPlaneUnavailableError` on the client promise and one `warn` log line; the app keeps running. A failure after the spawn kills the host it started, and a host that exits mid-session closes the client so later calls fail at once. `before-quit` closes the client and kills the host (`ui/packages/main/src/shell/app-lifecycle.ts:145`, `ui/packages/main/src/main.ts:336`). There is no restart: a host that dies stays down until the app restarts.

The launcher mints two tokens: the desktop token, which only the host and the main process hold, and a worker token for the host's WorkerGate service ([[pages/services/host-control-plane]]). Neither is set on the main process's own environment. While the host is launched, `connection.workerGate()` gives the socket path and the worker token; `null` when the launch was unsupported or failed or the host exited (`ui/packages/main/src/control-plane/launcher.ts:268`).

The Features IPC handlers (`ui/packages/main/src/ipc/features.ts:67`) call that client: list, set credentials, setup, delete credentials, enable and disable map one to one onto the `scout.controlplane.v1.Features` RPCs, and the client maps the wire messages onto the `FeatureDto` shapes in `ui/packages/shared/src/ipc-contract.ts`.
