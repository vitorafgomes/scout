## Public contract

- **Models → Translation** - the Translation tab (opened by `?tab=translation` too, `ui/packages/renderer/src/app/models/models.component.ts:1339`; panel at `:544`) chooses the model that translates the lines of a live transcript (the owner, 2026-11-07: "Models also has Translation; do the same here"). Translation runs on the provider in use for Analysis (`translationProvider`, `:1435`, Ollama while `llm.provider` is unset, as the worker reads it), so the tab lists only that provider's models: the cloud list the Analysis block uses, or, for Ollama, the downloaded local models under their Ollama tag, never the catalog id (`translationView`, `:1453`); the search box and chips are the Analysis ones. The first row, "Same as Analysis" with the Analysis model under it (`data-test="translation-same"`, `:617`), is the default and is selected while nothing is saved; the target language stays in the live transcript ([[pages/roadmap/live-assistant]] phase 4). Choosing a model writes `llm.translation-model` and `llm.translation-provider` (the provider in use); choosing Same as Analysis deletes both; a running worker restarts when the model translation uses changes, with "Restarting Scout to use <model> for translation." while main restarts it and no line once it has, or "Scout will use <model> for translation the next time it starts." when none was running (`chooseTranslation`, `:1650`, `:1678`); a failed write shows the error and keeps the choice. A choice saved under another provider is shown as "Not in use: <model> was chosen for <provider>, which is not the provider in use. Translation uses the Analysis model." (`data-test="translation-stale"`, `:591`) and Same as Analysis is selected; nothing cleans it up, because `buildEnv` sends `SCOUT__LLM__TRANSLATION__MODEL` only when `llm.translation-provider` equals the provider it is writing and that provider is not `None` (`ui/packages/main/src/worker/build-env.ts:137`), so when a provider is disconnected or changed the next start translates with the new Analysis model ([[pages/services/llm]]). With provider `None` the tab says nothing is translated and links AI Sources (`:530`). A list that fails to load says "Could not load the <provider> model list." (`:575`). Saving restarts the worker through main's restart path, which waits for the live listen to end, so while one is open the tab says "A live listen is running. Saving a choice restarts Scout once the listen ends." (`ui/packages/renderer/src/app/models/models.component.ts:580`) and locks nothing; a save made then shows "Scout waits for the running answer or the live listen to end, then restarts."; the quick-ask window is another renderer, so the tab asks main through `scout:local.listening` (`ui/packages/shared/src/ipc-contract.ts:169`), answered from the open sessions (`ui/packages/main/src/quick-ask/quick-ask.ts:1797`), when the tab opens (`readListening`, `ui/packages/renderer/src/app/models/models.component.ts:1842`), and since 2026-11-08 follows `scout:local.listeningChanged` while the screen is open (`ui/packages/renderer/src/app/models/models.component.ts:1544`); a failed read shows no warning. The combinations are table-driven: provider in use (OpenAI, Gemini, ChatGPT, Ollama, None) by saved choice (none, under that provider, under another) for the rows, the Selected mark, the stale line and the no-provider line; the four providers by worker running or idle by five clicks for the writes, the restart, the line while main is asked and the line after (`ui/packages/renderer/src/app/models/models.component.spec.ts:1084`, `:1218`); and `buildEnv` over provider unset, Ollama, OpenAI, Gemini, ChatGptPlan and None by the saved provider and model (`ui/packages/main/test/worker-build-env.test.ts:752`).

- **Models → Speech** - the Speech tab (2026-11-08, ADR 0050 amended; the owner: "Is there a way to change the voice that speaks?", then the approved prototype `context/prototypes/desktop/Models.dc.html`; opened by `?tab=speech` too, `ui/packages/renderer/src/app/models/models.component.ts:1339`; tab at `:198`, panel at `:206`) is `SpeechVoicesComponent` (`ui/packages/renderer/src/app/models/speech-voices.component.ts:523`), one card headed Speech, "The voice Scout uses to read answers aloud and to speak in conversation mode." It reads `scout:local.voices` and the two saved keys when it opens (`load`, `:613`); until they arrive the card shows one status line, "Loading voices..." (`data-test="speech-loading"`, `:107`). "Voice of your AI Source" lists the voices the worker sends, "via OpenAI API" for OpenAI, only when the AI Source has speech; otherwise it says "Your AI Source has no voice; Scout uses its local voice." "Scout's local voice", "Used when your AI Source has no voice.", lists only the local voices this machine has, the default one first and marked Default, the others by label in number order (Aru 01 before Aru 10, whatever order the worker lists the speakers in), each with its language read from the locale in its id, such as English (UK) (`languageOf`, `:61`); after the default it shows four, plus the chosen one, until "Show all N" (`aria-expanded`, "Show fewer" when open, `shownLocalRows`, `:574`); with no local voice on the machine the column says "Scout's local voice is not on this computer." (`:146`). In use marks the saved voice, or the AI Source's first voice and the default local voice when none is saved or the saved one is gone (`:581`, `:586`). Each group is a `radiogroup` of `role="radio"` rows with one in the tab order, the arrow keys moving the choice with wrap-around (`onKey`, `:651`). "Hear a sample" (pressed and "Stop sample" while it plays) speaks one fixed sentence (`SAMPLE_SENTENCE`, `:35`) through `scout:local.speak` with that row's voice as its `sample`, played by the tab's own Web Audio player (`SAMPLE_PLAYER`, `:26`) so a sample never cuts an answer read aloud; a sample started while another plays stops the first, and a failed one shows the worker's reason on its row in an alert (`playSample`, `:700`). Save (a Material filled button) stores the chosen voices under `speech.voice.provider`, only while the AI Source has speech, and `speech.voice.local`, and never asks for a restart (`save`, `:674`); the status reads "Scout reads aloud with <voice>, the voice of your AI Source." or "..., Scout's local voice.", then "Saved. The next sentence read uses <voice>.", above "Saving does not restart anything; the next sentence read uses the new voice." A listing that fails shows its reason in an alert on the error container colours, with Try again beside it (`:98`, `.notice--error`, `:484`). Every colour is an `--sc-*` token or the Material button's, so it follows both themes.
