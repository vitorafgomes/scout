## Public contract

- **Ollama models on the Ollama card** - while Ollama answers, its card offers "Manage local models" (`ui/packages/renderer/src/app/sources/sources.component.ts:394`), which opens the dialog "Local models in Ollama", 560 px wide and 160 px from the top: the LLM Server panel (see the Ollama view under Local Models screen below), then under "Installed" every model the local Ollama lists but the skill-matching one ("No models installed yet. Pull one below." when none), and under "Recommended" the catalog models it does not list; a catalog row is its name over what it reads, its size on disk and its memory, a row outside the catalog is its tag over the family, parameter size, quantization and size on disk Ollama reports, each when known, with Use this, Remove, Download, and the bar with "<done> of <size> GB · <percent>%" and Cancel while it downloads. Use this on any of them saves the tag itself as `llm.model`, on the click only, and the worker gets it unchanged; a model whose capabilities say embeddings only (or, when Ollama does not report them, whose name says embed or whose family is a BERT) shows "Embeddings only" with Remove and no Use this, and the model in use has Remove disabled with "In use. Choose another model before removing it." while Ollama is the provider in use or none is saved ([[pages/decisions/0008-local-models-real-downloads]], amendment of 2026-11-12; the key scheme and the capabilities read in [[pages/architecture/desktop-models-system]]). A model whose capabilities, as Ollama reported them, lack `tools` and that is not embeddings-only (`LocalModelsStore.cannotCallTools`, `ui/packages/renderer/src/app/core/local-models.store.ts:214`) carries a "No tools" chip on the warn colours and, under its row, "This model cannot call tools, so Scout cannot read your repositories or cluster with it. Choose a model that supports tools." (`NO_TOOLS`, `:508`), which its Use this names as its description with `aria-describedby`; Use this stays enabled and choosing it saves `llm.model` as for any model. While that model is in use with Ollama as the provider, or none saved, the LLM Server panel says the same sentence with `role="status"` (`inUseNoTools`, `ui/packages/renderer/src/app/sources/local-models.component.ts:1257`). Capabilities Ollama did not report, or that main could not read, say nothing, and so does a catalog model not installed (tests `ui/packages/renderer/src/app/sources/local-models.component.spec.ts:3109`, capabilities by state, and the preview states of the artboard). Between Installed and Recommended, "Pull by name" (`ui/packages/renderer/src/app/sources/local-models.component.ts:216`) pulls any model of the Ollama library: a field labelled "Any model of the Ollama library, as name or name:tag" (placeholder "For example llama3.2:3b") and Pull, Enter pulling too. The name is trimmed; one that is not `model`, `model:tag` or `namespace/model:tag` (lower-case letters, digits, dots, dashes and underscores, the tag in any case, each part at most 80 characters; no registry host, second slash, scheme, space or control character) shows "That is not a model name. Use name or name:tag, for example llama3.2:3b." tied to the field with `aria-describedby`, leaves Pull disabled and reaches nothing (`onPull`, `ui/packages/renderer/src/app/sources/local-models.component.ts:1420`); main checks the same rule again before any request and pulls only from an Ollama on this computer (`isOllamaModelName`, `ui/packages/shared/src/ipc-contract.ts:2339`; `ui/packages/main/src/ipc/llm-pull.ts:126`, `:130`). A name pulls through the same `LocalModelsStore.download` as a Download, a name without a tag as its `:latest`: the bar with "<percent>%" and Cancel while the field is disabled, the skill-matching model too while it is missing, and a name already installed pulled again, which updates it. When it ends the field empties and "Pulled <name>. It is under Installed: Use this makes it the model Scout uses." says where it is; a pull by name never puts a model in use or writes `llm.model`, and Cancel gives the field back with the name and no error. After every pull, a Download's too, the store reads Ollama's list again once any read in flight has settled, so a read that began before the pull ended cannot drop the model (`ui/packages/renderer/src/app/core/local-models.store.ts:384`). A Download or a Pull by name that fails says it the same way under its row or the field, with See logs (`pullFailure`, `ui/packages/renderer/src/app/sources/local-models.component.ts:74`): "The Ollama library has no model named <name>." when Ollama answers that its library has no such model, "Ollama is not answering. Open the Ollama app or run ollama serve, then scan again." when Ollama does not answer, otherwise "Ollama could not download <name>: " and Ollama's own words, from the code main carries in the message (`ui/packages/main/src/ipc/llm-pull.ts:65`, `:82`). Under the field "Browse the Ollama library" opens `https://ollama.com/library` in the owner's browser through `scout:app.openExternal` (`onBrowse`, `ui/packages/renderer/src/app/sources/local-models.component.ts:1436`) and says "Could not open the browser. The library is at ollama.com/library." when it cannot; Scout sends no request to that site ([[pages/decisions/0008-local-models-real-downloads]], second amendment of 2026-11-12). Above "Installed", "Skill matching" has one fixed row, `nomic-embed-text` with "274 MB on disk" and "Scout uses this model to match a message to a skill. Without it, Scout picks a skill by the words of the message.": Installed, or Download (aria-label "Download nomic-embed-text"), the bar with "<done> of 274 MB · <percent>%" and Cancel while it downloads, and its failure with See logs; it has no Remove (`ui/packages/renderer/src/app/sources/local-models.component.ts:126`). While it is not installed, "The first download also gets nomic-embed-text (274 MB), which Scout uses to match a message to a skill." stands under "Recommended" (`:308`), and Download on any Ollama chat model also pulls it, right after the chat model, each pull with its own request id, so its failure or Cancel stays on its row and the chat model still ends downloaded (`startDownload`, `:1362`); the dialog reads Ollama's list when it opens and counts the model installed only under its bare name or `nomic-embed-text:latest`, the model the worker asks for, so an install with only another tag of it reads as not installed, and that tag is listed under Installed as a model of its own (`refreshOllama`, `ui/packages/renderer/src/app/core/local-models.store.ts:437`), and a list Ollama cannot give changes nothing. Nothing pulls it at worker start or in the background; the name is `OLLAMA_EMBEDDING_MODEL` (`ui/packages/shared/src/ipc-contract.ts:432`), which `buildEnv` also passes to the worker as `SCOUT__LLM__OLLAMA__EMBEDDINGS__MODEL` with Ollama as the provider (`ui/packages/main/src/worker/build-env.ts:155`), so the worker asks for the model the desktop downloads ([[pages/decisions/0008-local-models-real-downloads]], Amendment 2026-11-11). Remove asks in the row ("Remove <model>? <size> is deleted from this computer.", an alert dialog whose Cancel takes the focus and whose Escape closes only the question). While Ollama does not answer the card shows neither the button nor the panel, and under Connect it says "Ollama is not answering. Open the Ollama app or run ollama serve, then scan again." (`ui/packages/renderer/src/app/sources/sources.component.ts:450`), except while a scan runs; it asks the worker nothing about Ollama and offers no Start or Autostart, because Scout does not start or stop Ollama (the owner's decision of 2026-11-11, [[pages/roadmap/ollama-local-models]]). The In use badge of an Ollama in use is green only while Ollama answers. When the owner's click moves the provider in use away from Ollama, or from no saved provider, which means Ollama, to a cloud provider (Use or a model choice on a card or in Models, a key saved while no cloud provider is in use, the ChatGPT plan), and the new provider is saved, Scout asks Ollama to unload the models Scout uses (`ui/packages/renderer/src/app/core/llm-config.store.ts:371`); a switch between cloud providers, to Ollama, or a save that fails asks nothing. Main reads from its own vault the Ollama endpoint the owner configured in Scout, `http://localhost:11434` by default and the same one chat uses, and Scout's models, the chat model, the translation model when its provider is Ollama and `nomic-embed-text`; it reads what that Ollama has loaded (`GET /api/ps`, 5 s) and sends `POST /api/generate` with a zero keep-alive (5 s each) only for loaded models whose tag is one of Scout's (`ui/packages/main/src/ipc/llm.ts:322`). Ollama keeps no record of which program loaded a model, so a model loaded under a tag Scout uses is unloaded whoever loaded it, and the next request from any program loads it again; a model under any other tag stays loaded, and the server keeps running: the owner deferred the server controls on 2026-11-11, so Scout does not stop the server, which the computer runs and other programs may use. The Ollama card then says "Ollama freed its models from memory. It keeps running for other programs." when Ollama unloaded them, or "Scout could not ask Ollama to free its memory. Ollama frees it by itself after a few minutes without use." when Ollama refused one of them, or when the call failed while Ollama was the provider in use, and nothing when none of them was loaded or when Ollama could not be reached and no provider had been saved before, since the owner may never have used Ollama (the typed `llm/ollama-unreachable` code, which main carries in the message across IPC, `ui/packages/renderer/src/app/core/llm-config.store.ts:383`) (`ui/packages/renderer/src/app/sources/sources.component.ts:456`, `:460`); the line goes when Ollama is chosen again or another switch is saved, and a failure never undoes the switch ([[pages/decisions/0032-per-feature-write-permissions]], amendment of 2026-11-11, bullet of 2026-11-12). The Ollama card has no Disconnect yet; when it lands it asks the same channel. The card's Download Ollama and the LM Studio card's Download LM Studio open `https://ollama.com/download` and `https://lmstudio.ai` through `scout:app.openExternal`, whose allow-list holds both hosts (`ui/packages/main/src/ipc/app.ts:19`, `:20`; tests `ui/packages/main/test/ipc-app.test.ts:153`, `:163`); the dialog's Browse the Ollama library opens `https://ollama.com/library` under the same host (`:158`). The same component manages the Whisper models in Models → Transcription (`ui/packages/renderer/src/app/sources/local-models.component.ts:323`; see Local Models screen below), with its Delete unused footer, which the Ollama dialog does not show (`:471`). Remove in Models asks "Remove <model>?" in the shared confirmation first (`:1515`), Remove in the Ollama dialog in its row. The dialog follows the theme on `--sc-surface`. The known defects of this flow, the decisions of 2026-11-11 and the order of the fixes are tracked in [[pages/roadmap/ollama-local-models]].
