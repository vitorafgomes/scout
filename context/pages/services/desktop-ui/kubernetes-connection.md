## Kubernetes connection

The Kubernetes side panel holds `sc-kubernetes-connect` (`ui/packages/renderer/src/app/features/kubernetes-connect.component.ts:47`) and gets a `connection` state like the GitHub card (`ui/packages/renderer/src/app/features/features.component.ts:238`), so it has no toggle and no credential dialog. It calls four channels, `scout:kubernetes.detect`, `use`, `status` and `disconnect`, handled in `ui/packages/main/src/ipc/kubernetes.ts:51`. `detectKubeconfig` (`ui/packages/main/src/kubernetes/kubeconfig.ts:32`) reads the first `KUBECONFIG` entry or `~/.kube/config` with `js-yaml` and returns each context's name, cluster, server, namespace, how its user signs in (token, client certificate, exec command, auth provider, username and password) and, for an exec user, the command and its arguments, with the value of any flag whose name contains secret, token, password, passwd, key or credential shown as `***` (`ui/packages/main/src/kubernetes/kubeconfig.ts:116`). It never returns or logs a token, key, certificate, password or exec env value; a malformed file logs only its path. `use` takes `{name, label}` pairs only, checks each name against the file main located itself and each label with the shared rule (`ui/packages/shared/src/kubernetes-labels.ts:9`), stores `{path, contexts: [{name, label}]}` under `kubernetes.selection` (a selection stored before labels reads with each name as its label) and restarts a running worker through `restartWorkerIfRunning`; `disconnect` deletes it and restarts the worker. `buildEnv` turns the selection into `SCOUT__PLUGINS__KUBERNETES__KUBECONFIGPATH` and `SCOUT__PLUGINS__KUBERNETES__CONTEXTS__<n>__NAME` and `__LABEL` (`ui/packages/main/src/worker/build-env.ts:88`), read at every worker start (`ui/packages/main/src/main.ts:831`) and used by the worker's [[pages/services/plugin-kubernetes]]. A status that cannot be read when the card opens shows its reason with Try again, which reads it again (`retry`, `ui/packages/renderer/src/app/features/kubernetes-connect.component.ts:342`; test `ui/packages/renderer/src/app/features/kubernetes-connect.component.spec.ts:422`). What the owner sees:

- **No kubeconfig:** "No Kubernetes configuration found on this computer (looked in $KUBECONFIG and ~/.kube/config)."
- **Unreadable kubeconfig:** "The Kubernetes configuration at <path> could not be read."
- **Detected:** "Use the Kubernetes configuration on this computer?", the path in a code pill, then "Contexts: N (tick the ones Scout may read)" with the contexts open under it, each time the panel is drawn (see Long lists on Features below; each context a row on the page colour, "No context matches the filter." when the filter leaves none, `noMatch`, `ui/packages/renderer/src/app/features/collapsible-list.component.ts:226`), one checkbox per context with its server and sign-in kind, "Runs <command> to get a token" under an exec context, and "Use selected contexts", disabled until a box is ticked. Under it, always: "Scout only reads from your clusters, but these credentials may allow changes. A read-only user is safer:" and three copyable `kubectl` commands that create a `scout-reader` service account bound to the `view` cluster role and a token for it.
- **Labels:** each ticked context gets a "Label" field prefilled with its name; an invalid or repeated label shows the reason under the list and disables "Use selected contexts". The chat bot and the model see only the labels ([[pages/decisions/0020-kubernetes-from-local-kubeconfig]]).
- **Connected:** "Using dev, qa, prod from <path>", the labels and never the context names or servers, and Disconnect, which asks first (see Disconnect asks first below).
- **Reads:** under the connection, connected or not, the panel lists "Reads 4" and the card shows the chip "Read 4", from the four read rows the control plane's catalog declares for Kubernetes ([[pages/services/control-plane]]): Namespaces, "List the namespaces of each context you chose"; Pods, "Read pod status and restarts; never logs or secrets"; Deployments, "Read replicas and rollout status"; Events, "Read recent events". No grant box: the feature declares no write. Tests: `ui/e2e/tests/features-loaded.spec.ts:40` (the real control plane host to the card and the panel), `ui/packages/renderer/src/app/features/features.prototype.spec.ts:1200` and `:1414`.
