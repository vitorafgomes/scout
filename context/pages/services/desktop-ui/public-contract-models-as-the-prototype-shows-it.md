## Public contract

- **Models, as the prototype shows it** (2026-11-07) - one "Models" heading with "Choose the model Scout uses for each task. Each source you connect in AI Sources lists its models here.", then underlined tabs in the order Analysis, Transcription, Translation, Speech, opening on Analysis when no `?tab=` names another (`ui/packages/renderer/src/app/models/models.component.ts:1339`). The tabs set no size of their own and take the page's 14 px base, as its artboard `context/prototypes/desktop/Models.dc.html` does (`.page`, `ui/packages/renderer/src/app/models/models.component.ts:774`), the active one in `--sc-fg` at 600 with a 2 px accent bar, over a rule the width of the page (`.tabs`, `:799`; `.tab`, `:805`). The tabs stay the hand-written `role="tab"` buttons and the model and voice rows the hand-written radio rows: Material's tab group cannot carry a `data-test` id on a tab label, and its radio button puts the role, the checked state, the id and the keys on an inner input, where the specs and the Speech rows' arrow keys read them on the row. Since 2026-11-11, as the artboard draws them, each tab has the id `tab-<task>` and `aria-controls="models-panel"` (`ui/packages/renderer/src/app/models/models.component.ts:154`), and the panel shown, the Analysis, Transcription or Translation section or the Speech card's host, is `models-panel`, a `tabpanel` labelled by its tab (`:225`, `:214`, `:548`, `:206`), with no wrapper element. The Analysis rows of every source are one `radiogroup` named "Analysis model" (`:307`), the Translation rows one named "Translation model" (`:608`); each row is a `role="radio"` with `aria-checked`, and at most one row is in the tab order, always one the owner can reach. On Analysis it is the chosen row while it is listed inside an open group, otherwise the first row of the first open group, and with every group closed no row is in the tab order and the groups' summaries are the way in (`analysisTabStop`, `:1500`); the screen follows each group's `toggle` event, so opening or closing a group moves the stop at once (`openGroups`, `:1497`; `onGroupToggle`, `:1611`), and a group that leaves the screen, its provider disconnected or the local list gone, is dropped from the open set when the rendered groups change (`:1532`), so it comes back closed unless its own `open` binding opens it, whose toggle then records it. Translation has no collapsible group: the chosen row while it is listed, otherwise Same as Analysis, the first row (`translationTabStop`, `:1522`). On those rows the arrow keys move the focus only, to the next or previous row of the group, wrapping and skipping the rows of a closed group (`onRowKey`, `:1622`); Space or Enter chooses, as a click does. They do not choose as the Speech rows' arrows do, because an Analysis or Translation choice saves the setting and restarts Scout at once, where a Speech arrow only sets a choice that Save stores, so choosing on each arrow press would save and restart on every key (decided 2026-11-11). Tests: `ui/packages/renderer/src/app/models/models.component.spec.ts:2600` (the four tabs and the panel each one controls, the rows in seven states, the tab stop by which groups are open and when a group leaves and comes back, and each key by focus position with no write and no restart). Material draws the progress bar, the two spinners and the filled buttons. Every colour is a theme token, so the screen follows the light and dark theme; the tabs are pinned by `ui/packages/renderer/src/app/models/models.component.spec.ts:1957`. Each Analysis group shows its source's official logo from the same local files and constants as the AI Sources cards (`OPENAI_ICON` for ChatGPT plan and OpenAI API, `GEMINI_ICON`, `CLAUDE_ICON`, `OLLAMA_ICON`; `GROUP_LOGOS`, `ui/packages/renderer/src/app/models/models.component.ts:118`, drawn by the `#logo` template, `:709`), a light and a dark variant switched by the theme, with the name "<source> logo"; the Not connected local runtime row, Ollama or LM Studio, keeps a generic icon named "Local LLM logo". A restart line names the AI Source card ("Restarting Scout to use OpenAI API.", ChatGPT plan, Google Gemini, Claude API, Ollama); a restart that fails says "Restart Scout in Settings, Scout worker, to use <source>." with "Settings, Scout worker" a link to `/settings`, on Analysis and on Translation (`restartFailedFor`, `ui/packages/renderer/src/app/models/models.component.ts:277`, `:695`). The Translation tab opens with "Live translation needs a voice model to transcribe first; none is installed." and a "Choose a voice model" button that opens the Transcription tab while main reports no verified Whisper model (`scout:whisper.listInstalled`, read when the tab opens; the app's own record when main cannot answer; `needsVoiceModel`, `:1375`, notice at `:561`); it lists and downloads no voice model itself.

- **TypeSafe (Jev) card** - a key-only form on the same screen (`ui/packages/renderer/src/app/sources/sources.component.ts:953`) stores the read-only guard key under `guard.typesafe-api-key` and never touches `llm.provider` (`:1982`); the badge reads Connected from `vault.has` on load (`:2029`). If that check fails, the card shows "Could not check the TypeSafe key; the read-only guard may still be on." in an alert and still offers Disconnect, so a key that exists can be removed. While Connected (or after a failed check), a Disconnect button, which first asks "Disconnect TypeSafe (Jev)?" with Cancel focused, (`:847`) deletes only that key, turns the badge Not connected and says "Disconnected. The read-only guard is off." without any "Saved." text; with Scout running it says "Disconnected. Restarting Scout to turn the read-only guard off." and, when the restart fails, "Disconnected. Restart Scout from the status screen to turn the read-only guard off." on the card (`:2007`). Saving and disconnecting both restart a running worker through the same helper as the cloud cards (`:2086`); a failed store or delete shows the error in an alert and leaves the badge as it was. `buildEnv` passes the key as `SCOUT__GUARD__TYPESAFE__APIKEY` for every provider (`ui/packages/main/src/worker/build-env.ts:136`). - **Usage on the cards** ([[pages/decisions/0046-ai-source-usage-on-the-cards]]) - while a source is connected its card carries a usage block (`ui/packages/renderer/src/app/sources/sources.component.ts:1873`, sources mapped at `:106`): "Scout today" and "Scout this month" in tokens (compact, "1.5K", "1.2M"), with the money where the provider reported a cost, from main's usage store; under it "Usage not reported for this model" when the last answer of that source carried no usage. OpenAI API and Google Gemini add "Balance: Not reported by the provider", ChatGPT Plus "Plan usage: Not reported by the provider" or, after the plan refused an answer for its usage limit, "Usage limit reached at HH:MM" (local time, cleared by the next answer), each with "Open the provider's usage page" (`https://platform.openai.com/usage`, `https://aistudio.google.com/usage`, `https://chatgpt.com/#settings`, the three hosts added to main's open-external allow-list, `ui/packages/main/src/ipc/app.ts:18`); Ollama adds "Cost: Local, free" and "Models installed", the count and size on disk of the models its last scan listed; OpenRouter adds "Credits: US$ X of US$ Y left", "Not reported by the provider (limit US$ Y)" when OpenRouter reports a limit without the credit left, or "No limit on this key", "Resets" (daily, weekly, monthly or never) and "OpenRouter this month", and after a failed read "Balance as of HH:MM; the latest read failed." with the last value kept. The block is the artboard panel on `--sc-bg` with 10 px corners, 13 px rows, "Usage limit reached" and the failed-read note in the warn colour after the info glyph, the line "Scout's own count, from the usage each answer reports." and the provider page as a 32 px outlined pill. No price table: money appears only where the provider reports it. The totals come from `scout:usage.get` on open and every `scout:usage.changed` push, the balance from `scout:usage.openRouterKey` (`ui/packages/shared/src/ipc-contract.ts:16`).

- **Usage store and OpenRouter read (main)** - `createUsageStore` (`ui/packages/main/src/ipc/usage.ts:113`) reads the worker's `SCOUT_LOCAL` lines with a null id and the event `usage` or `usage-limit` ([[pages/services/llm]], Usage count): main fans every such line out to the store and to quick ask (`ui/packages/main/src/main.ts:854`), and quick ask drops them. The store keeps per source a local-day and a local-month total of tokens, answers and reported cost, the last model, whether the last answer reported usage, and the time a plan limit arrived, in `usage.json` under the app's user data folder (`ui/packages/main/src/main.ts:770`); the day and month roll over by local date (`ui/packages/main/src/ipc/usage.ts:51`), the file is read once and written in order through a temporary file, and a corrupt or wrongly shaped file starts the count empty and logs one warning (`:134`). Each change is pushed to every window. The OpenRouter balance is the one declared read on that source: `GET https://openrouter.ai/api/v1/key` with the stored key as a bearer token (`:319`), only while a key is stored, when the AI Sources screen opens and at most once per ten minutes counted from the last attempt (`throttledRead`, `:267`), shared between concurrent opens, and at once when the stored key changes, even while the old key's read is still in flight, never answering with the old key's value (`:283`), with a 5-second timeout; a 401 or 403, another status or no answer keeps the last value with the time it was read and names the failure (`:324`). The log line carries the HTTP status or the error name only, never the key or a message. The optional Admin keys use the same throttle (`createOrgSpendReader`, `:432`): OpenAI `GET https://api.openai.com/v1/organization/costs` with the key as a bearer token, Anthropic `GET https://api.anthropic.com/v1/organizations/cost_report` with `x-api-key` and `anthropic-version: 2026-10-21`, both from the first of the UTC month in daily buckets, `limit=31` (`:371`, `:376`); the spend is the sum of the results, Anthropic's amounts being cents (`spendOf`, `:382`). `registerOrgSpendHandlers` (`:495`) checks an Admin key with that read and stores it only when accepted (`:514`), under the main-only `llm.openai.admin-key` or `llm.anthropic.admin-key` (`ui/packages/main/src/vault/safe-storage-vault.ts:15`, `:16`), and removes it on request; neither key is ever returned, logged or sent to the worker.
