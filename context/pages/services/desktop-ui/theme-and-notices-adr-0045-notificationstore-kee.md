## Theme and notices

ADR 0045 ([[pages/decisions/0045-theme-and-notification-center]]). `NotificationStore` (`ui/packages/main/src/notifications/notification-store.ts:55`) keeps at most 200 `AppNotification` entries (id, kind `running | done | failed | paused | github | mention`, title, detail, time, read, optional progress 0 to 100, optional link, source `worker | verdict | notice | github`), newest first; an entry recorded again with its id replaces the old one as unread and an update that changes nothing is ignored (`:117`), except that a job entry (`audit:` or `tests:`) the owner read stays read until its kind changes or a new note comes, so the end of an audit's next area moves its time and progress without raising the badge (the owner, 2026-11-12, `:189`), and a GitHub entry the owner read stays read unless its reason changed or its thread's comment count (`comments`, kept on the entry) went up (`:188`); `remove` drops the entries a source selects (`:126`). It reads the main-only vault key `app.notifications` on start (`:69`): an entry it does not recognise is dropped alone and the log says how many (`:213`), a running audit comes back as it was saved, in progress with its last "Area n of m done" and its share, because the worker resumes a job Scout closed in the middle on its next start ([[pages/services/audit]]; the owner, 2026-11-12, `:93`), any other entry saved as running, a test run included, comes back as failed with "Scout closed before this finished.", a value that is not a list starts the center empty, and a vault that cannot be read starts it empty and is never saved over for the rest of the run, so the saved list survives a locked keyring; writes it a second after the last change, and pushes the whole list on `scout:notifications` to every open window (`:251`). Channels (`:285`): `scout:notifications.list`, `scout:notifications.markRead` with `{ids}` or `{}` for all (more than 200 ids or a non-string is refused with "Scout could not read that request."), and `scout:notice.record` with `{message, kind: info | success | error}`; the bridge names are `notificationsList()`, `notificationsMarkRead(ids?)`, `onNotifications(listener)` and `noticeRecord(req)`.
