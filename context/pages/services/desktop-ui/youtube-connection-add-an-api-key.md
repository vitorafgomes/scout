## YouTube connection

- **Add an API key** (`ui/packages/main/src/oauth/google-auth.ts:230`): opens the credential dialog the Features artboard draws, "Connect YouTube" (`sc-youtube-key-dialog`, `ui/packages/renderer/src/app/features/youtube-connect.component.ts:582`), built on the shared dialog styles as GitHub's Use a token is: the lede, one required "YouTube Data API key *", a password field empty each time it opens, described by the help "Create it in the Google Cloud Console (APIs & Services, Credentials) for a project with the YouTube Data API v3 enabled. It reads public data only."; "Required permissions" folded (Channel overview, Comments); "How to get this credential" with three steps; no link, as the artboard draws none; Cancel focused and Save. Save with the field empty sends nothing and says "One required field is empty. Nothing was saved." with the help "Enter the API key."; Save sends the field as typed to `scout:youtube.saveApiKey`, the call the inline form made, and shows "Saving…" with Cancel and Save off; any failure main answers (a refused key, YouTube not answering, an HTTP error, the vault unable to store the key) keeps the dialog open with main's sentence, the field emptied and focused for a retry (`:614`). Esc closes only the dialog and does nothing while saving (`:609`); Cancel and Esc give the focus back to Add an API key (`:328`); a kept key closes the dialog, puts the keyboard on the panel's close button and reads the status again, which shows "YouTube connected with an API key" (`:334`). The key lives only in the field: no text, attribute or log line carries it, and no field holds it once the dialog is closed. "Open Google Cloud Console credentials" (`https://console.cloud.google.com/apis/credentials`, allowed in `ui/packages/main/src/ipc/app.ts:12`) stays in the OAuth client help. Main checks the key with one public `GET youtube/v3/channels?part=id&forHandle=youtube&key=...` (`:463`): 200 stores it under `youtube.api-key`; a 400 or 403 stores nothing and says why, from the reasons in Google's error body (`ui/packages/main/src/oauth/google-auth.ts:724`): `API_KEY_INVALID` "Google does not recognise this API key. Copy it again from Google Cloud Console credentials."; `SERVICE_DISABLED` or `accessNotConfigured` "The YouTube Data API v3 is not enabled for this key's project. Enable it in Google Cloud Console and try again in a minute." followed by the project (`projects/<n>`) when Google names it; `API_KEY_SERVICE_BLOCKED` or `forbidden` "This key's restrictions do not allow the YouTube Data API v3. Edit the key's API restrictions in Google Cloud Console."; `quotaExceeded` "YouTube's daily quota for this key is spent; it resets at midnight Pacific time."; any other reason the generic "Google rejected this API key. Check that the YouTube Data API v3 is enabled for it." with the reason identifier in parentheses. Google's own message text is never shown. No message, log line or status carries the key.

- **Pending:** "Waiting for the browser..." and Cancel, which aborts the listener and releases the port without an error; a connected card whose status is pending shows the same line and Cancel above the connected buttons (`ui/packages/renderer/src/app/features/youtube-connect.component.ts:65`). Revoke writes reaches it, because the grant change pushes `scout:features.changed` after the read-only sign-in has started; Allow writes does not: nothing is pushed while its sign-in waits, so the card offers no Cancel then, and the wait ends when the owner finishes or denies on Google's page, or after the 5-minute sign-in timeout.

- **Connected:** "Connected to <channel title>" and "Signed in with Google", with "Google access: <scopes>" listing the granted scopes by their short names, such as `youtube.readonly` (`ui/packages/renderer/src/app/features/youtube-connect.component.ts:51`, `:340`); the card reads its status again on `scout:features.changed` (`:284`), so the scopes change when writes are allowed or revoked; or "Connected with an API key" and "Public data only.", then "Open YouTube Studio" (`https://studio.youtube.com/channel/<channel id>`, or `https://studio.youtube.com/` without a channel id), "Open channel" (`https://www.youtube.com/channel/<channel id>`, only with a channel id; the status carries `channelId` from the session), "Open YouTube operator" and Disconnect; both links go through `scout:app.openExternal`, whose allow-list has `studio.youtube.com` and `www.youtube.com` (`ui/packages/main/src/ipc/app.ts:13`).

- **Open YouTube operator:** the third button of the connected row, between Open channel (or Open YouTube Studio) and Disconnect, as the artboard draws it, and not drawn while YouTube is not connected or a sign-in waits for the browser (`ui/packages/renderer/src/app/features/youtube-connect.component.ts:94`); it calls `scout:operator.window` (see Operator window) and shows a refusal under the card (`:358`).

- **Failed:** the reason above Sign in with Google, for example "Google could not finish the sign-in (HTTP 503). Sign in again in a moment." or "The Google sign-in was cancelled or timed out. Click Sign in with Google to try again."

- **Tests:** the state (not connected, connected with Google, connected with an API key, waiting for the browser, failed) by action (Add an API key, Save, Cancel, Esc, Disconnect) table, one row per failure the save can return, and the key kept out of every text, attribute, log line and closed field, in `ui/packages/renderer/src/app/features/youtube-connect.component.spec.ts:706`, `:735`, and Enter (saves, refuses an empty field, sends once while a save is on its way) at the end of the same block; one row per Preview state of the YouTube panel and of the Connect YouTube dialog in `ui/packages/renderer/src/app/features/features.prototype.spec.ts:2585`, `:2701`; the dialog opened and cancelled in the built app by `ui/e2e/tests/features-loaded.spec.ts:203`.

Like the GitHub card, it sits in the Features grid and is hidden with the grid when the control plane is not running.

**Disconnect asks first** on the GitHub, Kubernetes and YouTube cards, through the shared confirmation with Cancel focused (2026-11-07, the approved prototype): "Disconnect GitHub?" with "Scout stops reading and writing on GitHub and forgets the sign-in on this computer. The Scout GitHub App stays installed on your account until you remove it there." (`ui/packages/renderer/src/app/features/github-connect.component.ts:815`), "Disconnect Kubernetes?" with "Scout stops reading from the N contexts you chose. Your Kubernetes configuration is not changed." (`ui/packages/renderer/src/app/features/kubernetes-connect.component.ts:382`), and "Disconnect YouTube?", whose sentence names the sign-out or the API key (`ui/packages/renderer/src/app/features/youtube-connect.component.ts:305`). Remove the bot asks "Remove the Scout bot?" the same way (`ui/packages/renderer/src/app/features/github-connect.component.ts:868`), where the artboard removes at once; the confirmation is drawn there as a Preview state waiting for the owner ([[pages/roadmap/prototype-migration]], Features). Every button on the connect sections is an Angular Material button with its icon.
