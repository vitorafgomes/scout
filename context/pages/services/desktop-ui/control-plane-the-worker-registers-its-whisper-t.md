## Control plane

The worker registers its Whisper transcriber only when a model exists as it starts, so a model downloaded or chosen while it runs needs a restart. The restart path above handles every change one at a time: when the worker is running or starting and the model it would load now (`chooseWhisperModel` over `stt.model`) differs from the one `buildEnv` recorded at its start, it stops and starts the worker; while a quick-ask answer runs or a live listen is open it waits until the last of them ends (a listen ends on the worker's `complete` or `fail`, never the stop request, so the trailing final is kept) and records "The voice model is ready; Scout restarts to use it when the live listen ends." in the notification center under the fixed id `whisper-model-restart`; a restart that fails records "Scout could not restart to use the voice model." with the reason, and a deferred one that finds the worker stopped replaces the entry with "Scout stopped; it uses the voice model when it next starts." (`RESTART_MOOT_TITLE`, `ui/packages/main/src/worker/worker-restart.ts:19`). The triggers are the one downloader's `onDownloaded` (Models, the Desktop card, the voice ask and the bell's Download), an `stt.model` stored or deleted through `scout:vault.store` or `scout:vault.delete` (`onChanged`, `ui/packages/main/src/ipc/vault.ts:49`), and `scout:whisper.useModel` (`createWhisperModelUser`, `ui/packages/main/src/worker/worker-restart.ts:198`), which saves `stt.model` and answers `now`, `deferred` or `none`, or rejects with the restart's reason. After a restart the bell's voice entries read "Scout now transcribes voice messages." (`restarted`, `ui/packages/main/src/notifications/voice-notice.ts:165`). Tests: `ui/packages/main/test/whisper-restart.test.ts` (download done and Use this × worker running or stopped × live listen open or closed, the deferred restart made moot by a stop, the failed restart, Use this rejecting with the reason, a voice entry's download leading to exactly one restart, the wiring in `main.ts`).

### Local Models screen

There is no Local Models screen any more (2026-11-07, the approved prototype): `sources/local-models` redirects to `/llm?tab=transcription` (`ui/packages/renderer/src/app/app.routes.ts:45`), and AI Sources has no Local Models card (2026-11-11, the owner declined it): its section On this computer lists Ollama and LM Studio only, and the Whisper models, which run inside Scout and need no runtime, are reached through Models in the navigation, on its Transcription tab. Models → Transcription embeds `sc-local-models` for the Whisper models (`ui/packages/renderer/src/app/models/models.component.ts:210`): the "Local Whisper" header with "On this computer" and "N downloaded · size on disk." (`ui/packages/renderer/src/app/sources/local-models.component.ts:1304`), every catalog row with its size on disk and RAM, In use or Downloaded, Downloading with its progress bar and Cancel, Use this, Download and Remove (asks first), the Graphics card (GPU) line and the Downloads footer, which counts and sizes the voice models only, as the header does (`:472`), with Delete unused. The rows are exactly main's pinned table, in main's order and with its exact sizes, read once through `scout:whisper.modelTable` (`LocalModelsStore.loadWhisperTable`, `ui/packages/renderer/src/app/core/local-models.store.ts:239`); the renderer keeps only the display copy per variant, the title, note, memory and Recommended on Base (`WHISPER_COPY`, `ui/packages/renderer/src/app/core/local-models.catalog.ts:21`, joined in `whisperCatalog`, `:66`). When main cannot give the table the view says "Scout could not list the voice models: <reason>" and lists no rows (`ui/packages/renderer/src/app/sources/local-models.component.ts:354`). Delete unused counts only the voice models that are neither in use nor the saved choice, so a switch that waits for a restart never loses the model just chosen (`hasUnused`, `:1293`), asks "Delete unused models?" first with Cancel focused and "Scout deletes the voice models that are not in use from this computer. The model in use stays.", then deletes each file through `scout:whisper.deleteModel` (`onDeleteUnused`, `:1628`); a delete that fails shows its reason on its row and keeps it. A download or pull runs in `LocalModelsStore` (`download`, `ui/packages/renderer/src/app/core/local-models.store.ts:355`), which keeps its progress, so leaving the screen and coming back shows it still downloading; Cancel stops it through `scout:whisper.cancelDownload` or `scout:llm.cancelOllamaPull` (`onCancel`, `ui/packages/renderer/src/app/sources/local-models.component.ts:1348`) and the row goes back to Download with no error, in every window, since main's rejection carries `whisper/download-cancelled` or `llm/pull-cancelled` (`isCancelled`, `ui/packages/renderer/src/app/core/local-models.store.ts:515`); main stops one that receives nothing for 60 s with its reason on the row, and an Ollama pull is timed only while Ollama reports byte counts, while a phase it reports only by status (pulling the manifest, verifying the digest, writing the manifest) has 10 minutes before "Ollama reported no progress for 10 minutes; the download stopped." ([[pages/services/desktop-channels]], Whisper models). The renderer never writes `stt.model`; only main does, through Use this. Use this is never locked: it calls `scout:whisper.useModel`, the row says "Switching…" until main answers, then In use moves to the new model; when main deferred the restart, In use stays on the model the running worker loaded and a line says "The voice model is ready; Scout restarts to use it when the live listen ends." (`ui/packages/renderer/src/app/sources/local-models.component.ts:347`), and "base is selected; Scout switches to it when it restarts." stands in for the not-downloaded note while the saved choice is downloaded (`preferenceNote`, `:1325`); the screen reads main's answer again every 4 s while the Transcription tab is open, so In use moves once the restart ran (`ui/packages/renderer/src/app/sources/local-models.component.ts:1236`). A restart that fails keeps the choice main saved, since the worker is already stopped, and the line says "Saved; Scout starts with <variant> next time. It could not restart now: <reason>" (`useWhisper`, `:1601`). See Whisper models above for main's side.

On the Ollama view (the panel in AI Sources) the LLM Server panel is a status chip, three metrics and one line, and nothing to press. The chip reads Running while Ollama answers its model list, Not running when it does not and Checking before the first read (`serverState`, `ui/packages/renderer/src/app/sources/local-models.component.ts:1281`); SELECTED names the model in use while Ollama lists it; DOWNLOADED counts every model Ollama lists but the skill-matching one, and STORAGE sums their sizes, the catalog's figure for a catalog model and the size Ollama lists for any other (`downloadedCount`, `storageLabel`, `:1273`, `:1275`); the line reads "Ollama is run by this computer, not by Scout.", or, while Ollama does not answer, "Ollama is not answering. Open the Ollama app or run ollama serve, then scan again." (`serverLine`, `:1287`). The dialog reads the list (`scout:llm.listOllamaModels`) when it opens and every 4 s while it is open (`:1236`), one read for the panel and the Skill matching row: an answer makes the Ollama part of the downloaded list exactly what Ollama lists, so a model removed outside Scout leaves it, and a read that fails sets the chip to Not running and keeps the list (`refreshOllama`, `ui/packages/renderer/src/app/core/local-models.store.ts:437`); a read asked while one is in flight (a poll tick, the Models screen) gets that read's answer and sends no second request. In main, a model whose `/api/show` failed is not asked again for 60 s, and each failed read logs one warning naming the model. Opening the dialog first sets the chip back to Checking, so a dialog opened again never shows the last session's answer while the new read runs (`openOllama`, `:468`). Reading the list never chooses a model and writes nothing to the vault: with nothing chosen, SELECTED shows the dash until the owner picks one with Use this or downloads a model, whose download selects it when nothing of its kind is selected. The panel has no Autostart, Start, Stop or Restart and no hint to start Ollama before the first download: Scout does not start or stop Ollama, which the computer runs, and the owner deferred those controls on 2026-11-11 (the artboard draws them disabled under a "Not supported yet" note). Since 2026-11-08 Scout no longer runs `ssh-keygen` to create `~/.ollama/id_ed25519` before a pull, a write outside Scout's folders, and a pull ends only on Ollama's success line, so a stream that stops early or ends on an error line without a newline fails with the reason (`ui/packages/main/src/ipc/llm-pull.ts:276`, `:283`). An Ollama model is In use, and SELECTED names it, only while Ollama is the provider in use or none is saved (`ollamaInUse`, `ui/packages/renderer/src/app/sources/local-models.component.ts:1248`), and SELECTED only while Ollama lists it (`:1262`); Use this saves `llm.model` first and emits `ollamaModelChosen` only once it is saved (`useOllamaModel`, `:1586`); a save that fails shows its reason on the row, keeps the previous selection, and neither switches the provider nor restarts Scout, and AI Sources answers with its Use Ollama path, which makes Ollama the provider and restarts a running Scout ("Restarting Scout to use Ollama.", `useOllama`, `ui/packages/renderer/src/app/sources/sources.component.ts:1877`); removing the selected Ollama model moves `llm.model` to the model the selection moved to, and opening the panel never overwrites a saved `llm.model`. The Whisper view's Graphics card (GPU) line reads "Not reported" with the line "The Whisper runtime does not tell Scout whether it uses a GPU." (`ui/packages/renderer/src/app/sources/local-models.component.ts:463`): no IPC channel or setting carries a GPU state, and the bundled `Whisper.net.Runtime` ships only the CPU backend on Linux and Windows (Metal on macOS arm64). Removing a model calls the Ollama or Whisper delete and drops the model only when the call succeeds; a failed delete keeps the model downloaded and shows the error on its row with See logs (`:1546`).
