## Review

The Review screen (route `review`, `ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:36`; its heading reads Approvals since 2026-11-07, `ui/packages/renderer/src/app/review/review.component.ts:54`) is the full list and history of what Scout asks the owner to decide on an irreversible action ([[pages/decisions/0032-per-feature-write-permissions]]). Since 2026-11-07 the same pending actions also show as approval cards in the chat and in the quick-ask window, so the owner approves where the request came from ([[pages/services/desktop-quick-ask]], Approval cards); both go through the same channels, and a decision in either place shows in both. The operator window's Approvals page is the same component on a route whose data names a feature (`ui/packages/renderer/src/app/review/review.component.ts:618`): both tabs keep only that feature's items, filtered in the renderer after the load (`:741`); the main window's screen keeps every feature. The lede reads "What Scout is waiting to do, and what it did. Actions that cannot be undone wait here for you.", Refresh reads both lists again (`:60`), a progress bar over three skeleton cards shows until the first load answers (`:106`), and two tabs split the lists (`:65`):

- **Waiting for you** - the actions with status `pending` only (`:731`), and the tab's count on the warn container counts only those. Each action is a card with its feature's name (GitHub, YouTube, Kubernetes or Desktop, `featureName` in `ui/packages/renderer/src/app/core/pending-approvals.store.ts`), a "Cannot be undone" chip, when it was requested ("Requested today 14:02"), the action in words ("Approve a pull request"), "Target: <target>", the summary, a "Reason (optional)" field and Reject and Approve, each with its icon. A decision goes to `scout:actions.approve` or `scout:actions.reject` with the trimmed reason when there is one, and the control plane keeps the reason with either decision and logs it ([[pages/services/host-control-plane]]); then, since 2026-11-11, a decision the control plane took is told in a notice, and the screen reloads (`ui/packages/renderer/src/app/review/review.component.ts:708`, the notice `:720`). Since 2026-11-08 each action keeps its own in-flight state, so deciding a second action never re-enables the first one's buttons, and a second click on an action already being decided sends nothing, because its buttons are disabled while its decision is in flight (`:173`, `:182`). The control plane refuses an Approve while the feature holds no write grant, and rejects an action asked before the current grant; main turns that refusal into `control-plane/action-rejected` and the alert reads "Rejected: asked before writes were granted; ask again" (`decisionError`, `ui/packages/renderer/src/app/core/pending-approvals.store.ts:51`), while the action leaves the list on the reload. A decided action leaves the list and the count at once, whichever window decided it. A click that comes after another window decided shows "Already decided" in the alert and reloads, so the Approve disappears (`ui/packages/renderer/src/app/review/review.component.ts:725`; main turns the control plane's FAILED_PRECONDITION "Action '<id>' is already <status>." on ApproveAction or RejectAction into `control-plane/already-decided`, `ui/packages/main/src/control-plane/client.ts:976`, `:498`, `ControlPlaneAlreadyDecidedError` in `ui/packages/shared/src/errors.ts:146`, and since 2026-11-08 any other FAILED_PRECONDITION there, the grant refusals, into `control-plane/permission-denied` with the control plane's sentence, `ControlPlanePermissionDeniedError`); any other refusal shows its own reason. Empty: "Nothing is waiting. Actions that cannot be undone appear here before Scout performs them." with "See the history", which opens the other tab (`ui/packages/renderer/src/app/review/review.component.ts:133`); since 2026-11-08 it shows only while no load error stands, so a control plane that is down never reads as nothing waiting (`:123`).
