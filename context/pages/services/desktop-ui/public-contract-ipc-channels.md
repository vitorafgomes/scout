## Public contract

- **IPC channels** - the one hundred and eighty-six `scout:*` channels, grouped by family with their `ui/packages/shared/src/ipc-contract.ts` lines, are catalogued on [[pages/services/desktop-channels]]. The renderer sees only what `ui/packages/preload/src/preload.ts` bridges.

- **Vault keys** - the closed `VaultKey` union in `ui/packages/shared/src/client-kinds.ts:3` (Discord bot token, client and guild ids, LLM provider, model and endpoint, one API key per cloud provider (`llm.openai.api-key`, `llm.gemini.api-key`, `llm.anthropic.api-key`, `llm.openrouter.api-key`), the legacy shared `llm.api-key` kept only for migration, cloud model, the translation model and the provider it was chosen under (`llm.translation-model`, `llm.translation-provider`), STT provider and model, TypeSafe guard API key `guard.typesafe-api-key`, the Docker runs switch `sandbox.enabled`, and the voice read aloud with, `speech.voice.provider` and `speech.voice.local`). The renderer may read back only `llm.provider`, `llm.cloud-model`, the two translation keys, the Docker runs switch `sandbox.enabled`, the Discord application id `discord.client-id`, which every invite URL carries (test `ui/packages/main/test/ipc-vault.test.ts`, "returns the Discord application id main kept"), and the two speech voice keys (`PUBLIC_VAULT_KEYS`, `ui/packages/shared/src/client-kinds.ts:61`), none of them a secret. Main-only keys (the optional Admin keys `llm.openai.admin-key` and `llm.anthropic.admin-key`, `ui/packages/main/src/vault/safe-storage-vault.ts:6`), not in `VAULT_KEYS` so the renderer's vault channels reject them: `chatgpt.session`, `chatgpt.client-id`, `chatgpt.host-id`, `github.session`, `github.token`, `youtube.session`, `youtube.api-key`, `kubernetes.selection`, `access.allowed-users`, `slack.connection`, `app.keep-running`, `app.tray-notice-shown`, `quick-ask.shortcut`, `quick-ask.bubble`, `quick-ask.window`, `operator.window`, `update.check-enabled`, `update.skipped-version` and `update.last-check`.

- **Cloud LLM cards** - the OpenAI API, Google Gemini, Claude API and OpenRouter cards on the AI Sources screen have three states (`ui/packages/renderer/src/app/sources/sources.component.ts:1462`): Not connected (Connect opens a key form; the key is checked with the provider, then stored under that provider's own vault key), Connected (Disconnect, Change key) and In use (the model, Disconnect, Change key). Change key on the card in use checks the new key with the provider, stores it and restarts a running worker ("Key changed. Restarting Scout to use the new <card> key.", or "... the next time it starts." while Scout is stopped). A key the provider could not check, because it was unreachable or answered unexpectedly, stays masked in its field so the owner can retry; only a key the provider rejected is cleared, and the Admin key form follows the same rule. When the vault cannot be read, a keyed card that reads Not connected says "Could not check the <card> key; it may still be stored." in an alert, and a selection whose own vault check failed (a cloud provider's key, the ChatGPT plan's `llm.cloud-model`, Ollama's `llm.model`) keeps its localStorage mirror, so the next load that reads the vault restores the provider and its model; only a check the vault answered with no key wipes the mirror (`resetUnconfigured`, `ui/packages/renderer/src/app/core/llm-config.store.ts:291`). One provider action runs at a time: Save, Disconnect, Use, Sign out and Change key stay disabled until the action and its worker restart have finished (`exclusive`, `ui/packages/renderer/src/app/sources/sources.component.ts:2075`). Each message a card writes about a provider, "Connected. Restarting Scout to use Claude API." and the rest, names the provider by its card (`providerLabel`, `ui/packages/renderer/src/app/core/llm-config.store.ts:59`; until 2026-11-07 a key's Connect said Anthropic, OpenAI or Gemini; test: "the restart message names the card", one row per card, in `ui/packages/renderer/src/app/sources/sources.component.spec.ts`). AI Sources only connects and disconnects: a connected card shows the link "Choose a model in Models, Analysis" (`/llm?tab=analysis`) instead of a Use button or a model field, and the model is chosen on the Models screen (see Models → Analysis below). The first connect while no cloud provider is in use also makes that provider the one in use, and a ChatGPT plan that is still the chosen provider without a session counts as none in use (`ui/packages/renderer/src/app/core/llm-config.store.ts:325`); when that switch cannot be written the key stays stored and the card says "Connected, not switched: Scout still answers as before, not with <card>." with the reason; a switch whose `llm.provider` write fails puts the previous `llm.cloud-model` back, so the model never names another provider (`:355`); disconnecting the provider in use switches to the other connected cloud provider (the ChatGPT plan only after `scout:chatgpt.status` is read again and still reports a session with plan usage; a status that cannot be read counts as not connected, `ui/packages/renderer/src/app/core/llm-config.store.ts:423`; when that read finds the session ended, the ChatGPT card reads the status again and turns Not connected with Continue with ChatGPT, and a read that fails leaves the card as it was) or, with none left, to provider `None` (Scout replies that no AI provider is connected), never to Ollama, and restarts a running worker. The Ollama card offers Use while its server answers and then shows In use; Ollama and LM Studio have no Disconnect. Custom API is a dashed "Coming soon" card with no action ("Not available yet. It arrives in a later version."). [[pages/decisions/0015-cloud-llm-providers-by-api-key]], [[pages/decisions/0017-provider-connect-disconnect]]. Each card's icon (`ui/packages/renderer/src/app/sources/sources.component.ts:946`) is an image with an accessible name: OpenRouter shows its official glyph, unmodified, from local files (`glyph-cloud` on the dark theme, `glyph-ink` under `data-theme="light"`, `ui/packages/renderer/src/app/sources/sources.component.ts:194`, files in `ui/packages/renderer/src/assets/brands/` fetched from openrouter.ai/brand, which allows the marks unstretched and unrecoloured; the page's CSP loads no remote image); since [[pages/decisions/0049-provider-logos-on-the-ai-source-cards]] every provider card shows its owner's official logo the same way, from a local file per theme, in a 36 px tile on `--sc-surface-2`; Local Models and TypeSafe keep a generic filled mark and Custom API a muted outline mark. Settings > About lists "OpenRouter is a trademark of OpenRouter, Inc.", "Ollama is a trademark of Ollama, Inc.", that third-party logos are not under Scout's MIT licence, and that other names and logos are their owners' trademarks used to identify the service (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:224`), behind About's "Trademark notices" disclosure.

- **Claude API card** ([[pages/decisions/0048-claude-as-an-ai-source]]) - the card (`ui/packages/renderer/src/app/sources/sources.component.ts:1488`) is the OpenAI card's shape: Connect with key, Change key, Disconnect after "Disconnect Claude API?", the Models link and the usage block. The key is checked with a `GET https://api.anthropic.com/v1/models` sent as the worker's Anthropic client sends it, `Authorization: Bearer <key>` with `anthropic-version: 2026-10-21` (`ui/packages/main/src/ipc/provider-keys.ts:23`), 5 s timeout, the status logged and never the key; it is stored under `llm.anthropic.api-key`, which the renderer can store, check and delete but never read, and `buildEnv` sends it as `SCOUT__LLM__ANTHROPIC__APIKEY` with `SCOUT__LLM__ANTHROPIC__CHAT__MODEL` (`llm.cloud-model`, default `claude-opus-5-5`, `ui/packages/main/src/worker/build-env.ts:169`), never falling back to the legacy shared `llm.api-key`. Its help line (`:1338`) reads "A Claude Pro or Max subscription cannot be used by other apps; Scout needs an Anthropic API key." There is no Claude Plan card and nothing offers a Claude sign-in, because Anthropic does not allow third-party apps to offer claude.ai login without its approval (`ui/packages/renderer/src/app/sources/sources.component.spec.ts:1686`).

- **OpenRouter card** ([[pages/decisions/0046-ai-source-usage-on-the-cards]], Amended 2026-11-07) - the card (`ui/packages/renderer/src/app/sources/sources.component.ts:1499`, keyed at `:236`) is the OpenAI card's shape: Connect with key, Change key, Disconnect after "Disconnect OpenRouter?", In use, the Models link and the usage block with the credit left. The key is checked with `GET https://openrouter.ai/api/v1/key` as a bearer token (`ui/packages/main/src/ipc/provider-keys.ts:24`), because OpenRouter's model list answers without a key; Models → Analysis lists `GET https://openrouter.ai/api/v1/models`, only the models whose `supported_parameters` include `tools` (Scout answers through function calls), with their `id` and `name` (`:188`). It is stored under `llm.openrouter.api-key`, a renderer-writable `VaultKey` since this change (`ui/packages/shared/src/client-kinds.ts:15`, `:80`) that the renderer can store, check and delete but never read, and `buildEnv` sends it as `SCOUT__LLM__OPENROUTER__APIKEY` with `SCOUT__LLM__OPENROUTER__CHAT__MODEL` (`llm.cloud-model`, default `openai/gpt-4o-mini`) and no embeddings host (`ui/packages/main/src/worker/build-env.ts:174`), never falling back to the legacy shared `llm.api-key` (`:236`). After a connect the card reads the balance again (`ui/packages/renderer/src/app/sources/sources.component.ts:1810`).

- **Organization spend (optional Admin key)** ([[pages/decisions/0046-ai-source-usage-on-the-cards]], Amended 2026-11-07) - an OpenAI API or Claude API card carries, while it is connected or an Admin key is still stored (so a stored Admin key can always be removed), a collapsed `details` "Organization spend" (`ui/packages/renderer/src/app/sources/sources.component.ts:598`, cards at `:178`, shown by `adminProviderOf`, `:1545`) with "Optional. An Admin key can read your organization's billing; Scout uses it only to show this month's spend and keeps it on this computer." The rejected line is in the error colour; Remove and Add Admin key are 32 px outlined pills. Without a key it offers Add Admin key, a password field sent once to `scout:usage.adminKeySave` (`saveAdminKey`, `:1560`), which shows "The Admin key was rejected" when the provider refuses it; with a key it shows "US$ 12.40 spent this month (organization)"; a spend read that fails keeps the section with "Could not be read" and Remove, so the key never strands (`:1541`); in the currency the provider returned, "The Admin key was rejected" after a 401 or 403, "Spend as of HH:MM; the latest read failed." after another failure (`orgSpendLine`, `:186`), and Remove after "Remove the Admin key?"; a failure shows on that card only (`:1551`). The renderer learns only the spend: `scout:usage.orgSpend` answers null while no Admin key is stored (`ui/packages/shared/src/ipc-contract.ts:19`).
