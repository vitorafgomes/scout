## Theme and notices

Since 2026-11-06 ([[pages/decisions/0041-angular-material-in-the-renderer]]) the renderer carries Angular Material and the CDK at the Angular version (22.2.5; material and cdk 22.2.6, since 2026-11-08) and one global stylesheet, `ui/packages/renderer/src/styles.scss`, listed under `styles` in `ui/packages/renderer/angular.json`. Since 2026-11-07 ([[pages/decisions/0045-theme-and-notification-center]]) it themes both schemes: `mat.theme()` on `html` with `theme-type: color-scheme` and `color-scheme: light dark` (`ui/packages/renderer/src/styles.scss:96`; the palettes generated offline into `ui/packages/renderer/src/_theme-colors.scss`), then one block per scheme, `html[data-theme='light']` and `html[data-theme='dark']` (`ui/packages/renderer/src/styles.scss:115`, `:120`), each setting its `color-scheme`, pinning the Material colour roles with `mat.theme-overrides()` and defining the literal tokens, and the same two blocks under `prefers-color-scheme` for `html:not([data-theme])` (`:125`, `:131`), which paint the window until the theme store answers. Dark keeps the approved surfaces (surface #0f1623, surface-container #131c2d, surface-container-high #1a2436, outline-variant #253249, on-surface #e6e9f0, on-surface-variant #c3cadb, outline #9aa3b6, every artboard's muted text since 2026-11-10) with primary #8fb2f9, primary-container #3466e8 under white, error #f28b82 over on-error #0f1623; light is the prototype's palette (surface #f5f7fb, surface-container #ffffff, surface-container-high #e8ecf4, outline-variant #d7dce7, on-surface #18202e, on-surface-variant #3f4a61, outline #5d677d, primary #2a56c6, primary-container #3466e8, error #b3261e). The app-level aliases on `:root` (`:142`) point at the roles, so they follow the scheme: `--sc-bg`, `--sc-surface`, `--sc-surface-2`, `--sc-line`, `--sc-fg`, `--sc-fg-2`, `--sc-muted`, `--sc-accent`, `--sc-accent-strong`, `--sc-on-accent`, `--sc-error`, `--sc-focus`, `--sc-nav-active`, `--sc-mono`, `--sc-radius`, `--sc-radius-sm`; `--sc-ok`, `--sc-warn`, the ok, warn, error and info container pairs, `--sc-code-bg`, `--sc-scrim` and `--sc-danger` (the red under white text: #b3261e light, #c5372c dark) have a light and a dark literal each ([[pages/architecture/desktop-ui-design-system]], Theme tokens). One global `:focus-visible` ring (`:163`). The one `body` rule takes the page's margin away (`:168`), so the document is never taller than the window and no window-height scrollbar shows beside the shell; it sets no background, because the floating-button window is transparent and the screens paint their own colours. Material's buttons and badge are themed once, on `html` and on the dark canvas so the values resolve in the pinned scheme too (`:172`): an outlined button is the prototype's secondary button, `--sc-fg` on a `--sc-line` outline with 16 px at each side, a text button pads 10 px, a filled button is `--sc-on-accent` on `--sc-accent-strong` (since 2026-11-10; Material's own was its light primary under dark text in the dark theme), and a screen that needs another colour sets the Material token on its own button, as Clear and Delete do with `--sc-error`; the badge is white 11 px bold on `--sc-danger`, 18 px high, overlapping its host's corner by 14 px. An `sc-icon` inside a Material button's label is centred on the label (`:228`), not raised to the text baseline. A dialog opened with `backdropClass: 'sc-dialog-backdrop'` sits on `--sc-scrim` (`:208`), not on the CDK's 32 % black; every Material dialog of the renderer opens with it: the shared confirmation, Settings' credentials modal and the voice model dialog. The production build keeps the stylesheet as a plain `<link>`: `optimization.styles.inlineCritical` is false (`ui/packages/renderer/angular.json:39`), because the critical-CSS loader is an inline script the page's CSP (`script-src 'self'`) blocks. Inter ships inside the app since 2026-11-09 ([[pages/decisions/0041-angular-material-in-the-renderer]], amendment): one `@font-face` (`ui/packages/renderer/src/styles.scss:247`) loads the variable latin file from the pinned `@fontsource-variable/inter` package (`ui/packages/renderer/package.json:23`), the build copies it under `media/` and its licence text to `media/inter/LICENSE` (`ui/packages/renderer/angular.json:26`); no CDN is named and nothing is fetched at run time.

**Theme choice.** Main's theme module (`ui/packages/main/src/shell/theme.ts:65`, registered in `ui/packages/main/src/main.ts:919` before any window opens) reads the main-only vault key `app.theme` (light, dark or system; System when absent, unknown or unreadable, the last logged), sets `nativeTheme.themeSource`, answers `scout:theme.get` and `scout:theme.set` with `{ choice, resolved }`, refuses any other choice with `theme/invalid-choice`, keeps a choice the vault cannot store for the session and logs it, and pushes `scout:theme` to every window on each choice and on nativeTheme's `updated` event (`ui/packages/main/src/shell/theme.ts:118`), so System follows the operating system live. **No dark flash:** the page background of each scheme, the stylesheet's `--sc-bg` (`surface` in `$_light` and `$_dark`, `ui/packages/renderer/src/styles.scss:7`), is pinned in main as `WINDOW_BACKGROUND` (`ui/packages/main/src/shell/theme.ts:17`, a test compares both with the stylesheet); the main, quick-ask and operator windows open with `windowBackground(nativeTheme)` (`ui/packages/main/src/shell/theme.ts:20`), the scheme nativeTheme resolves from the stored choice, and each push repaints every open window with `setBackgroundColor` except a transparent one (`ui/packages/main/src/shell/theme.ts:89`). Main creates every window through `newWindow`, which marks a window created with `transparent: true` (`ui/packages/main/src/main.ts:303`), so the floating button keeps its transparent background (`ui/packages/main/src/main.ts:924`). In the renderer, `ThemeStore` (`ui/packages/renderer/src/app/core/theme.store.ts:27`) is started by the app root in every window (main, quick ask, floating button, operator; `ui/packages/renderer/src/app/app.component.ts:27`), sets `data-theme` on `html` from main's answer and pushes, and shows main's answer after a click, never the click itself; a refusal keeps the current theme and sets its error.

**Top bar.** `sc-top-bar` (`ui/packages/renderer/src/app/shell/top-bar.component.ts:115`) sits above the update bar in the main window (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:120`) and above the pages in the operator window (`ui/packages/renderer/src/app/operator/operator-shell.component.ts:109`), outside the one scrolling area: the screen's title, from the navigation entry the route belongs to (`screenTitle`, `ui/packages/renderer/src/app/shell/top-bar.component.ts:17`; Local Models reads AI Sources, a route outside the menu reads Scout or YouTube operator), the routed screen's own actions, a `topBarActions` template the shell reads from the routed component as it activates and passes in (`actions`, only Chat has them: Clear and Read answers aloud), the AI Source and model from `LlmConfigStore` ("ChatGPT · gpt-5.6-luna", "No AI Source" when none or not configured, the same label the quick-ask status shows, `ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:1492`), the theme switch (sun, moon, monitor; `aria-label` Light theme, Dark theme, Follow the system theme, the same text as tooltip, `aria-pressed` on main's choice) and `<sc-notification-bell>`, for now a button named Notifications that the notification center replaces. The search box of the prototype is left out until a search exists. The rail and the bar paint with the tokens. The rail is 200 px wide (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:140`): the logo mark, a white S on a 28 px `--sc-accent-strong` square, beside "Scout" (`:76`), then the entries in the prototype's order, Chat, AI Sources, Features, Models, Meetings, Approvals, Logs, Settings and, while YouTube is connected, YouTube operator (`:30`); each carries its icon, Approvals a checked box, and the active one is marked `aria-current="page"` with `--sc-nav-active` and a 3 px accent bar. A screen not on the tokens yet paints no background of its own, so the area behind it keeps the old dark literals (#0f1117, #e4e8f0) and carries `sc-dark-canvas`, decided per route: the main window's page area (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:122`, the themed routes at `:42`), the operator window's (`ui/packages/renderer/src/app/operator/operator-shell.component.ts:110`, its themed routes at `:49`) and, before setup, the wizard frame (`ui/packages/renderer/src/app/shell/shell.component.ts:36`, its wizard routes at `:15`). That class pins the dark roles, tokens and `color-scheme` (`ui/packages/renderer/src/styles.scss:137`), so in the light theme such a screen keeps its dark look, native controls included, until its own migration moves it to the tokens and takes its route off the pin. The operator window is fixed to the window like the main one (`:host` `position: fixed; inset: 0`, the grid at `height: 100%`), so its top bar stays in view and only the page area scrolls. The quick-ask window and the floating button paint with the tokens and follow the theme ([[pages/services/desktop-quick-ask]]), and so do the Chat connections section and its modals, which sit in the overlay outside the canvas. **Icons.** `sc-icon` (`ui/packages/renderer/src/app/core/icon.component.ts:84`) draws one named stroke path on a 24 grid from its registry (`:4`: check, check-square, edit, trash, plug, save, refresh, copy, download, external, sun, moon, monitor, bell, search, chat, sparkle, grid, cube, calendar, video, list, settings, close, play, stop, mic, warning, info, error) in the current text colour, hidden from screen readers; no icon font, no dependency.

**Notices.** Notices go through `NoticeService` (`ui/packages/renderer/src/app/core/notice.service.ts:25`, `show(message, kind, ms, action)` over `MatSnackBar` with the panel classes `sc-notice` and `sc-notice--info|success|error` (every kind drawn as the artboards' inverse card since 2026-11-10, [[pages/architecture/desktop-ui-design-system]]), the optional `action` a button with its label whose press runs it once (`NoticeAction`, since 2026-11-10, first used by Stop failed in Settings), `dismiss()` at `:35`); its first use is the Features screen, which toasts "Writes allowed for <feature>" after a grant and "Writes revoked for <feature>" after a revoke, only when the store kept no error (`ui/packages/renderer/src/app/features/features.component.ts:792`, `:798`); the specs turn Material's animations off through `MATERIAL_ANIMATIONS`.
