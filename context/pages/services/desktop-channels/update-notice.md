## Update notice

Scout Desktop tells the owner when a newer release is on GitHub Releases and shows what is new. Where the package can replace itself (an AppImage or the Windows installer) the bar offers Update and restart; elsewhere it offers Download. Nothing is downloaded or installed until the user clicks ([[pages/decisions/0031-desktop-self-update]]).

- **Check.** `registerUpdateNotice` (`ui/packages/main/src/update/update-notice.ts:144`, called at `ui/packages/main/src/main.ts:928`) schedules the first check 10 s after start and then one every 24 hours (`ui/packages/main/src/update/update-notice.ts:631`, `ui/packages/main/src/update/update-notice.ts:504`), while "Check for new versions" is on. A check (`ui/packages/main/src/update/update-notice.ts:285`) is one unauthenticated GET, on the Stable channel of `https://api.github.com/repos/vitorafgomes/scout/releases/latest` and on the Beta channel of `https://api.github.com/repos/vitorafgomes/scout/releases?per_page=30`, from which it takes the highest version that is not a draft, a pre-release included (`ui/packages/main/src/update/update-notice.ts:260`), with `Accept: application/vnd.github+json` and `User-Agent: Scout-Desktop/<version>`, nothing else, and a 15 s timeout (`ui/packages/main/src/update/update-notice.ts:234`); only one runs at a time. A development build (`app.isPackaged` false) never fetches and never schedules.
- **Decision** (`ui/packages/main/src/update/update-notice.ts:294`). The tag loses a leading `v` and is compared with `app.getVersion()` by `compareVersions` (`ui/packages/shared/src/version.ts:20`): numeric major.minor.patch, a prerelease below its release, anything unparseable as 0.0.0. A newer release that is not a draft, not a prerelease on the Stable channel, whether GitHub marked it or its tag carries a pre-release suffix (a prerelease counts on Beta), and not the version stored under `update.skipped-version`, becomes the notice: both versions, the release body as plain text, the release page and the download for this machine from `pickDownload` (`ui/packages/shared/src/version.ts:34`): on Linux the AppImage when `APPIMAGE` is set and the deb otherwise, and only the file whose name carries the machine's arch, `x86_64` or `amd64` for x64, the one Linux build a release has (`ui/build/electron-builder.yml:132`), so Linux on arm64 gets the release page and never a package it cannot run; the dmg whose name carries the arch on macOS; the exe on Windows, which Windows on arm64 runs under emulation; and the release page when no asset matches (`ui/packages/shared/test/version.test.ts:72`). The notice also carries `canInstall` (see Install). The notice goes on `scout:update.notice` to every window and to the tray; anything else clears it.
- **Result.** `update.last-check` keeps `{ at, result }`, the result being `up-to-date`, `available <version>`, `skipped <version>`, `error <kind>` with kind `http <status>`, `network`, `timeout` or `parse`, or `error install <kind>` after a failed install (see Install). A failed check is logged at info, leaves the notice as it was and never throws.
- **Install.** `canInstall` is `canSelfUpdate` (`ui/packages/main/src/update/update-notice.ts:75`) with an updater given: a packaged build on Windows, or on Linux with `APPIMAGE` set and the running executable inside the mount `APPDIR` names, so an `APPIMAGE` a `.deb` Scout inherited from another AppImage program never counts. `main.ts` passes `electron-updater`'s `autoUpdater` (dependency `electron-updater` ^6.8.12 in `ui/packages/main/package.json`) only in that case and `null` otherwise, so the updater is never constructed on macOS, in a `.deb` or in a development build (`ui/packages/main/src/main.ts:946`). The `Updater` interface (`ui/packages/main/src/update/update-notice.ts:52`) is the part of `AppUpdater` Scout uses. `scout:update.install` (`ui/packages/main/src/update/update-notice.ts:608`) does nothing while an install runs, and answers a `failed` progress when there is no notice or the package cannot update itself. Otherwise `install` (`ui/packages/main/src/update/update-notice.ts:427`) sets `autoDownload` and `autoInstallOnAppQuit` to false and `allowPrerelease` to true on the Beta channel and false on Stable, and no other option, so no token or header is configured (`ui/packages/main/src/update/update-notice.ts:456`), then runs `checkForUpdates`. If the updater offers a version other than the notice's, nothing is downloaded, the bar says "The release changed; check again" and the normal check runs again (`ui/packages/main/src/update/update-notice.ts:461`). Otherwise `downloadUpdate` runs, and electron-updater verifies the SHA-512 from `latest-linux.yml` or `latest.yml`. `quitAndInstall(false, true)` runs only after the download resolved and `update-downloaded` fired (`ui/packages/main/src/update/update-notice.ts:465`). Before it, `installing` is broadcast and `prepareForRestart` is awaited for at most 10 s (`ui/packages/main/src/update/update-notice.ts:407`); past that the restart goes ahead and a warning is logged. `main.ts` wires it (`ui/packages/main/src/main.ts:949`) to the lifecycle's `prepareForRestart`, which stops the worker through `stopWorker` (`ui/packages/main/src/shell/app-lifecycle.ts:90`), the same stop `before-quit` uses, so a stop in progress is never started twice and a worker started again later is stopped again on quit, and then calls `app.releaseSingleInstanceLock()`, so the new version can take the lock while the old process is still exiting. When the updater cannot apply the update (`apply`), `recoverFromFailedRestart` takes the lock again and starts the worker again if it was running before; while another Scout holds the lock it logs that and leaves the worker stopped, so two workers never run (`ui/packages/main/src/shell/app-lifecycle.ts:114`). An error or a rejection maps to a kind (`ui/packages/main/src/update/update-notice.ts:85`): `checksum` ("The download did not match the release; nothing was installed"), `no asset` (no `latest*.yml` for this platform), `http <status>`, `timeout`, `network`, `incomplete` (no `update-downloaded`) or `apply` (the updater could not replace the file). The kind becomes a `failed` progress and `error install <kind>` in `update.last-check`, logged at warn; the notice stays. The updater listeners are removed when the install ends and on `dispose`.
- **Progress.** `scout:update.progress` carries `UpdateProgress` (`ui/packages/shared/src/ipc-contract.ts:1900`) to every window: `checking`, then `downloading` with percent, bytes and total, at most once per whole percent, then `ready`, then `installing`, or `failed` with a message.
- **What the AppImage update writes.** electron-updater replaces the file `APPIMAGE` names. When that name carries a version, such as `Scout-Desktop-0.1.0-linux-x86_64.AppImage`, it deletes the old file and writes the new one under the release's name in the same folder, then starts it. On the next start, `refreshLoginEntry` (`ui/packages/main/src/shell/login-item.ts:102`) rewrites the start-at-login entry when it names another executable, so a renamed AppImage keeps starting at login; with start at login off nothing is written. The Windows update runs the NSIS installer (not silent) and starts Scout again.
- **Bar.** `sc-update-notice` (`ui/packages/renderer/src/app/shell/update-notice.component.ts:60`) sits above the page in the post-connect shell (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:121`), with `role="status"`: "Scout <latest> is available. You have <current>.", a "Release notes" link, then Update and restart when `canInstall` (`ui/packages/renderer/src/app/shell/update-notice.component.ts:82`) or Download otherwise, Later and Skip this version, and a "What's new" disclosure. While an install runs the buttons are disabled and a progress row (`ui/packages/renderer/src/app/shell/update-notice.component.ts:119`) shows "Checking the release", "Downloading <n>%" with a `<progress>` bar, or "Restarting to install". A failure shows its message with `role="alert"`, the buttons come back, and Download appears next to Update and restart as a secondary button (`ui/packages/renderer/src/app/shell/update-notice.component.ts:88`), so the file can still be fetched by hand. The notes are split into paragraphs on blank lines, lists from `- ` or `* ` lines and headings from `# ` lines, with the `**` around a leading label dropped (`ui/packages/renderer/src/app/shell/update-notice.component.ts:28`), and only ever interpolated as text, so an HTML tag in a release body shows as text. Release notes and Download go through `scout:app.openExternal` and its `github.com` allow-list. Later clears the notice for this run only, so the next daily check shows it again; Skip this version stores the version and clears the notice.
- **Tray.** While a notice exists the tray menu has "Update available: <version>" after Open Scout, which opens the window, and the tooltip ends with " - update available" (`ui/packages/main/src/tray/tray.ts:78`, `:85`).
- **Settings, Updates.** Its own card after Desktop (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:506`): "Nothing downloads or installs without a click.", "Current version" and the version, then "Check for new versions" (a slide toggle, on by default, `update.check-enabled`) and "Last check: <date> · <result>" with Check now (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:521`, `:1619`), the line "Scout checks GitHub Releases 10 seconds after it starts, then once a day." (`:529`), the date as "7 Nov 2026, 14:02" in local time and the result in words (`lastResultText`, `:1735`): "You have the latest version", "Version <v> is available", "Version <v> is available (skipped)" or "Could not check for updates (<reason>)", the reason "no connection to GitHub", "GitHub did not answer in time", "GitHub sent an unexpected answer" or "GitHub answered HTTP <n>"; a toggle or Check now main refuses says why in its own line under the update controls (`data-test="update-error"`, `:814`), so it never replaces a start-at-login or keep-running error; turning the check off cancels the timer and turning it on schedules the first check again, for the session even when the vault cannot store the choice (a warning is logged instead of an error reaching Settings); a vault read that fails at start is logged at warn and the check stays on. A development build shows "Update checks run only in the installed app." instead. While main holds a notice the card shows the bar's state too, from the same `scout:update.notice` and `scout:update.progress` pushes (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:1427`): "Scout <latest> is available. You have <current>.", Update and restart when `canInstall` (`installUpdate`, `:1693`, the bar's `scout:update.install`) or, when the package cannot replace itself, "This package cannot update itself. Download the new version and replace this copy; your settings stay on this computer." with Download, a "Release notes" link (Download and Release notes go through `openUpdateLink`, `ui/packages/renderer/src/app/wizard/settings/settings.component.ts:1751`, so a link main refuses says why in this card), the same progress lines, a failure as an alert with Update and restart and Download, and "Later and Skip this version are on the bar at the top of the window." (`:578`); Later and Skip on the bar clear the notice in every window, so the card drops it too. After a check that found nothing newer, with no notice, it says "You are up to date" and "Scout <version> is the newest version.".
- **Channel.** Settings, Updates has a Channel row, Stable or Beta (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:532`, `setChannel`, `:1686`), with "Stable gets released versions only." or "Beta also gets pre-releases, to try changes before they are released. A pre-release can have bugs; keep Stable for daily work."; a version with a pre-release suffix carries a Pre-release chip beside the current version and beside the headline of a notice; on Stable while running a pre-release it says "You are on the pre-release <version>. Stable never installs an older version: Scout offers the next stable version newer than it." in place of "You are up to date" (`:553`). Main keeps the channel in `update.channel` and reads `releases/latest` on Stable or the release list on Beta ([[pages/decisions/0031-desktop-self-update]], amendment of 2026-11-14).
- **A version the owner picks.** Settings, Updates folds "Install a specific version" (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:671`); opened, it asks `scout:update.listVersions` once (`toggleVersions`, `:1624`) and lists every version on the owner's channel, newest first, with its date, Running on the current one, Older below it and Pre-release where it applies, with "Loading the versions..." while it reads and "Could not list the versions: <reason>." with Try again when GitHub did not give it. Install installs a newer version at once; an older one asks "Install Scout <version>, an older version?" first (`pickVersion`, `:1664`); where the package cannot replace itself the button is Download and opens that version's page. While the picked version installs, the list shows "Downloading Scout <version> · <n>%" and hides its buttons until a failure. Main installs only a listed version, through that release's own metadata, with `allowDowngrade` only for an older one, and puts the updater back on the GitHub feed after (`ui/packages/main/src/update/update-notice.ts:385`; [[pages/decisions/0056-install-a-version-the-owner-picks]]).
