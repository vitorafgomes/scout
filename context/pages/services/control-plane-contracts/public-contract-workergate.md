## Public contract

- **WorkerGate** (`src/Scout.ControlPlane.Contracts/protos/worker.proto:10`): the worker's only door into the control plane ([[pages/decisions/0032-per-feature-write-permissions]]). It asks whether a declared write may run, records the writes it performed, and reads and saves the operator's state; it can never grant a permission, decide an action or decide a claim. It imports `operator.proto` for the shared messages.
  - `RequestWrite` (`:11`) takes `RequestWriteRequest` (`:40`: `feature_id`, `scope`, `target`, `summary`, the optional `payload`, and since 2026-11-11 the optional `group_id` and `repository` of the request, `:46`, which the control plane queues as sent and never reads from the payload) and answers `RequestWriteResponse` (`:50`): `decision` is exactly `allowed`, `queued` or `refused`, `reason` says why (empty when allowed), and the optional `action_id` is set only when queued.
  - `RecordWrite` (`:12`) takes `RecordWriteRequest` (`:56`: `feature_id`, `scope`, `target`, `outcome`, optional `action_id`, optional `result`, and since 2026-11-08 optional `signed_as`, field 7) and answers the empty `RecordWriteResponse` (`:66`), or `FAILED_PRECONDITION` when the write could not have been permitted. The semantics are on [[pages/services/control-plane]].
  - `CloseWriteGroup` (`:37`, since 2026-11-11) takes `CloseWriteGroupRequest` (`:68`, `group_id`) and answers `CloseWriteGroupResponse` (`:72`, `actions`, how many actions the group holds): the worker reports that a request ended, which stamps its group closed and decides nothing; a blank id answers `INVALID_ARGUMENT`.
  - `GetOperatorMandate` (`:13`) answers the owner's `Mandate`, empty when none is saved.
  - `SaveOperatorProject` (`:14`) takes `SaveOperatorProjectRequest` (`:76`: `project`, optional `origin_reference`) and answers the saved `Project`. An empty `project.id` creates a project of origin `chat` that keeps `origin_reference` and takes the project's `format` and `direction` under the rules of `StartProjectRequest`, `INVALID_ARGUMENT` with the same sentences and nothing stored otherwise, and `own_video` is `INVALID_ARGUMENT` "A video of your own recording is started in Scout Desktop, Production, where you attach the recording." with nothing stored; an existing project keeps its topic, origin, reference and `recording_file`, and takes `recording_ms` only while it is `transcribing`. It needs the owner's live `youtube` write grant (`PERMISSION_DENIED` with the gate's reason), except a save that changes only the publication's status, video id, upload time, error or arm times of a project with a YouTube action executing; a status, claim or scene value outside the vocabulary or an unsafe scene file name is `INVALID_ARGUMENT`; marking a claim `supported` or `waived`, changing or dropping an owner-decided claim, changing the topic or origin, adding or dropping a scene once the project has scenes, changing a scene's `order` or `locked`, changing a locked scene, or replacing or claiming the owner's media is `FAILED_PRECONDITION`; a package outside its vocabulary, with an unsafe file name, or reported `assembled` without its files is `INVALID_ARGUMENT`, and setting what only the owner sets on a package, or an assembly save on a project that is not `assembling`, is `FAILED_PRECONDITION`; a project without `package` keeps its stored one; an unknown id is `NOT_FOUND`. Every successful save is one entry in the write log, action "Scout's data folder", outcome `saved <status>`.
  - `NextQueuedProject` (`:15`) takes the empty `NextQueuedProjectRequest` (`:81`) and answers `NextQueuedProjectResponse` (`:83`): the oldest `queued` project moved to `researching`, or to `transcribing` for an `own_video` one; else the oldest project with a `presenter_request` that is not researching, scripting, transcribing, producing, assembling or presenting, moved to `presenting` with its `presenter_return_status`; else the oldest `production_queued` project moved to `producing`; else the oldest `assembly_queued` project moved to `assembling`; else the oldest project left in `researching`, `scripting`, `transcribing`, `producing`, `assembling` or `presenting` with no save for 15 minutes, moved back to `researching`, or kept in `transcribing`, `producing`, `assembling` or `presenting`; a `recording_waiting` project is never taken; with its optional `origin_reference`, or neither when nothing waits. It needs the same grant.
  - `GetOperatorProject` (`:16`) takes `GetProjectRequest` and answers the `Project`, also without the grant while a YouTube action of the project is executing, owner-decided claims with their status and note, never the origin reference; `ListOperatorProjects` (`:17`) takes `ListProjectsRequest` and answers `ListProjectsResponse`, newest first, a `limit` of 0 or less meaning 50 and at most 5000 for the worker. Both need the same grant; an unknown id is `NOT_FOUND`.
  - `GetOperatorMediaDirectory` (`:18`) takes `GetProjectRequest` and answers the same `MediaDirectory` as the desktop's, under the same grant. `GetVoiceSamplesDirectory` (`:26`) takes the empty `GetVoiceSamplesDirectoryRequest` and answers the same voice samples `MediaDirectory` as the desktop's, with no grant, because the samples are Scout's own data and the directory holds nothing of the owner's; the worker writes the samples only there. `ReportReadiness` (`:19`) takes the worker's `Readiness` and answers it as stored, `reported_at` replaced by the control plane's time; it needs no grant.
  - `NextApprovedAction` (`:20`) takes `NextApprovedActionRequest`, empty for the YouTube operator's queue or with `feature_id` (`:90`) naming another feature whose own approved actions the worker runs (GitHub since [[pages/decisions/0038-code-quality-assistant-on-the-write-gate]]; then the response carries no origin reference, which the worker's draft keeps), and answers `NextApprovedActionResponse` (`:102`) with the optional `PendingAction` it claimed for the worker, `status` `executing`, and the optional `origin_reference` (`:104`) of the project the action targets, set only when that project came from a chat; the claim lapses after 30 minutes, and without the grant, or when no action is due, the response is empty.
  - `CheckActionGrant` (`:21`, since 2026-11-08) takes `CheckActionGrantRequest` (`:93`: `feature_id`, `action_id`) and answers `CheckActionGrantResponse.granted`: the worker's grant read just before it sends a claimed action; false means the control plane rejected the action as writes were revoked ([[pages/services/host-control-plane]]). Its name keeps clear of the verbs the WorkerGate may never offer (`tests/Scout.ControlPlane.Tests/Integration/OperatorGrpcTests.cs:1393`).
  - `GetComments` (`:24`) takes `ListCommentsRequest` and answers the stored `CommentsView` under the grant. `SaveComments` (`:25`) takes the worker's `CommentsView` and answers it as stored: it needs the grant, except the steps of a reply or hold the worker is executing; a kind, status, id or length outside the vocabulary is `INVALID_ARGUMENT`; dropping a comment, changing what YouTube said, `approved_text` or `decided_at`, moving a comment the owner decided, quarantining a comment the owner marked not spam, adding a comment in any status but `new`, `quarantined` or `drafted`, or marking or changing a decided idea is `FAILED_PRECONDITION`. A `synced_at` at or after `sync_requested_at` clears the request, and so does a failed sync: a non-empty `sync_error` with no newer `synced_at`, which becomes the stored error; an unset or empty `sync_error` keeps the stored one, and a newer `synced_at` clears it. At most 200 ideas are kept, every `used` one first; an idea whose comment is gone keeps no text, and only a `used` one stays. Every successful save is one write-log entry, target `comments`, outcome `saved comments`.
  - The owner's edits from the chat (`src/Scout.ControlPlane.Contracts/protos/worker.proto:27` to `:36`), added in phase 8d with no new message or field and in phase 8c-B with `ChatRequestPresenter`, `ChatEditScenePicturePrompt` and `ChatRegenerateScenePicture` (`:34` to `:36`) on the desktop's request messages: `ChatEditSceneText` takes `EditSceneTextRequest`, `ChatRegenerateNarration` and `ChatRegenerateScene` take `SceneRequest`, `ChatSetSceneLocked` takes `SetSceneLockedRequest`, `ChatReorderScenes` takes `ReorderScenesRequest`, `ChatProduceProject` takes `ProduceProjectRequest` and `ChatDelegateProject` takes `DelegateProjectRequest`, and each answers the `Project` without the origin reference. Each makes the desktop's change of the same name with its rules and status codes, after asking for the owner's live `youtube` write grant (`PERMISSION_DENIED` with the gate's reason, nothing stored or logged), and is one write-log entry, action "Scout's data folder", the project id as target, outcome `<what changed> via chat`; an empty `narration_voice`, `direction` or `motion` on `ChatProduceProject` and `ChatDelegateProject` keeps the project's own instead of clearing it. The desktop token is denied all ten (`tests/Scout.ControlPlane.Tests/Integration/OperatorGrpcTests.cs:94`), and the worker token round-trips them into the write log (`:1345`, `:1495`). The outcomes are on [[pages/services/control-plane]].
  - The WorkerGate's methods are exactly the thirteen above and the ten `Chat` rpcs, none of them an attach, an approval, a decision, a publish, a confirmation, a delete or a grant (`tests/Scout.ControlPlane.Tests/Integration/OperatorGrpcTests.cs:1393`).
  - `NextJobControl` (`src/Scout.ControlPlane.Contracts/protos/worker.proto:22`, 2026-11-10) takes the empty `NextJobControlRequest` and answers `NextJobControlResponse` (`:119`), whose optional `JobControl` (`:108`: `id`, `kind`, `owner`, `repo`, optional `number`, `action`) is the oldest owner control not taken yet, now taken, never handed out again; unset when none waits. `SettleJobControl` (`:23`) takes `SettleJobControlRequest` (`:123`: `id`, `outcome`, the worker's sentence, and `status` (`:126`), `applied`, `not applied` or `not confirmed`) and answers `SettleJobControlResponse` (`:129`): `recorded` true when the control's record is kept now, false when no taken control waits for one; an empty id or outcome, or another status, is `INVALID_ARGUMENT`.

- **Build wiring:** `src/Scout.ControlPlane.Contracts/Scout.ControlPlane.Contracts.csproj:21` to `:25` list the five `Protobuf` items, all `GrpcServices="Both"`; packages are `Google.Protobuf`, `Grpc.AspNetCore`, `Grpc.Tools`. The desktop client loads `providers.proto`, `features.proto` and `operator.proto` with `@grpc/proto-loader` (the proto list in `createControlPlaneClient`, `ui/packages/main/src/control-plane/client.ts`); `Scout.Host.Console` uses the generated `WorkerGate` client ([[pages/services/host-console]]).

- **Configuration keys:** none. **External boundaries:** none; this is the contract.
