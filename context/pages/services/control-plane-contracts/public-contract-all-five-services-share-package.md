## Public contract

All five services share package `scout.controlplane.v1` and C# namespace `Scout.ControlPlane.Contracts`. The proto files carry no comments; what a field means is written here.

- **Providers** (`src/Scout.ControlPlane.Contracts/protos/providers.proto:8`): `ListProviders`, `GetProviderStatus`, `StartProvider`, `StopProvider`, `RestartProvider`, `SetAutostart`, `WatchProviderStatus` (server stream).

- **Models** (`src/Scout.ControlPlane.Contracts/protos/models.proto:11`): `PullModel` (server stream of progress), `DeleteModel`, `ListModels`.

- **Features** (`src/Scout.ControlPlane.Contracts/protos/features.proto:8`): `ListFeatures`, `SetCredentials`, `Setup`, `DeleteCredentials`, `Enable`, `Disable`, `SetWriteGrant`, `ListPendingActions`, `ApproveAction`, `RejectAction`, `ApproveSet`, `RejectSet`, `GetActionGroup` (since 2026-11-11, `:19`, `:20`, `:21`), `GetActionText`, `ApproveCardIssues` (since 2026-11-11, commit C, `:22`, `:23`), `ListWrites` ([[pages/decisions/0032-per-feature-write-permissions]]).
  - `FeatureScopeRow.access` (`:64`): 0 read, 1 write, 2 irreversible write. `FeatureScopeRow.summary` (`:65`, field 4, since 2026-11-12): the one sentence the desktop's details panel shows for the row; `actions` (field 2) still carries every action in full. `Feature` (`:69`) carries `write_class` (`:85`; 0 none, 1 descriptive, 2 executive), `granted` and the optional ISO 8601 round-trip time of the owner's grant, `granted_at` (`:87`). Every addition is a new field number, so a client built on the earlier proto still reads the message.
  - `EnableRequest.confirm_writes` (`:116`): the owner confirmed the write rows; enabling a feature with write rows without it answers `FAILED_PRECONDITION`. `SetWriteGrantRequest` (`:123`, `id`, `granted`, `confirm_writes`) grants or revokes the write permission of a feature with write rows; granting needs `confirm_writes`, revoking does not.
  - `PendingAction` (`:129`): an irreversible action waiting for the owner, times in ISO 8601, `status` one of `pending`, `approved`, `rejected`, `executed` (approved and recorded by the worker), `executing` (approved and claimed by a worker that has not recorded it yet, listed by `ListPendingActions` and refused by `ApproveAction` and `RejectAction` as already decided), and the owner's optional `reason` on either decision; `ApproveAction` and `RejectAction` take `ActionDecisionRequest` (`:184`, `id`, optional `reason`) and return the decided action with that reason. Since 2026-11-11 ([[pages/roadmap/approve-together]] phase 1) it also carries the optional `group_id` and `repository` of the request that queued it (fields 12, 13, `:141`) and, for an action still `pending` only, the `title` and `body` its payload will write, cut to 256 and, since commit C, 4,000 characters (a preview; the list fits the desktop's 16 MiB receive limit because the host bounds the text one answer carries, and a row past that bound carries no `title` or `body` and sets `text_clipped`, [[pages/services/host-control-plane]]), the payload's SHA-256 `payload_digest` in lowercase hex and its group's `group_state`, `open`, `closed`, `changed` or `over_bound` (fields 14 to 17); the optional `text_clipped` (field 18, `:147`, commit B) is set when the title or body was cut. A decided action carries none of the text in `ListPendingActions` or in a decision's answer.
  - `ApproveSet` and `RejectSet` (commit B) take `ActionSetRequest` (`:194`: `group_id`, the repeated `ActionRef` of `id` and `digest`, `:189`, as the desktop listed them, and the optional `reason`) and answer `ActionSetResponse` (`:205`): `decided`, true only when every listed action was decided, the `group_id`, the listed `actions` as they stand after, and the repeated `ActionMismatch` (`:200`, `id` and `reason`) of the ones that did not match, in which case none was decided. `RejectSet` ignores the digests. A set refused whole, no action or one twice, over 50, without the grant, or for `ApproveSet` a group open, changed or over the bound, answers `FAILED_PRECONDITION` with the sentence; a blank `group_id` answers `INVALID_ARGUMENT`. `GetActionGroup` takes `GetActionGroupRequest` (`:212`, `group_id`) and answers `GetActionGroupResponse` (`:216`): the `group_id` and every action of it in any status, each with its `group_state`, its title and body and `text_clipped`, and the digest only while `pending`. The rules are on [[pages/services/control-plane]], A decision on a set; the desktop does not call them yet (phase 3).
  - `GetActionText` (commit C) takes `GetActionTextRequest` (`:221`, `id`) and answers `GetActionTextResponse` (`:225`): the full `title` and `body` of that one action and its `payload_digest`, the digest a set decision is bound to, for an action in any status but `executed`; for an executed one, whose payload was cut to what says where it went, the title and body it still holds, none for an issue or a comment, no digest, and `cut_after_execution` (`:229`) true. An unknown or blank id answers `NOT_FOUND`.
  - `ApproveCardIssues` (commit C) takes `ApproveCardIssuesRequest` (`:237`: `card_id`, `repository` as `owner/repo`, and the repeated `CardIssue`, `:232`, of `title` and `body`, as the findings card renders them) and answers the `ActionSetResponse` above: `decided`, a `group_id`, the group the click queued its issues in or, when it queued none, the first row's group (since review round 2), one row per issue in `actions`, each with its own group, status and outcome (an issue an earlier click on the card queued answers its row; since review round 1 the key is per issue), and an `ActionMismatch` with "its approval is not in the write log; approve it again" for an action a repeated click finds without its approval in the log. A value out of bounds answers `INVALID_ARGUMENT` with the dotted path (`cardId`, `repository`, `issues`, `issues[i].title`, `issues[i].body`) and its sentence; without the GitHub grant `FAILED_PRECONDITION`. The rules are on [[pages/services/control-plane]], The findings card's issues; the desktop does not call it yet (phase 3).
  - `WriteLogEntry` (`:243`): one write a feature performed, or one decision on an action, `approved_by` `owner` or unset, and since 2026-11-08 the optional `signed_as` (field 8), the login that signed the write ([[pages/decisions/0044-scout-acts-on-github-as-its-own-app]]), and since 2026-11-11 the optional `group_id` (field 10, `:253`) of the action the entry is about; `ListWritesRequest.limit` (`:257`) is the number of newest entries to return, 0 or less means 50.
  - `ControlJob` (`src/Scout.ControlPlane.Contracts/protos/features.proto:28`, 2026-11-10) takes `ControlJobRequest` (`:279`: `kind` `audit` or `tests`, `owner`, `repo`, the optional `number`, a test run's pull request, left unset for an audit and never 0, and `action` `pause`, `continue` or `stop`) and answers `ControlJobResponse` (`:287`): `accepted`, the `reason` in a sentence the desktop shows as it is, and the optional `control_id` when it was queued, the id the write log entry of the control carries as `action_id`. A control that does not apply is answered `accepted` false with its reason, never an error status: another kind or action, a repository outside the audit's name rule, a test run without a number above zero or with any action but `stop`, an audit with a number, a store that could not keep it ([[pages/services/control-plane]]). Since 2026-11-10 `WriteLogEntry` carries the optional `control_status` (field 9, `:252`), set only on the record of an owner control: `applied`, `not applied`, `not confirmed` or `expired`; every other entry, and every record written before it, leaves it unset.
