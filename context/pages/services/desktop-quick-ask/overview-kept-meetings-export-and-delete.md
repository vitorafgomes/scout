## Overview

- **Kept meetings: export and delete.** The Meetings screen of the main window ([[pages/services/desktop-ui]], Meetings) exports and deletes the meetings kept from the Stop row; moved here from that page on 2026-11-07.
  - **Export** (`ui/packages/renderer/src/app/meetings/meetings.component.ts:117`, `:345`): `scout:local.exportMeeting` with the id answers `{ saved }` only; the row then says "Saved", "Not saved" or the refusal's sentence. Main sends `{"type":"export","id":"m-<n>","meetingId"}`, takes the worker's `markdown` text, offers Electron's save dialog at `<Documents>/<title>.md` with a Markdown filter and `showOverwriteConfirmation`, so it asks before it overwrites a file (`ui/packages/main/src/quick-ask/quick-ask.ts:1737`), the title read from the document's `# ` line with `\ / : * ? " < > |` and control characters made spaces and at most 120 characters, else `Meeting.md`, and writes the text to the file the owner chose (`exportMeeting`, `ui/packages/main/src/quick-ask/quick-ask.ts:1730`; `exportName`, `:608`; the dialog, `writeFile` and `app.getPath('documents')` wired at `ui/packages/main/src/main.ts:1111` to `:1113`). A cancelled dialog writes nothing and answers `saved: false`; a failed write is `local/export-failed` "Scout could not write the Markdown file." (`EXPORT_WRITE_FAILED`, `ui/packages/main/src/quick-ask/quick-ask.ts:77`). The path never reaches the renderer and no log line carries it, the title or the text: main logs the request id and type, the meeting id, the line and turn counts and the export's length.
  - **Delete** (`ui/packages/renderer/src/app/meetings/meetings.component.ts:127`, `:361`) and **Delete all** (`:52`): both ask first through the shared confirmation dialog with Cancel focused, "Delete this meeting?" or "Delete all meetings?", with Cancel and Delete or Delete all; only the confirm sends `scout:local.deleteMeetings` with `{ meetingId }` or `{ all: true }` and reloads the list, also when the delete is refused, so a meeting deleted elsewhere leaves its row (`ui/packages/renderer/src/app/meetings/meetings.component.ts:380`, `:385`). Delete all says "This removes every kept meeting, their transcripts and their questions from this computer. It cannot be undone.", since the screen lists at most 100 (`:367`). Main pushes `scout:local.meetingsChanged` after each delete (`ui/packages/main/src/quick-ask/quick-ask.ts:1766`), and the screen reads the list again on that push, so a meeting kept from the quick-ask window shows without leaving the screen (`ui/packages/renderer/src/app/meetings/meetings.component.ts:333`). Each row's Export stays disabled while its own export runs, whatever another row does (`:118`). Main writes `{"type":"delete","id":"m-<n>","meetingId"}` or `"all":true` and answers `{ deleted }` (`deleteMeetings`, `ui/packages/main/src/quick-ask/quick-ask.ts:1758`). A meeting id that is not 22 base64url characters is refused with "Scout has no meeting with that id." before the worker (`:580`, `:150`), and `meetings` takes a `limit` of 1 to 1,000 only.
  - **The four requests in main** share `askMeetings` (`ui/packages/main/src/quick-ask/quick-ask.ts:1647`): an `m-<n>` id from a counter, the worker's `fail` sentence passed through as `local/meeting-failed`, "Scout did not answer about the meetings in time." after 30 s (`MEETING_TIMEOUT_MS`, `:144`), "Scout stopped before it finished answering." for a failed stdin write, a worker exit or dispose (`endMeetingRequests`, `:1697`), and `local/not-running` with no worker. `handleWorkerLine` checks the pending meeting ids first (`applyMeeting`, `:1689`, `:1846`), so their events never touch a turn.

- **Worker side.** `buildEnv` sets `SCOUT__ADAPTERS__LOCAL__ENABLED=true` (`ui/packages/main/src/worker/build-env.ts:75`), so the worker always runs [[pages/services/adapter-local]], next to Discord or Slack or on its own: with neither connected `buildEnv` no longer throws and the worker starts with only the local adapter.

- **No chat platform.** The Chat app step shows "No chat app? Chat with Scout in its own window. You can connect Discord or Slack later in Settings." with "Use on this computer" while nothing is set up and client detection has finished (`ui/packages/renderer/src/app/wizard/welcome/welcome.component.ts:70`), so the skip cannot race the launch's own worker start. It calls `WizardStore.useLocalOnly` (`ui/packages/renderer/src/app/core/wizard.store.ts:130`), which keeps `scout:local-only` in `localStorage` and counts as provisioned, then starts the worker and opens Chat (`ui/packages/renderer/src/app/wizard/welcome/welcome.component.ts:223`). On later launches the welcome screen starts the worker by itself, as for Discord or Slack, and then, once per launch, opens Chat while neither Discord nor Slack is connected (`WizardStore.takeLandingUrl`, `ui/packages/renderer/src/app/core/wizard.store.ts:108`).
