## Overview

- **Screenshot.** The owner can attach one picture of the screen to a question ([[pages/decisions/0032-per-feature-write-permissions]]: a declared read of the owner's own machine, the `desktop` feature, no grant; [[pages/roadmap/live-assistant]] phase 2). The text on a picture can also be read locally by the worker (see Text from the screen; [[pages/decisions/0036-text-read-from-a-screenshot-by-a-local-ocr-program]]).
  - Attach screenshot (`data-test="attach-screenshot"`, `ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:259`), in the tools tray, calls `grabScreenshot` (`ui/packages/renderer/src/app/quick-ask/screen-grab.ts:17`), which asks for `getDisplayMedia({ video: true, audio: false })` (`:20`). While the system picker is open the button is disabled and "Choose what Scout may see..." shows with `role="status"` (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:525`), so a capture is never hidden; nothing captures without a click.
  - Main answers the request in `allowScreenCaptureOnlyForApp` (`ui/packages/main/src/quick-ask/quick-ask.ts:309`, applied on the default session beside the microphone rule at `ui/packages/main/src/main.ts:1120`, so both windows get it): only for the app's own page, the same check as the microphone, and only for video; a request with audio, unless the `others` lane armed it (see Live listening), from another page or with no frame answers `null` and the page's capture fails. Otherwise it calls `desktopCapturer.getSources({ types: ['screen', 'window'], thumbnailSize: { width: 0, height: 0 } })`, the zero size so no thumbnail of any other screen or window is taken, which on Wayland opens the desktop portal's dialog and returns the source the owner picked; on X11 and Windows Electron has no system picker, so main offers the first screen. An empty list (a cancelled portal) or a failure answers `null`. `useSystemPicker` (macOS 15+ only) is not used, because it would bypass these checks. The X11 relaunch of the quick-ask window keeps `XDG_SESSION_TYPE`, so WebRTC still uses the PipeWire capturer and the portal; on Linux main also appends `PulseaudioLoopbackForScreenShare` and `WebRtcPipeWireCapturer` to the `enable-features` switch at startup (the `app.commandLine.appendSwitch('enable-features', withSystemAudioFeatures(...))` call in `ui/packages/main/src/main.ts`, see Live listening), which is what the system audio needs and leaves the screen path as it was.
  - The renderer plays the stream in a muted `video` element through `srcObject` (no blob URL, which the CSP's `media-src` would block), takes one frame on a canvas scaled to at most 1920 by 1080 keeping the aspect (never up), encodes it as JPEG at quality 0.8 and stops every track, on success and on failure (`ui/packages/renderer/src/app/quick-ask/screen-grab.ts:37`, `:47`, `:51`). A `NotAllowedError` or `AbortError` (the owner cancelled) attaches nothing and shows nothing; any other failure shows "Scout could not capture the screen." with `role="alert"` (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:528`).
  - The frame shows as a chip above the question field with a thumbnail, `data:image/jpeg;base64,...` (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:744`), which the CSP's `img-src 'self' data:` already allows, with a remove button (an x icon named Remove the screenshot, `:751`), which drops it. Escape, Close and the window losing focus keep it, like the typed text.
  - The next typed question, or the next voice recording, carries it as `image: { contentType: 'image/jpeg', base64 }` on `scout:local.ask` (`ui/packages/renderer/src/app/core/local-conversation.ts:56`, `:66`), and the window drops it once main took the ask, keeping it after a refusal (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:1939`). Main accepts exactly `image/jpeg` base64 of 1 to 4,000,000 characters, about 3 MB decoded (`ui/packages/main/src/quick-ask/quick-ask.ts:362`, `:154`), otherwise it refuses with `local/invalid-request` and "The screenshot must be a JPEG of at most 3 MB." without quoting it; the worker applies the same sentence to an image that is not a JPEG or whose decoded bytes pass 3 MB, before any handler runs (`src/Scout.Adapter.Local/LocalChatAdapter.cs:349`, `:48`; test `tests/Scout.Adapter.Local.Tests/LocalChatAdapterTests.cs::An_image_that_is_not_a_jpeg_or_over_3_MB_fails_with_the_sentence`, `tests/Scout.Adapter.Local.Tests/LocalChatAdapterTests.cs:663`; [[pages/services/adapter-local]]). The image rides the same stdin line, `{"type":"ask","id":"<id>","text":"...","image":{...}}` or beside `audio`, through main ([[pages/decisions/0028-local-quick-ask-assistant]]); no port or channel is added.
  - The turn keeps only `screenshot: true` (`ui/packages/shared/src/ipc-contract.ts:1528`, set at `ui/packages/main/src/quick-ask/quick-ask.ts:1334`), never the bytes; no main log line carries the image, and nothing is written to disk. When the connected provider cannot read images the worker refuses before any model call and completes the turn with "The connected AI source cannot look at pictures; ask it in words or connect one that can." (`src/Scout.Conversation/Streaming/StreamPumpOptions.cs:98`, sent from `src/Scout.Conversation/Streaming/StreamPump.cs:178`; test `tests/Scout.Conversation.Tests/Routing/LlmStreamingRouterTests.cs::A_vision_unavailable_failure_is_answered_with_the_sentence`, `tests/Scout.Conversation.Tests/Routing/LlmStreamingRouterTests.cs:278`); the question is not answered as if no picture had been sent ([[pages/decisions/0035-screenshot-attached-to-a-question]]).
  - On Wayland the portal dialog takes the focus, so while a display-media request is pending the window ignores blur (`QuickAsk.screenCapture`, `ui/packages/main/src/quick-ask/quick-ask.ts`, wired in `ui/packages/main/src/main.ts`), and once the request is answered a window hidden meanwhile is shown again with `showInactive()`, so the status line and the preview stay visible and the focus is not stolen; a blur after that hides it as usual, unless a listening lane is open.
