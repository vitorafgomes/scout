## Overview

- **Replies.**
  - The supervisor hands each `SCOUT_LOCAL` JSON to `handleWorkerLine`, which applies it to the running turn whose id it carries: `update` sets the reply, `complete` the reply, citations and `done`, `fail` the state `failed` (`ui/packages/main/src/quick-ask/quick-ask.ts:1844`). Since 2026-11-07 a `fail` after part of the reply arrived keeps that partial reply and puts the sentence in `LocalTurn.failure` (`failed`, `ui/packages/main/src/quick-ask/quick-ask.ts:795`; `ui/packages/shared/src/ipc-contract.ts:1552`); a `fail` before any reply is still the reply. Both surfaces show the failure under the reply (`data-test="failure"`, `ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:705`, `ui/packages/renderer/src/app/chat/chat.component.ts:143`) as "Interrupted" for the worker's cancel sentence "Cancelled." (`LOCAL_CANCELLED_REPLY`, `ui/packages/shared/src/ipc-contract.ts:1571`, the same string as `LocalChatAdapter.CancelledReply`) and as the sentence otherwise. Unknown ids, events after `complete` or `fail`, and lines that are not one of these events are dropped; so is a `fail` whose id is null, which the worker sends for a request it could not read.
  - The worker also sends progress of its own, such as the channel operator's, as `{"id":null,"event":"notice","text":"..."}`. `toLocalEvent` branches on the event kind, not the id: only a `notice` with a null id and non-empty text is kept (`ui/packages/main/src/quick-ask/quick-ask.ts:686`). `handleWorkerLine` appends it as its own turn, never to a running one: id `notice:<n>` (a colon, so it never matches a question id), no question, the text cut to 32,000 characters as the reply, `done`, `notice: true` on `LocalTurn`, and `askedAt`, when it arrived (`ui/packages/main/src/quick-ask/quick-ask.ts:1864`, `ui/packages/shared/src/ipc-contract.ts:1534`). It arrives with or without a question running, is sent to every window like any turn, and counts toward the last 200. The quick-ask window and the Chat screen show it as a Scout message with no question line (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:642`, `ui/packages/renderer/src/app/chat/chat.component.ts:67`), rendered like every reply; the Chat screen shows the time it arrived beside "Scout" (`data-test="arrived-at"`), where a question shows its time beside "You". A notice that carries a `scout-findings` block shows its cards like a reply: an audit job ([[pages/services/audit]], [[pages/decisions/0042-audit-as-a-job-with-saved-progress]]) posts each batch's block, under a heading such as "Audit of owner/repo, area (1 of n):", through the local adapter's origin poster ([[pages/services/adapter-local]]), and a last notice with the verdict and the scope paragraph, which renders as text. `findingsCards` (`ui/packages/renderer/src/app/core/review-findings.store.ts`) decides which turn shows which cards: a review shows its own; the batches of one audit, the same repository and commit, merge by finding id into one set shown on the latest batch's turn, the first batch's turn keeping the decisions and the posting state, so a later batch adds cards under the newest post, a finding id already shown is never shown again, and the earlier batch turns keep their heading with one muted line under it, "Its findings are in the cards below." (`data-test="moved-below"`, `TurnCards.moved`). Once issues are opened on that repository, the next batch starts a new set with only the findings not shown before. Both surfaces read that map (`ReviewFindingsStore.cards`); main needs no change, since a notice is already a `done` turn whose reply carries the block and `scout:local.setDecisions` accepts any such turn.
  - A failed stdin write, or a worker exit, ends every running turn with "Scout stopped before it finished answering.", as the failure under a partial reply or as the reply (`ui/packages/main/src/quick-ask/quick-ask.ts:1357`, `:1775`).
  - Every change sends the whole conversation on `scout:local.turns` to every open window (`ui/packages/main/src/quick-ask/quick-ask.ts:765`). `scout:local.getTurns` returns it, and `scout:local.clearTurns` empties it (`clearTurns`, `ui/packages/main/src/quick-ask/quick-ask.ts:1414`): since 2026-11-08 a turn still running is cancelled first through `stopRunning` (a `cancel` line to the worker, or a held question dropped so it is never sent once Scout runs), then the list is emptied in every window and the worker gets `{"type":"reset"}`, whose own reset also cancels any ask still running ([[pages/services/adapter-local]]); while a card's issues are being queued it is refused with `local/busy` and the posting sentence instead, never a silent no-op, and the refusal is shown: `LocalConversation.clear` resolves to main's sentence (`ui/packages/renderer/src/app/core/local-conversation.ts:91`) and both surfaces put it on their error line (2026-11-09; until then the renderer swallowed it).
