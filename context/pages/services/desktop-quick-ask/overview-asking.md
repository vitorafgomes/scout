## Overview

- **Asking.**
  - The renderer's `LocalConversation` (`ui/packages/renderer/src/app/core/local-conversation.ts:15`) picks a UUID per question and calls `scout:local.ask` with the text or the recording.
  - Main validates it (`toWorkerRequest`, `ui/packages/main/src/quick-ask/quick-ask.ts:377`): an id of 1 to 64 letters, digits and hyphens, text of 1 to 4,000 characters (with `voice: true` for a dictated question, which main keeps on the turn, `:1338`, `:443`, and never sends to the worker), and an optional screenshot (see Screenshot). Since 2026-11-07 a recording is refused: the desktop dictates text, so no audio question reaches the worker and no turn reads "(voice message)" (`:449`). An id already in the conversation is refused. It then appends a running turn with the question and writes one JSON line to the worker's stdin (`:1327`).
  - With no running worker the turn fails with "Scout is not running. Start it from the tray or the app." as its reply and the call is refused with `local/not-running`. A refusal that never became a turn shows on the window's error line (`ui/packages/renderer/src/app/core/local-conversation.ts:113`).
  - While the worker is starting (the launch before it is ready, the backoff before a restart, or the start half of a settings restart) a question is held instead (2026-11-07): main keeps it as a running turn with "Scout is starting…" as its activity (`STARTING_ACTIVITY`, `ui/packages/main/src/quick-ask/quick-ask.ts:64`, `:1344`), writes it to the worker on the `running` state event, and gives it the not-running reply with `notRunning` when the start ends in `stopped` or in a `crashed` with `gaveUp`, or when the running worker's stdin refuses it (`releaseHeld`, `ui/packages/main/src/quick-ask/quick-ask.ts:1379`); a worker exit during that start does not give it the stopped sentence (`failRunning`, `ui/packages/main/src/quick-ask/quick-ask.ts:800`). Stop on a held question ends it as "Cancelled." and nothing is sent (`ui/packages/main/src/quick-ask/quick-ask.ts:1390`). Since 2026-11-08 quick ask tells a worker on its way back from a real stop or failure (`willRun`, `ui/packages/main/src/quick-ask/quick-ask.ts:1372`, used by `ask` at `:1343`): a question asked between a restart's stop and its start, or held when that stop lands, is held while main's restart path says it is restarting (`restarting`, wired in `ui/packages/main/src/main.ts:1118`), and a question held through a readiness timeout stays held across the `crashed` that still schedules a restart, and is refused only once the supervisor gives up (`gaveUp`). Once a restart settles, main calls `restartSettled` (`ui/packages/main/src/quick-ask/quick-ask.ts:1820`), which sends a held question if the worker runs and refuses it otherwise, so a Stop that lands in a restart's start half (the start then gives up without a `crashed`) leaves no question waiting, none sent on a later Start, and no running answer to keep the next restart waiting. A held question counts as a running answer, so a restart asked meanwhile waits for its answer ([[pages/services/desktop-ui]], Worker restarts). Tests: "a question asked between a restart's stop and its start is held and sent once the restarted worker runs", "a question held while Scout starts keeps a restart waiting, is sent once the worker runs, and the restart follows its answer", "a question held through a readiness timeout is sent once the automatic restart runs" and "... is refused once the worker gives up", "a question held when a Stop lands in a restart's start half gets the not-running reply, is never sent, and keeps no later restart waiting" (`ui/packages/main/test/worker-restart.test.ts:291`, `:324`, `:393`, `:357`).
  - A turn that fails, is stopped, or is cut off by a worker exit keeps its reply without the stream cursor "▌" the last interim update carried (`failed`, `ui/packages/main/src/quick-ask/quick-ask.ts:793`); the cursor shows only while the reply streams.
  - A Stop pressed while a question is still on its way to main is remembered and cancels that turn once main takes it, unless the turn is a card post (`stop`, `send`, `ui/packages/renderer/src/app/core/local-conversation.ts:79`, `:100`); this covers the quick-ask window and the Chat screen. When an answer ends and the focus was lost with the disabled question box, the box takes the focus again, so the next keys type there; focus in another field, a card's editor or the text from the screen, stays where it is (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:1618`).

The window is busy while its own ask is on its way to main or any turn runs (`busy`, `:1477`): the microphone and Space push-to-talk are off, and Stop (`data-test="stop"`, "Stop the answer") shows before Send and calls `LocalConversation.stop` (`:1700`) and so `scout:local.cancel` for the running turn. A card post cannot be cancelled (the owner's decision of 2026-11-07, Rule A): while the running turn is an audit's Open issues (`issues` on the turn; since 2026-11-10 main no longer reads a `Review to post` block, which nothing builds, so it is plain text of the question and makes no card turn) (`LocalConversation.posting`), Stop is disabled with the title "Queuing cards; cannot be stopped." on both surfaces (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:829`, `ui/packages/renderer/src/app/chat/chat.component.ts:334`), and `LocalConversation.stop` itself never cancels such a turn (`POSTING_CANNOT_STOP`, `posting`, `stop`, `ui/packages/renderer/src/app/core/local-conversation.ts:8`, `:30`, `:79`), because a cancel mid-write followed by a second click could write to GitHub twice; Escape and Space never cancel a turn. A plain question can still be stopped.
