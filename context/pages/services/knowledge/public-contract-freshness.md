## Public contract

- **Freshness:** the store keeps the repository path each project was last indexed from in the table `project_source` (`src/Scout.Knowledge/SqliteProjectKnowledgeStore.cs:36`, `GetIndexedPathAsync` `:107`, `SetIndexedPathAsync` `:116`); the indexer records it after the chunks (`src/Scout.Knowledge/ProjectIndexer.cs:65`). `ResolveAsync` (`src/Scout.Knowledge/ProjectResolutionService.cs:112`) answers from the store only when the project has chunks, is not marked stale and its recorded path equals the entry's (`:128`, `:161`); otherwise it indexes first. One point read per resolve, 30 to 40 microseconds on the owner's machine, the same as the existence check beside it. A database written before 2026-11-09 has no such table: the first connection creates it empty (`CREATE TABLE IF NOT EXISTS` in the schema batch every connection runs), and the first resolve of each project finds no recorded path, records the configured one and answers from the chunks already there, with no embedding call and no re-index; from then on a changed path is seen. Such an index holds the chunks it was written with: struct, enum, delegate, constructor, property, event and field chunks appear only when the project is next indexed (a changed path, a registration at run time, or the `index <project>` command). When the path cannot be written, after an index (`src/Scout.Knowledge/ProjectIndexer.cs:67`) or on adoption (`src/Scout.Knowledge/ProjectResolutionService.cs:170`), a warning is logged and the index answers as it is, never "Could not ... right now" for that alone; a later resolve records it, because a first or adopted index still has an empty path or none and is adopted again, and a re-index at a changed path still differs from the recorded one and is indexed again. The stale mark of a run-time registration is cleared only when the path registered now is the one that was indexed (`:138`), so a run that started on the old path never clears the mark of the new one. When indexing fails, `ResolveAsync` logs an error and answers from the chunks the project has only when their recorded path is the entry's own (`:147`), as for a snapshot registered again at the same place after a restart; the project stays stale and is indexed again on its next use. A timeout nobody asked for is such a failure (`:145`, the same filter on the caller's token as in the tools), so the Ollama connector's `TaskCanceledException` and the OpenAI connector's `AggregateException` get the same answer; a cancellation the caller asked for leaves `ResolveAsync` with nothing logged. When the recorded path differs, the chunks are another repository's under this name, so they are never served: with those, or with none, it returns null (`:154`), and both tools answer "Indexing project '<name>' failed, so it cannot be searched yet. Try again later." instead of "Unknown project" (`src/Scout.Knowledge/ProjectKnowledgeService.cs:138`).

- **Agent:** `ProjectExpertAgentFactory.Create` (`src/Scout.Knowledge/ProjectExpertAgentFactory.cs:60`). The agent is bound to a copy of the shared kernel with every plugin removed (`:66`, `:87`): it uses the kernel's chat service and filters, and offers the model nothing unless a turn passes its own kernel, which the gateway does with the turn's declared functions ([[pages/decisions/0054-functions-scoped-per-skill-and-job]], [[pages/services/llm]]; `tests/Scout.Knowledge.Tests/ProjectExpertAgentFactoryTests.cs:43`).

- **Configuration keys:** `Scout:Projects` with `Items` (`Name`, `RepoPath`), `Roots`, and `Watch` (`Enabled`, `DebounceMilliseconds`) (`src/Scout.Knowledge/ProjectsOptions.cs:7`).

- **External boundaries:** filesystem read of repository files (`src/Scout.Knowledge/ProjectIndexer.cs:41`, `:113`) and a `FileSystemWatcher` when enabled (`src/Scout.Knowledge/ProjectWatchService.cs:83`); filesystem write of `project-knowledge.db` under the user's local application data, folder `Scout` (`src/Scout.Knowledge/KnowledgeServiceCollectionExtensions.cs:100`), which now also holds the path of each configured repository; embedding calls through `IEmbeddingGenerator`.
