## Public contract

- **Entry point:** `AddYouTubePlugin(IServiceCollection, IConfiguration)` at `src/Scout.Plugin.YouTube/YouTubeServiceCollectionExtensions.cs:30`; returns early when both the API key and the token file are blank (`:45`). A token file takes precedence over a key: the client pipeline gets `YouTubeTokenFileHandler` or `YouTubeApiKeyHandler`, never both (`:56`).
- **Abstraction:** `IYouTubeClient` with six read methods (`src/Scout.Plugin.YouTube/Abstractions/IYouTubeClient.cs:7`): `GetMyChannelAsync` (`channels?mine=true`, sign-in only), `GetChannelByHandleAsync` (`channels?forHandle=`, without the `@`), `ListUploadsAsync` (`playlistItems` then one `videos` call, at most 50), `GetVideosAsync` (one `videos` call for at most 50 ids) and `SearchVideosAsync(query, max)` (`src/Scout.Plugin.YouTube/Abstractions/IYouTubeClient.cs:28`): one `search?part=snippet&type=video&order=relevance` call with `maxResults` clamped to 1..25 (`src/Scout.Plugin.YouTube/YouTubeClient.cs:97`), keeping only results that are videos, each a `YouTubeSearchResult` (video id, title, channel title, published date, description; no statistics, so one call spends one of the 100 searches `search.list` allows a day and nothing of the shared 10,000 units), and `ListCommentThreadsAsync(channelId, pageToken)` (`src/Scout.Plugin.YouTube/Abstractions/IYouTubeClient.cs:36`): one `commentThreads?part=snippet&allThreadsRelatedToChannelId=<id>&order=time&maxResults=100&textFormat=plainText` call, with `&pageToken=` after the first page (`src/Scout.Plugin.YouTube/YouTubeClient.cs:110`), each thread a `YouTubeCommentThread` (`src/Scout.Plugin.YouTube/Abstractions/YouTubeCommentThread.cs:8`: thread id, top-level comment id, video id, author display name, author channel id or null, plain text, published time and likes) in a `YouTubeCommentThreadPage` (`:19`) with the next page's token; it costs 1 unit. It needs the `youtube.force-ssl` scope, which only the write sign-in grants: with the read sign-in's `youtube.readonly` Google answers 403 `insufficientPermissions` (observed 2026-11-03 against the owner's channel, while `channels?mine=true` answered 200 with the same token), which the client turns into "Reading comments needs Scout's permission to reply to and moderate comments: open the YouTube card in Scout Desktop and allow writes again.", retryable like the comment-write variant (`src/Scout.Plugin.YouTube/YouTubeClient.cs:34`, `:173`); every other status keeps the mapping below, so a 403 with another reason is still "The YouTube credentials cannot read this.". Internal implementation `YouTubeClient` (`src/Scout.Plugin.YouTube/YouTubeClient.cs:17`); records `YouTubeChannel`, `YouTubeVideo` and `YouTubeSearchResult`; `YouTubeApiException` (`src/Scout.Plugin.YouTube/YouTubeApiException.cs:12`).
- **Signed-in clients:** registered only when a token file is configured, because an API key can neither write nor read analytics (`src/Scout.Plugin.YouTube/YouTubeServiceCollectionExtensions.cs:66`, `:77`), and never wrapped in a kernel plugin. `IYouTubeWriteClient` (`src/Scout.Plugin.YouTube/Abstractions/IYouTubeWriteClient.cs:8`) with `UploadVideoAsync(file, YouTubeUpload)` (`videos.insert`, resumable), `SetThumbnailAsync(videoId, file)` (`thumbnails.set`), `UpdateTitleAsync(videoId, title)` (`videos.list` then `videos.update`) and `GetVideoStatusAsync(videoId)` (`videos.list?part=status`), `ReplyToCommentAsync(parentId, text)` (`comments.insert`, the new reply's id, `src/Scout.Plugin.YouTube/Abstractions/IYouTubeWriteClient.cs:36`) and `HoldCommentAsync(commentId)` (`comments.setModerationStatus` with `heldForReview`, `:43`); `IYouTubeAnalyticsClient` (`src/Scout.Plugin.YouTube/Abstractions/IYouTubeAnalyticsClient.cs:4`) with `ReportAsync(videoId, start, end)` and `RetentionAsync(videoId, start, end)`; `IYouTubeReportingClient` (`src/Scout.Plugin.YouTube/Abstractions/IYouTubeReportingClient.cs:7`) with `FindReachJobAsync`, `CreateReachJobAsync` (`jobs.create`, which the operator calls only after the control plane allows the write), `ListReportsAsync(jobId, createdAfter)` and `DownloadReachAsync(url)`. Implementations `YouTubeWriteClient` (`src/Scout.Plugin.YouTube/YouTubeWriteClient.cs:21`), `YouTubeAnalyticsClient` (`src/Scout.Plugin.YouTube/YouTubeAnalyticsClient.cs:13`), `YouTubeReportingClient` (`src/Scout.Plugin.YouTube/YouTubeReportingClient.cs:17`). `YouTubeApiException.Retryable` (`src/Scout.Plugin.YouTube/YouTubeApiException.cs:22`) is true for a 5xx, a 429, a 401, a spent quota and a missing token file: the same request can succeed later.
- **Model tools:** plugin `YouTube` (`src/Scout.Plugin.YouTube/YouTubeServiceCollectionExtensions.cs:61`) with `youtube_channel_overview(handle?)` (`src/Scout.Plugin.YouTube/YouTubePlugin.cs:32`), `youtube_recent_videos(handle?, count = 10)` (`:54`) and `youtube_video_stats(videos)` (`:90`). Without a handle the first two read the owner's own channel. Search has no model function: the channel operator calls it under its own daily budget ([[pages/services/operator]]), and a function would let the model spend YouTube's 100 daily searches outside that count.
- **Configuration keys:** `Scout:Plugins:YouTube` with `ApiKey` (`src/Scout.Plugin.YouTube/YouTubeOptions.cs:13`) and `TokenFile` (`:20`), the path of a JSON file `{"access_token": "...", "expires_at": <unix ms>}` of which only `access_token` is read. The desktop sets `SCOUT__PLUGINS__YOUTUBE__TOKENFILE` while the owner is signed in with Google, or `SCOUT__PLUGINS__YOUTUBE__APIKEY` when the owner pasted a key. `src/Scout.Host.Console/appsettings.json:47` carries both names with empty values.
- **External boundaries:** HTTPS to `https://www.googleapis.com/youtube/v3/` with a 30 second timeout, `Accept: application/json` and `User-Agent: Scout` (`src/Scout.Plugin.YouTube/YouTubeServiceCollectionExtensions.cs:48`); GET requests only from the model's client (`src/Scout.Plugin.YouTube/YouTubeClient.cs:139`). With the sign-in, the write client POSTs to `https://www.googleapis.com/upload/youtube/v3/videos` and `.../thumbnails/set` GETs and PUTs `https://www.googleapis.com/youtube/v3/videos` and POSTs `https://www.googleapis.com/youtube/v3/comments` and `.../comments/setModerationStatus`, with no client timeout, a 30 second connect timeout and a handler that never follows a redirect (`src/Scout.Plugin.YouTube/YouTubeServiceCollectionExtensions.cs:86`); the Analytics client GETs `https://youtubeanalytics.googleapis.com/v2/reports`; the Reporting client GETs and POSTs `https://youtubereporting.googleapis.com/v1/jobs` and downloads reports from that host only; both with a 2 minute timeout. Scopes the sign-in must grant: `youtube.upload` for the upload and the thumbnail, `youtube` or `youtube.force-ssl` for `videos.update`, `youtube.force-ssl` for the reply, the hold and the comment threads of the owner's channel, `yt-analytics.readonly` for the Analytics and Reporting APIs; the desktop asks for them ([[pages/services/desktop-ui]]). The token file on the local filesystem. Plain `HttpClient` and `System.Text.Json`: no Google SDK package.
