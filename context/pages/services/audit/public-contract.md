## Public contract

- **Entry point:** `AddAudit(IServiceCollection, IConfiguration)` (`src/Scout.Audit/AuditServiceCollectionExtensions.cs:30`), called by [[pages/services/host-console]] only when the GitHub plugin registered its client (`src/Scout.Host.Console/HostComposition.cs:96`). It registers the store, the batch runner, one `RepositoryAudits` as both `IRepositoryAudits` and `IPullRequestReviews` (`src/Scout.Audit/AuditServiceCollectionExtensions.cs:57`, `:76`, `:77`) and the hosted `AuditWorker` (`:78`). In the same place the host registers its five adapters (`src/Scout.Host.Console/HostComposition.cs:99` to `:103`): `AuditSnapshotsAdapter`, this project's `IAuditSnapshots` over the plugin's `IRepositorySnapshots` (`src/Scout.Host.Console/AuditSnapshotsAdapter.cs:7`), `ReviewEnvironmentAdapter`, this project's `IReviewEnvironment` over the `Scout:Sandbox:Enabled` value the host reads once (`src/Scout.Host.Console/ReviewEnvironmentAdapter.cs:9`, `tests/Scout.Host.Console.Tests/HostAuditTurnTests.cs:328`), and `RepositoryAuditsAdapter`, the plugin's `IRepositoryAudits` over this project's (`src/Scout.Host.Console/RepositoryAuditsAdapter.cs:9`), so the plugin's `start_repository_audit`, `pause_repository_audit`, `stop_repository_audit` and `get_repository_audit_status` reach the job and neither library references the other; `PullRequestReviewsAdapter`, the plugin's `IPullRequestReviews` over this project's, a start that ran answering its sentence and each warning of its checks, one per line (`src/Scout.Host.Console/PullRequestReviewsAdapter.cs:11`, `tests/Scout.Host.Console.Tests/HostAuditTurnTests.cs:247`); and `ReviewPullRequestsAdapter`, this project's `IReviewPullRequests` over the plugin's `IGitHubClient` (`src/Scout.Host.Console/ReviewPullRequestsAdapter.cs:11`, `tests/Scout.Host.Console.Tests/HostAuditTurnTests.cs:336`, `:350`).
- **Abstractions:** `IAuditJobStore` (`src/Scout.Audit/IAuditJobStore.cs:47`), internal, the job's seventeen use cases (create, running jobs, job, latest job, batches, next batch, the next pending batches up to a count, a review's wave (`:76`), findings, begin, complete, not covered, stop, pause, resume, which also sets the job's `resumed` time (`:107`), finish, the checks a review kept, and the running time, the clock time during which any batch ran since that resume (`:121`)), where create, latest job and stop take the pull request a review is of, null for an audit, and create takes the checks a review ran before it started, null for an audit, which is what `RepositoryAudits` passes for an audit and the pull request's number for a review, over the records `AuditJob`, `AuditBatch` and `AuditFinding` and the status words of `AuditStatus` (`:4`); `RepositoryAudits`, `AuditWorker` and the registration see only it (`src/Scout.Audit/AuditServiceCollectionExtensions.cs:57`). `IRepositoryAudits` (`src/Scout.Audit/RepositoryAudits.cs:17`) with `StartAsync`, `PauseAsync` (`:26`), `ContinueAsync` (`:33`), `StopAsync` and `StatusAsync`, each `(owner, repo, ct)`, and `ControlAsync(owner, repo, action, ct)` (`:40`) for Scout Desktop, which answers `AuditControlAnswer(Applied, Sentence)` (`:50`) and each answering one sentence the model relays, the same shape as the plugin's. `IPullRequestReviews` (`src/Scout.Audit/RepositoryAudits.Reviews.cs:13`), public, with `StartAsync(owner, repo, number, headSha, files, diffsLeftOut, notListed, checks, ct)` (`src/Scout.Audit/RepositoryAudits.Reviews.cs:26`), `files` every changed file as `ReviewFile(Path, Patch)` (`:37`), the patch null when GitHub returned no diff for it, `notListed` how many changed files GitHub counts but did not list, kept as one batch not read (since 2026-11-19; below zero counts as none), and `checks` the head commit's check counts the caller read, null when it could not, answering a `ReviewStart` with the checks it ran (`src/Scout.Audit/ReviewPreflight.cs:53`), its records `ReviewPreflight`, `PreflightCheck`, `PreflightOutcome` and `ReviewCheckCounts` public with it, `StatusAsync(owner, repo, number, ct)`, answering one sentence, and `ControlAsync(owner, repo, number, action, ct)` (`src/Scout.Audit/RepositoryAudits.Reviews.cs:37`) for Scout Desktop's bell, which pauses a running review, continues a paused one or stops either and answers `AuditControlAnswer(Applied, Sentence)` (`:300`); the patches and the check counts arrive as arguments, so this project reads nothing of the GitHub plugin to get them. `IReviewPullRequests` (`src/Scout.Audit/IReviewPullRequests.cs:8`), what the review worker reads of the pull request: `ReadAsync`, the head commit and every changed file with its patch as `ReviewPullRequest` (`:14`, `:26`), once each time the worker takes a review up, and `HeadAsync`, the head commit alone before each later wave (`:20`); each answers null when GitHub does not find the pull request and throws when the read fails. `IReviewEnvironment.ContainerRunsOn` (`src/Scout.Audit/IReviewEnvironment.cs:7`), the fact of this computer a review is checked against, which the host adapts. `IAuditSnapshots.Find(owner, repo, commitOrShortSha)` and `AuditSnapshot(Owner, Repo, Commit, Root, TakenAt)` (`src/Scout.Audit/IAuditSnapshots.cs:7`), the shape of the plugin's `IRepositorySnapshots`. The implementation resolves the kernel and the notifier on use (`src/Scout.Audit/RepositoryAudits.cs:59`, `src/Scout.Audit/AuditServiceCollectionExtensions.cs:75`), because the plugin that calls it is built into that kernel and a chat adapter the notifier posts through may need it; the host composes the real plugin with the adapter and resolves the kernel without a cycle (`tests/Scout.Host.Console.Tests/HostAuditTurnTests.cs:303`).
- **Configuration keys:** `Scout:Audit:DbPath` (default `Scout/audit.db` under the user's local application data, beside the snapshots), `Scout:Audit:MaxBatchFiles` (40), `Scout:Audit:MaxBatchCharacters` (60,000, `src/Scout.Audit/AuditOptions.cs:29`) and `Scout:Audit:TurnTimeout` (10 minutes, `:32`) and `Scout:Audit:ReviewParallelBatches`, the batches of a review run at once, 1 to 8, 4 unless set and 1 when unset with `Scout:Llm:Provider` empty or `Ollama` (`:38`) (`src/Scout.Audit/AuditOptions.cs:7`, defaults applied at `src/Scout.Audit/AuditServiceCollectionExtensions.cs:40`). A `TurnTimeout` that is not above zero, or a `ReviewParallelBatches` outside 1 to 8, fails validation when the host starts (`src/Scout.Audit/AuditServiceCollectionExtensions.cs:52`, `:53`, `ValidateOnStart`), with `Scout:Audit:TurnTimeout must be above zero; every batch turn would end before the model answers.`, instead of ending every batch turn at once and leaving every area not covered. `Scout:Audit:RecordTurns` (false unless set, `src/Scout.Audit/AuditOptions.cs:18`; `Scout__Audit__RecordTurns=true` in the environment, which the desktop passes on to the worker it starts) records each review turn for diagnosis under `audit/<job>` in Scout's own data folder, whatever `DbPath` says (`src/Scout.Audit/AuditServiceCollectionExtensions.cs:94`); what it holds is [[pages/decisions/0073-the-numbers-of-each-model-turn-are-kept]]. Paths and numbers only; `appsettings.json` names none of them.
- **Schema:** the `audit_job` table gains the nullable `resumed` column, the time of the last continue, through the `JobResumed` migration (`src/Scout.Audit/Storage/AuditDbContext.cs:36`, `src/Scout.Audit/Storage/Migrations/20261119090000_JobResumed.cs`); a file migrated before it counts every batch (`tests/Scout.Audit.Tests/SqliteAuditStoreTests.cs:473`).
- **Packages:** `Microsoft.EntityFrameworkCore.Sqlite` 10.0.15 (`Directory.Packages.props:43`), which brings `Microsoft.Data.Sqlite` and the SQLite bundle at the versions [[pages/services/meetings]] pins, and `Microsoft.SemanticKernel`.
- **External boundaries:** the database file and its WAL companions; the model through the kernel's `IChatCompletionService`; the GitHub plugin's functions through the kernel and its snapshots through `IAuditSnapshots`; `IOriginNotifier` for the posts. No HTTP client and no file read of the plugin's own.

## Review inputs (2026-11-20)

`IPullRequestReviews.StartAsync` takes a trailing `ReviewPurpose? purpose = null` after `ct`, and `ReviewFile` carries `Status`, such as `removed` (`src/Scout.Audit/RepositoryAudits.Reviews.cs:44`). `IAuditJobStore.CreateJobAsync` takes a trailing `ReviewInputs? inputs = null`, kept in the job row's `inputs` column, and `InputsAsync` reads them back, null for a job that kept none or a value that cannot be read. `AuditBatchRunner.RunReviewAsync` takes the inputs after `ct` ([[pages/decisions/0064-the-review-batch-is-handed-the-purpose-the-rules-and-what-was-removed]]; [[pages/services/audit/how-it-works-review-inputs]]).

The review quality work (evidence, parts, focused readings, the second reading with reads, the turn table) is on [[pages/services/audit/public-contract-review-quality]].
