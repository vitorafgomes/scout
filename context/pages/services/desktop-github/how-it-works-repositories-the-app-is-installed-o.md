## How it works

**Repositories the App is installed on** (2026-11-11; the artboard draws "Connected as **acme-owner** · installed on 6 repositories"). Each time `GitHubAuth` reads the status with a browser session, after the sign-in and on every `scout:github.status`, it already lists the App's installations with `GET /user/installations`; it now also asks each listed installation for its repositories, `GET https://api.github.com/user/installations/{id}/repositories?per_page=1`, and reads only `total_count` (`checkInstalled`, `ui/packages/main/src/oauth/github-auth.ts:409`). The ids come from that one listing, never from a second one, and must be positive integers before they go into the path (`installationIds`, `:585`). The request goes through the existing `requestApi`: GET, with the `Accept`, `Authorization` (the owner's session token), `User-Agent` and `X-GitHub-Api-Version` headers and the 15-second timeout. The status carries the count as `repositories` (`:517`), a number and nothing else; the renderer never sees an installation id or a repository name. Decided for this change: with several installations the count is their sum; at 0 no suffix shows, since "Install Scout on your GitHub account" already does; at 1 the line reads "installed on 1 repository"; with a pasted token there is no App session, so there is no count and no call; when the count cannot be read the line shows without the suffix and the status still answers. A count read once is kept across a later failure, as the installed flag already was: a listing or a repository read that times out, answers a 5xx or answers something that is not a count keeps the last count read (none before the first one), logs "github: could not read the App's repositories" at warn with the error code only, never the token or a URL, once per failure streak: further failures in the same streak log nothing, and the first good read ends the streak, so a later failure logs again, since the card polls the status every 3 seconds while a code waits or the App is not installed (`:433`); it leaves `error` untouched. Keeping the last good count on a failed read is the pattern the installed flag already followed, kept on purpose. A partial answer is not summed: when GitHub lists fewer installations than its `total_count`, or one installation's read fails, the last count stays. Disconnect clears it and ends a failure streak (`:557`, `:558`). An answer that is not the shape GitHub documents is treated like a read that did not answer, without a log line: a listing without a numeric `total_count`, `installations` that is not a list, an entry that is not an object or an id that is not a positive safe integer sends no repositories read, and a repository count that is not a number is not summed; the last count stays. The renderer shows the suffix after the login on the same line (`installedOn`, `ui/packages/renderer/src/app/features/github-connect.component.ts:1033`, bound at `:70`); the card's fact on the grid stays "Connected as <login> · Writes ..." with no count. Ceiling: `GET /user/installations` answers 30 installations a page and only the first page is read, so an account with more than 30 installations of the App gets no count. The read is declared: the GitHub feature's `Metadata` row (Read) already says "List the repositories the Scout GitHub App is installed on" (`src/Scout.ControlPlane/Features/FeatureCatalog.cs:48`), and this call reads only the count of that list, so the catalog did not change. Tests: `ui/packages/main/test/oauth-github.test.ts:610` (no installation: 0 and no repositories read; one with 6; two with 6 and 8: 14; one listing per status read and the exact requests), `:646` (a pasted token: no count, no call), `:656` (fewer installations listed than counted: no count), `:666` (Disconnect clears the count, and the next sign-in never shows the one read before it), `:682` (three failed reads of the repositories or of the listing in a row log one warn line with the code and no token; a good read, then a failure, logs a second), `:742` (what GitHub answers never steers the URL or the count: an id of `101/../../x`, 0, -1 or 1.5, a missing id, an entry that is not an object, installations that are not a list and a listing without `total_count` send nothing but the listing; a repository count that is a string or missing is not summed; each keeps the card connected and installed with the last count read), `:791` (Disconnect ends a failure streak, so a new sign-in's first failure logs again), the Rule I rows `:284` (the repositories read times out or answers 503: still connected with no count, the last count kept on a later failure, the warn line, no token in a log line or the status); `ui/packages/main/test/ipc-github.test.ts:463` (`scout:github.status` over a real `GitHubAuth` carries 14); `ui/packages/renderer/src/app/features/github-connect.component.spec.ts:1423` (null, 0, 1, 6 and 14 against the exact line, Install at 0); `ui/packages/renderer/src/app/features/features.prototype.spec.ts:1064` (the line as the artboard draws it).
