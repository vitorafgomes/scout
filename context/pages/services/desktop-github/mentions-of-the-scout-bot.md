## Mentions of the Scout bot

ADR 0045 v1.4: a team asks Scout for a review by mentioning the owner's bot by name in a pull request, with no label and no workflow change ([[pages/roadmap/future-improvements]], F21). GitHub's `mentions:` qualifier does not find an App's bot (a 422 "users cannot be searched", or nothing), and Scout creates its App private, so `GET /apps/<slug>` and `GET /users/<slug>` answer 404 to anyone else's token; the poll therefore searches the phrase and confirms every hit against the slug the desktop keeps. While `mentionTarget()` answers (an installed bot, wired at `ui/packages/main/src/main.ts:594`), each read adds one search after the five, `"@<slug>" in:comments,body is:pr is:open user:<login>` or `org:<org>` for the account the installation is on, with the same `updated:>=` window, paging and 20-searches-a-minute budget, resumed from its page on the next tick like the others (`ui/packages/main/src/notifications/github-activity.ts:183`). Phrase search is tokenised, so once every search answered, each candidate pull request is confirmed (`confirm`, `:246`): its body from the search result, its issue comments and review comments updated since the window, `GET /repos/<owner>/<repo>/issues/<n>/comments` and `/pulls/<n>/comments` with `since`, and its review summaries, `GET /repos/<owner>/<repo>/pulls/<n>/reviews`, which takes no `since`, so a review counts only when its `submitted_at` is in the window (`:280`); 100 a page, up to 10 pages each, with the owner's token. These reads are not searches and do not count toward the 20. A text counts when it names `@<slug>` as a whole handle in any case, not inside an address or a longer handle (`@<slug>-two`, `@<slug>s`, `me@<slug>` do not; `mentionsBot`, `:392`), and never when its author is the bot itself (`<slug>[bot]`, any case); the owner's own mention counts. Each confirmed text is one `mention` entry, `mention:issue-comment:<id>`, `mention:review-comment:<id>`, `mention:review:<id>` or `mention:body:<pull request id>` (`mentionEntry`, `:405`): "@<author> mentioned @<slug> on <owner>/<repo>#<n>: <first non-empty line, trimmed, at most 140 characters>", the pull request's title as detail, the comment's `created_at` (a review's `submitted_at`) as its time, a link to the comment or review (`…/pull/<n>#issuecomment-<id>`, `#discussion_r<id>` or `#pullrequestreview-<id>`) or to the pull request for its body, the action Review it, source `github`. A later read of the same comment updates that entry in place, so an edit is never a second entry and a read entry stays read; a mention in another comment is a new entry. A comment read that times out, answers a 5xx or is rate limited is handled as a failed search: nothing from that read is recorded, the window does not move and the next tick reads it again; a 401 stops the poll as a search's does (`:275`). Disconnect removes the mention entries with the other GitHub entries. Review it is the window's ([[pages/services/desktop-ui]], Notification center): it asks the chat to review that pull request through the existing code-review flow, and nothing is written on GitHub by the entry or the poll. Ceilings: a review summary edited after it was submitted is not read again, since the reviews list has no update time; and a resume by page number can miss one candidate at a page boundary, as the other searches can. Tests: `ui/packages/main/test/github-activity.test.ts:718` (the extra query, user and organization, none without a bot), `:738` (the owner's own "@ScoutBot review" on a lowercase slug: the entry, its link, Review it and the two comment reads with `since`), `:773` (a review comment and the body), `:812` (whole handle, table of eleven texts), `:828` (the bot's own comments), `:844` (one entry per comment, an edit, a new comment), `:878` (Disconnect), `:901` (the mention search fails), `:930` (a comment read times out or answers 502: no entry, the window kept), `:958` (a 401 on a comment read), `:970` (the budget with the extra query, comment reads not counted), `:1034` (a review summary in the window, an older one, the bot's own and a phrase without the handle), `:1057` (a review read again stays one entry, a new review is a new one).
