## Public contract

- **Entry point:** `AddGitHubPlugin(IServiceCollection, IConfiguration)` at `src/Scout.Plugin.GitHub/GitHubServiceCollectionExtensions.cs:36`; returns early when both the token and the token file are blank (`:51`). A token file takes precedence: it adds `GitHubTokenFileHandler` to the read and the owner's write pipelines (`:74`) instead of a fixed bearer header. With a bot token file a second named client, `GitHubBotWrites`, reads its bearer from that file (`:78`), and `IGitHubWriteClient` is built over both (`:96`).
- **Abstraction:** `IGitHubClient` with the read methods (`src/Scout.Plugin.GitHub/Abstractions/IGitHubClient.cs:8`): the four listings and, since 2026-11-06, `GetPullRequestAsync` (`:33`), `ListPullRequestFilesAsync` (`:68`, the files alone, every page of a hundred up to the 3,000 GitHub lists, `src/Scout.Plugin.GitHub/GitHubClient.Reads.cs:146`; a page that fails fails the whole read, so a partial list never passes for the whole one), `ListPullRequestCommentsAsync` (`:75`), `GetIssueAsync` (`:81`) and `GetFileContentAsync` (`:88`); each answers null for a 404, so the plugin says "not found" and never "check the token" for a missing number; internal implementation `GitHubClient` in two parts (`src/Scout.Plugin.GitHub/GitHubClient.cs:15`, `src/Scout.Plugin.GitHub/GitHubClient.Reads.cs:12`); records `GitHubRepository`, `GitHubPullRequest`, `GitHubIssue`, `RepositoryInfo`, `PullRequestDetails` with `ChangedFile`, `PullRequestComment`, `IssueDetails`, `RepositoryFile`; `GitHubApiException` (`src/Scout.Plugin.GitHub/GitHubApiException.cs:11`). - **Model tools:** plugin `GitHub` (`src/Scout.Plugin.GitHub/GitHubServiceCollectionExtensions.cs:113`) with `list_repositories` (`src/Scout.Plugin.GitHub/GitHubPlugin.cs:34`), `list_pull_requests` (`:56`), `list_issues` (`:86`), `get_repository` (`:116`), and the single-item reads a review needs: `get_pull_request` (`src/Scout.Plugin.GitHub/GitHubPlugin.Reads.cs:43`), `get_pull_request_file` (`:81`), `list_pull_request_comments` (`:138`), `get_issue` (`:180`), `get_file_contents` (`:229`; every answer that is not the file's text, whole or cut, is marked through `ReadOutcome.MarkNoContent` for a caller that counts the files read, `:288`: a refused name, a file not found, a directory, a symlink or submodule, a binary or oversized file and an error line, from GitHub or from a snapshot, while the answer the model receives stays the same and a read outside such a caller's scope marks nothing; [[pages/services/llm]], [[pages/services/audit]]), and the two whole-project reads an audit needs: `list_repository_files` (`src/Scout.Plugin.GitHub/GitHubPlugin.Reads.cs:307`; the recursive tree in one call, counts by top-level folder and by extension, an optional folder prefix and extension list, at most 300 paths (`:295`), and a note when GitHub cut the tree) and `search_code` (`:359`; GitHub's code search on the default branch, first 30 files with the fragments GitHub highlights, about ten searches a minute). - **Bounds:** a pull request answer carries the diffs that fit 12,000 characters (`src/Scout.Plugin.GitHub/GitHubPlugin.Reads.cs:18`); one file's diff or text is cut at 20,000 (`:21`); a description at 4,000 (`:24`); the files are read a hundred per request, page after page, up to 30 pages (`src/Scout.Plugin.GitHub/GitHubClient.Reads.cs:18`), because GitHub lists at most 3,000 files for one pull request (`src/Scout.Plugin.GitHub/GitHubPlugin.Reads.cs:28`); a 404 on the first page is a pull request not found, and a later page that fails, a 404 included, fails the whole read, so a partial list never passes for the whole one (`src/Scout.Plugin.GitHub/GitHubClient.Reads.cs:155`). The answer lists the files with their status and line counts, diff or not, up to 60,000 characters of file lines (`src/Scout.Plugin.GitHub/GitHubPlugin.Reads.cs:31`), and counts the rest in a line, "N more files not listed here; read one with get_pull_request_file by its path" (`:542`); a diff left out to fit the budget gets no section under Diffs, and one line says how many of the files had their diff left out (`:569`); a file GitHub sent no diff for (binary or too large) gets no section either, and one line counts them and names at most 100 (`:574`); a larger pull request says how many files it changes and that the review covers part of it, and a file beyond the 3,000th is reported as not listed, never as not changed (`:116`); an answer about a path the pull request does not change names at most 100 of its files and counts the rest (`:34`, `:119`). `get_pull_request_file` finds any of the 3,000 and reads the whole listing again on each call, up to 30 requests ([[pages/roadmap/followups]]). Tests: `tests/Scout.Plugin.GitHub.Tests/GitHubClientReadsTests.cs:67` (127 files over two pages, in order, page parameters), `:85`, `:99` and `:113` (a later page that answers 5xx or 404 or times out fails the read), `tests/Scout.Plugin.GitHub.Tests/GitHubPluginReadsTests.cs:167` (file 120 read), `:179` (127 listed, 67 diffs counted, no section for them), `:75` (a left-out diff has no section), `:94` (150 files with no diff: one line, 100 names, the rest counted, no section), `:203` (the file lines stop at the cap and file 2,500 is still read), `:109` (100 names and the rest counted), `:226`, `:239` (a listing that never ends stops at 30 pages and says it was cut), `:39` (a small pull request reads as before but for its one no-diff file, now named on the line instead of a section). GitHub itself omits the diff of a binary or very large file and the inline content of a file over 1 MB, and types a symlink or a submodule as such; all are said in the answer.
- **Name grammar:** every owner, repository, path, reference and search query the model passes is checked before a URL is built; a query may not carry a `repo:`, `org:` or `user:` qualifier, so a search cannot leave the repository given (`src/Scout.Plugin.GitHub/GitHubNames.cs:58`, `tests/Scout.Plugin.GitHub.Tests/GitHubPluginReadsTests.cs:447`); every owner, repository, path and reference is checked (`src/Scout.Plugin.GitHub/GitHubNames.cs:42`, `:45`, `:61`): letters, digits, dots, hyphens and underscores for names; a relative path without `.` or `..` segments; a reference of letters, digits, dots, slashes, hyphens and underscores. A refused value answers a fixed sentence and sends nothing (`tests/Scout.Plugin.GitHub.Tests/GitHubPluginReadsTests.cs:334`, `tests/Scout.Plugin.GitHub.Tests/GitHubNamesTests.cs`).
