## The repository snapshot (ADR 0039, 2026-11-06)

`snapshot_repository(owner, repo, reference)` (`src/Scout.Plugin.GitHub/GitHubActionsPlugin.cs:622`), declared on the same data-folder row (`src/Scout.Plugin.GitHub/GitHubServiceCollectionExtensions.cs:150`), resolves the reference to a commit and streams GitHub's tarball of it into `RepositorySnapshotStore` (`src/Scout.Plugin.GitHub/RepositorySnapshotStore.cs:106`; folder `Scout/github-snapshots/<owner>__<repo>/<sha>`, or `Scout:Plugins:GitHub:SnapshotsDirectory`): regular files only, the tarball's top folder stripped and any entry outside it, under `.git` or with a `.`, `..`, drive or NUL segment dropped (`:345`), a cap of 20,000 files and 200 MB (`Scout:Plugins:GitHub:SnapshotMaxBytes`) that refuses the whole snapshot and leaves nothing behind (`:149`), the other snapshots of that repository older than seven days purged (`:320`), and the same commit never downloaded twice. The answer names the files, the size and the project name `owner/repo` under which the snapshot was registered with the host's `IRepositoryProjects` (`src/Scout.Plugin.GitHub/Abstractions/RepositorySnapshot.cs:13`, `src/Scout.Plugin.GitHub/GitHubActionsPlugin.cs:655`), so `search_project` and `find_symbol` search it ([[pages/services/knowledge]]); a host without the index registers nothing (`src/Scout.Plugin.GitHub/GitHubServiceCollectionExtensions.cs:168`). The local `search_code` is a case-insensitive substring over every text file, first 30 files with the matching lines (`src/Scout.Plugin.GitHub/RepositorySnapshotStore.cs:247`). Tests: `tests/Scout.Plugin.GitHub.Tests/RepositorySnapshotStoreTests.cs`, `tests/Scout.Plugin.GitHub.Tests/GitHubActionsPluginTests.cs:217`, `:236`, `:251`, `tests/Scout.Plugin.GitHub.Tests/GitHubPluginReadsTests.cs:467`.

**The repository's stack, recorded on access** ([[pages/decisions/0047-the-docker-card]] v1.4). Each time a snapshot is taken or reused (`snapshot_repository`, `run_pull_request_tests` and the verdict through it, the one path `src/Scout.Plugin.GitHub/GitHubActionsPlugin.cs:660`; an audit reads a snapshot taken this way), the plugin asks the host's `IStackDetector` (`src/Scout.Plugin.GitHub/Abstractions/IStackDetector.cs:8`) what a test run of it would use and writes the answer as `<owner>__<repo>.stack.json` in the snapshots folder, beside the repository's folder, replacing the earlier one (`src/Scout.Plugin.GitHub/RepositorySnapshotStore.cs:189`): `repository`, `commit`, `stack`, `image`, `runs`, `declared` (each with `source` and `version`), `refusal` and `detectedAt`. The detection reads the snapshot's manifests and runs nothing; the host implements it over the sandbox's own ([[pages/services/host-console]]), so this plugin never references `Scout.Sandbox`. Without a detector nothing is written. A detection or a write that fails is a `Warning` log line, "The stack of <owner/repo> at <short sha> was not recorded; the snapshot is unchanged: <reason>", and the snapshot, the review and the test run answer as without it (`src/Scout.Plugin.GitHub/GitHubActionsPlugin.cs:702`); a cancellation still cancels. It is a descriptive write in the same data folder as the snapshot, under the same grant. Scout Desktop's Docker card reads these files ([[pages/services/desktop-ui]]). Tests: `tests/Scout.Plugin.GitHub.Tests/GitHubActionsPluginStackRecordTests.cs` (the record's fields from the detection on the snapshot's root, `:53`; rewritten on reuse, `:73`; a refusal, `:87`; a test run's snapshot and the repository and number on its request, `:102`; a write that fails, `:120`; a detection that throws, `:136`).
