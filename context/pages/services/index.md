# Services

- [[pages/services/adapter-discord|Adapter.Discord]] - Discord chat adapter: receives mentions, direct messages and voice messages over the gateway, opens a thread per conversation in server channels, and streams the reply into embeds that continue across messages.
- [[pages/services/adapter-local|Adapter.Local]] - Local chat adapter for the desktop's quick-ask window: reads one JSON request per line from the worker's stdin and streams the reply as SCOUT_LOCAL lines on stdout, as the trusted local owner.
- [[pages/services/adapter-slack|Adapter.Slack]] - Slack chat adapter over Socket Mode: filters bot traffic, streams the reply by posting then updating one message.
- [[pages/services/adapter-teams|Adapter.Teams]] - Microsoft Teams adapter: the Bot Framework turn handler, translator and streaming sink; the inbound webhook is deliberately not wired in this repository.
- [[pages/services/audit|Audit]] - Runs a whole-repository audit as a job: plans the batches from the repository snapshot, runs one model turn per batch with a closed scope, keeps the plan, the files read and the findings in SQLite under Scout's data folder, posts the findings into the conversation that started it, and resumes after a restart.
- [[pages/services/control-plane-contracts|ControlPlane.Contracts]] - The gRPC contracts of the control-plane host: four proto files for the desktop UI and one for the worker, compiled to client and server stubs.
- [[pages/services/control-plane|ControlPlane]] - Domain logic behind the desktop UI: manage the local Ollama runtime and its models, keep the catalog, state, credentials and write grants of optional features, the approval queue and the write log, answer the worker's write requests, and keep the channel operator's mandate, projects, scenes, packages, publications, proposals and experiments, media directories, the worker's readiness, and the comments on the owner's channel with the owner's replies, holds and ideas.
- [[pages/services/conversation|Conversation]] - Platform-neutral conversation core: adapter and sink abstractions, the LLM streaming router with short-term memory, and the stream pump that edits a reply as tokens arrive.
- [[pages/services/desktop-channels|Desktop channels]] - The scout:* IPC channel catalogue of the desktop app grouped by family, with the two channel families that carry their own detail: the pinned Whisper models and the update notice.
- [[pages/services/desktop-github|Desktop GitHub card]] - The GitHub card on the desktop's Features screen and the GitHub calls main makes for it: the owner's sign-in or token, the optional Scout bot, and the verdict the owner gives from a review card.
- [[pages/services/desktop-operator|Desktop operator window]] - The desktop's YouTube operator window: its Production, Assembly, Reports, Experiments and Comments pages over the control plane's operator state, the publish dialog, the scout-media previews, and the ffmpeg and fonts the desktop bundles for the worker.
- [[pages/services/desktop-quick-ask|Desktop quick ask]] - The desktop's quick-ask surface: the floating button, the quick-ask window anchored to it, the global shortcut, voice turns, live listening to the microphone and the system audio with a transcript panel and its translation, screenshots and the text read from them, the meeting mode and the meeting the owner may keep, and the conversation shared with the Chat screen.
- [[pages/services/desktop-ui|Desktop UI]] - Electron desktop app (Bun workspace, Angular renderer): onboards a Discord bot or a Slack app, keeps credentials in the OS keychain, spawns and supervises the Scout.Host.Console worker, and manages local Ollama and Whisper models from Node.
- [[pages/services/host-console|Host.Console]] - The chat host executable: composes LLM, skills, conversation, knowledge, adapters (the local quick-ask one included), the GitHub, Kubernetes and YouTube plugins and the YouTube channel operator, runs the adapters, or runs a one-shot project index.
- [[pages/services/host-control-plane|Host.ControlPlane]] - ASP.NET gRPC host that serves the control-plane domain and the channel operator's state to the desktop UI, and the write gate and the operator's worker methods to the worker, over a Unix socket or named pipe, guarded by one role-scoped token per caller.
- [[pages/services/knowledge|Knowledge]] - Indexes configured repositories, and the repository snapshots the GitHub plugin takes from chat, into a local SQLite file (a vector collection and an FTS5 full-text table) and answers search_project, find_symbol and list_projects tool calls from it, through a Project Expert chat agent.
- [[pages/services/llm|Llm]] - Selects one LLM provider by configuration, builds the shared Semantic Kernel, and exposes a streaming chat gateway and an embedding generator to the rest of Scout.
- [[pages/services/meetings|Meetings]] - Keeps the meetings the owner chose to keep, their transcript lines and their questions, in one SQLite file under Scout's data folder, renders one as Markdown, and deletes them so their text does not linger; registered only when the meetings database is configured.
- [[pages/services/operator|Operator]] - The YouTube channel operator's pipeline inside the worker: researches a topic, writes the script with its claims, turns an approved script into scenes with narration and pictures, makes an animated character's presenter by itself, in versions with a preview, and finds the mouth on it with local face models, assembles the scenes into a video with Shorts, a thumbnail and checks, saves each stage through the control plane and posts progress to the chat that asked; started from chat through a gated write function or from the desktop's queue; once the owner approves, uploads the package and sets thumbnails and experiment arms, then learns from the analytics, proposes changes and decides experiments, never adopting one; keeps the comments on the owner's channel sorted, drafted and turned into ideas, and posts a reply or holds a comment only as an action the owner approved; for a video of the owner's own recording, transcribes it on this machine into the script and assembles the recording's clips with captions and chapters.
- [[pages/services/plugin-github|Plugin.GitHub]] - GitHub plugin: fourteen read functions over a typed REST client (listing, one pull request with its diffs, comments and checks, one issue, one file, the whole tree, code search, and the two that hand a review's or an audit's findings to the reply as the block the desktop renders as cards), declared writes: into Scout's data folder and a local container under the owner's grant (the conventions profile, a repository snapshot, an audit job and a container test run), and on GitHub only as actions the owner approves one by one (a commenting review, comments, replies, issues, and the verdict, an approval or a request for changes); authenticates from a token or from the token file the desktop GitHub sign-in writes, signs the writes the owner switched to the optional Scout bot with the bot's token, and self-gates off when neither token is configured.
- [[pages/services/plugin-kubernetes|Plugin.Kubernetes]] - Read-only Kubernetes plugin: six Semantic Kernel functions over the KubernetesClient library, reading the owner's kubeconfig in place for the contexts the owner allowed; self-gates off without a path and a context.
- [[pages/services/plugin-youtube|Plugin.YouTube]] - YouTube plugin: three read-only Semantic Kernel functions over a typed Data API v3 client, which also searches videos and lists the channel's comment threads for the channel operator; with the desktop sign-in, also the write, Analytics and Reporting clients the channel operator uses for the actions the owner approved and for its numbers, none of them a model function; authenticates from the token file the desktop Google sign-in writes or from an API key, and self-gates off when neither is configured.
- [[pages/services/sandbox|Sandbox]] - Runs a repository snapshot's tests in a disposable Docker container on the owner's machine, through the docker command line, under fixed isolation rules: the work folder under Scout's data folder is the only mount, the image is pinned by digest, the tests run without the network, as an unprivileged user on a read-only filesystem with every capability dropped and capped pids, memory, CPU and time.
- [[pages/services/skills|Skills]] - Loads markdown skill files, each with the functions its turn may call, and offers them to the model: embedding-matched injection into the system prompt, a pick by the words of the message and a skill catalog in the prompt when the provider has no embeddings, and list_skills and load_skill tools.
- [[pages/services/transcription-whisper|Transcription.Whisper]] - Transcribes Ogg Opus voice messages, 16 kHz mono WAV recordings and a live 16 kHz PCM16 stream on this machine with one local Whisper ggml model through Whisper.net, decoding Opus with the managed Concentus decoder, and yields the timed segments of a WAV recording up to the caller's limit for the YouTube operator; registered only when the configured model file exists.
