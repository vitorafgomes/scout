## Public contract

- **Configuration keys read here:** `Scout:Adapters:Discord:BotToken`, `Scout:Adapters:Slack:BotToken`, `Scout:Adapters:Teams:AppId`, `Scout:Adapters:Local:Enabled` (startup marker only, `src/Scout.Host.Console/Program.cs:47`, `:59`); everything else is read by the wired projects. `Scout:WorkerGate:SocketPath` and `Scout:WorkerGate:Token`, which the desktop sets as `SCOUT__WORKERGATE__SOCKETPATH` and `SCOUT__WORKERGATE__TOKEN` (empty when there is no control plane) and which are read through configuration binding only; the token goes on each call as `authorization: Bearer <token>` and is never logged. Right after composition reads the two values, it removes from the process environment every variable that configuration reads as the token, in any casing or ':' spelling and with or without the `DOTNET_` or `ASPNETCORE_` prefix, whether or not the gate is opened (`src/Scout.Host.Console/HostComposition.cs:98`, `:158`), so a process the worker starts, such as a kubeconfig exec credential plugin, does not inherit it; `GrpcWriteGate` keeps the value it was given. On Unix the removal changes .NET's own environment block, which `Process.Start` hands to children; native code that reads the C `environ` still sees the original. The `index` command never composes the write gate and so never removes the token. `Scout:Operator:FfmpegPath`, `Scout:Operator:FontPath` and `Scout:Operator:CategoryId` (the YouTube category of an upload, `22` People & Blogs when unset), which the desktop sets as `SCOUT__OPERATOR__FFMPEGPATH`, `SCOUT__OPERATOR__FONTPATH` and `SCOUT__OPERATOR__CATEGORYID` and which bind only when the operator is composed (`src/Scout.Host.Console/HostComposition.cs:145`); an empty program path means `ffmpeg` on the system path, then in `/opt/homebrew/bin` and `/usr/local/bin`, and an empty or missing font makes assembly unavailable ([[pages/services/operator]]). They carry paths, never credentials, and `appsettings.json` does not name them. `Scout:Tools:TesseractPath`, `Scout:Tools:TessdataPath` and `Scout:Tools:Locale`, which the desktop sets as `SCOUT__TOOLS__TESSERACTPATH`, `SCOUT__TOOLS__TESSDATAPATH` and `SCOUT__TOOLS__LOCALE`, are read by `AddScreenText` on every run (`src/Scout.Host.Console/HostComposition.cs:59`), whether or not YouTube is configured; without both paths existing no reader is registered and a `read` gets the not-installed sentence ([[pages/services/adapter-local]]); the locale is `en` when unset and nothing is read from the operating system. They are paths and a locale, never credentials, and `appsettings.json` does not name them. `Scout:Meetings:DbPath`, which the desktop sets as `SCOUT__MEETINGS__DBPATH` to `<userData>/meetings.db` on every worker start (`ui/packages/main/src/worker/build-env.ts:119`), is read by `AddMeetings` on every run (`src/Scout.Host.Console/HostComposition.cs:60`); without it, or when its folder does not exist, no store is registered and every meeting request gets the not-configured sentence ([[pages/services/adapter-local]]). It is a path, never a credential, and `appsettings.json` does not name it. Environment variable `SCOUT__PARENT_WATCHDOG` enables the watchdog when set to `1` (`src/Scout.Host.Console/ParentWatchdogRegistration.cs:13`). Configuration root is the binary directory (`src/Scout.Host.Console/Program.cs:17`, `:32`).

- **External boundaries:** stdout carries only the readiness and pairing markers, the local adapter's `SCOUT_LOCAL` reply lines, the usage sink's `SCOUT_LOCAL` usage and usage-limit lines with a null id, and the voice notice's `SCOUT_LOCAL` `voice-no-model` line with a null id and the chat platform only (`src/Scout.Host.Console/StdoutVoiceNotice.cs:11`, [[pages/services/conversation]]); stdin carries the desktop's quick-ask requests to the local adapter; all logs go to stderr (`src/Scout.Host.Console/Program.cs:38`). Network boundaries belong to the wired projects, and so do the `ffmpeg` processes the operator starts, with standard input closed so they never read the local adapter's input ([[pages/services/operator]]), except one: `GrpcWriteGate` calls the control plane's `WorkerGate` service (`RequestWrite`, `RecordWrite`, [[pages/services/control-plane-contracts]]) over the Unix socket the desktop passes, through a `SocketsHttpHandler` whose `ConnectCallback` opens a `UnixDomainSocketEndPoint`, with a 10 s deadline per call (`src/Scout.Host.Console/GrpcWriteGate.cs:58`) and messages up to 16 MB both ways (`:20`, `:53`), because a full comments view, 1000 comments of up to 2000 characters, passes the 4 MB gRPC default once the text is not ASCII; the control plane takes and sends the same size ([[pages/services/host-control-plane]]). Only `allowed` and `queued` are read as such; an empty, unknown or differently cased decision is a refusal (`src/Scout.Host.Console/GrpcWriteGate.cs:102`). A call that fails or misses the deadline throws, and the write gate filter then refuses the write. `GrpcOperatorControlPlane` calls `GetOperatorMandate`, `SaveOperatorProject`, `NextQueuedProject`, `GetOperatorProject`, `ListOperatorProjects`, `GetOperatorMediaDirectory` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:325`), `ReportReadiness` (`:334`) and `GetVoiceSamplesDirectory` (`:729`), and, for the owner's edits from the chat, `ChatEditSceneText`, `ChatRegenerateNarration`, `ChatRegenerateScene`, `ChatSetSceneLocked`, `ChatReorderScenes`, `ChatProduceProject`, `ChatDelegateProject` and, since phase 8c-B, `ChatRequestPresenter` (`:737` to `:770`), each reading the changed project back, the same way and maps the messages to the operator's records field by field, a project's scenes (`:222`), its presenter versions with an absent preview or mouth box absent on the wire (`:189`, `:199`) and its video package included (`:676`, `:713`), setting an optional field (a scene's `error`, `audio_file`, `visual_file`; a package's `video_file`, `thumbnail_file`, `approved_at`, `error`) only when it has a value and sending the owner's `rights_confirmed`, `approved_at` and `metadata_edited` back as read; it never sets the readiness `reported_at`, which the control plane stamps; a refusal the control plane words (`PERMISSION_DENIED`, `FAILED_PRECONDITION`, `INVALID_ARGUMENT`, `NOT_FOUND`) keeps its words, and any other failure, a missing socket included, becomes "Scout could not reach its control plane." (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:94`), while a call whose token was cancelled ends as a cancellation instead (`:90`, below), so no transport text reaches the chat or the desktop; that unreachable failure is a `ControlPlaneUnavailableException` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:100`), so the executor tells it from a worded refusal. `NextApprovedAction` (`:356`) maps the claimed `PendingAction` to an `OperatorAction`, with the response's `origin_reference` when the control plane sends one, `RecordWrite` (`:366`) records it with its id, scope, target and outcome, a refusal containing "already recorded in the write log" being a success and one containing "revoked" a `WriteRevokedException` (`:19`), and the publication travels field by field with its snapshots, proposals and experiment (`:515`, `:632`), each optional value (video id, publish time, upload time, error, impressions, click-through rate, a thumbnail file, an arm's start and end, a winner, a result) set only when it has one. `GetComments` and `SaveComments` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:403`, `:411`) carry the `CommentsView` field by field (`:419`, `:490`): every time, `published_at`, `decided_at`, `fetched_at`, `synced_at` and `sync_requested_at`, travels as the string the control plane sent and goes back byte for byte, because the control plane compares a comment the worker sends with the stored one and a reformatted time reads as tampering; a new comment's empty `fetched_at` goes as it is, for the control plane to stamp; `approved_text`, `reply_id`, `error`, `decided_at`, an idea's `project_id` and the sync's three values are set only when they have one. A refusal keeps its words and an unreachable control plane is a `ControlPlaneUnavailableException`, as for the other calls.
