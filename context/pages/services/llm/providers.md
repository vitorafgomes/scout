## Contract

- **Provider seam:** `ILlmProviderFactory` (`src/Scout.Llm/Abstractions/ILlmProviderFactory.cs:18`) with `AddToKernel`, `CreateEmbeddingGenerator` and `CreateChatCompletionService(model)`, a standalone chat service bound to another model of the same provider, null by default (see the live translation seam). Eleven factories live under `src/Scout.Llm/Providers/`: Anthropic (see Provider `Anthropic` below), Ollama (see Provider `Ollama` below), OpenAI, OpenRouter, AzureOpenAI, Mistral, HuggingFace, AzureAIInference, Gemini, None, ChatGptPlan (the Responses API with the owner's ChatGPT plan token read from a file, `src/Scout.Llm/Providers/ChatGptPlan/ChatGptPlanLlmProviderFactory.cs:21`, [[pages/decisions/0018-chatgpt-plan-sign-in]]). It invokes the model's function calls through Semantic Kernel's `UseKernelFunctionInvocation` (`src/Scout.Llm/Providers/ChatGptPlan/ChatGptPlanLlmProviderFactory.cs:109`), so every call passes the kernel's function filters and the write gate. It asks for encrypted reasoning so tool round trips work with `store: false` (`src/Scout.Llm/Providers/ChatGptPlan/ChatGptPlanChatClient.cs:56`), retries a transient error up to twice but never a 429 (`src/Scout.Llm/Providers/ChatGptPlan/ChatGptPlanLlmProviderFactory.cs:131`), keeps using an unexpired cached token when the file is briefly locked during replacement (`src/Scout.Llm/Providers/ChatGptPlan/ChatGptPlanTokenPolicy.cs:78`), and has no embedding generator (it fails at once with `NotSupportedException`, and skills and knowledge turn their embedding features off quietly), and turns a missing or expired sign-in into `LlmSignInRequiredException` (`src/Scout.Llm/Abstractions/LlmSignInRequiredException.cs:9`); each has an `Add<Name>LlmProvider` extension.
- **Provider `OpenRouter`**: chat on `https://openrouter.ai/api/v1` through the OpenAI connector (`src/Scout.Llm/Providers/OpenRouter/OpenRouterLlmProviderFactory.cs:26`). Embeddings come from the `Scout:Llm:OpenRouter:Embeddings` block (model, endpoint and key of a separate OpenAI-compatible host), all three set or all three empty; empty, as the desktop sends it since OpenRouter became connectable on its card ([[pages/decisions/0046-ai-source-usage-on-the-cards]], Amended 2026-11-07), the provider has no embeddings and every embedding call fails at once with `NotSupportedException` (`:85`, `:201`), as with Anthropic and the ChatGPT plan; a partly filled block still fails at start. `CreateChatCompletionService(model)` builds the same OpenRouter chat service on another model (`:160`), so a translation model chosen in Models → Translation reaches the live translator while the chat keeps the chat model (`tests/Scout.Llm.Tests/TranslationModelTests.cs`, OpenRouter row). Verified by `tests/Scout.Llm.Tests/Providers/OpenRouter/OpenRouterLlmProviderFactoryValidationTests.cs:132` and the host smoke row `tests/Scout.Host.Console.Tests/HostCompositionSmokeTests.cs:271`.
- **Provider `Mistral`**: chat and embeddings through the OpenAI connector over an `OpenAIClient` whose endpoint is `https://api.mistral.ai/v1` (`src/Scout.Llm/Providers/Mistral/MistralLlmProviderFactory.cs:22`) or the configured `Scout:Llm:Mistral:Endpoint` as written (`:92`), with the one API key as `Authorization: Bearer`; the client appends `/chat/completions` or `/embeddings`, so a configured endpoint hits the same URL the Mistral preview connector hit before 2026-11-12, with or without a trailing slash and with or without `/v1` (`tests/Scout.Llm.Tests/Providers/Mistral/MistralProviderWireTests.cs:31`, pinned on the old connector first). A turn sends what the OpenAI connector sends OpenAI: `max_completion_tokens`, `temperature`, `stream_options` asking for usage, and the declared functions as `tools` with `tool_choice` `auto` (`tests/Scout.Llm.Tests/ProviderRequestSettingsTests.cs`, the Mistral rows), and no longer the old connector's `safe_prompt`, `temperature` 0.7 and `top_p` 1. An embedding request is `input`, `model` and `encoding_format` `base64`, with no `dimensions` because `OpenAIEmbeddingDimensions.For` gives none for a model outside `text-embedding-3`, and a float-array answer comes back as the vector (`tests/Scout.Llm.Tests/Providers/Mistral/MistralProviderWireTests.cs:52`). The client's default retry policy, which the OpenAI and OpenRouter factories also keep, retries a 429, a 5xx or a reset three times before the gateway sees it: a 429 is `LlmRateLimitException` after four requests, a 401 `LlmKeyRejectedException` after one without the key (`:79`, `:66`); a reset reaches the gateway as the client's `AggregateException` after four attempts and is not translated, a generic failure to the pump as the old connector's `HttpOperationException` was; the backoff between attempts in production was not measured (in the tests the four requests took no measurable time). It has no translation chat service, no media and no vision. Not verified against the live Mistral API (Hot spots).
- **Provider `HuggingFace`**: chat through the OpenAI connector over an `OpenAIClient` whose endpoint is the `v1` path of `https://api-inference.huggingface.co` (`src/Scout.Llm/Providers/HuggingFace/HuggingFaceLlmProviderFactory.cs:22`) or of the configured `Scout:Llm:HuggingFace:Endpoint`, joined with a `/` only when the endpoint's path does not already end in one (`:127`), which is the rule the HuggingFace connector used to build its chat URL; the client appends `/chat/completions`, so every form pinned on the old connector first posts to the same URL with the one API key as `Authorization: Bearer`: no endpoint and `https://hf.example.com` go to `<host>/v1/chat/completions`, and a configured `https://hf.example.com/v1`, with or without a trailing slash, goes to `https://hf.example.com/v1/v1/chat/completions`, kept as it was (`tests/Scout.Llm.Tests/Providers/HuggingFace/HuggingFaceProviderWireTests.cs:50`). A turn sends what the OpenAI connector sends OpenAI: `max_completion_tokens`, `temperature`, `stream_options` asking for usage, and the declared functions as `tools` with `tool_choice` `auto` (`tests/Scout.Llm.Tests/ProviderRequestSettingsTests.cs`, the HuggingFace rows), and no longer the old connector's `temperature` 1 on every request or `stream` false on a translation. Embeddings stay on the HuggingFace connector (`src/Scout.Llm/Providers/HuggingFace/HuggingFaceLlmProviderFactory.cs:143`): a POST of `{"inputs":[...]}` to `<endpoint>/pipeline/feature-extraction/<model>` whose answer is a bare array of vectors, which is not the OpenAI embeddings shape, so `Microsoft.SemanticKernel.Connectors.HuggingFace` stays referenced; the pins of their URL, body and vector were green before and after (`tests/Scout.Llm.Tests/Providers/HuggingFace/HuggingFaceProviderWireTests.cs:67`). The client's default retry policy, as on OpenAI, OpenRouter and Mistral, retries a 429, a 5xx or a reset three times before the gateway sees it: a 429 is `LlmRateLimitException` after four requests (`:91`), a reset the client's `AggregateException` after four attempts, untranslated (`:103`), where the old connector made one request each; a 401 is `LlmKeyRejectedException` after one request without the key, as before (`:78`); a 500 on an embedding request is still the HuggingFace connector's `HttpOperationException` with the status after one request (`:116`). It has no translation chat service, no media and no vision. Not verified against the live Hugging Face API (Hot spots).
- **Provider `None`:** `src/Scout.Llm/Providers/None/NoneLlmProviderFactory.cs:15`, selected at `src/Scout.Llm/LlmServiceCollectionExtensions.cs:108`. The desktop app writes it when no AI provider is connected ([[pages/decisions/0017-provider-connect-disconnect]]). It needs no settings; every chat request streams the one assistant message "No AI provider is connected. Connect one on the AI Sources screen in Scout." and no model or network is called; the embedding generator throws `InvalidOperationException("No AI provider is connected.")`, so skill and project indexing fail the way they do when a provider is unreachable. A blank or absent provider still means Ollama.
