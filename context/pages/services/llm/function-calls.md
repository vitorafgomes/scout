## How it works

**Functions per turn** ([[pages/decisions/0054-functions-scoped-per-skill-and-job]], 2026-11-08). The shared kernel holds every plugin, but no turn is offered all of them: `KernelScope.Only(shared, qualified)` (`src/Scout.Llm/KernelScope.cs:19`) clones it, keeping its services and invocation filters (the write gate and the activity filter run on the copy), clears the plugins (`:25`) and adds back only the declared functions that exist, so a name the kernel does not hold is skipped. The direct path passes that copy to the chat service (`src/Scout.Llm/ChatGateway.cs:199`), the agent path through `AgentInvokeOptions.Kernel` with execution settings of its own (`:265`, `:273`), and the agent's own kernel holds nothing ([[pages/services/knowledge]]). `ProviderSettings.BuildSettings` sends `FunctionChoiceBehavior.Auto()` only when the copy holds a function (`src/Scout.Llm/Providers/ProviderSettings.cs:19`, `:23`): with none, the OpenAI connector would otherwise send a placeholder tool, so an empty or missing set sends no `tools` at all. The model can still name a function the turn was not offered; it is not on the copy, Semantic Kernel answers it with an error and it never runs, and after the stream the gateway logs one Warning per such name, `The model called <name>, which this turn (<skills or "no skill">) does not declare; it was not offered and did not run.`, never the arguments (`src/Scout.Llm/ChatGateway.cs:103`); `KernelScope.IsDeclared` accepts `Plugin-function`, `Plugin_function`, `Plugin.function` and the bare name (`src/Scout.Llm/KernelScope.cs:48`). `tests/Scout.Llm.Tests/ChatGatewayFunctionScopeTests.cs:80` (the tools in the request body equal the set, both paths), `:98` (no tools for an empty or missing set), `:115` (an undeclared call never runs, the gate is asked nothing, one Warning without the argument), `:140` (a declared call runs); on the Gemini, ChatGPT plan and Anthropic paths an undeclared sibling of the declared function is absent from the request's tools (`tests/Scout.Llm.Tests/Guard/WriteGateProviderPathTests.cs:29`, `:62`, `tests/Scout.Llm.Tests/Providers/Anthropic/AnthropicProviderTests.cs:112`); `tests/Scout.Llm.Tests/KernelScopeTests.cs:28`, `:46`, `:68`.

The kernel adds every `KernelPlugin` from DI (`src/Scout.Llm/LlmServiceCollectionExtensions.cs:131`). Every path caps the function calls in a turn: on the `IChatClient` path through `UseKernelFunctionInvocation` (the ChatGPT plan, Anthropic and Ollama), Semantic Kernel 1.82's `KernelFunctionInvokingChatClient` sets `MaximumIterationsPerRequest` to 128, not Microsoft.Extensions.AI's documented 40 (read by reflection on 2026-11-11). Over the recording handler the Anthropic loop made 128 calls offering tools, then one last call without them (`tests/Scout.Llm.Tests/Providers/Anthropic/AnthropicEmptyAnswerTests.cs`, the cap row). Semantic Kernel's auto invocation has its own cap on the other providers, not re-read here; a task that needs more reads than a turn allows, such as a whole-repository audit, is split into turns by Scout ([[pages/roadmap/gap-plan]] G4), never by asking the model to go on. The gateway streams through the Project Expert agent when one is registered (`src/Scout.Llm/ChatGateway.cs:81`) and through plain chat otherwise (`:90`). Both stream loops hand a provider error to one helper, `ProviderFailures.TranslateProviderFailure` (`:218`, `:297`, helper at `src/Scout.Llm/Providers/ProviderFailures.cs:43`, beside the connectors because it reads their exception types), that turns HTTP 429, 402, 401 and a missing model's 404 into domain exceptions, whether the connector raised the OpenAI SDK's `ClientResultException` (the streaming OpenAI connector, which OpenRouter, Mistral and Hugging Face chat also use) or Semantic Kernel's `HttpOperationException` (the other connectors, and the Anthropic and Ollama chat clients, which turn their client's failures into it). A 429 whose OpenAI-shaped body carries a billing code (`credit_balance_exhausted`, `organization_spend_limit_exceeded`, `project_spend_limit_exceeded`, `organization_usage_limit_exceeded`) or the type `insufficient_quota` becomes `LlmQuotaExceededException` (`:54`); any other 429, including an unreadable body, becomes `LlmRateLimitException`. A 402 is always a billing refusal, `LlmQuotaExceededException` with the body's billing code or `payment_required` (`:57`), and a 401 is `LlmKeyRejectedException` (`:60`), which keeps no inner exception so the provider's text never travels. A 404 whose OpenAI-shaped body carries the error type `not_found_error` or the code `model_not_found` is `LlmModelNotFoundException` (`src/Scout.Llm/Providers/ProviderFailures.cs:58`, read at `:76`) naming the model the call asked for: both stream loops pass the chat service's own model id, `GetModelId()`, read only once a call has failed (`src/Scout.Llm/ChatGateway.cs:218`, `:297`), which every connector reports except Azure OpenAI's, whose deployment-based service names none, so its sentence says "it is set to use"; Ollama's native chat endpoint answers a model it does not have, installed or still downloading, with `404 {"error":"model '<id>' not found"}`, which the Ollama client raises as an `HttpRequestException` with the status and without the body, and `OllamaChatClient` gives it the code `model_not_found` (Provider `Ollama` above; its OpenAI-compatible `/v1`, used before 2026-11-12, answered `{"error":{...,"type":"not_found_error"}}`), and OpenAI's shape is `invalid_request_error` with the code `model_not_found`. `LlmFailures.Translate(exception, model)` (`src/Scout.Llm/Abstractions/LlmFailures.cs:18`), the audit's door to the same rule, inherits all of them. Any other status (500), and a 404 of any other shape (a plain-text `404 page not found` from a wrong endpoint, another error type), still propagates as the raw SDK exception. The domain exceptions keep the SDK exception as `InnerException`, typed only as `Exception`. The embedding generator is built from the factory, not from the kernel, to avoid a construction cycle (`src/Scout.Llm/LlmServiceCollectionExtensions.cs:161`). The project index stores vectors of 768 values ([[pages/services/knowledge]]); OpenAI, OpenRouter, Azure OpenAI and Mistral pass the connector's `dimensions` option, 768, when the embedding model id (after any `openai/` prefix), or for Azure the deployment name, starts with `text-embedding-3` (`OpenAIEmbeddingDimensions.For`, `src/Scout.Llm/Providers/OpenAI/OpenAIEmbeddingDimensions.cs:12`), the one family that accepts it; any other model is sent no `dimensions`, because OpenAI's API reference supports the option only "in `text-embedding-3` and later models" (the openai-openapi spec, read 2026-11-07), and a model that answers another size is handled by the indexer, which then indexes the text without vectors. An Azure deployment with another name is asked for its own size even when the model behind it is a `text-embedding-3` model. When a stream ends with no text, the gateway logs one Warning after the completion line naming the number of updates, the last finish reason or status the provider reported (the connector's `FinishReason` metadata, or on the ChatGptPlan path the Responses API's completed status, `incomplete` reason, `failed` or `error` code, or a refusal, which Semantic Kernel otherwise drops with no text and no exception) and the names of the functions the model called, never the prompt, the reply, an argument or a provider message (`src/Scout.Llm/ChatGateway.cs:113`, the finish and the failure code read by `ProviderStreamEnd` at `src/Scout.Llm/Providers/ProviderStreamEnd.cs:14` and `:25`, a failed or error update without a code named `unknown`, `tests/Scout.Llm.Tests/ChatGatewayEmptyReplyLogTests.cs:31`, `:46`, `:101`, and a function call before an incomplete end on the ChatGptPlan path at `:117`). When that stream's last terminal status was `failed` or an `error` event, the gateway then throws instead of ending with no answer, using the code only (`src/Scout.Llm/ChatGateway.cs:117`): a code containing `usage_limit` or `quota` is `LlmQuotaExceededException` with that code, `rate_limit` is `LlmRateLimitException`, and any other code is an error whose message is "The AI provider ended the answer with an error (<code>).", which the pump reports through its failure path (`tests/Scout.Llm.Tests/ChatGatewayEmptyReplyLogTests.cs:135`, `:149`, `:162`, `:177`, and through the pump `:193`, `:205`); an `incomplete` status or a refusal with no text still ends with the empty-stream placeholder (`:216`). With provider `Anthropic`, a stream that ends with no text and no failure throws `LlmNoAnswerException` (`src/Scout.Llm/Abstractions/LlmNoAnswerException.cs`), whose message is a sentence naming the Claude API's stop reason. The pump completes the reply with that sentence, as it does with a rejected key ([[pages/services/conversation]]), so the chat shows it instead of an empty reply or a generic failure:
  - `max_tokens`: "The answer was cut off by the model's output limit before any text arrived."
  - `model_context_window_exceeded`: "The answer stopped before any text arrived because the conversation and what Scout read for it filled the model's context window."
  - `refusal`: "The model declined to answer this request."
  - `pause_turn`: "The model paused its turn before any text arrived."
  - `end_turn` or `stop_sequence`: "The model ended its turn without writing an answer."
  - `tool_use`: "The model was still asking to call functions when the answer ended, so no text arrived."

  Two cases are exceptions, and neither throws:
  - The turn holds an attached block (`TurnAttachments.Pending`), such as the findings card a review presented before ending silently. That block is the answer.
  - The provider is not Anthropic. Its finish words can mean something else; the ChatGPT plan's refusal is one.

  Measured on this path over the recording handler:
  - A tool call cut by the limit is answered with an error result, never run with its truncated input, and the model is asked again.
  - The function loop makes 128 calls with tools, then one last call without them.
  - A 1,000,000-character tool result reaches the next request whole; the GitHub plugin's own budgets bound what it returns.
  - An HTTP 400 for a prompt over the context window is thrown once, with no retry, as `HttpOperationException` with the status, the error type and the API's sentence, the key redacted.

  Tests: `tests/Scout.Llm.Tests/Providers/Anthropic/AnthropicEmptyAnswerTests.cs`.
