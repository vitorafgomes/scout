## Contract

- **Usage seam:** `ILlmUsageSink` with `Answered(LlmUsage)` and `UsageLimitReached(source)` (`src/Scout.Llm/Abstractions/ILlmUsageSink.cs:7`), and `LlmUsage(Source, Model, PromptTokens, CompletionTokens, TotalTokens, Cost)` (`src/Scout.Llm/Abstractions/ILlmUsageSink.cs:22`), the counts null when the provider reported none and the cost in US dollars only where the provider reports one. Optional: `AddScoutLlm` hands the gateway the registered sink, if any (`src/Scout.Llm/LlmServiceCollectionExtensions.cs:175`); the console host registers one that prints the desktop's lines ([[pages/services/host-console]]). See Usage count below.

## How it works

**Usage count** ([[pages/decisions/0046-ai-source-usage-on-the-cards]]). The gateway counts what each answer used where every stream update passes, `StreamTrace.Observe` (`src/Scout.Llm/ChatGateway.cs:374`), which hands the update's metadata to `ProviderUsage.Count` (`:378`, `src/Scout.Llm/Providers/ProviderUsage.cs:13`) and keeps the sums in a `UsageTally` that holds only numbers (`src/Scout.Llm/UsageTally.cs:7`), and reports it once per answer that completes, after the empty-stream check (`src/Scout.Llm/ChatGateway.cs:126`), as one `LlmUsage` whose source is the configured provider name (a blank provider is `Ollama`), whose model is the last one the provider named on the stream, and whose tokens are summed over every model call of the answer, a function round trip being several calls. The gateway names no connector's usage type: one static reader per shape under `src/Scout.Llm/Providers/` reads it, chosen by the shape of the metadata and never by the provider's name, Gemini's metadata first, then the value under the `Usage` key; `tests/Scout.ArchTests/ArchitectureTests.cs:169` fails when a file of `src/Scout.Llm` outside `Providers/` names a connector type: one of the four usage types, the OpenAI SDK's `ClientResultException`, a Responses API streaming update, a connector's execution settings type, `System.ClientModel`, a `Microsoft.SemanticKernel.Connectors.` namespace, or the `OpenAI.` or `Azure.` SDK namespaces. What stays outside `Providers/` is Semantic Kernel's own types (`PromptExecutionSettings` in the media seam and the read-only guard, `ITextGenerationService` removed by the guard's registration) and Microsoft.Extensions.AI's abstractions (`ILlmProviderFactory`, `LlmServiceCollectionExtensions`). A usage without a total counts the prompt plus the completion tokens when either is known, and a call without a cost leaves the cost as it is (`src/Scout.Llm/UsageTally.cs:23`). What each connector hands over, read from the real connectors over a recording handler, one source per shape: the OpenAI connector (OpenAI, Azure OpenAI, OpenRouter, Mistral and Hugging Face) puts an `OpenAI.Chat.ChatTokenUsage` under the `Usage` metadata key of the last chunk of each call, the OpenAI .NET SDK asking for it with `stream_options.include_usage`, read by `OpenAIChatUsageReader` (`src/Scout.Llm/Providers/OpenAI/OpenAIChatUsageReader.cs:14`); OpenRouter's `cost` rides that object as an additional property and is read through `ModelReaderWriter` (`:24`); the ChatGPT plan's Responses `response.completed` event and the Azure AI Inference connector put a Microsoft.Extensions.AI `UsageContent` under the same key, read by `UsageContentReader` (`src/Scout.Llm/Providers/UsageContentReader.cs:12`); Mistral, which puts its usage on the chunk that carries the finish reason, is read there by the same OpenAI reader; Gemini repeats a running `usageMetadata` on every chunk, read by `GeminiUsageReader` (`src/Scout.Llm/Providers/Gemini/GeminiUsageReader.cs:15`), so the last one of each call counts, a call ending at the chunk that carries a finish reason (`:23`), and a running count no finish reason ended counts when the answer is reported (`src/Scout.Llm/ChatGateway.cs:392`); Hugging Face chat, on the OpenAI connector since 2026-11-12, asks for usage with `stream_options` and is counted from the usage chunk by the same OpenAI reader (`tests/Scout.Llm.Tests/ChatGatewayUsageTests.cs:150`), where the HuggingFace connector streamed none and threw on a usage-only chunk; whether a Hugging Face server sends that chunk is not verified; the Anthropic client's `IChatClient` turns the `usage` of `message_start` and `message_delta` into one Microsoft.Extensions.AI `UsageContent` per call under the same key, input and output tokens with no running double count (`tests/Scout.Llm.Tests/Providers/Anthropic/AnthropicProviderTests.cs:135`, `:146`), so the gateway needed no reader of its own for it; the Ollama client's chat client puts a `UsageContent` with the done line's `prompt_eval_count` and `eval_count` on the last update of each call, read by the same reader, and reports zero tokens when the done line carries neither count, so such an answer is reported with 0, where the `/v1` path reported null (`tests/Scout.Llm.Tests/ChatGatewayUsageTests.cs`, the two Ollama tests). An answer without usage is still reported, with null counts, so the desktop can say the model does not report it. When the gateway throws the quota exception for `subscription_sharing_usage_limit_exceeded`, from a 429 or from a stream the Responses API ended failed, it reports `UsageLimitReached` with the source before throwing (`src/Scout.Llm/ChatGateway.cs:334`); any other quota code is not a plan limit. A sink that throws is logged as one Warning and never costs the owner the answer (`:353`). The live translator calls the provider outside the gateway, so a translation is not counted. Tests: `tests/Scout.Llm.Tests/ChatGatewayUsageTests.cs:31` (each connector shape, the two function round trips, the missing usage, the plan limit over a 429 and over a failed stream followed by an answer, another quota code, the agent path, a failing sink, and `AddScoutLlm` passing the sink; pinned before the readers moved: a Gemini stream that ends with no finish reason (`:339`), a usage without a total (`:360`), costs summed over the calls of an answer (`:373`), and metadata with no usage of a known shape (`:388`)).
