## How the rules are kept

- [[pages/invariants/no-executive-writes]]: `PullModel` and `DeleteModel` (`src/Scout.Host.ControlPlane/Services/ModelsGrpcService.cs:22,59`) and the start and stop calls are reachable by any holder of the desktop token, never by the worker's (`tests/Scout.ControlPlane.Tests/Integration/WorkerGateGrpcTests.cs:50`, `tests/Scout.ControlPlane.Tests/Security/TokenAuthInterceptorTests.cs:62`). Since 2026-11-11 they are ruled a reviewed local write on the owner's click, outside the feature grant ([[pages/decisions/0032-per-feature-write-permissions]], amendment of 2026-11-11), and the domain logs a download's start and end and a delete's outcome to this host's log, not the write log ([[pages/services/control-plane]]). The desktop starts this host with its stdout discarded (`ui/packages/main/src/control-plane/launcher.ts:149`), so those lines are kept nowhere under the desktop; the change that makes the desktop call `Models` keeps that output first.
- [[pages/decisions/0032-per-feature-write-permissions]]: granting a write and approving an action happen only through this host with the desktop token (`tests/Scout.ControlPlane.Tests/Integration/FeatureWritesGrpcTests.cs:344`). The worker can request but never approve: its token gets `PERMISSION_DENIED` on `ApproveAction`, `RejectAction`, `ApproveSet`, `RejectSet`, `GetActionGroup`, `GetActionText`, `ApproveCardIssues` (`tests/Scout.ControlPlane.Tests/Integration/ActionSetGrpcTests.cs:84`), `SetWriteGrant`, `Enable`, `Disable`, `DeleteCredentials`, `ListFeatures`, `StartProvider` and `DeleteModel`, and the action stays pending and the feature ungranted (`tests/Scout.ControlPlane.Tests/Integration/WorkerGateGrpcTests.cs:29`); the desktop token gets `PERMISSION_DENIED` on `RequestWrite` and `RecordWrite` (`:66`); no or a wrong token stays `UNAUTHENTICATED` on the gate (`:147`); a host started without a worker token keeps the gate closed and still serves the desktop (`:163`). The role table is pinned per method at `tests/Scout.ControlPlane.Tests/Security/TokenAuthInterceptorTests.cs:72`.
- [[pages/decisions/0033-channel-operator-architecture]]: the `Operator` service belongs to the desktop alone and the whole `WorkerGate` service, every method of it, to the worker alone, by service prefix (`src/Scout.Host.ControlPlane/Security/TokenAuthInterceptor.cs:31`). The role table checks it on the `Operator` methods and on seven operator methods of `WorkerGate`, the mandate, the save, the take, the project read and list, the media directory and the readiness (`tests/Scout.ControlPlane.Tests/Security/TokenAuthInterceptorTests.cs:191`, `:209`), the four package methods and the four publication methods included (`:223`, `:237`), and on `NextApprovedAction` for the worker (`:208`); the ten `Chat` rpcs and `GetVoiceSamplesDirectory` are checked over the socket, below. Over the socket the worker token gets `PERMISSION_DENIED` on the thirty-two project methods of `Operator` the two tests list, twenty-four and eight, `DelegateProject`, `DeleteProject`, `GetVoiceSamplesDirectory`, `EditSceneText`, `RegenerateNarration` and `RemovePresenterVersion` among them, and the mandate and projects stay as they were (`tests/Scout.ControlPlane.Tests/Integration/OperatorGrpcTests.cs:47`, `:746`), and on its five comment methods (`:1207`), and the desktop token on `GetOperatorMandate`, `SaveOperatorProject`, `NextQueuedProject`, `GetOperatorMediaDirectory`, `ReportReadiness`, `NextApprovedAction`, `GetVoiceSamplesDirectory` and the ten `Chat` rpcs, which then stores nothing (`:94`). Over the socket the worker's chat edits change the scene text, the narration, a scene, a lock, the order, and queue production or delegate keeping the stored voice when none is sent; a chat edit of a locked scene is `INVALID_ARGUMENT`, one after the owner revoked the grant `PERMISSION_DENIED` with the gate's sentence, and each accepted edit is one `ListWrites` entry of `youtube` on "Scout's data folder" with its `via chat` outcome, no approver and no queued action (`:1345`). `WorkerGate` offers exactly its twenty-three methods, the ten `Chat` rpcs last, and none that attaches, approves, publishes, confirms, deletes, grants, decides, enables or rejects (`:1393`). `RemovePresenterVersion` round-trips over the socket for the desktop token alone: the worker token is `PERMISSION_DENIED`, the current version `INVALID_ARGUMENT` with the control plane's sentence, and the removed version leaves the project and its picture and preview leave the media directory (`:1569`). `UsePresenterVersion` and `RemovePresenterVersion` pass the request's `version_id` to the control plane (`src/Scout.Host.ControlPlane/Services/OperatorGrpcService.cs:108`, `:112`), and `OperatorMapping.ToWire` sets each version's `id` from `PresenterVersion.Id` while the mapping back from the wire ignores an id the worker sends (`src/Scout.Host.ControlPlane/Services/OperatorMapping.cs:162`, `:230`); over the socket the ids are the same on two reads and after a worker save that sends the versions back, Use and Remove act on the version named, and a removed or empty id answers `NOT_FOUND` "That presenter version is no longer there." with the project unchanged (`tests/Scout.ControlPlane.Tests/Integration/OperatorGrpcTests.cs:1619`). The mandate the desktop saves is the one the worker reads (`:138`); the desktop's start is refused without the grant and lists nothing, and a project the desktop starts is taken by the worker only under the grant, saved as `script_ready` with its claims, shown to the desktop, and decided by the owner, whose decision the worker cannot overwrite (`:161`); a chat project's origin reference reaches the worker and never the desktop (`:207`); the desktop token gets `PERMISSION_DENIED` on `GetOperatorProject` and `ListOperatorProjects` (`:254`); the worker reads a project only under the grant, sees the owner's claim decisions, lists newest first within its limit without the origin reference, and each of its saves and each project it takes shows in `ListWrites` (`:269`). Production over the socket (`:308`): `ProduceProject` with a claim pending is `INVALID_ARGUMENT` "1 claim is still pending; decide it before production.", and once the claim is decided it queues the project, which the worker takes as `producing`; the worker and the desktop get the same media directory; the scenes the worker saves come back to the desktop field for field, optional fields unset when absent; reorder, attach, lock and regenerate answer the edited project, regenerating a locked scene is `INVALID_ARGUMENT`, an unknown scene `NOT_FOUND`, `../x.mp3` and the media directory of `../x` `INVALID_ARGUMENT`, and a worker save that changes a locked scene `FAILED_PRECONDITION`. The readiness the worker reports is the one the desktop reads, with the control plane's `reported_at` in place of the worker's, and before any report the desktop reads the empty one with its note (`:426`). Scenes cross the mapping and back unchanged, optional fields unset when absent (`:506`), and readiness keeps the control plane's stamp on the way out and drops the sender's on the way in (`:535`). Assembly over the socket (`:777`): `AssembleProject` queues a media-ready project with an empty package, the worker takes it as `assembling` with its package `assembling`, a worker package that confirms the rights is `FAILED_PRECONDITION` "Only the owner confirms the media rights of project '<id>'.", one with a 101-character title `INVALID_ARGUMENT` "The title is 1 to 100 characters.", one with `approved_at` "yesterday" is `INVALID_ARGUMENT`, the reported package comes back field for field, `ApprovePackage` before the rights is `INVALID_ARGUMENT` "Confirm the media rights first.", `EditPackageMetadata` trims the title and refuses one of 101 characters, and after `ConfirmMediaRights` the approval answers `approved` with `approved_at` and shows in `ListWrites` as `approved package` by `owner`. A package crosses the mapping and back unchanged, optional fields unset when absent, and a project without one has no `package` (`:845`). Publication over the socket (`tests/Scout.ControlPlane.Tests/Integration/OperatorGrpcTests.cs:914`): a `publish_at` of "tomorrow" is `INVALID_ARGUMENT`, `PublishPackage` with a browser-style `publish_at` answers `publish_approved` with the owner's settings, and the worker's `NextApprovedAction` answers the upload as `executing` once, then nothing while it runs; the worker's saves of the approved project, `published` with its video id and upload time and a running arm's start, both in the worker's `yyyy-MM-ddTHH:mm:ssZ` form, and an unchanged echo of what it read, are accepted (`:952`); an approved action carries its project's origin reference to the worker only when the project has one, never to the desktop (`:985`); without the grant it answers nothing and no error (`:1009`). A publication crosses the mapping and back unchanged but for the arm hours, optional fields unset when absent (`:1023`). Deleting the YouTube credentials purges topic candidates and claim sources and keeps the package (`:1073`), and a purge that cannot write fails the call with the grant kept (`:1100`). The worker token gets `PERMISSION_DENIED` on the five comment methods of `Operator` and the desktop token on `GetComments` and `SaveComments`, while the desktop lists and the worker reads the empty comments (`:1207`); a comment the worker saves comes back to the desktop field for field with the control plane's `fetched_at`, and the owner's approved reply answers `reply_approved` (`:1241`).
- [[pages/invariants/secrets-never-in-source]]: both tokens are minted by the desktop or read from the environment, never from a file in the repository, and never logged (`tests/Scout.ControlPlane.Tests/Security/CallerTokensTests.cs:14`, `:45`).
