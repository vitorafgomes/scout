## How it works

**The animated character** (phase 8c-A, [[pages/decisions/0033-channel-operator-architecture]]). `animated_character` is the fourth format a project starts in, the constant `OperatorService.AnimatedCharacter` (`src/Scout.ControlPlane/Operator/OperatorService.cs:60`); any other value is refused with "The format is generated_pictures, own_pictures, own_video or animated_character." (`:97`), from the desktop and from a chat project alike, and a chat project in this format starts with no presenter description, picture or mouth box whatever the worker sends (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Format.cs:91`, `:124`, `:148`). The project carries the owner's presenter description, who the character is and where they are, cleaned by `OwnerText` and at most 300 characters ("A presenter description is at most 300 characters.", `src/Scout.ControlPlane/Operator/OperatorService.cs:2419`), refused before the grant is asked for, so nothing is stored or logged; it is given at the start and on produce and delegate, where a blank one keeps the stored one, on the desktop's call too, unlike the direction, and the chat variants never set it (`:229`, `:639`, `:709`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:36`, `:59`). The kind `presenter` of `AttachSceneMediaAsync` sets the presenter picture (`src/Scout.ControlPlane/Operator/OperatorService.cs:961`, `:2448`): the scene id must be empty ("A presenter picture is attached to the project, not to a scene."), the name passes the visual file name rule and is the one Scout Desktop gives its copy, `owner-presenter-` and 12 hex digits ("A presenter picture is attached from Scout Desktop, which names the copy for you."), the project must be `animated_character` ("The project is not an animated character.") and on a status a background is accepted on ("A presenter picture is attached to a project whose script or media is ready, an assembled or approved one, one queued for assembly or assembling, or a failed one; this one is <status>."), and the file must already be in the media directory; it sets `PresenterFile`, changes the status and the package like a background, needs no grant, writes no write-log entry, and once stored deletes the picture it replaced, a plain name inside the media directory only, a file it cannot delete logged and left (`:2509`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:88`, `:130`, `:148`, `:309`). Replacing or regenerating the picture clears the mouth box, which the owner marks again: an attach of another picture stores no `MouthBox`, and an attach of the picture already set keeps it (`src/Scout.ControlPlane/Operator/OperatorService.cs:2492`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:88`). `SetMouthBoxAsync(projectId, mouthBox)` (`src/Scout.ControlPlane/Operator/OperatorService.cs:2525`) stores where the mouth is on the picture: four finite fractions, each between 0 and 1, at least 0.02 wide and high and inside the picture, else, a missing box included, "A mouth box is four fractions of the picture, each between 0 and 1, at least 0.02 wide and high and inside the picture." before the store is read; another format is refused with "The project is not an animated character."; it is accepted on the statuses a presenter attach is accepted on except `assembling`, so a box never sends a running assembly back to the queue, and refused on any other with "A mouth box is set on a project whose script or media is ready, an assembled or approved one, one queued for assembly, or a failed one; this one is <status>." inside the store update, with nothing stored (`:2542`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:385`, `:405`); a box that changes the stored one takes the approval back like a scene edit, the same box changes nothing (`src/Scout.ControlPlane/Operator/OperatorService.cs:2548`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:167`, `:203`, `:216`). `RegeneratePresenterAsync(projectId)` (`src/Scout.ControlPlane/Operator/OperatorService.cs:2569`) no longer clears anything: since phase 8c-B production makes no presenter, it is a presenter request with no feedback and no prompt, `RequestPresenterAsync(projectId, "", "")`, so the picture, mouth box, preview and versions stay, `PresenterRequest` is `another`, an assembled or approved project goes back to media ready without its rights and approval, a project that is producing or assembling is refused with the presenter request sentence, another format is refused with "The project is not an animated character.", and no call asks for a grant or logs (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:236`, `:267`). Phase 8c-A refused a scene regeneration and a scene picture in this format; phase 8c-B lifted both, below. A worker save takes scenes whose `VisualSource` is `presenter` (`src/Scout.ControlPlane/Operator/SceneRules.cs:27`), never changes the presenter description or the mouth box, and records the presenter picture the worker made only while the project is `animated_character` and has none, never replacing or clearing one that is set (`src/Scout.ControlPlane/Operator/OperatorService.cs:419`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:167`, `:280`). The name must pass the visual file name rule, else the save is refused, and must start with `presenter-` and name a file already in the project's media directory, else the project keeps no presenter picture, so a worker save never names the background, the thumbnail or a scene picture as the presenter picture, which a later replace or regeneration would delete (`src/Scout.ControlPlane/Operator/OperatorService.cs:2435`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:357`). None of this adds a call leaving the process; the files touched are inside the project's media directory.
