## How it works

**Production and scenes.** `ProduceProjectAsync(id, narrationVoice, direction, motion)` first trims the narration voice the owner chose for this video and refuses one longer than 80 characters or holding anything but ASCII letters, digits, `_`, `:`, `.`, `#` and `-`, as `OperatorValidationException` "A narration voice is an id of at most 80 letters, digits, _ : . # or -." (`src/Scout.ControlPlane/Operator/OperatorService.cs:720`); then it takes the owner's direction for this video, which the script and the picture prompts follow, with every control character but a newline made a space and the ends trimmed (`OwnerText`, `:732`), and refuses one over 1000 characters ("A direction is at most 1000 characters.", `:735`; the visual brief it replaced in phase 8a was at most 500), and the motion preset, `still`, `gentle` or `dynamic`, trimmed, an empty one meaning `gentle`, refusing any other ("Motion is still, gentle or dynamic.", `:754`); all three before anything is read or written. The voice is an id the worker's readiness offered, `<Provider>:<voice>` or `piper:<voice>`, and empty means Scout's choice; the control plane does not check that the worker offers it, because the worker fails a scene on a voice it cannot use ([[pages/services/operator]]). It then asks the write gate for the `youtube` grant like `StartProjectAsync`, then refuses, as `OperatorValidationException`, a project that is not `script_ready`, `media_ready`, `assembled`, `approved` or `failed` with a script (an assembled or approved one goes to `production_queued` with the package's rights confirmation and approval cleared, as an attached scene file does; one queued for assembly or assembling is refused), so a run that failed, planning included, is produced again (`src/Scout.ControlPlane/Operator/OperatorService.cs:590`) ("Only a project with its script ready, its media ready, an assembled or approved one, or a failed one with a script goes to production; this one is <status>.") and one with claims still `pending` ("1 claim is still pending; decide it before production.", "<n> claims are still pending; decide them before production."), and otherwise sets `production_queued`, clears the project's error and stores the voice, the direction and the motion on the project (`src/Scout.ControlPlane/Operator/OperatorService.cs:633`, `:636`, `:637`, `:638`). The request's voice, direction and motion always win, an empty one included, so the desktop sends the stored ones back when the owner keeps them, which is how the owner edits the direction until production; a delegated project stays delegated. Only `StartProjectAsync`, a worker's creation of a chat project, this call, `DelegateProjectAsync` and their chat variants set `Direction`, and only this call, `DelegateProjectAsync` and their chat variants set `NarrationVoice` and `Motion`: the desktop's call checks its values, asks for the grant and hands them to a private core, `ProduceAsync` (`src/Scout.ControlPlane/Operator/OperatorService.cs:610`), whose null voice, direction or motion keeps the stored one inside the store update, a null only the chat variant passes; a worker save of an existing project builds it from the stored one and never takes the voice, direction, motion or format it sends, a project the worker creates from chat starts with no voice, `gentle` and the direction it was asked for, and a regenerate keeps them (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.cs:172`, `:185`, `:203`, `:220`, `:237`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Direction.cs:13`, `:33`, `:61`, `:77`). The direction reaches only the script writer's and the scene planner's model requests, and the motion only the assembler's choice among its presets ([[pages/services/operator]]); `Direction` keeps the JSON key `visualBrief` (`src/Scout.ControlPlane/Operator/OperatorModels.cs:76`), so a `projects.json` written before phase 8a reads with its brief as the direction and as `generated_pictures` (`tests/Scout.ControlPlane.Tests/Operator/JsonFileOperatorStoreTests.cs:269`). The owner's scene edits change Scout's own state, not anything the model wrote, so they need no grant; each answers the project without its origin reference and `NOT_FOUND` for an unknown project or scene ("Unknown scene '<id>' in project '<id>'."). `ReorderScenesAsync` takes the scene ids in the owner's order, refuses anything but every scene exactly once ("The new order must name every scene of the project exactly once."), and numbers them from 1. `SetSceneLockedAsync` sets `Locked`. `RegenerateSceneAsync` refuses a locked scene ("Scene '<id>' is locked; unlock it before regenerating it."), otherwise sets the scene to `planned` without its error, clears the audio file, the visual file and the duration where the source is not `owner` (the source names stay, except that a `stock` picture becomes `text_card` and every visual credit is cleared, `src/Scout.ControlPlane/Operator/OperatorService.cs:838`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.StockPictures.cs:48`), keeps the owner's media, and sets the project to `production_queued`. `EditSceneTextAsync(projectId, sceneId, text)` (`src/Scout.ControlPlane/Operator/OperatorService.cs:861`) is the owner's scene text, in every format: the text cleaned by `OwnerText` must be 1 to 700 characters, the planner's longest part (`ScenePlanner.MaxNarration`), else "A scene's text is 1 to 700 characters." before the store is read; a locked scene is refused with "Scene '<id>' is locked; unlock it before editing its text."; otherwise the scene takes the text and its narration is sent back to be made again. In an `own_video` project, whose format the call reads inside the same store update, the text is only the scene's captions: the scene keeps its status, sources, clip and duration, nothing goes back to production, and the project and its package change as any scene edit that changes the video, an assembled or approved one back to `media_ready` without its rights confirmation and approval (`src/Scout.ControlPlane/Operator/OperatorService.cs:875`, `:882`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.OwnVideo.cs:240`); a delegated one goes to `assembly_queued` instead, its package queued again the way the delegated hand-on queues it, so the new captions are assembled without the owner, as a scene edit of another format re-queues production and hands on by itself (`:1960`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.OwnVideo.cs:391`). `RegenerateNarrationAsync(projectId, sceneId)` (`src/Scout.ControlPlane/Operator/OperatorService.cs:896`) does the same without a text, keeping one a hook or call to action carried past 700 characters, and refuses a locked scene with the regenerate sentence above. Both reset the scene through `WithoutNarration` (`:906`): `planned`, no error, `AudioSource` `none` and no audio file, the owner's audio included, duration 0, and the visual source, file, credit, prompt and search terms as they were, unlike a regenerate; both set the project to `production_queued`, and the package as any scene edit that changes the video (below); neither asks for a grant or writes a write-log entry, like the other scene edits (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.SceneText.cs:31`, `:50`, `:74`, `:106`, `:121`, `:134`, `:150`). The worker makes the narration again on its next take, keeping a generated or stock picture whose file is on disk ([[pages/services/operator]]). An `own_video` project has neither to make again: `RegenerateSceneAsync` and `RegenerateNarrationAsync` refuse its scenes with "A project of your own video has no narration or pictures to make again; edit the scene's text to change its captions.", nothing stored (`src/Scout.ControlPlane/Operator/OperatorService.cs:820`, `:896`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.OwnVideo.cs:272`), from the chat too, with nothing logged (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Chat.cs:193`); a lock and a reorder work as in every format. `AttachSceneMediaAsync` takes `audio`, `visual`, `background` or `recording` ("Media is attached as audio, visual, background or recording."), refuses `audio` and `visual` on an `own_video` project with "A project of your own video shows the recording in every scene; it takes no pictures or narration." (`src/Scout.ControlPlane/Operator/OperatorService.cs:993`), checks the file name, requires the file to be in the project's media directory already ("'<name>' is not in the project's media folder; copy it there first."), sets that source to `owner` with the name, sets the duration to 0 for the owner's audio, unknown until it is measured, and sets the scene `ready` without its error once it has a visual and its audio is decided (`src/Scout.ControlPlane/Operator/OperatorService.cs:988`). A visual is a visual file, or a `text_card` production chose; decided audio is an audio file, or `AudioSource` `none` production chose. Production chose them only on a scene it saved `ready`; on a `planned` or `failed` scene the planner's `none` and `text_card` are placeholders, so an image attached there leaves the scene as it was and the next run still makes its narration. The kind `background` attaches the project's background instead (`src/Scout.ControlPlane/Operator/OperatorService.cs:996`): the scene id must be empty ("A background is attached to the project, not to a scene."), the name passes the visual file name rule, no grant is asked for, as for a scene's media, the file must already be in the project's media directory ("'<name>' is not in the project's media folder; copy it there first."), and the project must be `script_ready`, `media_ready`, `assembled`, `approved`, `assembly_queued`, `assembling` or `failed` ("A background is attached to a project whose script or media is ready, an assembled or approved one, one queued for assembly or assembling, or a failed one; this one is <status>."); it sets `BackgroundFile` and `UpdatedAt` and changes the status and the package like a scene attach: an assembled or approved project goes back to `media_ready` with the package kept but without its rights confirmation and approval, and a project queued for assembly or assembling goes to `assembly_queued`, so the next assembly renders the new background (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.cs:1274`, `:1296`, `:1311`, `:1324`, `:1338`, `:1350`, `:1381`). The kind `recording` attaches the recording of a project of the owner's own video instead (`src/Scout.ControlPlane/Operator/OperatorService.cs:1035`): the scene id must be empty ("A recording is attached to the project, not to a scene."), the name passes the recording file name rule and starts with `owner-`, the name Scout Desktop gives its copy, so no name of Scout's own output is taken as the recording ("A recording is attached from Scout Desktop, which names the copy for you.", `:1043`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.OwnVideo.cs:347`), no grant is asked for, as for a background, the project must be `own_video` ("Only a project of your own video takes a recording.") and `recording_waiting`, `queued`, or `failed` without a script, so before Scout transcribes it ("A recording is attached before Scout transcribes it; this one is <status>."), and the file must already be in the project's media directory ("'<name>' is not in the project's media folder; copy it there first."); it sets `RecordingFile`, sets `RecordingMs` to 0 until the worker measures the new recording, clears the error and queues the project, so the worker's next take transcribes it, and writes only `projects.json`, with no write-log entry (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.OwnVideo.cs:74`, `:100`, `:136`). Once that update is stored, the recording it replaced is deleted from the project's media directory, a plain name inside it only, a missing file ignored and a file it cannot delete logged and left (`src/Scout.ControlPlane/Operator/OperatorService.cs:1089`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.OwnVideo.cs:327`). An `own_video` project takes no background either: the background attach refuses it with the same sentence as a picture, nothing stored (`src/Scout.ControlPlane/Operator/OperatorService.cs:1010`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.OwnVideo.cs:361`).
