## How it works

**The worker's comment saves.** `GetCommentsForWorkerAsync` and `SaveCommentsFromWorkerAsync` ask the gate for the same row and refuse with its sentence without the grant, nothing written and nothing logged (`tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:631`); each save is one write-log entry, target `comments`, outcome `saved comments`. `CommentRules.MergeFromWorker` validates the kinds and statuses, an id matching `^[A-Za-z0-9_.-]{1,100}$`, text at most 2000, draft 1000, theme 40 and idea text 200 characters, then refuses as tampering: dropping a comment, a new comment in any status but `new`, `quarantined` or `drafted` or carrying an approval, decision or reply (`tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:285`), a change of `ApprovedText` ("Only the owner sets the approved reply of comment '<id>'.", `:199`) or `DecidedAt`, any change to what YouTube said, moving a comment out of an owner status (`dismissed`, `reply_approved`, `hold_approved`, `held`, `replied`, `failed`) other than by the execution steps, quarantining or changing the kind of a comment the owner decided, and an idea that is not `proposed` or that changes or drops a decided one (`:260`); the idea checks build their sets once (`src/Scout.ControlPlane/Operator/CommentRules.cs:209`). The worker may set the kind, theme and draft of a `new`, `draft_requested`, `drafted` or `quarantined` comment and move `new` or `draft_requested` to `drafted` and `new` to quarantined. The execution steps are `reply_approved` to `replying`, `replying` to `replied` with the reply id, `reply_approved` or `replying` to `failed` with the error, and `hold_approved` to `held` or `failed` (`src/Scout.ControlPlane/Operator/CommentRules.cs:52`); without the grant only those steps, on a comment whose action is executing, are saved, as a revoked publication's are (`src/Scout.ControlPlane/Operator/CommentService.cs:277`, `tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:234`). A new comment's `FetchedAt` is the control plane's time, never the worker's. The caps (`src/Scout.ControlPlane/Operator/CommentRules.cs:230`): at most 1000 comments, the newest by `PublishedAt` and every one with a live action (`tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:719`), and at most 200 ideas, every `used` one and the rest newest by their comment's `PublishedAt`. An idea whose comment the cap or the 30-day clearing removed loses what came from a stranger: a `proposed` or `dismissed` one is removed, and a `used` one keeps only its id, status, comment id and project (`src/Scout.ControlPlane/Operator/CommentRules.cs:260`, `tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:881`).

**Comment actions.** A comment action's target is `comment:<id>`. `ProjectOf` answers null for it (`src/Scout.ControlPlane/Operator/OperatorService.cs:1918`), so it is never a project's: it has no origin reference, never blocks a project's action or a publish, and is never delayed by `Due`; the claim queues it by its own target (`:1921`, `:1681`), so actions on two comments and a project's are all claimable (`tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:701`). `CommentRules.Reconcile` (`src/Scout.ControlPlane/Operator/CommentRules.cs:93`) repairs a comment waiting on a YouTube action without a live one: `reply_approved` goes back to `drafted` without its approved text, `hold_approved` to `quarantined`, and `replying` to `failed` with "The reply may already be on YouTube; check the video's comments in YouTube Studio before replying again.". `CancelApprovedYouTubeActionsAsync` runs it after rejecting the approved actions, over what is still live rather than what that call rejected, so a comment whose action is executing keeps its status and a revoke retried after a failed comments write still repairs the rest (`src/Scout.ControlPlane/Operator/OperatorService.cs:1715`, `tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:680`, `:820`); after a revoke and a re-grant an action claimed before the new grant is stale, and the clearing fails the comment it left `replying` (`:795`). `PurgeYouTubeDataAsync` deletes every comment, `SyncedAt`, `SyncRequestedAt` (since 2026-11-11, `tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:928`), `SyncError` and every idea not `used`, and a used idea keeps only its id, status, comment id and project (`src/Scout.ControlPlane/Operator/OperatorService.cs:1817`, `tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:660`). `ClearOldResearchAsync` reconciles first, so a status written before its approval was queued heals within 6 hours (`src/Scout.ControlPlane/Operator/OperatorService.cs:1773`, `tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:843`), then removes the comments fetched more than 30 days ago unless their action is live, with their ideas as the cap handles them, writing `comments.json` only when something changed (`tests/Scout.ControlPlane.Tests/Operator/CommentServiceTests.cs:644`).

**Readiness.** `ReportReadinessAsync` stores the worker's latest report in `readiness.json`, its `ReportedAt` replaced by the control plane's time; it needs no grant, because it describes the worker and writes only that file. A report that cannot be written fails as `OperatorStoreException` (`src/Scout.ControlPlane/Operator/OperatorExceptions.cs:29`) "Scout could not save the worker's readiness report in its data folder." and the earlier report stays readable (`src/Scout.ControlPlane/Operator/OperatorService.cs:1841`); the host answers it `FAILED_PRECONDITION` with that sentence ([[pages/services/host-control-plane]]), so the worker logs the real reason. The report keeps the voices the worker offers, each an id, a label, a source and, for a bundled voice whose sample is on disk, the sample's file name in the voice samples directory; a sample file that is not a plain `.wav` file name is refused as `OperatorValidationException` "A voice sample is a plain .wav file name.". `GetReadinessAsync` answers the report or, before the first one, every flag false, no provider, no voices and the note "The Scout worker has not reported yet.".
