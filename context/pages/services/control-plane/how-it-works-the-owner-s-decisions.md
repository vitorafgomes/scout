## How it works

**The owner's decisions.** `ActionDecisionService` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:39`, a singleton, `src/Scout.ControlPlane/ControlPlaneServiceCollectionExtensions.cs:81`, since 2026-11-08) takes the desktop's approve and reject and the rejections a cleared grant causes. `ApproveAsync` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:361`) refuses, as `WriteNotGrantedException`, an approval while the feature holds no grant and leaves the action waiting (`:371`); an action asked before the grant's `GrantedAt` is rejected with `AskedBeforeGrant`, "asked before writes were granted; ask again" (`:42`, `:377`), logged, and the approval refused, because the claim never hands it out. Each decision writes the queue first and then appends `approved` or `approved: <reason>` (`WriteGateService.Approval`), or `rejected` or `rejected: <reason>` (`WriteLogEntry.Rejected`, `src/Scout.ControlPlane/Actions/WriteLogEntry.cs:21`), approved by `owner`, with the action id and, since 2026-11-11, the action's group id (`ApprovalOf`, `src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:332`, `tests/Scout.ControlPlane.Tests/WriteGate/ActionDecisionServiceTests.cs:38`); `RejectUnstartedAsync` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:404`) logs one `rejected: writes were revoked` entry per action it rejects. `PullRequestVerdictService` logs each stale approved verdict a card verdict sweeps aside, "rejected: GitHub's write permission changed after this verdict was given, so it will not be sent; give it again." (`src/Scout.ControlPlane/WriteGate/PullRequestVerdictService.cs:161`, `tests/Scout.ControlPlane.Tests/Integration/ApprovalsGrpcTests.cs:320`). **A group's state** (2026-11-11): `ListPendingAsync` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:130`) is the list the desktop reads, each waiting action of a group with its group's state and every other action with none; since commit B it takes the actions and their groups from one read of the queue, and since review round 1 it reads a state only for a group that holds a waiting action (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:133`), `IActionQueue.ListWhereAsync` (`src/Scout.ControlPlane/Actions/IActionQueue.cs:177`), so a file that changes between two reads can no longer fail the list with `KeyNotFoundException` (`tests/Scout.ControlPlane.Tests/WriteGate/ActionGroupStateTests.cs:77`). A group is one group id, one feature and one repository; its state is read over every action of it the queue still holds, in any status, so the stamp outlives a rejected action, on the service's `TimeProvider`. `GroupStateOf` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:100`) answers, in order: `over_bound` with more than `MaxGroupSize`, 50, waiting (`:57`, `:105`); with the worker's report, its first stamp, `changed` when an action was asked after it and `closed` otherwise, whatever quiet spells came before (`:111`), so a request whose model paused longer than the spell between two writes reads as closed once its end is reported; without a report, a quiet spell longer than `GroupQuietClose`, ten minutes since commit C, closes the group: `changed` when an action was asked after a spell between two of its actions (`:118`), `closed` after a spell since its newest (`:73`, `:130`), `open` otherwise. A second report after a late action keeps the first stamp, so it does not undo `changed`; a timeout close is derived on each read and writes nothing; an action that joins a closed group is queued and the group becomes `changed`, never refused. The table of cases is `tests/Scout.ControlPlane.Tests/WriteGate/ActionGroupStateTests.cs:56`. Nothing here decides an action: a closed group changes no action's status and logs nothing (`tests/Scout.ControlPlane.Tests/Integration/WorkerGateGrpcTests.cs:191`). **A decision on a set** (2026-11-11, commit B of [[pages/roadmap/approve-together]] phase 1, [[pages/decisions/0032-per-feature-write-permissions]] amendment): `ApproveSetAsync` and `RejectSetAsync` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:169`, `:183`) decide exactly the actions the desktop listed, through `DecideSetAsync` (`:189`) over `IActionQueue.DecideSetAsync` (`src/Scout.ControlPlane/Actions/IActionQueue.cs:187`, `src/Scout.ControlPlane/Actions/JsonFileActionQueue.cs:750`), which hands the group's actions to the decision under the queue's gate and writes every decision of the set in one write, none when a check fails (`tests/Scout.ControlPlane.Tests/Actions/ActionQueueTests.cs:598`, `:621`). A set that names no action or one twice, `SetNotAList`, or more than 50, `SetOverTheBound`, is refused whole as `ActionSetRefusedException` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:8`, `:82`, `:85`; `tests/Scout.ControlPlane.Tests/WriteGate/ActionSetDecisionTests.cs:176`, `:303`), never split. The group is the listed actions' group id on the feature and repository of the first listed action the queue holds; an unknown id, one of another request or another repository is answered `NotInTheGroup` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:76`; `tests/Scout.ControlPlane.Tests/WriteGate/ActionSetDecisionTests.cs:276`). Approve set then needs the grant, as the single approval (`WriteNotGrantedException`, `src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:248`), and a group `GroupStateOf` reads as closed: open is refused with `StillQueuing`, changed with `ChangedAfterClose` and over the bound with `GroupTooLarge` (`:258`, `:79`, `:82`, `:85`); each listed action must be waiting ("already approved", "already rejected" otherwise) and carry the digest the desktop listed, `ChangedAfterListing` otherwise (`:277`, `:79`; `tests/Scout.ControlPlane.Tests/WriteGate/ActionSetDecisionTests.cs:119`). One asked before the grant is rejected with `AskedBeforeGrant` and logged as the single approval does, and answered as a mismatch (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:281`). Any mismatch decides none of the others. Reject set needs no grant and no digest and is taken on an open, changed or over-bound group, since a rejection writes nothing outside Scout (the owner's answer 5); each listed action must still be waiting and in the group. A set decided logs one entry per action with its group id: `approved` or `approved: <reason>`, `rejected` or `rejected: <reason>`. The table of every state crossed with Approve set, Reject set, the single Approve and the single Reject is `tests/Scout.ControlPlane.Tests/WriteGate/ActionSetDecisionTests.cs:100`; an action that joined after the listing stays pending (`:136`) and a changed group takes Reject set only (`:154`). A second call over actions already approved, executing or executed is answered from the actions as they stand and appends nothing (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:231`, `tests/Scout.ControlPlane.Tests/WriteGate/ActionSetDecisionTests.cs:193`); it needs no grant, since it approves nothing, but since review round 1 each listed action whose payload is still whole must still carry the listed digest, else it is answered with `ChangedAfterListing` and decided is false, while an executed action, whose payload was cut, is answered as it stands (`:230`; `tests/Scout.ControlPlane.Tests/WriteGate/ActionSetDecisionTests.cs:252`, `:276`). Decided means the decision was applied, never that a send succeeded: each answered row carries its status, outcome and result, so a failed send shows on its row; the queue is written before the log, so after a log that failed part way a repeated Approve set answers the actions with no `approved` entry as mismatches with `ApprovalNotInLog`, never as decided, and the claim rejects them after the one-minute window (`ApprovalsNotInLogAsync`, `src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:343`, which the findings card's click shares, as it shares `ApprovalOf`, `:332`; `tests/Scout.ControlPlane.Tests/Integration/ActionSetGrpcTests.cs:160`). `GetGroupAsync` (`src/Scout.ControlPlane/WriteGate/ActionDecisionService.cs:146`) reads one group id's actions in any status, each with its group's state, for the desktop's group view. The single Approve and Reject keep their behaviour, with no group check. `GroupQuietClose` is ten minutes since commit C (two before): no turn time limit exists to set it just above (`StreamPumpOptions.OverallTimeout` is null and nothing binds it, `src/Scout.Conversation/Streaming/StreamPumpOptions.cs:36`, `src/Scout.Conversation/ConversationServiceCollectionExtensions.cs:40`; only a Teams reply is capped, `src/Scout.Adapter.Teams/Streaming/TeamsResponseSink.cs:99`); once phase 2's worker reports each turn's end the quiet close covers only a worker that stopped mid-turn, and a slow local model may pause several minutes between two queued calls, which at two minutes read as a changed group; single decisions and Reject all are offered meanwhile (`tests/Scout.ControlPlane.Tests/WriteGate/ActionGroupStateTests.cs:56`, the rows at ten minutes). A set may be approved without every text having been opened: an action whose listed text is only a preview is approved by the set that listed it, as the owner's answer 1 decided (`tests/Scout.ControlPlane.Tests/WriteGate/ActionSetDecisionTests.cs:252`).
