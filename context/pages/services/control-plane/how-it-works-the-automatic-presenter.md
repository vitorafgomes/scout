## How it works

**The automatic presenter** (phase 8c-B, [[pages/decisions/0033-channel-operator-architecture]]). The mandate's `DefaultFormat` (`src/Scout.ControlPlane/Operator/OperatorModels.cs:28`), `generated_pictures` until the owner chooses, is the format of a project started with a blank one, on the desktop and from the chat; `SaveMandateAsync` stores a blank one as `generated_pictures` and refuses any other value Scout does not make with "The default format is generated_pictures, own_pictures, own_video or animated_character.", joined with the other mandate refusals, nothing saved, and `GetMandateAsync` reads a stored value Scout does not make as `generated_pictures` (`src/Scout.ControlPlane/Operator/OperatorService.cs:135`, `:182`, `:741`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Format.cs:51`, `:75`). A chat start with no format in a mandate whose default is `own_video` is refused like an explicit `own_video` (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Format.cs:165`). The worker save that makes an `animated_character` project `script_ready`, while it has no presenter version, no presenter picture and no request, stores `PresenterRequest` `first` (`src/Scout.ControlPlane/Operator/OperatorService.cs:424`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:69`); the presenter fields `PresenterVersions`, `PresenterPreviewFile`, `PresenterRequest`, `PresenterSource`, `PresenterReturnStatus` and `PresenterRequestPrompt` (`src/Scout.ControlPlane/Operator/OperatorModels.cs:117` to `:135`, the record `PresenterVersion` at `:142`) are never taken from any other worker save (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:239`). `NextQueuedProjectAsync` takes, after a queued project and before any production, the oldest project with a request that is not researching, scripting, transcribing, producing, assembling or presenting, moves it to `presenting` and keeps the status it had in `PresenterReturnStatus`; a presenting project with no save for 15 minutes is taken again, still presenting (`src/Scout.ControlPlane/Operator/OperatorService.cs:1880`, `:564`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:97`, `:201`). Any save of a presenting project is the job's save (`src/Scout.ControlPlane/Operator/OperatorService.cs:382`, `:2780`): it must clear the request, else "The worker may not save the presenter of project '<id>' without clearing its presenter request.", and may add one version at the end and change none it has, else "The worker may add one presenter version to project '<id>' and change none it has.", both as tampering; the new version's picture, and its preview when it has one, must be plain names starting with `presenter-` already in the media directory ("A presenter version is a picture Scout made in the project's media folder, named presenter-."), its mouth box under the mouth box rule and its source `generated`, `builtin` or `owner` ("A presenter version is generated, builtin or owner."), and its `MadeAt` is the control plane's time (`:2826`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:130`, which also covers a source outside those three and a mouth box outside the picture, each refused as `OperatorValidationException` with the store unchanged). The save takes only the project's error besides, clears the request, its prompt and the return status, gives the status back, and makes the version current, its picture, mouth box, preview and source, unless the job was the automatic `first` and the project already had a presenter picture, which an automatic presenter never replaces (`:2682`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:187`, `:217`); a save of `presenting` on a project that is no longer presenting is refused with "The project is no longer presenting." (`:396`). Past 10 versions the oldest whose picture is not the current one is dropped, the oldest of all when every one shows it, and once the store holds the change its picture and preview are deleted from the media directory unless the current pointers or another version still name them, a file that cannot be deleted logged and left (`:2687`, `:2724`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:447`, `:482`, `:503`). An owner's presenter attach is source `owner` and clears the preview, and does not delete a picture a version keeps (`:2291`, `:2360`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:522`). A scene edit that would send the project back to production (`RegenerateSceneAsync`, `RegenerateNarrationAsync`, `RegenerateScenePictureAsync`, `EditSceneTextAsync` outside `own_video`) is refused while the project is `presenting`, with "The project is making its presenter; wait for it to finish.", so the worker's presenter save is never refused as "no longer presenting"; a scene lock, which changes no status, still works (`src/Scout.ControlPlane/Operator/OperatorService.cs:2224`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:349`). The first job on a picture the owner attached saves a version whose source is `owner` and whose file is the attached `owner-presenter-` name, which the `presenter-` rule alone would refuse; the project keeps that picture, and takes the version's mouth box only when it has none (`src/Scout.ControlPlane/Operator/OperatorService.cs:2835`, `:2812`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:371`, `:395`). Feedback that is `first`, `another` or `prompt`, the words the worker reads as no feedback, is refused with "Presenter feedback cannot be first, another or prompt." before the store is read, nothing stored or logged (`src/Scout.ControlPlane/Operator/OperatorService.cs:2618`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:404`). `RegeneratePresenterAsync` asks for another presenter: it is `RequestPresenterAsync` with no feedback and no prompt, and the 8c-A paragraph above says what that keeps (`src/Scout.ControlPlane/Operator/OperatorService.cs:2569`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Character.cs:236`).

`RequestPresenterAsync(projectId, feedback, prompt)` (`src/Scout.ControlPlane/Operator/OperatorService.cs:2602`) cleans both like a direction and refuses, before the store is read, feedback over 300 characters ("Presenter feedback is at most 300 characters."), a prompt over 1500 ("A presenter prompt is at most 1500 characters.") and feedback `builtin:` with an id that is not letters, digits, `-` and `_` ("A built-in presenter is named by its id of letters, digits, - and _."); inside the store update another format is refused with "The project is not an animated character." and any status but `script_ready`, `media_ready`, `production_queued`, `assembly_queued`, `assembled`, `approved` or `failed` with a script with "A presenter can be asked for on a project whose script or media is ready, one queued for production or assembly, an assembled or approved one, or a failed one with a script; this one is <status>." (`:2754`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:305`, `:323`). It stores the feedback as the request, `prompt` when only a prompt is given, `another` when neither is, and the prompt beside it, and takes the approval back like a scene edit, with no grant and no write-log entry (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:265`). A presenter version is named by `PresenterVersion.Id`, the lower-hex SHA-256 of the record's JSON, computed and marked `JsonIgnore`, so it is never stored in `projects.json`, takes no part in the record's equality and is the same on every read, for a project stored before ids as for a new one; a stored version never changes, so neither does its id, and two versions equal in every field, `MadeAt` included, share it and are interchangeable ([[pages/conventions/decisions-that-look-like-defects]]) (`src/Scout.ControlPlane/Operator/OperatorModels.cs:156`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:821`). `UsePresenterVersionAsync(projectId, versionId)` makes the version with that id current under the same format and status rules and takes the approval back when it changes the project; an id the project has no version for, an empty one included, is `OperatorNotFoundException` with "That presenter version is no longer there." and nothing stored, looked up inside the store update by `VersionAt` (`src/Scout.ControlPlane/Operator/OperatorService.cs:2655`, `:2912`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:419`). A list the desktop read before the cap dropped a version or a removal took one never makes Use or Remove act on another version: the stale id answers not found and the project and its media are left as they were (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:766`). `ListBuiltInPresentersAsync` answers the latest readiness's `BuiltInPresenters`, beside its `FaceDetectionAvailable` and `PicturesLeftToday` (`src/Scout.ControlPlane/Operator/OperatorService.cs:2677`, `src/Scout.ControlPlane/Operator/OperatorModels.cs:297`, `:300`, `:303`). In `generated_pictures` and `animated_character`, `EditScenePicturePromptAsync` replaces an unlocked scene's picture prompt, 1 to 700 characters after cleaning ("A picture prompt is 1 to 700 characters."), with no status change, and `RegenerateScenePictureAsync` sends the scene back to planned with a generated picture to make and no file, credit or error, keeping its narration and audio, and the project to production with its approval taken back; both refuse `own_video` and `own_pictures` with "This format has no generated picture." and a locked scene with its locked sentence (`src/Scout.ControlPlane/Operator/OperatorService.cs:2687`, `:2713`, `:2744`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:544`, `:581`). An `animated_character` scene now takes a scene picture and a scene regeneration as in `generated_pictures`, its presenter staying the project's (`tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:596`). The three are also the chat's, `RequestPresenterFromChatAsync`, `EditScenePicturePromptFromChatAsync` and `RegenerateScenePictureFromChatAsync`, under the grant and logged via chat (`src/Scout.ControlPlane/Operator/OperatorService.cs:2731`, `:2736`, `:2741`, `tests/Scout.ControlPlane.Tests/Operator/OperatorServiceTests.Presenter.cs:613`, `tests/Scout.ControlPlane.Tests/Integration/OperatorGrpcTests.cs:1495`).
