## How the rules are kept

- [[pages/decisions/0033-channel-operator-architecture]] - `scout:operator.window` opens or focuses Scout's own operator window and changes nothing else; the other thirty-six `scout:operator.*` channels read or change only the control plane's own operator state (the mandate with its default format, a queued project with its format and direction, a claim decision, a production request with its narration voice, direction and motion, a delegation with the same three, a project deletion (the project's record and its media folder under Scout's data folder, never anything on YouTube), the scene order, a lock, a regeneration request, a scene's text, a narration regeneration request, a mouth box, a presenter regeneration request, a presenter request with the owner's prompt, feedback or built-in choice, the current presenter version, a presenter version removal (the version and the files only it names, under Scout's data folder), a scene's picture prompt, a scene picture regeneration request, an attached file name, an assembly request, the package metadata, the media-rights confirmation, the package approval, the owner's publish settings, a proposal decision, an experiment start, an adoption, a comment sync request, a comment decision, an approved reply and an idea decision) and, for `sceneMedia`, write one file the owner chose, a scene's audio or picture or the project's background or presenter picture, into that project's media directory under Scout's data folder; none calls YouTube, a model or anything outside Scout; delegating runs only the control plane's reversible stages and stops at the package approval; approving a package uploads nothing, and publishing, starting an experiment, adopting a winner, approving a reply and holding a comment hand the control plane the owner's decision, after which the upload, the thumbnail, each arm or winner change, the reply and the hold run as approved actions the worker performs through the write gate ([[pages/services/operator]]); the desktop never calls YouTube's write API. The desktop writes nothing for the voice preview: `scout-media://voice-samples/` only reads an audio file from the folder the main-only `GetVoiceSamplesDirectory` names, the control plane's own `operator/voice-samples` under Scout's data folder, which the control plane creates when it is missing; the renderer never sees that path, and no port is opened. The channel names pass the contract test's write-verb scan without an allow-list entry (`ui/packages/shared/test/ipc-contract.test.ts`, `ui/packages/main/test/ipc-operator.test.ts`).
- [[pages/invariants/no-executive-writes]] - the media tools are fetched at build time by the packaging script only, from pinned URLs whose SHA-256, and size where the table pins one, is checked before anything is kept; nothing at run time downloads or replaces them, and neither the worker nor chat can reach the script.
- [[pages/invariants/secrets-never-in-source]] - the fetch needs no credential and the worker environment gains nine paths, none secret. The face models are fetched at build time only, from pinned URLs whose size and SHA-256 are checked before anything is kept, and the worker runs them in-process on local files; nothing at run time downloads them.
