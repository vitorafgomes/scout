## Media tools

Scout Desktop ships the `ffmpeg` the worker assembles with, the font it draws captions and text cards with, the Piper text-to-speech engine with two British English voices, Rhubarb Lip Sync with Scout's own nine mouth shapes for the animated character, the two face models the worker finds the mouth on a presenter picture with, and Scout's four own presenters; the worker measures media with `ffmpeg` itself, so no `ffprobe` is shipped.

- **Pinned table.** `ui/build/media-tools.json:1` names, per bundled target, the archive URL, its SHA-256 and its top folder, and the fonts with theirs. `ffmpeg` is `n9.0.2-39-g7adfbe40dc`, the LGPL static build of BtbN/FFmpeg-Builds release `autobuild-2026-10-31-12-59`, the last October 2026 build (BtbN keeps the last build of each month for two years and deletes daily builds after 14 days), for `linux-x64` and `win32-x64`, with the SHA-256 of the release's `checksums.sha256`; the configure line in both binaries enables `libopenh264`, `libvpx`, `libopus` and `libfreetype` and not `gpl` (read from the files, never run). The fonts are Noto Sans Regular and Bold (hinted TTF) and their SIL Open Font License 1.1 text, from `notofonts/notofonts.github.io` at commit `e408cf09bf2042e9fe0d7d22789c29510e876359`, with the SHA-256 computed on download.

- **Fetch.** `ui/build/scripts/fetch-media-tools.mjs:381` runs inside `package:all`, after the Google client step and before the worker publish (`ui/package.json:23`), so every `dist` script has the files before electron-builder runs; it targets the machine's `<platform>-<arch>`, or the target given as its argument (`ui/build/scripts/fetch-media-tools.mjs:436`). Each download lands in `ui/build/media-cache/` only when its length matches the table's `size` where the entry has one (the Rhubarb zips) and its SHA-256 matches the table (`:54`, `:59`): a size mismatch ("media tools: size mismatch for <url>: expected N, got M"), a checksum mismatch or an error status fails the build and keeps nothing. Only `bin/ffmpeg` and `LICENSE.txt` are extracted (`:31`), with the system `tar`, on Windows the `tar.exe` of System32, which reads zip (`:89`); outside Windows a zip goes to the system `unzip` instead, which unpacks the whole archive into the scratch folder, since GNU `tar` reads no zip, and the step copies only what it takes from there (`extractArchive`, `ui/build/scripts/fetch-media-tools.mjs:105`); a failing `tar` or `unzip` fails the build, into `ui/packages/main/resources/media-tools/<platform>-<arch>/`, `ffmpeg` made executable outside Windows (`:204`), with a `NOTICE.txt` naming the version, the release, the archive's SHA-256 and the FFmpeg source of the build (`:75`); the fonts and `OFL.txt` go to `ui/packages/main/resources/fonts/` on every target, macOS included, before the archive step (`:392`). Nothing is downloaded or extracted again when the notice and the files are in place and the fonts match (`:187`); the notice no longer names `ffprobe`, so a folder fetched before is extracted once more. A target the table has no archive for, macOS, gets the fonts only and no `media-tools` folder (`:414`). The cache and both output folders are gitignored; `fetch-media-tools.d.mts` types the script for its tests.

- **Piper.** `ui/build/media-tools.json` pins Piper `2023.11.14-2` (https://github.com/rhasspy/piper, MIT, archived 2025-10-06) with one archive per target, `linux-x64`, `win32-x64`, `darwin-x64` and `darwin-arm64`, each with its URL, SHA-256 and root folder `piper`. The fetch extracts the whole folder (the `piper` executable, the onnxruntime, espeak-ng and piper-phonemize libraries, `espeak-ng-data/` and the tashkeel model are all needed at run time) into `ui/packages/main/resources/media-tools/<platform>-<arch>/piper/`, makes the executable runnable outside Windows and writes a `NOTICE.txt` there naming the version, the MIT licence, the source tag, the archive SHA-256 and that the archive also holds espeak-ng (GPL-3.0, https://github.com/espeak-ng/espeak-ng), onnxruntime (MIT) and piper-phonemize (MIT), each run as a separate program from Scout. macOS has Piper builds, so a target can have Piper and no ffmpeg; the ffmpeg step replaces only its own files and leaves `piper/`, `rhubarb/` and `tesseract/` alone (`ui/build/scripts/fetch-media-tools.mjs:198`).

- **Rhubarb.** The table pins Rhubarb Lip Sync `1.14.0` (https://github.com/DanielSWolf/rhubarb-lip-sync, MIT, `ui/build/media-tools.json:161`) with the release zips `Rhubarb-Lip-Sync-1.14.0-Linux.zip` for `linux-x64`, `-Windows.zip` for `win32-x64` and the one `-macOS.zip` for both `darwin-x64` and `darwin-arm64`, each with its URL, size, SHA-256 and root folder `Rhubarb-Lip-Sync-1.14.0-<Linux|macOS|Windows>`. The archive holds the `rhubarb` executable (`rhubarb.exe` on Windows), `res/` with the PocketSphinx acoustic model (86 MB, resolved beside the executable), `LICENSE.md`, and editor plugins and test fixtures; the fetch takes only the executable, the whole `res/` and `LICENSE.md` into `ui/packages/main/resources/media-tools/<platform>-<arch>/rhubarb/` (`ui/build/scripts/fetch-media-tools.mjs:249`, `:254`), makes the executable runnable outside Windows and writes a `NOTICE.txt` naming the version, the MIT licence, the source, the archive SHA-256, that Scout runs rhubarb as a separate program and that the archive bundles PocketSphinx under its BSD licence (`:116`). It is checked against its pinned size and SHA-256 before anything is kept, and skipped when the notice and the three are in place.

- **Mouths.** Nine PNGs, `A.png` to `H.png` and `X.png` (Preston Blair's shapes as Rhubarb names them: A closed, B slightly open with teeth, C open, D wide open, E slightly rounded, F puckered, G top teeth on the lower lip, H tongue up, X rest), 512 x 256 with a transparent background, a flat cartoon mouth with dark red lips, white teeth and a dark interior, are committed under `ui/packages/main/resources/mouths/` with a `VERSION` file (`1`) the worker keys rendered segments by and a `LICENSE.txt` saying they are part of Scout under its MIT licence; they were drawn once with Pillow and are not generated at build time.

- **Voices.** The same table pins `en_GB-cori-medium` (dataset LibriVox, public domain) and `en_GB-aru-medium` (University of Liverpool Acoustics Research Unit speech corpus, CC-BY 4.0, https://creativecommons.org/licenses/by/4.0/) from https://huggingface.co/rhasspy/piper-voices at commit `e7229f7d33a10e145e109b886d661984201ac3c4`: the `.onnx`, the `.onnx.json` and the model card of each, the card renamed `<voice>.MODEL_CARD`. They go to `ui/packages/main/resources/voices/` on every target, macOS included, with a `LICENSES.txt` written from the table (voice, dataset, licence, attribution and the repository commit); the folder is gitignored and shipped as the resource `voices`.

- **Face models.** `ui/build/media-tools.json:192` pins two ONNX models under fixed names, each with its URL at a pinned commit, its size, its SHA-256, its repository, its commit and its licence: `blazeface-short-range.onnx`, Google's MediaPipe BlazeFace short-range face detector converted to ONNX, from https://huggingface.co/fernandotonon/QtMeshEditor-blazeface-onnx at commit `50f2c66ffbdf84beae8c267df2b49e5c5a5162e9` (the file `face_detector.onnx`, 418437 bytes, Apache-2.0), and `face-landmarker.onnx`, Google's MediaPipe Face Mesh V2 weights converted to ONNX (a format conversion only), from https://huggingface.co/naklitechie/face-landmarks-onnx at commit `575c33816c840c5b156398adb485e4f8d138adc2` (the file `face_landmarks.onnx`, 4920995 bytes, Apache-2.0), whose model card places identification and life-critical decisions outside its intended use. The fetch puts both into `ui/packages/main/resources/media-tools/<platform>-<arch>/face/` on every target, macOS included, renamed to the fixed names, each kept only when its length and SHA-256 match (`ui/build/scripts/fetch-media-tools.mjs:308`, `:425`), with a `NOTICE.txt` naming both sources, commits, digests and licences and the model card's out-of-scope use (`:289`); a model in place with its pinned digest is not fetched again, and a new ffmpeg build leaves `face/` alone (`:198`).

- **Presenters.** Four PNGs, `ada.png`, `kofi.png`, `mei.png` and `rafa.png`, 1024 x 1024 with a transparent background, four flat cartoon people, head and shoulders, front-facing, mouth closed, with distinct skin tones, hair and clothing, the closed mouth drawn as Scout's `X` mouth shape at its mouth box, are committed under `ui/packages/main/resources/presenters/` with `presenters.json`, a list of `id`, `label`, `file` and `mouthBox` (fractions of the picture, the box the mouth shapes are scaled into: `x` 0.389, `y` 0.534, `width` 0.224, `height` 0.111 for all four), and a `LICENSE.txt` saying they are part of Scout under its MIT licence; they were drawn once with Pillow and are not generated at build time.

- **Packaged.** electron-builder copies the folders as resources `media-tools`, with `face/` inside it, `fonts`, `voices`, `mouths` and `presenters` (`ui/build/electron-builder.yml:53`, `:57`, `:66`, `:70`) and keeps them out of the app archive, so the binaries ship once (`:28`, `:29`, `:31`, `:32`).

- **Worker environment.** `resolveMediaTools` (`ui/packages/main/src/worker/resolve-binary.ts:144`) looks under the resources folder when packaged and under `ui/packages/main/resources` in development, and answers each path only when its file exists. `buildEnv` always sets `SCOUT__OPERATOR__FFMPEGPATH` and `SCOUT__OPERATOR__FONTPATH` (`ui/packages/main/src/worker/build-env.ts:107`), empty for what was not bundled, and main passes the resolved paths at every worker start (`ui/packages/main/src/main.ts:841`). The supervisor drops any inherited spelling of the two keys (`ui/packages/main/src/worker/supervisor.ts:468`), so only the desktop's values reach the worker. `SCOUT__OPERATOR__PIPERPATH` is `<media-tools>/piper/piper` (`piper.exe` on Windows) and `SCOUT__OPERATOR__VOICESPATH` the `voices` folder when it holds a `.onnx`, both empty otherwise, and the supervisor drops inherited spellings of them too. `SCOUT__OPERATOR__RHUBARBPATH` is `<media-tools>/rhubarb/rhubarb` (`rhubarb.exe` on Windows) and `SCOUT__OPERATOR__MOUTHSPATH` the `mouths` folder only when it holds all nine shapes (`ui/packages/main/src/worker/resolve-binary.ts:171`, `:172`, `ui/packages/main/src/worker/build-env.ts:111`), both empty otherwise, and the supervisor drops inherited spellings of both (`ui/packages/main/src/worker/supervisor.ts:472`). `SCOUT__OPERATOR__PRESENTERSPATH` is the `presenters` folder only when its `presenters.json` reads as a list naming plain file names that are all there, and `SCOUT__OPERATOR__FACEMODELSPATH` the `<media-tools>/face` folder only when both models are there (`ui/packages/main/src/worker/resolve-binary.ts:113`, `:175`, `:176`, `ui/packages/main/src/worker/build-env.ts:113`, `:114`), both empty otherwise, and the supervisor drops inherited spellings of both (`ui/packages/main/src/worker/supervisor.ts:474`, `:475`). The worker reads an empty program path as `ffmpeg` on the system path, then `/opt/homebrew/bin/ffmpeg`, then `/usr/local/bin/ffmpeg`, and an empty font path as no font ([[pages/services/operator]]).

- **macOS.** BtbN publishes no LGPL macOS build, so no `ffmpeg` is bundled: the worker runs the one on the system path, or the Homebrew or `/usr/local/bin` one when the app was started without the shell's path, with the bundled Noto Sans as its font. That ffmpeg must have every filter the assembly uses (`gblur` and `drawtext` among them); the readiness note names the first one missing.

- **CI.** `release.yml` and `ui-ci.yml` cache `ui/build/media-cache` keyed by the hash of `ui/build/media-tools.json` on every OS, so macOS caches the fonts (`.github/workflows/release.yml:180`, `.github/workflows/ui-ci.yml:124`); the fetch itself runs in the existing Package step.
