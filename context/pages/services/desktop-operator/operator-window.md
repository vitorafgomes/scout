## Operator window

The YouTube channel operator has its own window of the desktop app, not a local web site ([[pages/decisions/0033-channel-operator-architecture]]): no port is opened, its pages reach the control plane only through main like every other page, and approvals stay in the desktop. Its `scout:operator.*` channels are listed on [[pages/services/desktop-channels]].

- **Opening.** "Open YouTube operator" on the YouTube card (see YouTube connection) calls `scout:operator.window` (`ui/packages/shared/src/ipc-contract.ts:91`), handled by `registerOperatorWindow` (`ui/packages/main/src/operator/operator-window.ts:39`, called at `ui/packages/main/src/main.ts:1126`). The first call creates the window; while it exists, a second call restores it if minimised, shows it and focuses it, and never opens a second one. After the owner closes it, the next call makes a new one.
- **Window.** 1400 x 900, at least 960 x 640, resizable, titled "Scout - YouTube operator"; the page's own `<title>` does not replace it (`ui/packages/main/src/operator/operator-window.ts:94`). It loads `index.html#/operator`, or the dev server's `/#/operator` in development, and shows once ready.
- **Hardening.** The main window's `webPreferences`: context isolation, no Node integration, sandbox, web security, no insecure content, no experimental features, and the same preload (`ui/packages/main/src/operator/operator-window.ts:78`). Every `window.open` is denied (`:89`) and every navigation is blocked and logged (`:90`). It runs in the default session, so the CSP main sets on every response (`ui/packages/main/src/main.ts:1070`, `:219`) and the microphone rule apply to it unchanged.
- **Who may decide.** `owns` (`ui/packages/main/src/operator/operator-window.ts:127`) tells main whether an IPC call came from the operator window's renderer, so main's sender check reads it as `operator` ([[pages/decisions/0053-electron-fuses-and-ipc-sender-check]]). The eleven deciding `scout:operator.*` channels (claims, delegation, media rights, package approval, publication, proposals, experiments and their winner, comments, replies and ideas; `ui/packages/main/src/ipc/operator.ts:100`) answer only the operator and main windows' own pages, and its Approvals page may approve and reject actions; a grant, a feature's credentials or its setup from the operator window is refused (tests `ui/packages/main/test/ipc-operator.test.ts:1728`, `ui/packages/main/test/operator-window.test.ts:307`).
- **Place.** The bounds are stored as JSON under the main-only vault key `operator.window` (`ui/packages/main/src/vault/safe-storage-vault.ts:23`) when the window is moved or resized (Electron emits those events on macOS and Windows), when it closes, and when Scout quits (`ui/packages/main/src/operator/operator-window.ts:98`, `:100`, `:123`). Read once at start, they are restored only when their top-left corner lies in the work area of a current display (`:88`); otherwise the window opens at the default size. A vault that cannot be read or written is logged with the error code only and never stops the window.
- **Closing with the app.** `dispose` saves the place, destroys the window and removes the handler (`ui/packages/main/src/operator/operator-window.ts:123`); `disposeAll` calls it on quit (`ui/packages/main/src/main.ts:319`), so the tray's Quit and closing the main window with keep running off still quit Scout and take the operator window with them. Closing the operator window alone never quits Scout while the main window or the tray keeps it running.
- **Pages.** `sc-operator-shell` (`ui/packages/renderer/src/app/operator/operator-shell.component.ts:72`) has its own left navigation, Production, Assembly, Comments, Reports, Experiments and Approvals, each with the artboards' own stroke icon (`ui/packages/renderer/src/app/operator/operator-shell.component.ts:28`), and none of the main window's sidebar, wizard shell or update bar. As the prototype draws it, the rail opens with a brand tile (the video icon on the strong accent) beside "YouTube operator" and, under it, the signed-in channel's title from `scout:youtube.status` (`ui/packages/renderer/src/app/operator/operator-shell.component.ts:374`, read once on open, `:372`; a status that cannot be read leaves the brand without the channel line), and the active item sits on surface-2 without the accent bar (`:294`). Since 2026-11-11 "Back to Scout" sits between the brand and the list, as the five artboards draw it (`operator-back-to-scout`, `ui/packages/renderer/src/app/operator/operator-shell.component.ts:88`): a `<button type="button">` styled as the artboards' link, the 15 px stroke arrow before the words, 13 px in `--sc-accent` (#8fb2f9 dark, #2a56c6 light), padding 6 px 10 px 14 px, the arrow 8 px from the words, no underline, the global focus outline, and the brand above it padded 4 px below as the artboards draw it (`:202`, `:204`). It is a button because there is nothing to navigate to and the operator window blocks every navigation. A click calls `scout:app.showMainWindow` (`showScout`, `:381`), which main answers by showing, restoring and focusing the Scout window, or making it again when it is gone, the tray's Open path (`ui/packages/main/src/shell/app-lifecycle.ts:130`, wired at `ui/packages/main/src/main.ts:512`); the operator window stays open and on its page, and a call main does not answer changes nothing in the rail. It shows on every page of the operator window, Approvals included, whether or not YouTube's writes are granted. Only the operator window may call the channel ([[pages/services/desktop-channels]]). Tests: "The operator shell as the five operator artboards draw it, state by state" (`ui/packages/renderer/src/app/operator/operator-shell.component.spec.ts:441`, `:477`, `:494`, `:527`, `:539`, `:550`) and the end-to-end flow `ui/e2e/tests/back-to-scout.spec.ts:3`. Since 2026-11-10 the rail ends with "YouTube feature granted" while the owner has granted the YouTube feature's writes, read from `scout:features.list` on open and again on `scout:features.changed` (hidden when not granted or unreadable), and Approvals carries the main window's count pill for the YouTube actions waiting, the ones its page lists (the shared pending-approvals store, read on open, every 15 s and on `scout:actions.changed`). Production, Assembly, Reports, Experiments and Comments are described below. Approvals is the Review screen filtered to `youtube` (see Review); an action the worker is running has the status `executing` and shows an "Executing" badge instead of Approve and Reject (`ui/packages/renderer/src/app/review/review.component.ts:242`), though today's host lists only `pending` actions in `ListPendingActions`, so an executing one does not reach the list yet; because the filter runs after the last 50 writes are loaded, it can show fewer than 50 YouTube writes when other features wrote more recently. Main pushes `scout:actions.changed` and `scout:features.changed` to every window, so the operator window hears both. The main window's sidebar has no Production entry: its eight entries run from Chat to Settings (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:30`), and the operator window is opened from the YouTube operator entry under them (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:328`).
- **Theme and frame.** The window is fixed to the screen with its top bar outside the one scrolling area, so the bar stays in view on a long page. Production, Assembly, Reports, Experiments and Comments paint only with the theme tokens and follow the light and dark theme; Approvals, the Review screen, follows the theme too since 2026-11-10; any other route keeps the dark canvas, decided per route by the operator shell. The filled main actions carry their icon before the text, as the approved prototype draws them. The tokens and the routes are on [[pages/architecture/desktop-ui-design-system]] and [[pages/services/desktop-ui]].
