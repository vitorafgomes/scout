## Production

- **Presenter** (`:834`), only in an Animated character project, after Claims and before Scenes; the Background block stays as the fallback behind a scene without a picture of its own. Beside its title, the help mark and a header (`presenter-header`, `:847`, `presenterHeader`, `:3096`), "Version <i> of <n> · <source> · <k> of 40 pictures left today", the version and source only while a version is current and the pictures from the readiness's `picturesLeftToday`. Under it "Presenter: <text>" when the project has a presenter description (`project-presenter`, `:850`). The block (`presenter`, `:852`) has two columns, one above the other while the detail is narrower than 720 pixels, a container query on the detail (`:2222`). Left: while the project is `presenting`, "Scout is making the presenter." (`presenter-making`, `:855`); else the current presenter's 5-second preview as a `<video controls>` through `scout-media://<id>/<presenterPreviewFile>?v=<the current version's madeAt>` (`presenter-preview`, `:860`, `presenterStamp`, `:2837`); else, with a picture, the picture (`presenter-picture`, `:866`). Before any version "The presenter is made as soon as the script is ready." (`presenter-pending`, `:876`), and without a picture "No presenter picture yet: Scout makes one when it produces the video if the connected AI Source makes pictures; or attach your own." (`presenter-empty`, `:881`). Under it the versions strip (`presenter-versions`, `:887`), oldest first, each version a 96-pixel thumbnail through `scout-media` with its number and source (Generated, Scout's presenter, Your picture) and the first 60 characters of its feedback, else its prompt. A version is current when both its picture and its preview are the project's (`isCurrent`, `:2831`), the control plane's rule, so two versions of one built-in presenter, which share the picture, are told apart by their previews; the strip is keyed by the version's id, the name the control plane gives it (`ui/packages/renderer/src/app/production/production.component.ts:1255`). The current one is outlined and carries "Current" (`presenter-current-<index>`, `:942`). Every version that is not current is a button (`presenter-use-<index>`, `:902`, labelled "Use presenter version <i>") while the project accepts a presenter request (`presenterRequestable`, `:3025`, the statuses at `:56`), which sends the project id and that version's id, never its position, to `scout:operator.presenterVersion` (`usePresenterVersion`, `ui/packages/renderer/src/app/production/production.component.ts:4283`), and carries a remove mark (`presenter-version-remove-<index>`, `:924`, labelled "Remove presenter version <i>"). The mark follows the control plane's rule (`removable`, `:3392`): never while `presenting`, on every version that is not current, and on a current one only while another version names the same picture and preview, as when the same built-in presenter was asked for twice before it had a preview; every such twin is outlined as current, and the last one cannot be removed. The mark sends the project id and that version's id to `scout:operator.presenterVersionRemoval` (`removePresenterVersion`, `ui/packages/renderer/src/app/production/production.component.ts:4277`) with no confirmation, since remaking costs one of the day's pictures. When either call answers `control-plane/not-found`, the list on screen named a version the control plane no longer has, removed or dropped past 10 since the last read: the page reads the project again from `scout:operator.project`, shows the versions it holds now and says "That version is no longer there; the list was refreshed." in `presenter-error`, sending nothing more; any other failure shows its own sentence there and the rows stay (`presenterVersionAction`, `:4290`, `VERSION_GONE`, `:36`). While either call waits, every Use and Remove button of the strip is disabled (`projectMediaBusy`), so a second click sends nothing (`ui/packages/renderer/src/app/production/production.component.spec.ts:3886`, `:3909`, `:3959`, `:3990`); an end-to-end run on a seeded data folder rewrites `projects.json` behind the open page and clicks Remove on the version it took out (`ui/e2e/tests/production-stale-presenter-version.spec.ts:13`). Right, on a project that accepts a presenter request: "What would you change?" (`presenter-feedback`, `:957`) with "<n> / 300" and "Ask for a change" (`presenter-change`, `:969`), the primary action, which sends the trimmed feedback and an empty prompt (`:3070`), is disabled while the feedback is empty or over 300 and clears the field on the answer; then "Edit the full prompt" (`presenter-prompt-options`, `:984`), closed at first, with "Prompt" (`presenter-prompt`, `:990`), a textarea prefilled with the current version's prompt, else the prompt the worker composes, the direction, then the presenter description or the topic, then the fixed style line, each without a trailing full stop, joined with ". " (`presenterPromptOf`, `:3036`, the style at `:102`), with "<n> / 1500" of the trimmed text; under it, greyed, the safety tail the worker always appends and the owner never edits, "no text, no letters, no logos, no trademarks, no real person's likeness and no public figure." (`presenter-safety`, `:998`, `:104`); and "Generate" (`presenter-generate`, `:1003`), which sends the project id, an empty feedback and the trimmed prompt to `scout:operator.presenterRequest` (`:3057`) and is disabled over 1500 characters. Generate and Ask for a change are disabled with the title "The connected AI Source makes no pictures" while the readiness says no images (`:2548`). Then "Use one of Scout's presenters, or your own picture" (`presenter-own`, `:1020`), closed at first except when the project has a presenter picture and no mouth box, the one case where the owner must act there, and shown while the project accepts a presenter request, offers Attach background or has a picture: when the readiness lists built-in presenters and the project accepts a request, "Scout's presenters" (`presenter-builtin`, `:1031`), a select of their labels, with "Use this one" (`presenter-builtin-use`, `:1044`), which sends the feedback `builtin:<id>` (`:3083`), so the renderer chooses one by id and never sees its file; on the statuses that offer Attach background, "Attach picture", or "Replace picture" once there is one (`presenter-attach`, `:1057`), which sends the project id, an empty scene id and the kind `presenter` to `scout:operator.sceneMedia`; and, with a picture, "Mark the mouth" (`:1066`). "Regenerate picture" is gone, replaced by Generate, and the renderer no longer calls `scout:operator.presenterRegeneration`, which main still serves. Replacing the picture clears the mouth box, which the owner marks again ([[pages/services/control-plane]]). The prompt and the feedback the owner types belong to the selected project: the 10 s refresh keeps them, choosing a project clears them, and a sent prompt goes back to the prefilled one. The answers replace the project and a refusal shows under the block (`presenter-error`, `:1129`), apart from the background's. **Mark the mouth**: over the picture (`presenter-image`), a drag draws a rectangle (pointer events on the wrapper `mouth-area`, `:1068`), which captures the pointer on the press (`:3127`), so a release outside the picture still ends the drag, at the picture's edge, and a `pointercancel` only ends it, keeping the box where the last move left it and reading nothing from the cancel (`:1073`, `:3143`); the pointer is read against the rendered picture, clamped to it and kept in thousandths of its width and height, so the box is stored as fractions of the picture and its natural size is never needed (`:3158`). The saved `mouthBox` is drawn the same way (`mouth-current`, `:1085`) and the new one dashed (`mouth-drawn`, `:1095`); "Save mouth" (`mouth-save`, `:1110`) is enabled once the drawn box is at least 0.02 wide and high (`:2628`) and sends the project id and the box to `scout:operator.mouthBox` (`:3147`), the answer replacing the project and clearing the drawing; "Clear" (`mouth-clear`) drops the unsaved drawing and sends nothing; the hint reads "Drag a box around the mouth so the character speaks." (`mouth-hint`). The drawing belongs to the selected project: the 10 s refresh keeps it and choosing a project clears it.
