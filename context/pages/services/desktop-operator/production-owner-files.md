## Production

**Owner files.** The renderer never sends or receives a path. On `scout:operator.sceneMedia` main asks the control plane for the project's media directory (`GetMediaDirectory`, main only), opens the native file dialog filtered to the kind's extensions (`chooseWithDialog`, `ui/packages/main/src/operator/media.ts:257`, wired at `ui/packages/main/src/main.ts:1011`), and `copyOwnerMedia` (`ui/packages/main/src/operator/media.ts:211`) refuses another extension (audio mp3, wav, m4a, ogg; pictures png, jpg, jpeg, webp; recordings mp4, mkv, webm, mov), a folder, audio over 100 MB, a picture over 20 MB and a recording over 8 GB (`:50`, `:57`, `:64`), with "A recording must be an mp4, mkv, webm or mov file." and "Recordings are at most 8 GB." for a recording (`:65`, `:66`), then copies the file into that directory as `owner-<scene>-<12 hex>.<ext>` without overwriting, as a reflink where the filesystem supports one and a plain copy elsewhere, `COPYFILE_EXCL | COPYFILE_FICLONE`, so on a filesystem with reflinks (Btrfs, APFS, XFS formatted with reflink) an 8 GB recording takes no second 8 GB; a copy refused because the name is taken leaves that file as it was (`:235`, `ui/packages/main/test/operator-media.test.ts:454`). A background is chosen and checked as a picture and copied as `owner-background-<12 hex>.<ext>`, then recorded with the kind `background` and an empty scene id; a presenter picture the same way as `owner-presenter-<12 hex>.<ext>` with the kind `presenter` (`ui/packages/main/src/ipc/operator.ts:719`, `ui/packages/main/test/ipc-operator.test.ts:1152`); a recording is chosen under the filter "Recordings" and copied as `owner-recording-<12 hex>.<ext>` the same way as every owner file, the `owner-` name the control plane requires of a recording ([[pages/services/control-plane]]), then recorded with the kind `recording` and an empty scene id (`ui/packages/main/src/ipc/operator.ts:717`). Only that name goes to `AttachSceneMedia`; when the control plane refuses it, main deletes the copy (`ui/packages/main/src/ipc/operator.ts:736`). A failed copy reaches the renderer as `operator/media-unavailable` with a message that names no path; a closed dialog answers `{ project: null }`. One of Scout's own presenters is chosen by its id from the readiness (`builtin:<id>` on `scout:operator.presenterRequest`, see Presenter above): main copies nothing for it and the renderer never learns its file; the worker copies it into the project's media folder.

**Previews.** Main registers the `scout-media` scheme as standard, secure and streaming, without `bypassCSP`, before the app is ready (`ui/packages/main/src/operator/media.ts:15`, `ui/packages/main/src/main.ts:365`), and serves `scout-media://<projectId>/<fileName>`, any query string ignored (`ui/packages/main/src/main.ts:1014`, `ui/packages/main/src/operator/media.ts:139`): the project id must be letters, digits, `-` and `_` (`:70`), the decoded file name a plain name of at most 120 characters with no separator, no `..`, no leading dot and a known media extension (`:77`); the directory comes from `GetMediaDirectory` and must be absolute, and main keeps it 60 s per project id so a page of previews makes one gRPC call, forgetting it on any error (`:94`, `:195`); the real path of the file, after symlinks, must sit directly in the real directory on every request (`:104`). The reserved host `voice-samples` (`ui/packages/main/src/operator/media.ts:12`; the URL parser lowercases a host, so any case of it), never a project id, which is 32 hex characters, serves `scout-media://voice-samples/<fileName>` from the folder `GetVoiceSamplesDirectory` answers, a main-only rpc of the desktop token, called only from the handler and never from the renderer, which never sees the path (`:148`, wired at `ui/packages/main/src/main.ts:1019`); that directory is kept 60 s and forgotten on any error like a project's, under the same confinement, with the file name and its real path both a plain name with an audio extension, mp3, wav, m4a or ogg (`ui/packages/main/src/operator/media.ts:88`, `:161`), and the same streaming and byte ranges. Anything else, a missing project or sample and a picture or video in that folder included, is a 404. The file is streamed, never read whole: without a `Range` header the answer is 200 with the content type, `Content-Length` and `Accept-Ranges: bytes`; one byte range (`bytes=a-b`, `bytes=a-`, `bytes=-n`) is a 206 with `Content-Range` and its `Content-Length` (`:110`, `:186`); a range that starts past the end, ends before it starts or asks for no bytes is a 416 with `Content-Range: bytes */<size>` (`:171`); a `Range` header that is not one byte range is ignored. The renderer builds the URL from the project id and the file name in the DTO, with `?v=<updatedAt>` encoded so a regenerated or attached file with the same name is fetched again (`ui/packages/renderer/src/app/production/production.component.ts:2847`). The presenter's preview, `presenter-preview-<n>.mp4`, and each version's picture are files of the project's media folder and are served the same way, the mp4 as `video/mp4` like the assembled video. The content security policy allows `scout-media:` for `img-src` and is the only `media-src`, in the header main sets (`ui/packages/main/src/main.ts:223`, `:224`) and in the page's meta tag (`ui/packages/renderer/src/index.html:10`).
