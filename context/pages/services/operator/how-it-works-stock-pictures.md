## How it works

**Stock pictures.** `OpenversePictures` (`src/Scout.Operator/OpenversePictures.cs:20`) reaches Openverse without an account or a key. `FindAsync` (`src/Scout.Operator/OpenversePictures.cs:82`) sends one `GET https://api.openverse.org/v1/images/?q=<terms>&license=cc0,by,pdm&mature=false&page_size=5` (`src/Scout.Operator/OpenversePictures.cs:212`), the terms cut to 200 characters as the API asks, and takes the first result whose `license` is `cc0`, `pdm` (public domain mark) or `by`, whose `url` is https (an http result is skipped for the next one), whose `width` is at least 800 (a result without a width is skipped) and whose `filetype`, or when it is empty the extension of its `url`, is `jpg`, `jpeg`, `png` or `webp` (`src/Scout.Operator/OpenversePictures.cs:240`, `src/Scout.Operator/OpenversePictures.cs:253`); `by-sa`, `by-nc`, `by-nd` and their combinations are never taken ([[pages/decisions/0033-channel-operator-architecture]]). It downloads that `url` with one GET, reading the headers first (`src/Scout.Operator/OpenversePictures.cs:132`), refuses a response that is not a success (a redirect included: the named client follows none, `src/Scout.Operator/OperatorServiceCollectionExtensions.cs:39`), whose `Content-Type` is not `image/jpeg`, `image/png` or `image/webp` (so no SVG and no GIF) or whose `Content-Length` is over 20 MB (`src/Scout.Operator/OpenversePictures.cs:136`), and streams the body through `MediaFiles.RenderAsync` (`src/Scout.Operator/OpenversePictures.cs:145`) into a hidden file in the media directory, stopping past 20 MB when no length was given (`src/Scout.Operator/OpenversePictures.cs:232`) and refusing a file under 1 KB, then moves it over `scene-<id>.<ext>`; any refusal deletes the hidden file. Each request ends at a deadline that covers the headers and the body, so a body that stalls cannot hang the run: 10 s for the search, 60 s for the picture, from the start of the send and after any pacing wait (a linked `CancellationTokenSource` with `CancelAfter`, `src/Scout.Operator/OpenversePictures.cs:197`, `src/Scout.Operator/OpenversePictures.cs:127`); the expiry gives the unreachable or the not-downloaded note, while the caller's own cancellation still leaves the method. The credit is Openverse's `attribution`, else "<title> by <creator>, <CC0, Public Domain Mark or CC BY> <license_version>, via Openverse" (`src/Scout.Operator/OpenversePictures.cs:256`), cleaned of control characters and of `<` and `>`, which YouTube refuses in a description. Only the search takes one of 100 requests a day (`src/Scout.Operator/OpenversePictures.cs:34`, `src/Scout.Operator/OpenversePictures.cs:90`), counted in this process by its own `SearchBudget` and reset at midnight Pacific time; the download goes to the picture's own host, not to Openverse, so it is neither counted nor paced. Openverse's anonymous burst limit is 20 requests a minute, so the searches are paced: one lock (`_gate`) makes every search, from any caller, start at least 3.1 s (`Interval`) after the start of the previous one, waiting with the injected `TimeProvider`; a 429 that carries `Retry-After` pushes the next start back by that many seconds (capped at 60) and the search is retried once (`src/Scout.Operator/OpenversePictures.cs:160`), a second 429 giving the note below, and a 429 without the header gives it at once (`tests/Scout.Operator.Tests/OpenversePicturesTests.cs`). Spent, the note is "The Openverse picture budget for today is spent; it resets at midnight Pacific time." A 429 gives "No picture: Openverse is limiting Scout's requests for now." (`src/Scout.Operator/OpenversePictures.cs:56`), a timeout, a stalled body, a reset, a 5xx or an answer that is not the JSON gives "No picture: Scout could not reach Openverse.", no result of an allowed licence "No picture: Openverse has no CC0, public domain or CC BY picture for this scene.", and a transport failure or any refusal of the download "No picture: Scout could not download the picture Openverse named as an image of at most 20 MB."; a failure of `MediaFiles` (a folder outside the project, a file that could not be saved, an empty file) carries `MediaFiles`' own sentence instead (`src/Scout.Operator/OpenversePictures.cs:148`), each followed by " The scene shows a text card; attach a background to the project in Scout Desktop, Production, or connect an AI Source with pictures."; nothing but a cancellation leaves the method. The API facts it relies on, read on 2026-11-03 from the API reference (`https://api.openverse.org/v1/#tag/images/operation/images_search`, schema at `/v1/schema/`) and the headers of a live anonymous search: `license` takes `by`, `by-nc`, `by-nc-nd`, `by-nc-sa`, `by-nd`, `by-sa`, `cc0`, `nc-sampling+`, `pdm` and `sampling+`; `mature` defaults to false; `page_size` defaults to 20 and is capped for anonymous users; there is no `fields` parameter; `q` should not exceed 200 characters. The result fields used are `url`, `title`, `creator`, `license`, `license_version`, `filetype` (empty on most Flickr results), `width` ("not always available") and `attribution` ("legally valid attribution for the media item in plain-text English"); `thumbnail`, `creator_url`, `license_url`, `foreign_landing_url` and `height` are returned and not used. The reference states no numbers for anonymous rate limits; the response headers name them, `x-ratelimit-limit-anon_burst: 20/min` and `x-ratelimit-limit-anon_sustained: 200/day`, and an exceeded limit answers 429.

`MediaFiles` (`src/Scout.Operator/MediaFiles.cs:9`) is the only writer of files. It refuses, with "Scout refused to write a file outside the project's media folder.", a media directory that is not an absolute path, and a file name that is empty, starts with a dot (`.` and `..` among them), contains `..` or a backslash, or holds a character the platform forbids in a file name, `/` included (`:67`); it then resolves the full path and refuses one that is not inside the directory or is the directory itself (`:62`, `:77`). It writes a new temporary file in the same directory, opened with `CreateNew` so a planted file or link is never written through, and renames it over the target (`:22`, `:28`); on an I/O failure it deletes the temporary file and fails with "Scout could not save <file> in the project's media folder." A scene id from the control plane that would leave the directory therefore fails the project before anything is written.
