# Desktop operator window

> The part of [[pages/services/desktop-ui]] where the owner runs the YouTube channel operator; the pipeline is the worker's ([[pages/services/operator]]) and its state the control plane's ([[pages/decisions/0033-channel-operator-architecture]]).

- [[pages/decisions/0032-per-feature-write-permissions]] - the owner's YouTube write grant gates a start, a production, an assembly, a publish, an experiment, a comment sync request, a draft request, a reply approval, a hold and using an idea; the approval of a package, its publish settings, a proposal decision, an adoption, each reply and each hold are the owner's, in the desktop. ## Operator window

The YouTube channel operator has its own window of the desktop app, not a local web site ([[pages/decisions/0033-channel-operator-architecture]]): no port is opened, its pages reach the control plane only through main like every other page, and approvals stay in the desktop.

- **Opening.** "Open YouTube operator" on the YouTube card (see YouTube connection) calls `scout:operator.window` (`ui/packages/shared/src/ipc-contract.ts:75`), handled by `registerOperatorWindow` (`ui/packages/main/src/operator/operator-window.ts:39`, called at `ui/packages/main/src/main.ts:721`). The first call creates the window; while it exists, a second call restores it if minimised, shows it and focuses it, and never opens a second one. After the owner closes it, the next call makes a new one.
- **Window.** 1400 x 900, at least 960 x 640, resizable, titled "Scout - YouTube operator"; the page's own `<title>` does not replace it (`ui/packages/main/src/operator/operator-window.ts:94`). It loads `index.html#/operator`, or the dev server's `/#/operator` in development, and shows once ready.
- **Hardening.** The main window's `webPreferences`: context isolation, no Node integration, sandbox, web security, no insecure content, no experimental features, and the same preload (`ui/packages/main/src/operator/operator-window.ts:78`). Every `window.open` is denied (`:89`) and every navigation is blocked and logged (`:90`). It runs in the default session, so the CSP main sets on every response (`ui/packages/main/src/main.ts:159`, `:173`) and the microphone rule apply to it unchanged.
- **Place.** The bounds are stored as JSON under the main-only vault key `operator.window` (`ui/packages/main/src/vault/safe-storage-vault.ts:22`) when the window is moved or resized (Electron emits those events on macOS and Windows), when it closes, and when Scout quits (`ui/packages/main/src/operator/operator-window.ts:98`, `:100`, `:123`). Read once at start, they are restored only when their top-left corner lies in the work area of a current display (`:88`); otherwise the window opens at the default size. A vault that cannot be read or written is logged with the error code only and never stops the window.
- **Closing with the app.** `dispose` saves the place, destroys the window and removes the handler (`ui/packages/main/src/operator/operator-window.ts:123`); `disposeAll` calls it on quit (`ui/packages/main/src/main.ts:231`), so the tray's Quit and closing the main window with keep running off still quit Scout and take the operator window with them. Closing the operator window alone never quits Scout while the main window or the tray keeps it running.
- **Pages.** `sc-operator-shell` (`ui/packages/renderer/src/app/operator/operator-shell.component.ts:10`) has its own left navigation, Production, Assembly, Reports, Experiments, Comments and Approvals (`ui/packages/renderer/src/app/operator/operator-shell.component.ts:10`), and none of the main window's sidebar, wizard shell or update bar. Production, Assembly, Reports, Experiments and Comments are described below. Approvals is the Review screen filtered to `youtube` (see Review); an action the worker is running has the status `executing` and shows an "Executing" badge instead of Approve and Reject (`ui/packages/renderer/src/app/review/review.component.ts:57`), though today's host lists only `pending` actions in `ListPendingActions`, so an executing one does not reach the list yet; because the filter runs after the last 50 writes are loaded, it can show fewer than 50 YouTube writes when other features wrote more recently. Main pushes `scout:actions.changed` and `scout:features.changed` to every window, so the operator window hears both. The main window's sidebar no longer has Production: Features is followed by Review (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:43`).

## Production

The Production page (route `operator/production` in the operator window, see Operator window above, `ui/packages/renderer/src/app/app.routes.ts:86`) is the desktop side of the channel operator ([[pages/roadmap/youtube-channel-operator]] phases 2, 3 and 7, [[pages/decisions/0033-channel-operator-architecture]]). It reads and edits the operator's state in the control plane and holds no pipeline logic; the worker researches, writes the script and makes the media. `ui/packages/renderer/src/app/production/production.component.ts:1096` has these parts:

- **What Scout can make** (`:92`) - the readiness the worker last reported, read once on open from `scout:operator.readiness` (`:1528`): "Narration: available" or "not available", "Generated pictures: available" or "not available", a pictures line (`data-test` `readiness-stock`): "Pictures: generated by <provider>" when images are available, else "Pictures: from Openverse (CC0, public domain or CC BY, credited in the description)" when the worker reported stock pictures, else "Pictures: text cards unless you attach your own", the provider ("none" when empty), "YouTube: signed in" or "not signed in", "Voices: <n> available" or "Voices: none" (`data-test` `readiness-voices`, `:107`), and each note. Before the worker reports, the control plane answers all false with the note "The Scout worker has not reported yet."
- **Mandate** (`:120`) - objective, audience, up to five pillars, cadence, language, voice and style (the `mandate-style` input, `:177`), blocked topics as a comma list, the target metric (Views, Watch hours, Subscribers or Engagement, stored as `views`, `watch_hours`, `subscribers`, `engagement`, `:68`) and the target value. The narration voice is not part of the mandate: it belongs to each video and is chosen when the owner produces it (see Scenes). Save sends every field trimmed, the filled pillars only and the blocked topics split on commas to `scout:operator.saveMandate` (`:1198`), then shows "Saved <yyyy-MM-dd HH:mm>". The renderer builds the URL from the project id and the file name in the DTO, with `?v=<updatedAt>` encoded so a regenerated or attached file with the same name is fetched again (`ui/packages/renderer/src/app/production/production.component.ts:1307`). The content security policy allows `scout-media:` for `img-src` and is the only `media-src`, in the header main sets (`ui/packages/main/src/main.ts:159`, `:173`) and in the page's meta tag (`ui/packages/renderer/src/index.html:10`).

## Assembly

The Assembly page (route `operator/assembly`, `ui/packages/renderer/src/app/app.routes.ts:97`, between Production and Approvals in the operator window's navigation, `ui/packages/renderer/src/app/operator/operator-shell.component.ts:12`) is the desktop side of phase 4 of [[pages/roadmap/youtube-channel-operator]]: the owner asks for the assembled video, watches it, checks it, edits its upload metadata, confirms the media rights and approves the package.
