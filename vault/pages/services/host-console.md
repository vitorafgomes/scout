# Host.Console

> The process the desktop app launches and supervises: it starts whichever adapters are configured and answers until stopped.

## Responsibility

Owns composition, the conversation worker, the readiness marker, the parent watchdog and the `index` command. Does not own behaviour of any piece it wires.

## Public contract

- **Entry point:** `src/Scout.Host.Console/Program.cs`. `ConsoleCommand.Parse` selects run or `index <project>` (`src/Scout.Host.Console/ConsoleCommand.cs:22`); the index path builds a minimal graph (`src/Scout.Host.Console/Program.cs:14`).
- **Composition:** `AddScoutHost` (`src/Scout.Host.Console/HostComposition.cs:33`) registers in order: readiness signal (`:40`), pairing signal (`:41`), LLM (`:43`), skills (`:47`), conversation (`:48`), knowledge (`:49`), Whisper transcription when `Scout:Transcription:ModelPath` exists (`:52`, [[pages/services/transcription-whisper]]), the local adapter when `Scout:Adapters:Local:Enabled` is true, first so stdin has a reader before any network adapter starts (`:56`, [[pages/services/adapter-local]]), three chat adapters (`:57` to `:59`), GitHub plugin (`:62`), Kubernetes plugin (`:63`), YouTube plugin (`:64`, [[pages/services/plugin-youtube]]), the write gate (`:65`), the YouTube channel operator (`:66`, [[pages/services/operator]]), worker (`:68`), watchdog (`:72`). The operator is composed only when the YouTube plugin registered its client (`:108`), the same self-gating as the plugin; it gets `GrpcOperatorControlPlane` when the write gate is open (`:115`) and `ClosedOperatorControlPlane` otherwise (`:119`), and its `OperatorMediaOptions` bound from `Scout:Operator` (`:122`); the operator's publishing and learning (`AddYouTubePublishing`, [[pages/services/operator]]) are added only when the YouTube plugin registered `IYouTubeWriteClient`, which it does only with the desktop sign-in (`:126`). `AddScoutIndexHost` (`:166`) registers LLM and knowledge only, and no write gate, because it composes no plugin. A publish target keeps the target platform's Whisper native libraries as loose files beside the single-file binary (`src/Scout.Host.Console/Scout.Host.Console.csproj:39`). The Kubernetes plugin builds its clients on the first call, so composing it reads no kubeconfig (`tests/Scout.Host.Console.Tests/HostCompositionSmokeTests.cs:159`); the YouTube plugin, configured with a dummy key, lands on the kernel without a call to YouTube (`tests/Scout.Host.Console.Tests/HostCompositionSmokeTests.cs:208`).
- **Runtime types:** `ConversationWorker` (`src/Scout.Host.Console/ConversationWorker.cs:14`), `IReadinessSignal` printing the `SCOUT_READY` marker on stdout (`src/Scout.Host.Console/IReadinessSignal.cs:18`), `StdoutPairingSignal`, the `IPairingSignal` of owner pairing, printing `SCOUT_PAIRED=<id>` when a user pairs and `SCOUT_PAIRING_BURNED` when the code is burned (`src/Scout.Host.Console/StdoutPairingSignal.cs:10`, [[pages/decisions/0021-allowed-users]]), `ParentWatchdogService` (`src/Scout.Host.Console/ParentWatchdogService.cs:13`) with a stdin-EOF probe (`src/Scout.Host.Console/IParentLivenessProbe.cs:23`), or, when the local adapter is registered, a probe that waits on that adapter's `InputClosed`, so stdin has one reader (`src/Scout.Host.Console/IParentLivenessProbe.cs:65`, chosen at `src/Scout.Host.Console/ParentWatchdogRegistration.cs:29`; `AddLocalAdapter` must run before `AddParentWatchdog`, as it does in `AddScoutHost`), `IndexEntryPoint` (`src/Scout.Host.Console/IndexEntryPoint.cs:12`), and the two `IWriteGate` implementations of [[pages/services/llm]]'s write gate: `GrpcWriteGate` (`src/Scout.Host.Console/GrpcWriteGate.cs:15`), registered as itself and as the `IWriteGate` when both the socket path and the token are set (`src/Scout.Host.Console/HostComposition.cs:95`), and `ClosedWriteGate` (`src/Scout.Host.Console/ClosedWriteGate.cs:9`) otherwise, which refuses every write with "Writes are off: Scout Desktop's control plane is not available." The two `IOperatorControlPlane` implementations of [[pages/services/operator]]: `GrpcOperatorControlPlane` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:14`), which calls `WorkerGate` on the `GrpcWriteGate`'s own client, token header and deadline (`src/Scout.Host.Console/GrpcWriteGate.cs:60`), so there is one channel and one token; and `ClosedOperatorControlPlane` (`src/Scout.Host.Console/ClosedOperatorControlPlane.cs:9`), whose every call, the media directory, the readiness report, the approved actions and the comments included, fails with a `ControlPlaneUnavailableException` "Scout Desktop's control plane is not available, so the video operator is off."
- **Configuration keys read here:** `Scout:Adapters:Discord:BotToken`, `Scout:Adapters:Slack:BotToken`, `Scout:Adapters:Teams:AppId`, `Scout:Adapters:Local:Enabled` (startup marker only, `src/Scout.Host.Console/Program.cs:47`, `:59`); everything else is read by the wired projects. `Scout:WorkerGate:SocketPath` and `Scout:WorkerGate:Token`, which the desktop sets as `SCOUT__WORKERGATE__SOCKETPATH` and `SCOUT__WORKERGATE__TOKEN` (empty when there is no control plane) and which are read through configuration binding only; the token goes on each call as `authorization: Bearer <token>` and is never logged. Right after composition reads the two values, it removes from the process environment every variable that configuration reads as the token, in any casing or ':' spelling and with or without the `DOTNET_` or `ASPNETCORE_` prefix, whether or not the gate is opened (`src/Scout.Host.Console/HostComposition.cs:88`, `:135`), so a process the worker starts, such as a kubeconfig exec credential plugin, does not inherit it; `GrpcWriteGate` keeps the value it was given. On Unix the removal changes .NET's own environment block, which `Process.Start` hands to children; native code that reads the C `environ` still sees the original. The `index` command never composes the write gate and so never removes the token. `Scout:Operator:FfmpegPath`, `Scout:Operator:FontPath` and `Scout:Operator:CategoryId` (the YouTube category of an upload, `22` People & Blogs when unset), which the desktop sets as `SCOUT__OPERATOR__FFMPEGPATH`, `SCOUT__OPERATOR__FONTPATH` and `SCOUT__OPERATOR__CATEGORYID` and which bind only when the operator is composed (`src/Scout.Host.Console/HostComposition.cs:122`); an empty program path means `ffmpeg` on the system path, then in `/opt/homebrew/bin` and `/usr/local/bin`, and an empty or missing font makes assembly unavailable ([[pages/services/operator]]). They carry paths, never credentials, and `appsettings.json` does not name them. Environment variable `SCOUT__PARENT_WATCHDOG` enables the watchdog when set to `1` (`src/Scout.Host.Console/ParentWatchdogRegistration.cs:14`). Configuration root is the binary directory (`src/Scout.Host.Console/Program.cs:17`, `:32`).
- **External boundaries:** stdout carries only the readiness and pairing markers and the local adapter's `SCOUT_LOCAL` reply lines; stdin carries the desktop's quick-ask requests to the local adapter; all logs go to stderr (`src/Scout.Host.Console/Program.cs:38`). Network boundaries belong to the wired projects, and so do the `ffmpeg` processes the operator starts, with standard input closed so they never read the local adapter's input ([[pages/services/operator]]), except one: `GrpcWriteGate` calls the control plane's `WorkerGate` service (`RequestWrite`, `RecordWrite`, [[pages/services/control-plane-contracts]]) over the Unix socket the desktop passes, through a `SocketsHttpHandler` whose `ConnectCallback` opens a `UnixDomainSocketEndPoint`, with a 10 s deadline per call (`src/Scout.Host.Console/GrpcWriteGate.cs:57`) and messages up to 16 MB both ways (`:19`, `:52`), because a full comments view, 1000 comments of up to 2000 characters, passes the 4 MB gRPC default once the text is not ASCII; the control plane takes and sends the same size ([[pages/services/host-control-plane]]). Only `allowed` and `queued` are read as such; an empty, unknown or differently cased decision is a refusal (`src/Scout.Host.Console/GrpcWriteGate.cs:82`). A call that fails or misses the deadline throws, and the write gate filter then refuses the write. `GrpcOperatorControlPlane` calls `GetOperatorMandate`, `SaveOperatorProject`, `NextQueuedProject`, `GetOperatorProject`, `ListOperatorProjects`, `GetOperatorMediaDirectory` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:246`), `ReportReadiness` (`:255`) and `GetVoiceSamplesDirectory` (`:634`) the same way and maps the messages to the operator's records field by field, a project's scenes (`:160`) and its video package included (`:581`, `:618`), setting an optional field (a scene's `error`, `audio_file`, `visual_file`; a package's `video_file`, `thumbnail_file`, `approved_at`, `error`) only when it has a value and sending the owner's `rights_confirmed`, `approved_at` and `metadata_edited` back as read; it never sets the readiness `reported_at`, which the control plane stamps; a refusal the control plane words (`PERMISSION_DENIED`, `FAILED_PRECONDITION`, `INVALID_ARGUMENT`, `NOT_FOUND`) keeps its words, and any other failure, a missing socket included, becomes "Scout could not reach its control plane." (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:89`), so no transport text reaches the chat or the desktop; that unreachable failure is a `ControlPlaneUnavailableException` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:95`), so the executor tells it from a worded refusal. `NextApprovedAction` (`:272`) maps the claimed `PendingAction` to an `OperatorAction`, with the response's `origin_reference` when the control plane sends one, `RecordWrite` (`:282`) records it with its id, scope, target and outcome, a refusal containing "already recorded in the write log" being a success and one containing "revoked" a `WriteRevokedException` (`:18`), and the publication travels field by field with its snapshots, proposals and experiment (`:420`, `:537`), each optional value (video id, publish time, upload time, error, impressions, click-through rate, a thumbnail file, an arm's start and end, a winner, a result) set only when it has one. `GetComments` and `SaveComments` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:308`, `:316`) carry the `CommentsView` field by field (`:324`, `:395`): every time, `published_at`, `decided_at`, `fetched_at`, `synced_at` and `sync_requested_at`, travels as the string the control plane sent and goes back byte for byte, because the control plane compares a comment the worker sends with the stored one and a reformatted time reads as tampering; a new comment's empty `fetched_at` goes as it is, for the control plane to stamp; `approved_text`, `reply_id`, `error`, `decided_at`, an idea's `project_id` and the sync's three values are set only when they have one. A refusal keeps its words and an unreachable control plane is a `ControlPlaneUnavailableException`, as for the other calls.

## How it works

```mermaid
flowchart TD
    cmd["ConsoleCommand.Parse"] -->|run| full["AddScoutHost"]
    cmd -->|index| min["AddScoutIndexHost"]
    full --> w["ConversationWorker"]
    w --> ad["each IChatAdapter.StartAsync(conductor.HandleAsync)"]
    ad --> rdy["SCOUT_READY on stdout"]
    min --> ix["IndexEntryPoint -> ProjectIndexer"]
```

With no adapter registered the worker writes a hint to stderr and stops the application (`src/Scout.Host.Console/ConversationWorker.cs:25`); a failing adapter start does the same (`:52`). Readiness is signalled only after every adapter has started (`:66`).

- [[pages/invariants/no-executive-writes]]: composes every plugin the model can call, and the write gate every declared write asks; without the desktop's socket and token that gate refuses every write.
- [[pages/invariants/secrets-never-in-source]]: the worker gate token arrives only through configuration binding (`src/Scout.Host.Console/HostComposition.cs:87`), travels only in the call metadata, and leaves the process environment once read (`tests/Scout.Host.Console.Tests/WorkerGateTokenEnvironmentTests.cs:26`).

## Hot spots

- `src/Scout.Host.Console/HostComposition.cs:47`: registration order matters; skills must precede conversation.
- `src/Scout.Host.Console/HostComposition.cs:65`: the operator is composed after the write gate and the YouTube plugin, because it needs the gate's `GrpcWriteGate` and checks for the YouTube client.
- `src/Scout.Host.Console/ConversationWorker.cs:45`: adapters start sequentially, one failure aborts the host.
