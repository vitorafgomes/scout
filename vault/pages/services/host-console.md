# Host.Console

> The process the desktop app launches and supervises: it starts whichever adapters are configured and answers until stopped.

## Responsibility

Owns composition, the conversation worker, the readiness marker, the parent watchdog and the `index` command. Does not own behaviour of any piece it wires.

## Public contract

- **Entry point:** `src/Scout.Host.Console/Program.cs`. `ConsoleCommand.Parse` selects run or `index <project>` (`src/Scout.Host.Console/ConsoleCommand.cs:22`); the index path builds a minimal graph (`src/Scout.Host.Console/Program.cs:14`).
- **Composition:** `AddScoutHost` (`src/Scout.Host.Console/HostComposition.cs:33`) registers in order: readiness signal (`:40`), pairing signal (`:41`), LLM (`:43`), skills (`:47`), conversation (`:48`), knowledge (`:49`), Whisper transcription when `Scout:Transcription:ModelPath` exists (`:52`, [[pages/services/transcription-whisper]]), the local adapter when `Scout:Adapters:Local:Enabled` is true, first so stdin has a reader before any network adapter starts (`:56`, [[pages/services/adapter-local]]), three chat adapters (`:57` to `:59`), GitHub plugin (`:62`), Kubernetes plugin (`:63`), YouTube plugin (`:64`, [[pages/services/plugin-youtube]]), the write gate (`:65`), the YouTube channel operator (`:66`, [[pages/services/operator]]), worker (`:68`), watchdog (`:72`). The operator is composed only when the YouTube plugin registered its client (`:106`), the same self-gating as the plugin; it gets `GrpcOperatorControlPlane` when the write gate is open (`:113`) and `ClosedOperatorControlPlane` otherwise (`:117`). `AddScoutIndexHost` (`:159`) registers LLM and knowledge only, and no write gate, because it composes no plugin. A publish target keeps the target platform's Whisper native libraries as loose files beside the single-file binary (`src/Scout.Host.Console/Scout.Host.Console.csproj:39`). The Kubernetes plugin builds its clients on the first call, so composing it reads no kubeconfig (`tests/Scout.Host.Console.Tests/HostCompositionSmokeTests.cs:159`); the YouTube plugin, configured with a dummy key, lands on the kernel without a call to YouTube (`tests/Scout.Host.Console.Tests/HostCompositionSmokeTests.cs:208`).
- **Runtime types:** `ConversationWorker` (`src/Scout.Host.Console/ConversationWorker.cs:14`), `IReadinessSignal` printing the `SCOUT_READY` marker on stdout (`src/Scout.Host.Console/IReadinessSignal.cs:18`), `StdoutPairingSignal`, the `IPairingSignal` of owner pairing, printing `SCOUT_PAIRED=<id>` when a user pairs and `SCOUT_PAIRING_BURNED` when the code is burned (`src/Scout.Host.Console/StdoutPairingSignal.cs:10`, [[pages/decisions/0021-allowed-users]]), `ParentWatchdogService` (`src/Scout.Host.Console/ParentWatchdogService.cs:13`) with a stdin-EOF probe (`src/Scout.Host.Console/IParentLivenessProbe.cs:23`), or, when the local adapter is registered, a probe that waits on that adapter's `InputClosed`, so stdin has one reader (`src/Scout.Host.Console/IParentLivenessProbe.cs:65`, chosen at `src/Scout.Host.Console/ParentWatchdogRegistration.cs:29`; `AddLocalAdapter` must run before `AddParentWatchdog`, as it does in `AddScoutHost`), `IndexEntryPoint` (`src/Scout.Host.Console/IndexEntryPoint.cs:12`), and the two `IWriteGate` implementations of [[pages/services/llm]]'s write gate: `GrpcWriteGate` (`src/Scout.Host.Console/GrpcWriteGate.cs:14`), registered as itself and as the `IWriteGate` when both the socket path and the token are set (`src/Scout.Host.Console/HostComposition.cs:95`), and `ClosedWriteGate` (`src/Scout.Host.Console/ClosedWriteGate.cs:9`) otherwise, which refuses every write with "Writes are off: Scout Desktop's control plane is not available." The two `IOperatorControlPlane` implementations of [[pages/services/operator]]: `GrpcOperatorControlPlane` (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:13`), which calls `WorkerGate` on the `GrpcWriteGate`'s own client, token header and deadline (`src/Scout.Host.Console/GrpcWriteGate.cs:52`), so there is one channel and one token; and `ClosedOperatorControlPlane` (`src/Scout.Host.Console/ClosedOperatorControlPlane.cs:9`), whose every call fails with "Scout Desktop's control plane is not available, so the video operator is off."
- **Configuration keys read here:** `Scout:Adapters:Discord:BotToken`, `Scout:Adapters:Slack:BotToken`, `Scout:Adapters:Teams:AppId`, `Scout:Adapters:Local:Enabled` (startup marker only, `src/Scout.Host.Console/Program.cs:47`, `:59`); everything else is read by the wired projects. `Scout:WorkerGate:SocketPath` and `Scout:WorkerGate:Token`, which the desktop sets as `SCOUT__WORKERGATE__SOCKETPATH` and `SCOUT__WORKERGATE__TOKEN` (empty when there is no control plane) and which are read through configuration binding only; the token goes on each call as `authorization: Bearer <token>` and is never logged. Right after composition reads the two values, it removes from the process environment every variable that configuration reads as the token, in any casing or ':' spelling and with or without the `DOTNET_` or `ASPNETCORE_` prefix, whether or not the gate is opened (`src/Scout.Host.Console/HostComposition.cs:88`, `:128`), so a process the worker starts, such as a kubeconfig exec credential plugin, does not inherit it; `GrpcWriteGate` keeps the value it was given. On Unix the removal changes .NET's own environment block, which `Process.Start` hands to children; native code that reads the C `environ` still sees the original. The `index` command never composes the write gate and so never removes the token. Environment variable `SCOUT__PARENT_WATCHDOG` enables the watchdog when set to `1` (`src/Scout.Host.Console/ParentWatchdogRegistration.cs:14`). Configuration root is the binary directory (`src/Scout.Host.Console/Program.cs:17`, `:32`).
- **External boundaries:** stdout carries only the readiness and pairing markers and the local adapter's `SCOUT_LOCAL` reply lines; stdin carries the desktop's quick-ask requests to the local adapter; all logs go to stderr (`src/Scout.Host.Console/Program.cs:38`). Network boundaries belong to the wired projects, except one: `GrpcWriteGate` calls the control plane's `WorkerGate` service (`RequestWrite`, `RecordWrite`, [[pages/services/control-plane-contracts]]) over the Unix socket the desktop passes, through a `SocketsHttpHandler` whose `ConnectCallback` opens a `UnixDomainSocketEndPoint`, with a 10 s deadline per call (`src/Scout.Host.Console/GrpcWriteGate.cs:49`). Only `allowed` and `queued` are read as such; an empty, unknown or differently cased decision is a refusal (`src/Scout.Host.Console/GrpcWriteGate.cs:74`). A call that fails or misses the deadline throws, and the write gate filter then refuses the write. `GrpcOperatorControlPlane` calls `GetOperatorMandate`, `SaveOperatorProject`, `NextQueuedProject`, `GetOperatorProject` and `ListOperatorProjects` the same way and maps the messages to the operator's records field by field, setting an optional field only when it has a value; a refusal the control plane words (`PERMISSION_DENIED`, `FAILED_PRECONDITION`, `INVALID_ARGUMENT`, `NOT_FOUND`) keeps its words, and any other failure, a missing socket included, becomes "Scout could not reach its control plane." (`src/Scout.Host.Console/GrpcOperatorControlPlane.cs:86`), so no transport text reaches the chat or the desktop.

## How it works

```mermaid
flowchart TD
    cmd["ConsoleCommand.Parse"] -->|run| full["AddScoutHost"]
    cmd -->|index| min["AddScoutIndexHost"]
    full --> w["ConversationWorker"]
    w --> ad["each IChatAdapter.StartAsync(conductor.HandleAsync)"]
    ad --> rdy["SCOUT_READY on stdout"]
    min --> ix["IndexEntryPoint -> ProjectIndexer"]
```

With no adapter registered the worker writes a hint to stderr and stops the application (`src/Scout.Host.Console/ConversationWorker.cs:25`); a failing adapter start does the same (`:52`). Readiness is signalled only after every adapter has started (`:66`).

- [[pages/invariants/no-executive-writes]]: composes every plugin the model can call, and the write gate every declared write asks; without the desktop's socket and token that gate refuses every write.
- [[pages/invariants/secrets-never-in-source]]: the worker gate token arrives only through configuration binding (`src/Scout.Host.Console/HostComposition.cs:87`), travels only in the call metadata, and leaves the process environment once read (`tests/Scout.Host.Console.Tests/WorkerGateTokenEnvironmentTests.cs:26`).

## Hot spots

- `src/Scout.Host.Console/HostComposition.cs:47`: registration order matters; skills must precede conversation.
- `src/Scout.Host.Console/HostComposition.cs:65`: the operator is composed after the write gate and the YouTube plugin, because it needs the gate's `GrpcWriteGate` and checks for the YouTube client.
- `src/Scout.Host.Console/ConversationWorker.cs:45`: adapters start sequentially, one failure aborts the host.
