# Desktop quick ask

> The part of [[pages/services/desktop-ui]] that lets the owner ask Scout from anywhere on the desktop; the worker side is [[pages/services/adapter-local]].

The owner's way to ask Scout from anywhere on the desktop, without a chat platform ([[pages/decisions/0028-local-quick-ask-assistant]]).

- **Shortcut.**
  - `registerQuickAsk` (`ui/packages/main/src/quick-ask/quick-ask.ts:227`, called at `ui/packages/main/src/main.ts:692`) registers `CommandOrControl+Alt+Space`, or the shortcut stored under the main-only vault key `quick-ask.shortcut` (`ui/packages/main/src/vault/safe-storage-vault.ts:19`), with `globalShortcut`. `disposeAll`, run by the single `before-quit`, unregisters it (`ui/packages/main/src/main.ts:224`).
  - Settings, "Floating button and quick ask", shows it and saves a new one through `scout:local.setShortcut` (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:107`, `:436`). `scout:local.getShortcut` and `setShortcut` answer the accelerator, `registered` (what `globalShortcut.register` returned) and `hint` (`ui/packages/main/src/quick-ask/quick-ask.ts:426`). On Wayland the hint is "Your desktop (Wayland) does not let apps register global shortcuts. Add a custom shortcut in your system settings that runs: <command>", the command being the `APPIMAGE` path or the running executable followed by `--ask`, quoted when the path holds a space (`ui/packages/main/src/quick-ask/quick-ask.ts:419`); main passes `process.execPath`. Settings shows it under the shortcut while the input stays usable (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:177`); elsewhere it is null.
  - Main registers the new shortcut before it releases the old one. A `false` from `register` keeps the old shortcut and returns "That shortcut is taken"; an accelerator `register` throws on also keeps the old one (`ui/packages/main/src/quick-ask/quick-ask.ts:449`).
- **Window.**
  - `openQuickAsk()` (`ui/packages/main/src/quick-ask/quick-ask.ts:98`) is what the shortcut calls, and what the tray's Ask Scout... item calls.
  - It shows one 640 by 420 frameless, always-on-top window, resizable down to 360 by 240, sandboxed, with context isolation and the existing preload. Navigation and new windows are blocked. A 14 px strip labelled "Scout" across the top of the page drags the window; its input and buttons are marked `no-drag` so they stay clickable (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:36`).
  - The window loads `index.html` at `#/quick-ask`. When it is created it goes back to the bounds it was last left at, stored as JSON `{ x, y, width, height }` under the main-only vault key `quick-ask.window` whenever it hides or closes (`ui/packages/main/src/quick-ask/quick-ask.ts:326`), if their top-left point lies in the work area of a current display; otherwise, and when nothing or something malformed is stored, it goes to the floating button's corner of the chosen display (see Floating button). A failed save is a warning. A window that was only hidden shows again where it was. It is focused, and hidden on blur or on `scout:local.hide`, which Escape and the page's Close button call (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:271`); hiding it shows the floating button again (`ui/packages/main/src/quick-ask/quick-ask.ts:352`). On the owner's COSMIC desktop (Wayland, Scout as an XWayland client) a window closed with Close came back behind other apps on the next click; the X window manager there (Smithay) never sets `_NET_WM_STATE_ABOVE` on Scout's windows and the X stacking list does not show native Wayland windows, so the exact cause is not visible from X11. The owner confirmed on 2026-11-02 that the window reopens in front after `open()` re-asserts it at the `floating` level and raises the window with `moveTop` every time it shows it, and `showBubble()` re-asserts it at `screen-saver` every time it shows the floating button, on every platform (`ui/packages/main/src/quick-ask/quick-ask.ts:377`, `:318`).
- **Floating button.**
  - A 64 by 64 window of its own (`ui/packages/main/src/quick-ask/quick-ask.ts:297`), created at startup unless the owner turned it off: transparent, frameless, always on top, out of the taskbar, not resizable, not focusable, no shadow, `acceptFirstMouse` so a click on the inactive window reaches the page on macOS, the same sandboxed web preferences as the quick-ask window, shown with `showInactive` so it never takes focus. It loads `#/floating-button`, `FloatingButtonComponent` (`ui/packages/renderer/src/app/floating-button/floating-button.component.ts:56`): one 56 px blue round button labelled "Ask Scout", on a page whose background it makes transparent and whose margin it removes (`:59`). The window is a 64 px square around the 56 px circle, so it takes clicks only in that square.
  - A click calls `scout:local.open` (`:67`), which runs the quick-ask `open()` (`ui/packages/main/src/quick-ask/quick-ask.ts:529`); the bubble hides while the quick-ask window is shown (`:352`).
  - `placeInCorner` (`ui/packages/main/src/quick-ask/placement.ts:11`) gives the point 16 px inside a corner of a display's work area; `place` (`ui/packages/main/src/quick-ask/quick-ask.ts:287`) uses the display nearest the mouse cursor, or the primary display, as stored. It positions on Wayland too. On Linux in a Wayland session that also has XWayland (`DISPLAY` set), main relaunches Scout once with `--ozone-platform=x11` before anything else starts (`ui/packages/main/src/shell/x11-relaunch.ts:12`, `ui/packages/main/src/main.ts:114`), exiting only once the new process has started and otherwise staying a native Wayland client with a warning (`ui/packages/main/src/shell/x11-relaunch.ts:41`), the AppImage from `APPIMAGE` when the app is packaged, and never when an ozone platform is already on the command line; the position and always-on-top then go through XWayland. COSMIC's X window manager overrides the position, always-on-top and frame of every window it manages and leaves unfocusable windows alone, but an unmanaged window never gets the keyboard there, so only the bubble is created with `focusable: false`; the quick-ask window is focusable on every platform (`ui/packages/main/src/quick-ask/quick-ask.ts:352`), and on COSMIC it opens where the window manager places it, with a frame. Without XWayland Scout stays a native Wayland client and the compositor places the windows. A runtime `appendSwitch('ozone-platform', 'x11')` from main does not change the browser process's platform and crashes the GPU process, hence the relaunch. On macOS both windows join every Space and stay above full-screen apps (`ui/packages/main/src/quick-ask/quick-ask.ts:276`).
  - Settings, "Floating button and quick ask" (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:107`), has the "Show the floating button" switch, Top left, Top right, Bottom left and Bottom right, and "Display with the mouse cursor" or "Primary display", each with `aria-pressed`. Every change sends the whole `{ enabled, corner, display }` through `scout:local.setBubble` and shows what main returned, or main's refusal (`:422`).
  - Main validates the three fields (otherwise `quick-ask/invalid-bubble`), stores the JSON under the main-only vault key `quick-ask.bubble` (`ui/packages/main/src/vault/safe-storage-vault.ts:20`) and applies it: off destroys the window, on creates it if missing, a new corner or display moves it (`ui/packages/main/src/quick-ask/quick-ask.ts:430`). An unreadable or malformed stored value means the default, bottom-right on the cursor's display, with a warning (`:383`).
  - `--ask` opens quick ask: a second launch with it calls `onAsk` instead of showing the main window (`ui/packages/main/src/shell/app-lifecycle.ts:156`). On a first launch `launchWindow` opens quick ask at once when the launch is hidden, and otherwise only when the main window emits `show` (`:65`, `:66`), so the main window's show does not take the focus and hide quick ask. This is the command the Wayland hint tells the owner to bind.
- **Asking.**
  - The renderer's `LocalConversation` (`ui/packages/renderer/src/app/core/local-conversation.ts:13`) picks a UUID per question and calls `scout:local.ask` with the text or the recording.
  - Main validates it (`ui/packages/main/src/quick-ask/quick-ask.ts:135`): an id of 1 to 64 letters, digits and hyphens, text of 1 to 4,000 characters, `audio/wav` base64 of at most 14,000,000 characters. An id already in the conversation is refused. It then appends a running turn with the question, or "(voice message)" for a recording, and writes one JSON line to the worker's stdin (`:491`).
  - With no running worker the turn fails with "Scout is not running. Start it from the tray or the app." as its reply and the call is refused with `local/not-running`. A refusal that never became a turn shows on the window's error line (`ui/packages/renderer/src/app/core/local-conversation.ts:62`).
  - A new question while a turn is still being answered sends `scout:local.cancel` for it (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:288`), so the worker stops that reply.
- **Replies.**
  - The supervisor hands each `SCOUT_LOCAL` JSON to `handleWorkerLine`, which applies it to the running turn whose id it carries: `update` sets the reply, `complete` the reply, citations and `done`, `fail` the reply and `failed` (`ui/packages/main/src/quick-ask/quick-ask.ts:535`). Unknown ids, events after `complete` or `fail`, and lines that are not one of these events are dropped; so is a `fail` whose id is null, which the worker sends for a request it could not read.
  - The worker also sends progress of its own, such as the channel operator's, as `{"id":null,"event":"notice","text":"..."}`. `toLocalEvent` branches on the event kind, not the id: only a `notice` with a null id and non-empty text is kept (`ui/packages/main/src/quick-ask/quick-ask.ts:203`). `handleWorkerLine` appends it as its own turn, never to a running one: id `notice:<n>` (a colon, so it never matches a question id), no question, the text cut to 32,000 characters as the reply, `done`, and `notice: true` on `LocalTurn` (`ui/packages/main/src/quick-ask/quick-ask.ts:538`, `ui/packages/shared/src/ipc-contract.ts:1158`). It arrives with or without a question running, is sent to every window like any turn, and counts toward the last 200. The quick-ask window and the Chat screen show it as a Scout message with no question line (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:79`, `ui/packages/renderer/src/app/chat/chat.component.ts:41`), as plain text like every reply.
  - A failed stdin write, or a worker exit, ends every running turn with "Scout stopped before it finished answering." (`:270`, `:518`).
  - Every change sends the whole conversation on `scout:local.turns` to every open window (`:248`). `scout:local.getTurns` returns it, and `scout:local.clearTurns` empties it unless a turn is running (`:512`). It keeps the last 200 turns, in memory only.
  - The box lists every turn, the question then the reply as plain text with its line breaks, scrolled to the newest. Citations with a URL open through `scout:app.openExternal` and its host allow-list.
- **Microphone.**
  - Holding Space while the question box is empty, or holding the microphone button, records (`ui/packages/renderer/src/app/quick-ask/quick-ask.component.ts:247`).
  - `WavRecorder` (`ui/packages/renderer/src/app/quick-ask/wav-recorder.ts:51`) captures with `getUserMedia`, an `AudioContext` at 16 kHz and a `ScriptProcessorNode`, because the CSP blocks a blob-URL `AudioWorklet`. The processor reaches the output only through a gain node at 0 (`:105`), so the microphone is never played back through the speakers, where echo cancellation could take the owner's voice for echo.
  - It keeps the samples in memory, stops at 5 minutes, and encodes 16-bit PCM WAV on release. A stop that arrives while the microphone is still opening waits for it and then stops the stream and closes the context, and each start first releases any microphone still open. Escape, or the window losing focus, discards the recording and sends nothing.
  - `allowMicrophoneOnlyForApp` (`ui/packages/main/src/quick-ask/quick-ask.ts:103`, applied at `ui/packages/main/src/main.ts:688`) grants `media` only to the app's own page (the `file:` URL of `index.html`, or the dev server origin) and only for audio. Other permissions keep Electron's default grant.
  - macOS gets `NSMicrophoneUsageDescription` (`ui/build/electron-builder.yml:83`) and the audio-input entitlement (`ui/build/entitlements.mac.plist:11`).
- **Worker side.** `buildEnv` sets `SCOUT__ADAPTERS__LOCAL__ENABLED=true` (`ui/packages/main/src/worker/build-env.ts:60`), so the worker always runs [[pages/services/adapter-local]], next to Discord or Slack or on its own: with neither connected `buildEnv` no longer throws and the worker starts with only the local adapter.
- **No chat platform.** The welcome screen shows "Skip for now — use Scout from this computer" and "No Discord or Slack needed: chat with Scout in this window." while nothing is set up and client detection has finished (`ui/packages/renderer/src/app/wizard/welcome/welcome.component.ts:61`), so the skip cannot race the launch's own worker start. It calls `WizardStore.useLocalOnly` (`ui/packages/renderer/src/app/core/wizard.store.ts:91`), which keeps `scout:local-only` in `localStorage` and counts as provisioned, then starts the worker and opens Chat (`ui/packages/renderer/src/app/wizard/welcome/welcome.component.ts:195`). On later launches the welcome screen starts the worker by itself, as for Discord or Slack, and then, once per launch, opens Chat while neither Discord nor Slack is connected (`WizardStore.takeLandingUrl`, `ui/packages/renderer/src/app/core/wizard.store.ts:84`).
- **Chat screen.** The main window's Chat screen (route `chat`, first in the sidebar) asks Scout over the same `scout:local.*` channels, for owners whose desktop does not deliver the global shortcut or show the tray (COSMIC on Wayland). It and the quick-ask window show one and the same conversation, held in main.
  - `LocalConversation` (`ui/packages/renderer/src/app/core/local-conversation.ts:13`) is provided in root in each window; it loads the list with `scout:local.getTurns` and follows `scout:local.turns`, so a reply that finishes while another screen is open, or a question asked from the quick-ask window, still lands in the history. The history is in memory only, never on disk, and Clear empties it for both windows (`:52`).
  - Enter sends and Shift+Enter adds a line. One question runs at a time: Send, the microphone and Clear wait, and Stop sends `scout:local.cancel` for the running turn (`:44`).
  - Holding the microphone button records with the same `WavRecorder` and sends the voice request. Releasing the button, or the window losing focus or the screen closing, ends the recording (`ui/packages/renderer/src/app/chat/chat.component.ts:264`, `:282`).
  - With no running worker the turn's reply is "Scout is not running. Start it from the tray or the app.", and for that `local/not-running` refusal only the turn also shows Start Scout (`:48`), which calls `scout:worker.start` once and then disappears (`:249`); the owner asks again with Send. Any other refusal shows on the error line.
  - Clear empties only the conversation main holds. The worker's conversation memory for the local channel survives until it expires or the worker restarts, so a question after Clear can still draw on earlier turns (followup in [[pages/roadmap/followups]]).
