# Desktop channels

> The IPC channel catalogue of [[pages/services/desktop-ui]], and the detail of the whisper and update channel families.

## IPC channels

- **IPC channels** - one hundred and forty-five `scout:*` channels declared in `ui/packages/shared/src/ipc-contract.ts:5`, grouped as detect, discord, vault, worker, app, diagnostics, llm, whisper, shell, providers, features (with `scout:features.writeGrant`, `ui/packages/shared/src/ipc-contract.ts:54`), actions and writes (`scout:actions.list`, `approve`, `reject`, the pushed `changed`, and `scout:writes.list`, `:56`), operator, thirty-seven channels (`scout:operator.mandate`, `saveMandate`, `projects`, `project`, `startProject`, `decideClaim`, `production`, `delegation`, `projectDeletion`, `sceneOrder`, `sceneLock`, `sceneRegeneration`, `sceneText`, `narrationRegeneration`, `mouthBox`, `presenterRegeneration`, `presenterRequest`, `presenterVersion`, `presenterVersionRemoval`, `scenePicturePrompt`, `scenePictureRegeneration`, `sceneMedia`, `readiness`, `window`, `assembly`, `mediaRights`, `packageMetadata`, `packageApproval`, `publication`, `proposalDecision`, `experiment`, `experimentAdoption`, `comments`, `commentSync`, `commentDecision`, `replyApproval` and `ideaDecision`, `ui/packages/shared/src/ipc-contract.ts:61` to `:97`), chatgpt, github, youtube, kubernetes, access, slack, desktop, update (`scout:update.getState`, `setCheckEnabled`, `checkNow`, `skipVersion`, `remindLater`, `install` and the pushed `notice` and `progress`, `ui/packages/shared/src/ipc-contract.ts:138`) and local (`scout:local.ask`, `cancel`, `getTurns`, `clearTurns`, `turns`, `hide`, `getShortcut`, `setShortcut`, `open`, `getBubble`, `setBubble`, and for live listening `listen` (with a lane, `me` or `others`, and a translation mode, `off`, `system` or `channel`), `audio`, `stopListening` and the pushed `transcript`, which also carries each final's translation, and `readText` for the text on a screenshot, and for kept meetings `keepMeeting`, `meetings`, `exportMeeting` and `deleteMeetings`, `ui/packages/shared/src/ipc-contract.ts:118`, `:129`, `:133`, `:134`). Two channels call a cloud LLM provider, both a `GET` of its model list: `scout:providers.validateKey` (`ui/packages/main/src/ipc/provider-keys.ts:44`) checks an API key before it is stored, and `scout:llm.listModels` (`ui/packages/main/src/ipc/provider-keys.ts:161`) lists a connected provider's chat models with the stored key. `scout:vault.getPublic` (`ui/packages/main/src/ipc/vault.ts:89`) is the renderer's only vault read, limited to `llm.provider` and `llm.cloud-model`. The renderer sees only what `ui/packages/preload/src/preload.ts` bridges.

## Whisper models

`WHISPER_MODEL_FILES` (`ui/packages/main/src/worker/whisper-model.ts:17`) pins every model Scout downloads or loads by byte size and SHA-256. The values were read from `https://huggingface.co/api/models/ggerganov/whisper.cpp/tree/main` on 2026-11-04 at 00:09 UTC, each entry's `size` and `lfs.oid` (the LFS object id, which is the file's SHA-256; the API has no `lfs.sha256` field), and `ggml-base.bin` was downloaded once through the handler below and measured at the pinned size and digest:

|---|---|---|---|
| tiny | `ggml-tiny.bin` | 77,691,713 | `be07e048e1e599ad46341c8d2a135645097a538221678b7acdd1b1919c6e1b21` |
| base | `ggml-base.bin` | 147,951,465 | `60ed5bc3dd14eea856493d334349b405782ddcaf0028d4b5df4088345fba2efe` |

| large-v3-turbo | `ggml-large-v3-turbo.bin` | 1,624,555,275 | `1fc70f774d38eb169993ac391eea357ef47c88757ef72ee5943879b7e8e2bc69` |
| large-v3 | `ggml-large-v3.bin` | 3,095,033,483 | `64d182b440b98d5203c4f9bd541544d84c605196c4f7b845dfa11fb23594d1e2` |

- **Verified before use.** `verifyWhisperModel` (`ui/packages/main/src/worker/whisper-model.ts:78`) accepts a file only at the pinned size and then the pinned SHA-256, hashed as a stream. After a successful hash it writes `<file>.sha256` with the digest, the size and the mtime; the next check trusts that sidecar and skips the hash only while it names the pinned digest and the file's size and mtime are unchanged, so a 1.6 GB model is hashed once, not at every start. A file that fails either check is never loaded and stays on disk.
- **Which model.** `chooseWhisperModel` takes the `stt.model` vault value (`whisper-<variant>` or `<variant>`) when that model is verified, otherwise the first verified of large-v3-turbo, large-v3, small, base and tiny (`:45`); main reads `stt.model` with a failed read counting as none. `LocalModelsStore` writes `stt.model` with the catalog id (`whisper-<variant>`) when the owner selects a transcription model on the Local Models screen, or when the first one downloaded is selected automatically, and deletes it when the selected model is removed (`ui/packages/renderer/src/app/core/local-models.store.ts:132`, `:143`, `:163`); with none set the best verified model is used. The choice is read at worker start only, so a change applies from the next worker start, as for a downloaded model, and the screen shows no restart hint for it, as it shows none for `llm.model`.
- **Download.** `scout:whisper.downloadModel` (`ui/packages/main/src/ipc/whisper.ts:73`) refuses a `content-length` other than the pinned size before it reads or writes anything, hashes every chunk as it arrives, cuts off a body that runs past the pinned size, and after the last chunk requires the pinned size and digest; any failure, a reset or an HTTP error included, removes the `.partial` file and rejects, a digest mismatch with "whisper: checksum mismatch for <file>" (`:173`), the shape of `fetchPinned` in `ui/build/scripts/fetch-media-tools.mjs:51`. Only then is the file renamed into place and its sidecar written. Progress counts against the pinned size. Delete removes the model, its `.partial` and its sidecar.
- **Verified flag.** `scout:whisper.listInstalled` answers `{ variant, verified }` per model file present (`ui/packages/main/src/ipc/whisper.ts:60`, `WhisperInstalledModel` in `ui/packages/shared/src/ipc-contract.ts`), and the Local Transcriptions screen marks only verified ones as downloaded (`ui/packages/renderer/src/app/sources/local-models.component.ts:841`), so a file with a wrong hash shows Download again.
- **Catalog.** Local Transcriptions offers Whisper Tiny, Base, Small, Large v3 and Large v3 Turbo with their sizes (`ui/packages/renderer/src/app/core/local-models.catalog.ts:18`); Base carries the Recommended tag and "Recommended for live transcription: words appear within about a second on most computers." (`:29`), and Large v3 keeps its row for existing installs without the tag.

## Update notice

Scout Desktop tells the owner when a newer release is on GitHub Releases and shows what is new. Where the package can replace itself (an AppImage or the Windows installer) the bar offers Update and restart; elsewhere it offers Download. Nothing is downloaded or installed until the user clicks ([[pages/decisions/0031-desktop-self-update]]).

- **Check.** `registerUpdateNotice` (`ui/packages/main/src/update/update-notice.ts:131`, called at `ui/packages/main/src/main.ts:579`) schedules the first check 10 s after start and then one every 24 hours (`ui/packages/main/src/update/update-notice.ts:467`, `ui/packages/main/src/update/update-notice.ts:382`), while "Check for new versions" is on. A check (`ui/packages/main/src/update/update-notice.ts:374`) is one unauthenticated `GET https://api.github.com/repos/vitorafgomes/scout/releases/latest` with `Accept: application/vnd.github+json` and `User-Agent: Scout-Desktop/<version>`, nothing else, and a 15 s timeout (`ui/packages/main/src/update/update-notice.ts:218`); only one runs at a time. A development build (`app.isPackaged` false) never fetches and never schedules.
- **Decision** (`ui/packages/main/src/update/update-notice.ts:246`). The tag loses a leading `v` and is compared with `app.getVersion()` by `compareVersions` (`ui/packages/shared/src/version.ts:20`): numeric major.minor.patch, a prerelease below its release, anything unparseable as 0.0.0. A newer release that is neither a draft nor a prerelease, and not the version stored under `update.skipped-version`, becomes the notice: both versions, the release body as plain text, the release page and the download for this machine from `pickDownload` (`ui/packages/shared/src/version.ts:34`): the AppImage when `APPIMAGE` is set, otherwise the deb on Linux, the dmg whose name carries the arch on macOS, the exe on Windows, and the release page when no asset matches. The notice also carries `canInstall` (see Install). The notice goes on `scout:update.notice` to every window and to the tray; anything else clears it.
- **Result.** `update.last-check` keeps `{ at, result }`, the result being `up-to-date`, `available <version>`, `skipped <version>`, `error <kind>` with kind `http <status>`, `network`, `timeout` or `parse`, or `error install <kind>` after a failed install (see Install). A failed check is logged at info, leaves the notice as it was and never throws.
- **Install.** `canInstall` is `canSelfUpdate` (`ui/packages/main/src/update/update-notice.ts:62`) with an updater given: a packaged build on Windows, or on Linux with `APPIMAGE` set and the running executable inside the mount `APPDIR` names, so an `APPIMAGE` a `.deb` Scout inherited from another AppImage program never counts. `main.ts` passes `electron-updater`'s `autoUpdater` (dependency `electron-updater` ^6.8.12 in `ui/packages/main/package.json`) only in that case and `null` otherwise, so the updater is never constructed on macOS, in a `.deb` or in a development build (`ui/packages/main/src/main.ts:597`). The `Updater` interface (`ui/packages/main/src/update/update-notice.ts:43`) is the part of `AppUpdater` Scout uses. `scout:update.install` (`ui/packages/main/src/update/update-notice.ts:444`) does nothing while an install runs, and answers a `failed` progress when there is no notice or the package cannot update itself. Otherwise `install` (`ui/packages/main/src/update/update-notice.ts:309`) sets `autoDownload`, `autoInstallOnAppQuit` and `allowPrerelease` to false and no other option, so no token or header is configured (`ui/packages/main/src/update/update-notice.ts:338`), then runs `checkForUpdates`. If the updater offers a version other than the notice's, nothing is downloaded, the bar says "The release changed; check again" and the normal check runs again (`ui/packages/main/src/update/update-notice.ts:343`). Otherwise `downloadUpdate` runs, and electron-updater verifies the SHA-512 from `latest-linux.yml` or `latest.yml`. `quitAndInstall(false, true)` runs only after the download resolved and `update-downloaded` fired (`ui/packages/main/src/update/update-notice.ts:350`). Before it, `installing` is broadcast and `prepareForRestart` is awaited for at most 10 s (`ui/packages/main/src/update/update-notice.ts:289`); past that the restart goes ahead and a warning is logged. `main.ts` wires it (`ui/packages/main/src/main.ts:600`) to the lifecycle's `prepareForRestart`, which stops the worker through `stopWorker` (`ui/packages/main/src/shell/app-lifecycle.ts:87`), the same stop `before-quit` uses, so a stop in progress is never started twice and a worker started again later is stopped again on quit, and then calls `app.releaseSingleInstanceLock()`, so the new version can take the lock while the old process is still exiting. When the updater cannot apply the update (`apply`), `recoverFromFailedRestart` takes the lock again and starts the worker again if it was running before. An error or a rejection maps to a kind (`ui/packages/main/src/update/update-notice.ts:72`): `checksum` ("The download did not match the release; nothing was installed"), `no asset` (no `latest*.yml` for this platform), `http <status>`, `timeout`, `network`, `incomplete` (no `update-downloaded`) or `apply` (the updater could not replace the file). The kind becomes a `failed` progress and `error install <kind>` in `update.last-check`, logged at warn; the notice stays. The updater listeners are removed when the install ends and on `dispose`.
- **Progress.** `scout:update.progress` carries `UpdateProgress` (`ui/packages/shared/src/ipc-contract.ts:1418`) to every window: `checking`, then `downloading` with percent, bytes and total, at most once per whole percent, then `ready`, then `installing`, or `failed` with a message.
- **What the AppImage update writes.** electron-updater replaces the file `APPIMAGE` names. When that name carries a version, such as `Scout-Desktop-0.1.0-linux-x86_64.AppImage`, it deletes the old file and writes the new one under the release's name in the same folder, then starts it. On the next start, `refreshLoginEntry` (`ui/packages/main/src/shell/login-item.ts:102`) rewrites the start-at-login entry when it names another executable, so a renamed AppImage keeps starting at login; with start at login off nothing is written. The Windows update runs the NSIS installer (not silent) and starts Scout again.
- **Bar.** `sc-update-notice` (`ui/packages/renderer/src/app/shell/update-notice.component.ts:60`) sits above the page in the post-connect shell (`ui/packages/renderer/src/app/shell/post-connect-shell.component.ts:104`), with `role="status"`: "Scout <latest> is available. You have <current>.", a "Release notes" link, then Update and restart when `canInstall` (`ui/packages/renderer/src/app/shell/update-notice.component.ts:82`) or Download otherwise, Later and Skip this version, and a "What's new" disclosure. While an install runs the buttons are disabled and a progress row (`ui/packages/renderer/src/app/shell/update-notice.component.ts:119`) shows "Checking the release", "Downloading <n>%" with a `<progress>` bar, or "Restarting to install". A failure shows its message with `role="alert"`, the buttons come back, and Download appears next to Update and restart as a secondary button (`ui/packages/renderer/src/app/shell/update-notice.component.ts:88`), so the file can still be fetched by hand. The notes are split into paragraphs on blank lines, lists from `- ` or `* ` lines and headings from `# ` lines, with the `**` around a leading label dropped (`ui/packages/renderer/src/app/shell/update-notice.component.ts:28`), and only ever interpolated as text, so an HTML tag in a release body shows as text. Release notes and Download go through `scout:app.openExternal` and its `github.com` allow-list. Later clears the notice for this run only, so the next daily check shows it again; Skip this version stores the version and clears the notice.
- **Tray.** While a notice exists the tray menu has "Update available: <version>" after Open Scout, which opens the window, and the tooltip ends with " - update available" (`ui/packages/main/src/tray/tray.ts:78`, `:85`).
- **Settings, Desktop.** "Check for new versions" (on by default, `update.check-enabled`) and "Last check: <date> · <result>" with Check now (`ui/packages/renderer/src/app/wizard/settings/settings.component.ts:223`, `:514`); turning the check off cancels the timer and turning it on schedules the first check again, for the session even when the vault cannot store the choice (a warning is logged instead of an error reaching Settings); a vault read that fails at start is logged at warn and the check stays on. A development build shows "Update checks run only in the installed app." instead.
